## 三、整改清单

### P0 必做（不做就再退）

1. **说明书重写成人写版（30–60 页）**，替换当前 110 页机器排版版：
   - 每章配**实机截图**（按操作流程：启动 → 首个关卡 → 吸附 → 过关 → 商店），图注写清"哪一版、什么机型/分辨率"。
   - 写**真实失败与改法**：如吸力场在低帧率迟滞、改为帧率无关 lerp；某关卡目标数过高导致首通 3 分钟。
   - 每个数字标来源（配置表/实测/案卷），不写"约""若干"。
2. **建研发证据链**（提交时随附或备查）：
   - `git log` 的真实提交时间分布（不是打包后的 mtime）、分支与修复记录；
   - 设计迭代稿（至少两版，能看出改动）、测试报告、缺陷单；
   - 说明「AI 作辅助、人工做了哪些具体修改」——这是新规下唯一能翻案的说法。
3. **材料一致性**：软件名称/版本/功能描述/截图必须四处一致（新规高频驳回点）。

### P1 机械修（可脚本批量）

4. 7 套源程序每页行数 <50（G04/G20/G23/G28/P03/P05/P07）→ 重切 55 行/页、页眉连续。
5. `G09_医院大当家` 补 `icon_512.png`。
6. 两对雷同材料（P03↔P04、G13↔G14）→ 换成各自项目的真实代码，并把文件顺序/结构拉开；否则按"重复提交"处理。

### P2 声明与平台

7. 若软件本身含生成式能力 → 提交《合法合规及原创性声明》；若不含 → 备"未使用 AI 生成"的说明与反证（人类修改记录）。
8. 上架 Android 商店时，分发平台会核验 AIGC 标识材料（标识办法第七条），与软著分开准备。

```bash
python Tools/softcopyright_audit.py --only <目录>     # 页数/行数/页眉/名称一致性
python Tools/aigc_trace_audit.py --doc <说明书> --src <源程序> --project <工程>
```

任一条红 → 不送审。**D4（无截图/无失败记录）视为硬红**，不是建议。

## 五、红线

- **不伪造**：不改文件时间戳、不编造 git 历史、不把 AI 生成的说明书伪装成手写。mtime 同源是打包事实，用工 git 历史解释，而不是改时间。
- 不把「AI 辅助」写成「完全没用 AI」——一旦被查（查重/元数据），性质从补正变不诚信。
- 说明书截图必须是**当前版本实机**，不用设计稿冒充。

## 六、一句话

**驳回不是因为用了 AI，是因为材料里找不到"人"：没有截图、没有失败、没有过程、还自己写着"自动生成"。**
