# 捞个宝游戏软件 V1.0 软件设计说明书

## 1. 软件概述

捞个宝是一款深海打捞题材合成经营游戏，运行于Unity引擎，面向Android与iOS小游戏平台。玩家扮演深海打捞队队长，驾驶潜水器在海底遗迹中打捞文物碎片，通过合成系统修复完整文物，在博物馆中展览获取收益，逐步解锁更深海域与剧情线索。

游戏采用打捞-合成-经营核心循环：BattleLauncher驱动深海打捞关卡，玩家在限定时间内收集文物碎片；MuseumSim管理博物馆展览与收益；BuildService提供文物修复与合成功能。每完成一次打捞，消耗体力值，获得碎片与金币奖励。

命名空间为Sy.P07，运行时代码共14个.cs文件，有效代码行1755行。

## 3. 系统架构

游戏启动流程由BootRunner驱动，依次执行BootSequence中的场景切换，注入BootServices注册的单例服务。核心服务包括SaveService（本地存档）、MuseumSim（博物馆经营）、BuildService（合成修复）、ShareService（微信分享）。

打捞模块由BattleLauncher统一调度：传入DiveState当前海域与体力值，BattleView负责渲染潜水器、海底场景与收集特效。打捞采用限时收集玩法，玩家操控潜水器在海底移动，触碰文物碎片自动收集，避开障碍物与海洋生物。

```
BootRunner → BootSequence → BootServices
                           ├── SaveService
                           ├── MuseumSim
                           ├── BuildService
                           └── ShareService
MainLoop → BattleLauncher（深海打捞）→ BuildService（合成修复）→ MuseumSim（博物馆经营）
         → StoryLauncher（剧情探索）→ CollectionBook（图鉴）
```

## 4. 核心模块设计

### 4.1 深海打捞系统

BattleLauncher驱动打捞关卡。每个海域有独立的海底地图，地图中散布文物碎片、金币宝箱、障碍物与海洋生物。玩家操控潜水器在2D侧视视角中移动，上下浮动控制深度，左右移动探索区域。

打捞关卡有时间限制（默认90秒），时间结束或体力耗尽时自动返回。收集到的碎片按文物类型分类，稀有度分为：普通、稀有、史诗、传说。稀有碎片出现概率更低，需要探索更深海域。

障碍物包括：礁石（碰撞损失时间）、暗流（推动潜水器）、水母（触碰损失体力）。海洋生物有概率掉落稀有碎片，但需要躲避攻击。

### 4.2 合成修复系统

BuildService管理文物的合成与修复。每件完整文物由3-6个碎片组成，收集齐所有碎片后可合成完整文物。合成过程需要消耗金币与修复材料，修复材料从打捞中获取。

文物修复有品质判定：根据修复时的材料选择与操作精度，修复结果分为：破损、普通、完好、完美。完美修复的文物展览收益翻倍，并解锁特殊图鉴条目。

合成系统采用二合一机制：两个低级碎片可合成一个高级碎片，降低收集难度。BuildService提供批量合成功能，自动合并重复碎片。

### 4.3 博物馆经营系统

MuseumSim管理博物馆的展览与收益。修复完成的文物可放置在展厅中展览，每件文物每分钟产生金币收益。展览收益由文物稀有度、修复品质、展厅等级共同决定。

博物馆分为多个展厅：古代文明厅、海洋文明厅、艺术珍品厅、神秘遗迹厅。每个展厅有独立的主题加成，放置对应主题的文物获得额外收益。展厅升级提升容量与加成倍率。

游客系统由VisitorSim驱动，游客数量随博物馆声望提升。游客有概率触发特殊事件：高价收购、捐赠请求、媒体采访，完成事件获得额外奖励。

### 4.4 海域探索系统

海域分为五个深度层级：浅海（0-50米）、中海（50-200米）、深海（200-500米）、深渊（500-1000米）、海沟（1000米以上）。每个海域有独立的文物类型与海洋生物，越深的海域稀有文物概率越高。

海域解锁需要满足博物馆声望等级与潜水器升级条件。潜水器升级由BuildService管理，提升潜水器的深度上限、体力值、移动速度与碎片容量。

每个海域有独立的剧情线索，收集特定文物后解锁StoryLauncher驱动的剧情对话，逐步揭开海底遗迹的秘密。

### 4.5 剧情探索系统

StoryLauncher驱动剧情对话与任务系统。剧情分为主线与支线：主线围绕海底遗迹的起源与神秘文明展开，支线涉及特定文物的历史背景与打捞队成员的故事。

剧情对话采用分支选择，玩家的选择影响后续剧情走向与NPC关系。关键剧情节点需要收集特定文物才能解锁，鼓励玩家探索不同海域。

任务系统由QuestManager管理，日常任务包括：打捞指定碎片、修复指定文物、达到展览收益目标。完成任务获得体力药水与金币奖励。

### 4.6 图鉴收集系统

CollectionBook记录已收集的文物、已探索的海域、已解锁的剧情。每件文物有独立的图鉴条目，包含文物名称、年代、出土地点、历史背景描述。图鉴完成度在MainUI显示百分比。

图鉴解锁触发CodexFlowCheck校验的动画反馈，收集齐特定系列文物解锁专属头像框与博物馆装饰。

## 5. 数据持久化

SaveService使用PlayerPrefs存储关键进度，BuildSnapshotCodec序列化文物与博物馆数据：

```json
{
  "prestige": 1250,
  "gold": 86000,
  "energy": 45,
  "diverLevel": 4,
  "unlockedSeas": ["shallow", "middle", "deep"],
  "fragments": {"vase_001": 3, "coin_002": 5},
  "artifacts": {"vase_001_perfect": true},
  "museum": {"hall1_lv3": true, "hall2_lv2": true},
  "storyProgress": 3
}
```

存档在每次打捞结束与文物修复时自动写入，体力值根据时间自动恢复。

## 6. 社交与增长

ShareService封装微信分享接口，玩家修复传说文物或解锁深海海域后弹出分享卡片。WxOpenDataBoard驱动微信开放数据域的好友排行榜，FriendBoardPanel展示好友博物馆声望排名。

AdPointFunnel控制广告点位：体力恢复、双倍收益、稀有碎片加成、加速修复四个点位，由LauncherTelemetry上报转化数据。

## 7. 技术特点

- 深海打捞限时收集玩法，5个深度层级差异化内容
- 合成修复系统80+可收集文物，4稀有度4修复品质
- 博物馆经营系统4个主题展厅，游客动态事件
- 剧情探索系统主线+支线，分支选择影响走向
- 代码基于Unity引擎C#编写，命名空间Sy.P07统一管理

## 8. Steam买断分支说明

本项目规划Steam买断制分支。Steam版移除广告点位与体力限制，改为纯单机合成经营体验：

- 移除所有IAA广告点位与体力系统，打捞无次数限制
- 增加深度内容：更多海域类型、文物数量、剧情分支
- 增加沙盒模式：自由布置博物馆展厅，自定义展览主题
- 支持Steam创意工坊：玩家分享自定义文物与展厅布局
- 支持Steam成就与云存档
- 定价策略：买断制，后续DLC扩展新海域与文物系列
