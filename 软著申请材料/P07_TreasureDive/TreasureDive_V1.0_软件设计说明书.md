# 捞个宝游戏软件 V1.0 软件设计说明书

## 1. 软件概述

捞个宝是一款深海打捞题材经营游戏，运行于Unity引擎，面向Android与iOS小游戏平台。玩家扮演打捞队队长，调度打捞船队出海打捞文物残件，通过修复玩法将残件复原为珍品文物，在海底博物馆上架展览，以展位吸引力驱动门票经济，逐步扩张船队与博物馆。

游戏采用出海—回收—修复—上架—门票的核心循环：SalvageHub调度打捞队出海，SalvageFleet按三个深度带打捞，种子决定打捞战利品；RestoreMini承载文物修复玩法，残件集齐三合一复原为珍品；MuseumSim管理海底博物馆的八个展位，展位吸引力转化为门票收益；DailyTide提供潮汐日令，SalvageOffline负责离线结算。

命名空间为Sy.P07，运行时代码共18个.cs文件，有效代码行2226行。

## 3. 系统架构

游戏启动流程由BootRunner驱动，依次执行BootSequence中的场景切换，注入BootServices注册的单例服务。I18nBoot注册多语言文本表。核心服务包括SalvageHub（打捞中枢）、MuseumSim（博物馆经营）、DailyTide（潮汐日令）与SalvageOffline（离线结算）。

打捞模块由SalvageHub统一调度：SalvageConfig定义深度带与战利品表，SalvageFleet执行出海航程，MuseumSim结算门票经济，MuseumView与MuseumHall负责博物馆渲染，RestoreMini承载修复玩法交互。

```
BootRunner → BootSequence → BootServices → I18nBoot（多语言）
SalvageHub → SalvageFleet（三深度带出海）→ SalvageConfig（战利品表）
           → RestoreMini（残件修复）→ MuseumSim → MuseumHall（八展位）→ MuseumView
DailyTide（潮汐日令）→ SalvageOffline（离线结算）
MainUI → NewbieConfig / TutorialFlow
```

## 4. 核心模块设计

### 4.1 打捞队系统

SalvageFleet是打捞核心模块。打捞海域分为三个深度带，越深的带位文物稀有度越高、航程越长。出海采用时间戳航程机制：记录出海时间，航程随真实时间推进，归航即结算打捞成果——天然兼容离线场景，玩家无需挂机等待。每舱战利品由种子决定，同一种子必得同批残件；大潮带提供产出乘数窗口，配合潮汐日令形成出海节奏。

### 4.2 文物修复系统

RestoreMini承载残件修复玩法。每件珍品文物由三个残件组成，集齐后进入修复三合一玩法：残件拼合、清理、还原三个步骤逐次完成，最终复原为珍品文物。修复完成的文物进入博物馆可上架位，品质与珍稀度共同决定展位吸引力加成。

### 4.3 海底博物馆经营系统

MuseumSim管理博物馆经营。博物馆共八个展位，每个展位上架文物后按吸引力产生门票收益；吸引力由文物珍稀度、修复完成度与展位等级共同决定。MuseumHall定义展位结构，MuseumView渲染展厅与展品陈列。门票收益反哺船队扩张与出海成本，形成经营闭环。

### 4.4 潮汐日令系统

DailyTide驱动每日玩法：按日期生成潮汐日令（当日出海加成目标与奖励），与打捞队的深度带乘数联动，给出每日的出海优先级指引。日令内容由种子按日期生成，离线与在线行为一致。

### 4.5 离线结算系统

SalvageOffline负责全部离线结算：出海航程按时间戳推进，归航结算、门票收益按离线时长累计，玩家回到游戏时一次性领取。离线收益精确到秒，全部持久化于本地。

### 4.6 多语言与主界面系统

I18nBoot注册多语言文本表，主界面与玩法内文本统一走文本表取值。MainUI提供打捞、修复、博物馆、日令、设置五入口中枢，NewbieConfig与TutorialFlow承载新手引导，通过高亮交互区域完成教学。

## 5. 数据持久化

全部持久化采用PlayerPrefs本地存档，零服务器依赖：

```json
{
  "salvageSeed": 20261010,
  "fleet": [{"band": 2, "sailStamp": 1760000000, "returns": 3}],
  "museum": {"hallSlots": 8, "exhibits": ["vase_001", "coin_002"], "ticketRate": 12.5},
  "fragments": {"vase_001": 2, "coin_002": 1},
  "tideDate": "2026-10-10",
  "offlineStamp": 1760000000
}
```

存档在出海结算、修复完成与退出游戏时自动写入，加载时做版本号兼容校验。

## 6. 社交与增长

好友排行榜由微信开放数据域单键KV驱动，无需自建服务器。AdHubBoot聚合广告点位调度，出海加速与门票收益加成等点位与经营节奏挂钩，转化数据随结算上报。分享内容随珍品修复完成与展位解锁生成。

## 7. 技术特点

- 时间戳航程机制：出海归港按真实时间推进，天然离线兼容，收益精确到秒
- 种子决定论战利品：同种子同批次残件，离线在线行为完全一致
- 三深度带打捞+大潮乘数，出海节奏与稀有度曲线分层
- 残件三合一修复玩法，收集与修复操作深度结合
- 海底博物馆八展位门票经济，吸引力模型驱动经营决策
- 代码基于Unity引擎C#编写，命名空间Sy.P07统一管理

## 8. Steam买断分支说明

本项目规划Steam买断制分支。Steam版移除广告点位，改为纯单机打捞经营体验：移除全部IAA广告点位与加速，增加深度内容（更多深度带、文物系列、博物馆自定义布局），支持Steam创意工坊、成就与云存档，定价策略为买断制，后续DLC扩展新海域与文物系列。
