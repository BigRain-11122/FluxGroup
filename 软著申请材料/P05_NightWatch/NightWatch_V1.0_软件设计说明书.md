# 守夜人游戏软件 V1.0 软件设计说明书

## 1. 软件概述

守夜人是一款冰雪末日题材生存经营游戏，运行于Unity引擎，面向Android与iOS小游戏平台。玩家扮演极寒避难所的守夜人，管理炉火温度、建造生存设施、招募幸存者、采集资源，在暴风雪与物资短缺中维持避难所运转，同时与联盟成员协作抵御外部威胁。

游戏采用昼夜循环结构：白天在BuildService管理的建筑系统中升级设施、派遣幸存者采集资源；夜晚进入FurnaceSim驱动的生存阶段，管理炉火消耗与温度衰减，应对随机事件与外部袭击。每完成一个昼夜周期，结算资源产出与幸存者状态。

命名空间为Sy.P05，运行时代码共14个.cs文件，有效代码行1611行。

## 3. 系统架构

游戏启动流程由BootRunner驱动，依次执行BootSequence中的场景切换，注入BootServices注册的单例服务。核心服务包括SaveService（本地存档）、FurnaceSim（炉火生存）、BuildService（建筑经营）、ShareService（微信分享）。

生存模块由FurnaceSim统一调度：传入DayState当前天数与ShelterState避难所状态，FurnaceSim每帧计算温度衰减、燃料消耗与幸存者饥饿值，FurnaceView负责渲染炉火特效、温度仪表与暴风雪粒子。

```
BootRunner → BootSequence → BootServices
                           ├── SaveService
                           ├── FurnaceSim
                           ├── BuildService
                           └── ShareService
DayCycle → DayPhase（建造/采集）→ FurnaceSim（夜晚生存）→ EventLauncher（随机事件）
         → BuildService（建筑升级）→ SurvivorManager（幸存者管理）
```

## 4. 核心模块设计

### 4.1 炉火生存系统

FurnaceSim是核心生存模块。避难所温度由炉火等级与燃料量决定，温度低于阈值时幸存者开始损失生命值。燃料分为木材、煤炭、精炼油三个等级，燃烧效率依次提升。

温度衰减公式：温度下降速率 = 基础衰减 × (1 + 暴风雪强度 × 0.5) × (1 - 保温建筑加成)。FurnaceSim每帧更新温度值，当温度降至0度时触发严寒警告，幸存者每秒损失1点生命值。

燃料消耗与炉火等级正相关，高级炉火燃烧效率更高但消耗更快。玩家需在燃料储备与温度需求之间做平衡决策。

### 4.2 建筑经营系统

BuildService管理避难所的建筑建造与升级。建筑分为四类：

- **生存类**：熔炉（温度）、净水器（水源）、厨房（食物）、医疗站（治疗）
- **生产类**：伐木场（木材）、煤矿（煤炭）、工坊（精炼油）、农田（食物）
- **防御类**：围墙（防御值）、瞭望塔（预警）、陷阱（伤害）
- **居住类**：宿舍（幸存者容量）、娱乐室（士气）

每个建筑有独立的等级与升级消耗，升级后提升产出效率或功能效果。BuildService在建造时校验资源可用性与建筑位占用。

### 4.3 幸存者管理系统

幸存者是核心资源。每个幸存者有独立的属性：生命值、饥饿值、士气值、技能特长。技能特长分为：采集、建造、战斗、医疗、烹饪，分配到对应建筑可提升效率。

幸存者招募通过EventLauncher触发的随机事件完成：流浪者上门请求加入、救援任务解救幸存者。幸存者数量受宿舍容量限制，超过容量时新幸存者无法加入。

幸存者状态每帧更新：饥饿值随时间下降，归零后开始损失生命值；士气值受娱乐设施与事件影响，低士气降低工作效率。

### 4.4 资源采集系统

资源分为：木材、煤炭、食物、水、医疗用品。采集由派遣幸存者到对应建筑完成，采集速率由幸存者技能等级与建筑等级决定。

采集有风险机制：派遣幸存者外出采集时，有概率遭遇暴风雪或野兽袭击，损失部分资源或幸存者生命值。BuildService提供安全采集选项，消耗广告点位可确保采集无风险。

### 4.5 随机事件系统

EventLauncher在每个昼夜周期结束时触发随机事件。事件类型包括：

- **正面事件**：流浪者加入、物资空投、商人到访、天气转暖
- **负面事件**：暴风雪加剧、野兽袭击、疾病爆发、燃料泄漏
- **选择事件**：救援任务（消耗资源获得幸存者）、商人交易（资源互换）

事件结果由EventTemplates配置，选择类事件有多个选项，每个选项有不同的资源消耗与收益。

### 4.6 联盟协作系统

联盟系统允许玩家组建或加入联盟。联盟成员可互相支援燃料与资源，联盟仓库共享物资。联盟战每周开启，联盟之间争夺资源点控制权，获胜方获得专属建筑图纸与稀有资源。

联盟聊天由ChatService驱动，支持文字与表情消息。联盟科技由联盟成员共同捐献资源解锁，提供全局加成。

## 5. 数据持久化

SaveService使用PlayerPrefs存储关键进度，BuildSnapshotCodec序列化建筑与幸存者数据：

```json
{
  "day": 23,
  "temperature": 18,
  "fuel": {"wood": 150, "coal": 80, "oil": 20},
  "resources": {"food": 320, "water": 280, "medical": 45},
  "buildings": {"furnace_lv3": true, "sawmill_lv2": true},
  "survivors": [{"name": "张三", "hp": 90, "skill": "gather_lv2"}],
  "allianceId": "alliance_001"
}
```

存档在每个昼夜结束与退出游戏时自动写入，加载时做版本号兼容校验。

## 6. 社交与增长

ShareService封装微信分享接口，玩家招募到稀有幸存者或度过高难度天数后弹出分享卡片。WxOpenDataBoard驱动微信开放数据域的好友排行榜，FriendBoardPanel展示好友最高存活天数。

AdPointFunnel控制广告点位：安全采集、双倍产出、紧急补给、加速建造四个点位，由LauncherTelemetry上报转化数据。

## 8. Steam买断分支说明

本项目规划Steam买断制分支。Steam版移除广告点位与联盟社交系统，改为纯单机生存经营体验：

- 移除所有IAA广告点位，资源获取完全依赖游戏内玩法
- 移除联盟系统，改为NPC商人与交易站
- 增加深度内容：更多建筑类型、幸存者技能树、剧情事件线
- 支持Steam成就与云存档
- 定价策略：买断制，后续DLC扩展内容
