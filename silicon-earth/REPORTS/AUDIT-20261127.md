## 二 发现（按严重度）

### P0 与自己的裁决矛盾：运行时状态仍在 git

`git ls-files` 命中四个文件：

```
modules/m-w2-clock/data/events.jsonl
modules/m-w2-clock/data/time.json
modules/m-w3-settle/data/state.json
modules/m-p2-memory/data/memory.json
```

`DECISIONS.md` D2 写的是"运行时状态不进 git"，B22 一直挂着没做。后果：两台机器各自推进后合并，必然出现重复日；`validate` 的缺日校验会红，但没有补洞工具（运维席原话："丢的是历史，不是缓存"）。

**动作**：`git rm --cached` 四件 + 补 `setup.py`（首次生成）+ ready 引导。

### P1 验收标准仍可被改（B21 只做了一半）

`verify` 命令已移进 `CONTRACTS/verify.json` 并与任务板交叉校验；但 `acceptance` 仍是 `TASKS.json` 里的自由文本，worker 可随便改而不触发任何检查。

**动作**：`acceptance` 一并移入 `CONTRACTS/`，或降级为纯说明、验收只认 verify。

### P1 身份是自报（B20）

`--agent 总控` 可越界写（红队 R6 实测 rc=0）。当前靠"只有 bm-a 在跑"这一事实兜底，不是机制。

**动作**：pre-commit/pre-push 硬门 + 身份来自远端，属 B20。

### P2 万级居民只有千分之八被点名

10,141 人里产生过记忆的只有几十人——事件每天只挑两个 actor。绝大多数居民"入了户籍，没有生活"。

**动作**：事件影响面扩散（一个事件波及一片人），或做"随机点开一个人"入口。

### P2 导入脚本硬编码绝对路径

`tools/import_census.py` 里写死 `D:\FluxGroup\life\BigLife\census\export\citizens-light.jsonl`。换机器或目录调整即失效。

**动作**：改环境变量 `SILICON_CENSUS`，默认值保留。

### P3 坏地人口各 3 人

创始 27 人平均分到九区，导致裂谷/封锁区/边境各 3 人、住人的六区被户籍填满。数据自洽，但语义上"烂地也有人住"值得复核。
