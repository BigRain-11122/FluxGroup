## 二、社区调研结论（有实锚）

1. **"去 AI 味"无效**。Fokkyp/SoftwareCopyright-Skill issue #29 记录：同一材料、同一检测器，四轮根本不同写法（标准 AI 技术散文 / 短句口语体 / 织入 38 条真实 UI 字符串的特异性密度体 / 公文语域体无对仗无排比），腾讯朱雀**全部判 0% 人工特征**。检测器认整体统计签名，与措辞、语域、信息密度、格式无关。
2. **审查重心转向研发过程核验**。2026 年新版通知的代办解读（搜狐/网络弧线 2026-09-17）：收到 AIGC 补正不等于代码有问题，而是机械化泛化的说明书描述触发预警；现在看"软件如何一步步研发出来"，需连贯可核验的工程证据链。要求的六项：规范目录树、源程序文件 SHA-256 哈希清单、连贯研发日志、Git/SVN 版本管理日志、PR/MR 与 Code Review 记录、实测记录与测试报告。
3. **说明书要删套话换实操**：删"旨在为用户提供便捷、智能化体验"类模板句，改为"在何处操作、输入什么字段、触发什么逻辑、产生什么结果"，且截图、模块名、数值与源码完全一致。
4. **"建议撤回"可能是死路**。多份代办解读：意见一旦明确写"建议撤回此申请"，补正通道对应关闭，最稳妥是撤回后换名重报（2026-05-14 搜狐/网络弧线）。但也有开发者反映纯手写原创也被一刀切。官方在通知书里留了电话 010-83771607 可核实。

## 三、本地实测：雷同判定的是模板骨架，不是字面

对材料库 33 份说明书两两比对（tools/dup_audit.py）：

| 指标 | 中位 | 90 分位 | 最大 |
|---|---|---|---|
| 字面 3-gram Jaccard | 0.0388 | 0.2063 | 0.3127 |
| 章节标题词重合 | 37.50% | 100% | 100% |
| 章节骨架序列重合 | 0.50 | 1.00 | 1.00 |

典型 100% 标题重合对：G06_ArrowRush↔G28_ArrowOut、G17_UnboxIt↔G18_PalacePlunder、G03_MergeMania↔G17_UnboxIt。

**关键判据**：两份旧文档字面只像 4.8%，仍被判雷同 ⇒ 系统看结构/模板特征。所以「改几个词」无效，「换体裁、换章节骨架」才有效。

## 四、有效整改法（本次采用）

1. 文档类型从「软件设计说明书」改为「操作说明书」——设计说明书是连续技术散文，正是 AIGC 高发文体；操作手册是截图+条目。
2. 两份文档体裁互斥：吸嘟嘟＝界面巡览体（按菜单层级逐界面）；摸鱼＝生涯时间线体（按玩家从入职到投胎）。
3. 文字全部锚定源码：摸鱼逐字引用 `Assets/_Game/Resources/Texts_zhCN.json`（176 条中文文案）并标文本键；吸嘟嘟伙伴名册取自 `CompanionDef`、广告文案取自 `AdCopy`、界面文字取自实机截图。
4. 配「独创性真实开发证明包」六件：源程序目录+每文件 SHA-256、git 提交全量、按日研发日志、真实开发情况说明（可签章）、源程序量口径说明、测试与实机验证记录。
5. 效果实测：新版 vs 旧库章节标题重合 **0.00%**，字面 0.008～0.012。

## 七、环境限制（本轮实锤）

CLI 会话无交互桌面：`Start-Process` 起的 GUI 程序 `MainWindowHandle` 非零但 `GetWindowRect` 返回 0×0，`Screen.AllScreens` 为空 ⇒ **窗口截图路线在本会话不可用**。可行替代：WebGL 构建 + Playwright（Chrome `executable_path` 需显式指定，默认浏览器未装）；团结编辑器命令行 `-executeMethod` 构建可用（本机有 windowsstandalonesupport，**无 WebGL 模块**）。
