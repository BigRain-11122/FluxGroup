## 三、发前必过的编造闸（真实拦下的样例）

2026-11-18 清点 35 条队列，**只有 3 条能过**（可用率 8%）。拦下的典型：

- `@漫泰视觉，你们这些大 V 太无耻了，居然盗我的教程还能卖钱！`
  → 冒充受害者 + 指控真实账号 = 诽谤。已把「@提及 / 盗抄剽窃骗侵权无耻起诉维权」写进
  **生成器**（`social_comment_gen.gate`），不只发前拦——否则它会一直堆在队列里等人手滑。
- `老寒这教程太良心了…坐等 2026 版本上线`
  → 编造称呼（标题里没有"老寒"）+ 编造发布计划。
- 「以为是新手教程结果全是干货」这类**编造观看经历**：没看过就不能说自己看过。
- 带 `**`/`##` 的 Markdown 痕迹 = 一眼 AI。

规则实现：`social_practice.safe_to_send()`（编造）+ `social_comment_gen.gate()`（语言/红线），
两道都过才允许发。

## 四、四个必踩的运维坑（都已修）

1. **别给注销号回复**：`账号已注销: UP主加油！` 这种回过去没人看，只让账号像空转 → 加活人过滤。
2. **BV→aid 裸 HTTP 会被风控**：`/x/web-interface/view` 直接抛异常；要用**已登录页面同源 fetch**。
3. **浏览器 profile 独占**：采集循环（sociallearn）拿着 `browser-bilibili` 的 SingletonLock，
   发帖会报 "ProcessSingleton ... already in use"。正法=停采集→清残留 SingletonLock→发→恢复采集。
4. **不要截断服务端响应**：rpid 在返回体里，早期截到 300 字导致解析失败，撤不回也验不了。

## 五、撤回

`python3 Tools/fleet/social_practice.py --withdraw <rpid> --aid <aid>`
走 `/x/v2/reply/del`（wbi + csrf，同源）。撤回也是真动作，要记账。

## 六、生态与法务边界（2026-11-18 GitHub 调研）

**`Nemo2011/bilibili-api`（4.2k star）已于 2026-07-06 永久关停**，仓库只剩声明 + B站《侵权告知函》，
理由是"对非公开接口、认证体系做逆向适配"。连带 `adoresever/bilibili-mcp`（MIT，196 star，
支持评论/弹幕/回复）也成了死基础。

结论（路线级）：**不引入逆向库**。我们现有的"在已登录页面里用页面自己的签名接口发"更安全，
代价是操作必须真的像人。这条同时是技术选择与合规选择。

## 七、拟人操作：两层，先环境后行为

**第一层 环境隐形** = `Patchright`（Apache-2.0，Playwright 补丁分支，抹 CDP/自动化指纹），
改 import 即用，已接进 `social_comment` 并保留原生 Playwright 回落。
备选：`Camoufox`（Firefox 内核反指纹）、`ghost-cursor`/`human_mouse`（MIT，贝塞尔鼠标轨迹，可再叠）。

换 patchright 后踩的三个坑（都已修）：
1 空间页 6 秒抓不到链接（实锚 0 条）→ 用 `wait_for_selector` + 兜底等待，实测抓到 41 个视频
2 `window.__INITIAL_STATE__.aid` 不再注入 → 页面内问 `/x/web-interface/view` 要 aid
3 浏览器 profile 被采集循环独占（SingletonLock）→ 停 sociallearn → 清锁 → 干完 → 恢复

**第二层 行为拟人** = `human_rhythm.py`（自检 7/7，纯分布、零 LLM）：
- 作息双峰（22 点活跃度远高于 4 点），不硬切时间窗，用权重做概率
- 会话：约 44% 的会话只看不动手；一次看 6 条左右、动手 0-2 条
- **回复延迟对数正态、中位约 39 分钟、几乎无秒回**，深夜到点顺延到次日
- 选择性：提问 p≈0.62、普通夸奖 p≈0.13、注销号 0 —— **全回就是最像机器人的行为**
- 发帖前强制"阅读停留"20-120 秒 + 滚动（`social_comment.human_read`）
- 接口：`--queue` 按分布排期（写 reply-queue.jsonl），`--flush` 到点且在线时才发

## 九、频率的判据：可见率驱动，不靠感觉（2026-11-18 立）

| 时间 | 动作 | 公开可见 |
|---|---|---|
| 11-17 | 子回复 rpid 324260408320 | 24 小时后仍不可见 |
| 11-18 | 子回复 324368666544 | 1 小时后不可见 |
| 11-18 | 顶级评论 324366980272 | 1 小时后不可见 |
| 11-18 | 子回复 324368900816 | **可见** |

**判读：`code=0 发送成功` 不等于发出去了；"待审核"过 24h 仍不可见 = 实际丢弃。**
加频率只会成倍制造看不见的废帖。

判据落成 `Tools/fleet/freq_policy.py`（自检 4/4）+ `social/FREQ-POLICY.json`：
- 只认公开可见为有效；样本 <6 不下"可以加"的结论
- 阶梯：档0 = 2 条/日·90 分 → 档1 = 3 条·60 分（6 条样本、可见率 ≥75%）→ 档2 = 4 条·45 分（12 条、≥80%）→ 档3 = 6 条·30 分（20 条、≥85%）
- 回退红线：连续 2 条不可见，或近 5 条可见率 <50% → 立即降一档
- `social_comment` / `social_practice` 都读它，工具内不再写死 2 条

要升频的前置动作：4 个对照臂（短句 vs 长句、子回复 vs 顶级评论、不同视频）各打几条，
用数据找"哪种形态能过审"，而不是猜。
