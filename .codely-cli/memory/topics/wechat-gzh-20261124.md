## 一、微信桌面客户端 4.2.1：静默不可行（硬事实，别再试）

- 实测 `desktop_snapshot app=微信`：AX 树只有 **1 个 window + 3 个 button**
  （Close / Full Screen / Minimize），`role:group` 里 0 个内容节点。
- 微信 4.x 是**自绘 UI**，聊天内容不在系统可访问性树里。
- 因此：**读消息读不到、发消息发不了**，除非"截图 + 定位坐标 + 物理点击"——
  那正是 CEO 禁止的动作，且个人微信自动化风控极高，封号不可逆。
- 结论口径：桌面客户端只能做「截图我来看」的**只读**辅助（我可以读图理解内容并写草稿，
  但发送那一下必须人来做）。

## 二、静默的正解：Playwright headless + 独立 profile

- 工具=`Tools/fleet/silent_browser.py`（提交 `58561d0e0` / `a5f6d974b`）。
- 三件套：`launch_persistent_context(PROFILE, headless=True)` +
  独立 Chrome for Testing（`~/.fluxgroup/chrome/`）+ profile 隔离（`~/.fluxgroup/silent-profile`）。
- 效果：不动物理光标、不抢前台焦点、Dock 里无窗口、不弹任何窗。
- 动作集：`goto/wait/wait_for/click/fill/press/text/html/eval/shot/cookies`，可写成 JSON 脚本跑。
- **自检 5/5 + 双向负控**：把 `_launch` 的 `headless` 改 False 判红；把 `login()` 的可见窗口
  改 headless 也判红（扫码流程缺失）。自检用 AST 精确匹配关键字参数，避免"检查字符串自指"。
- `--login` 是**唯一允许 headless=False** 的路径（人要看得见二维码），扫完即回静默。

## 四、公众号后台的接口与限制（重要，会撞坏号）

- ✅ `cgi-bin/searchbiz?action=search_biz&query=<号名>`：能搜到公众号并拿 `fakeid`。
  实测：汽车之家 `MjM5MzA0NDM0MA==`、懂车帝 `MzkxODcxODc0MA==`、38号车评中心 `Mzg4NzU4ODEwMg==`。
- ❌ `cgi-bin/appmsg?action=list_ex&fakeid=...`：**`ret=200013 freq control`**。
  等 60 秒仍不解封 → 是**账号级配额**，不是秒级限流。**新号（0 文章 0 粉丝）风控最严**。
- 教训：撞两次就停手，别把一个新号撞进黑名单。查重只能查 1–2 个候选名。
- **改名流程**（弹窗实测）：`验证身份(管理员微信扫码) → 同意协议 → 改名称 → 确定修改`。
  额度在**第 3 步**才显示。→ 改名不可代做，必须 CEO 扫码。
- **个人主体不能做微信认证**（需企业/组织）。改名后审核 1–7 天。

## 六、边界（CEO 明说 + 我的判断）
