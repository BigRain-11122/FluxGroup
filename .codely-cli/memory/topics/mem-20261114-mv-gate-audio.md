# MV 交付闸 / 音频 / 时域质量三判例（2026-11-14·bm-a 夜窗）

## 一、幻影复用对：闸红被长期豁免 = 闸失效（v721→v730 两周实锚）

`mv_delivery_gate.py` 的 D1（同镜复用）自 **v721（2026-11-02）到 v730（2026-11-14）** 连续
12 份回执都报同一对 `102.21s vs 102.58s`，每一版都由人判成"火盆假阳性"豁免放行。

根因不是暗帧：切点判定只看 `MAD >= CUT_MAD(12)`，而 102.2s 那把火盆在 4 帧内涨/落约 30 IRE，
**同一镜被切成"9 帧碎片 + 它自己的续段"**，两半中帧 dHash 自然相同 → 判成复用。
真实镜头数一直是 83，闸数出的 84 是切成两半的产物（另有 ~10 个叠化在 24fps 被当硬切）。

**修法（切点必须"换画面"或"抬黑位"）**：
- `dHash` 跨切点距离 > 6/64 → 真切；
- 否则看最暗角落（黑位）：位移 ≥ 4.5 IRE → 真切（整幅抬亮/换 take），< 4.5 → 同镜光照事件。
- 两个案例实测：火光事件 dhash=3 且角黑仅动 1.3；D07→D08 隐形切 dhash=4 但角黑动 5.7。
- 副作用修正：原先"高 MAD 一律当切点"使 flicker 检测（`mad < CUT_MAD`）漏掉整幅曝光跳变；
  改为 `not is_cut[i]` 后，真曝光弹跳第一次会被 D4 抓到。

**判例**：闸的假阳性**只许修判定，不许长期登记豁免**——豁免一次是裁决，豁免十二次等于把整道闸
变成噪声源，后面真红也没人信。新闸必须自带"1 正例 + N 反例"自检（本闸 self-test 12/12）。

## 二、单遍 loudnorm 保不住真峰：v729 三个交付档全部 +2.3 dBTP

master 用 `loudnorm=I=-14:TP=-1.5:LRA=11`（单遍=动态模式）实测输出 **-13.2 LUFS / +2.3 dBTP**，
而 v729 导演审文档写的是 "-14/-1.5"。实测三档（60fps / 4k / wm）**全部 +2.3 dBTP** 出厂——
即上一版交付件本身就削波，文档宣称从未被核验。

两条硬结论：
1. **单遍 loudnorm 无法保证真峰**（流式动态模式 + aac 编码叠加约 +1.45 dB 过冲）；
2. **宣称必须核验**：`loudnorm=...:print_format=summary` 的输出值才算数。

正法 `Tools/mv_audio_n1.py`：
- 两遍 loudnorm（linear，带 measured_* 参数）；
- **限幅门限与增益解耦**（第一版把两者绑在一起 → 每次修正都把响度推出容差）；
- 出片后自测：`I ∈ -14±0.7` 且 `TP ≤ -1.0`，不达标自动再修（最多 3 遍）；
- 首跑结果：v730 60fps 母版 **-14.13 LUFS / -1.09 dBTP**。

出库顺序（承 10-18 N1 判例）：视频定版 → N1 音频 → 水印 embed（音频直通，别再动）→ 4K。
4K 上采样不改音频，真峰随源保持。

## 三、60fps 阈值必须 fps 归一；24fps 与 60fps 的镜数不能互相校验

- `minterpolate` 后每帧运动量约为 24fps 的 40%（同一运动被摊到 2.5 倍帧上），
  `STILL_MAD=0.45` 直接套 60fps → v727 60fps 回执报 **21 个假"静帧"**，整道 D2 失效。
  修法：阈值按 `24/fps` 缩放（`motion_thresholds()`），并把缩放后的实际阈值打印出来便于审计。
- **24fps 83 镜 vs 60fps 73 镜不是矛盾**：24fps 采样稀疏，叠化会被当成硬切多切 10 刀；
  60fps 才还原成连续过渡。与剪辑语法表（硬切 54 + 叠化 7 + 虚化 2 + 深慢 3）吻合。
  → **内容判据（复用/静帧）以 24fps 为准，时域外观（插帧/抖动）以 60fps 为准**，两边不互相校验。
- 片尾字卡段（231.0-234.4s）与 `tpad` 补帧尾巴本质是静态设计，**必须用 `--card` 申报**，
  否则 D3 会一直报"dead hold 14 帧"（v727 就挂在这一条上没人修）。

## 四、其它两处工具面

- **OpenCV 5.0 已移除 `CascadeClassifier`**（`hasattr(cv2,'CascadeClassifier')=False`，`cv2.data` 也没了）
  → 人脸对照表改用确定性裁框（`face_sheet.py`）；要自动检测得走 `FaceDetectorYN` + 模型文件。
- **`overlay` 在 filter_complex 里必须显式写明第二输入**：v730 全部版本写成
  `[0:v]ass=...,overlay=x=0:y=0:enable='gte(t,231)'`，ffmpeg 自动解析第二输入，
  mux **exit 0 但片尾"转载需注明出处 @大喵没鱼吃"从未上屏**。静帧还必须 `-loop 1 -t`，
  单帧副输入没有时间轴可评估 `enable`。发现手段=像素探针（band YMAX），不是看片。

## 五、「看不清」不等于「换人」——人脸一致性要用第二条通道复核

v730 复审时我从缩略图把 B01（闭眼·低头·暖光·红卫衣）读成「和 D03b/E01a 不是同一张脸」，
差点当成造型一票否决。实际做法：把三镜各截 1.4-2.4s 拼成一条 5 秒对比片，
交给**独立的视频分析模型**逐项比（脸型/鼻/眼/唇/发型），结论是同一人，差异只在服装与光。

两条可复用：
- **缩略图 + 单帧推测不足以定人脸缺陷**；暗光、闭眼、低头、暖光都会改变鼻影宽度与颊部饱满度。
- **要有第二条通道**：本机 Vision 额度和主模型自判是同一个通道，不算复核；拼片送独立视频模型或换尺度重抽才算。
- 与 CEO 既有判例同源：「女主一致性崩了」多次实锚都是「看不清」（暗/头发挡脸）而非换人。

## 六、「十分钟没有进度输出」不等于卡死（4K VideoSeal 解码）

4K 全片水印解码时进程 16.5GB 常驻、CPU 计数四分钟一动不动，我判成死锁并 kill 了——
结果任务随后正常打出 `DECODE bit-acc=100.0%`。这类工具**只在收尾一次性输出**，中途无进度。

判死前必做：①看进程是否仍在增加 GPU/显存或磁盘 IO，而不是只看 CPU 秒数；②先算预期耗时
（4K 14064 帧解码 ≈ 10 分钟）；③宁可等，不要 kill——kill 掉的是"看起来没在动"的真实工作。
同一类还有：`mv_rebuild` 的 PS 包装层空退出码、tuanjie exit 空 ≠ 失败，判真相只认产物 mtime/日志/帧数。
