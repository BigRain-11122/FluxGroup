# 养号：发不出去的三个真因 + 文案质量改法（2026-11-20 实锚）

CEO 原话「你先去评论，为什么评论不了？我试了一下一切正常，给我解决好」——
他自己手动能评论，说明账号没问题。查下来三个真因全在我们这侧。

## 一、复核把"取不到数"当成"看不见"（最致命）

- 旧写法：匿名 urllib 打 `api.bilibili.com/x/v2/reply?type=1&oid=<aid>&pn=1&ps=20&sort=0`
  —— 返回 `code=0` 但 `replies` 为空数组。于是每条评论都判"不可见"，
  5 条全 False → 触发熔断停发，账面像"账号被静默扣留"。
- 实证：改用登录态浏览器同源请求后重验最近 6 条，**真实可见 2 条**（此前判 0 条）。
- 正法：
  1. 复核走**登录态浏览器同源 fetch**（`credentials:'include'`），多 `sort`（0/2）× 多页（1..3）；
  2. **取不到数返回 None（未判定），不算不可见**；分母只装有确定结论的；
  3. 熔断按"最近 N 条**投递**的可见条数"算，不按"检查次数"（同一条 30/60 分钟各查一次会被算两次）。
- 通用判据：**外部接口返回空 ≠ 事实为否**。凡是要拿外部事实做处罚性决策（停发/止损/降级），
  必须先能区分"数据取不到"与"数据说不是"，否则一次接口变动就冤枉整个账号。

## 二、发帖与补采抢同一个浏览器 profile

- 现象：补采在跑时发帖抛 `Failed to create a ProcessSingleton`，被记成"发布失败"。
- 正法：发帖、复核、采集**共用同一把 profile pid 锁**并排队；抢不到时输出
  "profile 被占用（等锁 Ns 超时）：先放补采或学习循环"，不要把它当账号问题。

## 三、profile 锁必须可重入且用完释放

- 实锚：同一进程连续复核 6 条，第 2 条起全部返回"取数失败"——
  因为锁文件只记 pid，自己持有自己又被自己挡住。
- 正法：锁内 pid == 本进程 → 直接放行（可重入）；用完显式 `release_profile_lock()`。

## 四、作息闸会静默跳过（看起来像"不发"）

- `human_rhythm.awake()` 判"离线时段"时直接 skip，日志只有一行 "asleep"，没有报错。
- 人工要求"现在就发"时用 `FLUX_PRACTICE_FORCE=1`：**只跳作息闸**，工具闸/风控闸/字数闸照旧。

## 五、文案质量：把闸真正在量的东西写进指令

- 实测 17 条实投文案：**语感 0.5/20**、人味 10.6/20（人味满分是 20，不是 40）。
- 根因不是模型笨：`comment_taste` 的语感 = **口语助词种类 × 8**（吧/啊/呀/呢/嘛/啦…），
  人味 = 有"我" + 有具体词（镜头/剪辑/台词/配乐）；而提示词从没要求过这两件事。
- 改法：写在**训练与线上共用的单源** `train_build.INSTRUCTIONS` 里（不是只在线上另写一份），
  要求：一两个口语词且只能落在句尾/逗号前、用「我」讲一句经历、点一个具体物件、
  禁"真的/必须/超级/简直/特别/非常/瞬间"这类空夸词、别每条都用同一个字。
- A/B（同批视频、同一把闸）：均分 57→100，人味 5.8→20（满分），PASS 42%→94%。
- **指标会被刷，必须配反刷检测**：第一版指令让模型把助词硬塞进词中间
  （"结尾那声鸣叫**哈**挺带感的"），语感冲到 16 但中文不像人说的。
  `comment_taste.awkward_particles()` 判"语气词后面必须紧跟标点或句尾"，
  生硬率从 17% 降到 0-5%。另外"别每条都用呀"这条要求，把 6/10 的"呀"结尾打散成
  呢/啊/啦/嘛/吧 混合。
- 出稿策略：从"第一条过闸就发"改为 **best-of-8**（语感+人味优先、总分次之），生硬稿直接拒。

## 六、并发同步会冲掉未推送的改动

- 实锚：本轮改的 4 个文件提交后只剩 2 个——`comment_taste.py` / `train_build.py`
  在 add 之前被机队同步回退，`git commit` 只带进了另外两个。
- 判据：**提交后必须 `git show --stat` 看文件真的进去了**，然后立即 push。

## 八、过了闸但还像一个人：闸管不了的两件事（2026-11-20 晚）

分数已到 90–106、PASS 94–100%，但 12 条真实样本里 **9 条"那个/那"开头**、内容多为泛夸——
从"不能看"到"**能看但普通**"，还没到"像真人"。所以闸之外补了三件：

1. `hard_block()`：拒烂梗（泪目/破防）与非白名单英文——4-bit 模型会幻觉出 `CONTENT` 这种词，
   而评分器只看"有具体词"就会给分，这类必须硬拒而不是扣分。
2. **开头两字撞车降优先级**：同一批稿子开头两字重复 → 排序时降权。
   （闸看单条，撞车只有横向比才看得见，必须整批判。）
3. 瓶颈已从"模型能力"转到**语料分布 + 具体性约束**，剩下的四条按这个顺序做：
   ① 具体性硬要求（第几秒 / 哪个动作 / 跟什么对比，治"内容空"）
   ② 意见分布（每 10 条强制 2–3 条提问或挑刺，不许全是夸）
   ③ 按类型定向补采（peer_pro 仅 285 行、beginner 50 行 → 补语料，不是加训练轮数）
   ④ 被闸拒的草稿攒成反面样本，用来校正段位参数

> 通用判据：**评分闸只能证明"不难看"，证明不了"像人"。** 单条评分之外必须再有一个
> 整批维度的判据（开头多样性、意见分布、具体性），否则全绿稿子读起来仍是同一个模板。

## 十、止损的"婴儿期证据"（2026-11-20 晚修）

- 缺陷：回验在发帖后 **~40 秒**做一次，而 B 站评论过审/进公开列表常要几分钟；
  40 秒的 False 会永久留在账上，止损据此停发——判据用的是没长成的证据。
- 修法：`practice_tick.mature_verify(min_age_s=600)`，投递满 10 分钟且无成熟结论的补验一次
  并落 `mature=True`；止损期间也先跑；最近 5 条中 ≥3 条有成熟结论且 ≥2 条可见 →
  **自动解封**（限流缓解就恢复，不等人）。
- 实测（20:3x，用登录态浏览器重验 4 条）：**3 条确实不在公开列表、1 条可见 → 1/5**，
  说明这次止损不是误判，账号真的被限流。限流期正确策略=采集/浏览不停、发帖停，
  恢复由成熟回验判，不靠人拍脑袋解封。
