## 二、零引用 ≠ 没用（最重要的一条判据）

`gzh_daily.py` 用 `"gzh_%s.py" % step` 拼路径调子工具，所以
`gzh_trainset.py` / `gzh_publish.py` / `gzh_formstats.py` / `gzh_metrics.py`
这些**当天刚跑过自检的活工具**，字面名在任何文件里都搜不到 → 被判"零引用"。

第一版判据差点把生产线归档。正解：零引用必须再过一道**新鲜度闸**：

| 档 | 判据 | 处置 |
|---|---|---|
| high | 名字即一次性（`_` 前缀 / 带日期 / test·old·bak·fix） | 可归档 |
| stale | 零引用 **且** git 最后提交 > 14 天前 | 过时候选，发卡问拥有者 |
| recent | 零引用但近期改过 | **一律不动**（很可能是拼接调用的活工具） |

## 三、体检器 `Tools/repo_audit.py`（自检 13/13）

八项：目录规模 / 零引用 / 低版本残留 / 重复内容 / 空文件 / 硬编码绝对路径 / 失效引用 / 断链。

自检与实测抓出的**三个真缺陷**（都是"看起来绿其实是假绿"的类型）：
1. `ROOT = dirname(dirname(HERE))` 多剥一层 → 指到家目录 → 扫 0 个文件却报"全 0"。
   补的闸：**扫不到文件即退 4**，绝不把空扫当干净。
2. 断链检查前用 `os.stat`，一抛错就把整条记录跳过 → 断链永远查不到。改 `os.lstat`。
3. 归档区按等值忽略 `_archive` → 新建 `_archive-20261125/` 没被跳过 → 归档后数字不降。改**前缀匹配**。

失效引用还要排除自检夹具（`nope.py`/`no_such_tool.py`/`not_a_tool.py` 是负控用例），
第一版把它们 13 条里的 8 条报成真问题。
