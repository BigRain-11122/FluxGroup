# 主控职责 v3 · 存储分级 · 抽检（2026-11-13）

## 一、CEO 给的分工（这一轮的核心校正）

「你只是看产出，质量要他们自己闭环，你抽检，你硬盘本来就不多。具体怎么弄你科学规划。」

四条落到设计上：
1. **质量闭环在机队**：每台机自己跑闸、自己写带 sha256 的回执、自己判 DONE/REVISE。
2. **主控只抽检**：核可复算的事实（产物在不在/大小/哈希/判据可信度），不做审美判断，不改由主控发指令。
3. **主控不当仓库**：产物归产出机，主控只留 (path,size,sha256,ts) 清单。
4. **抽检要有成本意识**：主控磁盘与算力有限，抽检量与回执量挂钩。

## 二、主控职责 36 项（MASTER-DUTIES-v3.json）

六域各 6 项，每项强制三件套：`executor`（真实工具）+ `evidence`（可核产物）+ 周期。

| 域 | 覆盖 |
|---|---|
| 赋能 | 模型服务可达、调用账分账、常驻不白占内存、版本雷达、端点阶梯、算力调度 |
| 调度 | 排班到期、可达性探测、空转判定下令、本工位供给、跨机交接、阻塞升级 |
| 监督 | 产出年龄、产品交付缺口、空转 24h 告警、僵尸卡、git 分叉、一屏汇总 |
| 审查 | 抽检重算哈希、人判不许 DONE、假完成、对外材料闸、评审一致性、产物真伪 |
| 契约 | 状态机、身份、文档与配置、测试目录、深度审计、情况台账 |
| 自健 | 心跳、进程单例、全量回归、磁盘与存储分级、内存常驻、复盘落点 |

审计器 `Tools/fleet/duties_audit.py`：
- 三判据：执行体存在 / 证据存在 / 证据在周期 3 倍内；
- 四态：OK / IDLE（事件触发未触发，须显式声明 `on_demand`）/ STALE / NO-EVIDENCE / NO-EXECUTOR；
- 首跑抓出 10 项未履行（算力调度与内存常驻状态停了 2 天、情况台账与评审一致性无证据、四项判据选错用队列文件当证据），补跑后 35 OK + 1 IDLE；
- 已接 L3 全量（红=有职责没履行）+ 排班每日一次。

## 三、存储分级（STORAGE-POLICY-v1.json + storage_curator.py）

五级：`keep`（规则/契约/当前状态，永不删）/ `roll`（事件流，超 8MB 轮转保留尾部 5000 行 + gzip 归档）/ `archive`（30 天过期快照）/ `offload`（产物只导清单不搬）/ `drop`（明确无用一次性件，删除前先写台账）。

实测：主控 494MB 中 **422MB 是产物素材**（mv0001-handover 210MB、mv-album 33MB、drama 12MB、media 150MB）；`state` 73MB 里 eventlog.db 20MB、soak.jsonl 17MB、embed-cache 11MB。轮转后 state 73→54MB，总 494→466MB。offload 清单 2371 件 / 422.6MB 已导出（未删任何文件）。

**事故与修复**：轮转把 `eventlog.db`（SQLite 二进制）当行文本切分，库直接损坏（`file` 报 data、sqlite 报 not a database）。已从 `.archived-*.gz` 完整恢复（20.8MB / 7 个对象）。防护：前 4KB 含 NUL 字节一律判二进制并跳过，配负控用例。

## 四、抽检科学化（master_patrol.sample）

旧：每机每天从"最近的回执"取 N 件——只看头部，早期问题永远抽不到。
新：
- 样本量 = ≤20 份全检；>20 份抽 5%，且受每日上限约束；
- 抽样 = 按时间排序后**等间隔**覆盖整个窗口（可复现，不靠随机）；
- 只读元数据（存在/大小/哈希/判据），不下载不复制产物；
- "没抽到"继续分四态（无候选/已抽满/配置为 0/真 bug），避免每日假红。
