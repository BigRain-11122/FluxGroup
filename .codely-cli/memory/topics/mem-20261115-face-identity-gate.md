# 人脸一致性必须过闸：SFace 实测判例（2026-11-15·CEO「新加的男主一致性太差」）

## 一、结论先行

**"看着像"不是判据，"问多模态模型像不像"也不是判据。** 只有人脸识别向量的余弦相似度能当闸。
本机现成件：`Tools/models/face_detection_yunet_2023mar.onnx` + `face_recognition_sface_2021dec.onnx`
（OpenCV `FaceDetectorYN` + `FaceRecognizerSF`，注意 OpenCV 5 已移除 Haar `CascadeClassifier`）。

## 二、实测数字（mv0001 v730/v731 交付片）

- 六个男主镜两两相似度：**中位 0.200，最差 0.028**（C01 77.7s vs D03b 151.2s）。
- 参考值：真人同人 0.55–0.85；**不同人 < 0.30**。→ 交付片里基本是六张不同的脸。
- KF 源头（v730 的 KF 库）：互相中位 **0.117**，最差 -0.188。
- **这套管线的"同一身份"现实上限 = 0.49**（同一提示词两个种子的 D03b a/b 之间）。
  这条基线很关键：拿真人 0.55 当阈值会永远不过，必须用自家管线的同源基线定标。

## 三、根因与修法

**根因**：v730 的"jman 身份锁"把**三张不同的官方照**塞进 style-reference 的三个槽位
（`ref_main_9 / ref_close_1 / ref_mv_91`）。模型会把三张脸平均成一个"中间脸"，
然后每个场景各自漂移 → 六镜六脸。

**修法（已实测有效）**：**同一张锚定脸喂满三个槽位**。
同一镜同一提示词：0.246 → **0.423**（逼近 0.49 上限）。
配套 `Tools/kf_male_locked.py`：锚定图复制进 ComfyUI input，三槽同图，
每镜多跑种子，**SFace < 阈值就直接丢弃重跑**，不过闸的 KF 不准往下烧 take（省云端钱）。

## 四、纪律

1. **闸要焊在出生地**：KF 出生时就有 SFace 闸，比成片后再发现便宜两个数量级。
2. **装配前必跑一次全镜相似度矩阵**，低于阈值不许装配（`Tools/mv_face_consistency.py` 支持
   视频时间点与静图混测，输出配对矩阵 + VERDICT）。
3. **多模态模型不能当人脸闸**：我曾用一条三镜拼接片请视频模型逐项比脸型/鼻/眼，答"同一个人"，
   而 SFace 实测 0.028–0.32。**VLM 对人脸跨越度宽容，只能做辅助描述，不能做判定。**
4. 阈值定标必须用**自家管线同源基线**（本例 0.49），不能套真人照片区间。

## 五、ComfyUI 运行面

- 探活：`GET http://127.0.0.1:8188/system_stats`；队列：`GET /queue`。
- 起服务：`python_embeded\python.exe -s ComfyUI\main.py --listen 127.0.0.1 --port 8188 --disable-auto-launch`，
  必须 `Start-Process` 分离启动（CLI 重启会带走子进程树）。
- 单张 krea2 turbo 8 步在本机约 60s；满载时飘到 2-7 分钟。
- **慢≠死**：GPU 100% 时 `/history` 轮询会 30s 超时，脚本必须容忍（一个超时曾杀掉整批）；
  真要中断当前作业用 `POST /interrupt`，别杀服务（杀服务要重载模型）。
- 本机 **没有** ReActor / InstantID / IPAdapter 等换脸或身份注入自定义节点（custom_nodes 为空），
  身份只能靠 conditioning（参考图 / 编辑模型），不能指望"换脸节点"。

## 六、denoise 两难与「MAD 会被道具骗过」（2026-11-16 实测）

以锚定脸做 img2img 时，denoise 决定「保脸 / 换场景」的取舍，krea2 turbo 8 步实测：

| denoise | 脸相似度 | 与锚定帧 MAD | 观感 |
|---|---|---|---|
| 0.62 | 0.66 | 4–7 | 四镜几乎同一张图（构图相关 0.95+） |
| 0.70 | 0.64–0.68 | 14.4–14.9 | 仍同机位同墙同袍 |
| 0.80 | 0.63–0.67 | 16.6–19.4 | 脸稳、MAD 达标，但对照图**仍是同一地点** |

**关键教训：全帧 MAD 不是「换了场景」的判据。** 火把、手势、道具一亮，MAD 就从 5 抬到 17，
而机位 / 背景 / 服装没变——人眼一看还是重复镜。判「换场景」必须只量**背景区**
（或背景直方图 / 结构相似度），把人物主体区排除；否则门槛（15）会被道具轻松骗过。

**结论**：单锚 img2img 做不到「同一人 + 真换场景」两头兼顾。
正解=编辑模型 `qwen_image_edit_2511`（蓝图参数：**40 步 / cfg 4 / euler / simple / shift 3.1 /
clip `qwen_2.5_vl_7b_fp8_scaled` type=qwen_image / vae qwen_image_vae**），

## 七、denoise 只能按 1/8 跳档（krea2 8 步）+ 实测 Pareto（2026-11-16 续）

**测量陷阱先说**：`BasicScheduler(steps=8, simple)` 下 denoise 被量化到 1/8 步，
所以 **0.85 与 0.88 输出完全相同**（实测脸/背景差数字一模一样到小数点），
可用的真实档位只有 0.75(6/8) 与 0.875(7/8)。任何"微调 denoise 0.85→0.88 看变化"的实验都是白跑。

实测 Pareto（krea2 turbo 8 步，锚定脸 img2img）：

| 有效档位 | 脸相似度 | 背景差 | 判定 |
|---|---|---|---|
| ≈0.62 | 0.66 | 4–7 | 同布景 |
| 0.75 | 0.62–0.67 | 4.9–16.6 | 多数仍同布景 |
| **0.875(7/8)** | **0.659** | **20.9** | **唯一双达标档** |
| 0.90 | 0.423 | 28.3 | 换景但换脸 |

编辑模型那侧（`qwen_image_edit_2511`，40 步/cfg4/shift3.1）：
换景很强（背景差 26.9/25.8/40.5/34.4，服装也能按提示词改成麻布），
但**同一批镜的身份只有 0.02–0.47**；加"图1=锚定脸 + 图2=场景图"双参考也只抬到 0.374。

**根治路线与限制**：kohya sd-scripts（本机 cb70b96）**没有 Qwen-Image-Edit 的 LoRA 训练脚本**
（`anima_train_network.py` 是另一个模型，用 Qwen3 文本编码器，不是 krea2），
要训男主人脸 LoRA 需另装第三方训练器（现成轮子：`nbeerbower/Qwen-Image-Edit-LoRA-Trainer`、
ostris `ai-toolkit` 支持 Qwen-Image-Edit-2509，<10GB 显存档位存在）。

## 八、ComfyUI 批处理必卡（第二镜起挂住）

连续投多个 job 时，**第 2 个常挂住**（`/queue` 显示 running=1/pending=1、GPU 100% 但不出图）。
可复现多次。正法=**一镜一进程**跑，卡住就 `POST /interrupt` 再起下一镜；
脚本内轮询必须容忍超时（一个 URLError 曾杀掉整批、丢后续全部镜）。
