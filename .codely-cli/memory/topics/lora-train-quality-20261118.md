# 养号 LoRA 训练质量线（2026-11-18 起）

> 正身验收口径 = `cph4/fleet/social/train/ACCEPTANCE-TRAIN.md`（写在结果之前，防事后挑好看的）
> 训练台 = `Tools/fleet/train_lora.py`（跑批壳 `train_run.sh`）；造集 `train_build.py`；选点 `train_eval.py`

## 一、"欠训"假设已证伪：是**过拟合**（2026-11-18 16:2x 实测定谳）

原判断（965 行×batch1×400 步≈0.41 epoch → 判欠训）**已被实测推翻**。Run A 把同一份
965 行数据跑到 1600 步，结果：
- train_loss 3.14 → **2.385**（一直降）
- **val_loss 900 步见底 3.08，1600 步升回 3.50**（后段发散）
- 拿 900 步那个点做 E2E 闭环验收：**覆盖率 29/43，比现役 35/43 更差** → 判 REJECT，已回滚 ACTIVE

结论：**965 行的问题不是训练不够，是数据太少**。下次动的是数据量（h≥5 有 2161 行）
与选点方式（按验证拐点+E2E，不按末尾），**不是加步数**。

## 二、指令模板口径必须统一（已改）

三条训练指令里**只有一条**写了字数（"不超过 25 字"），另外两条没有。结果模型只在撞上
那条时才收口，其余照样写到 60-100 字——产线失败原因里"太长"占四分之一。
已把三条统一成「8-35 字，一到两句话」（依据：3 万条 PASS 评论中位 22 字、P75=42）。
**训练与推理必须共用同一份模板**（推理侧 `llm_client.lora_comment_prompt` 复用
`train_build.INSTRUCTIONS`），两边各写一份就等于没触发微调。

**2026-11-20 补充：模板有多套分支时，"改了常量"不等于"每条样本都改了"。**
当天给指令加人味/语感要求，只改了 `INSTRUCTIONS`（带视频标题那一套），
`INSTRUCTIONS_NOCTX`（无标题样本用的三套）没拼 `_HUMAN`——而 peer_pro 254 条里
**166 条（65%）走的是 NOCTX**，等于训练在教"只写 8-35 字"，推理却要求"带语气词+用我+具体细节"，
方向相反，训出来会把线上分数往回拉。
正法：改完模板要**逐样本校验**（`for line: assert "语气词" in user_content`，
实测缺要求 0/254），而不是 grep 常量存在就收工。同族问法：
**这份 prompt 有几个入口？每个入口都带上新要求了吗？**

## 三、长度上限的判据来源

3466 条 PASS 评论：中位 22 / P90 70 / P95 86 / P99 111，只有 14% 超 60 字。
第一版拍脑袋设 60，把 14% 真评论连带模型正常输出判死。现取 **90（≈P95）**。

## 四、加数据不解决分段短板

同一批语料按人味阈值造三档集，段位分布完全同比例（generic 恒占 **41%**）：
h>=8 → 1018 行、h>=5 → 2161、h>=3 → 2631，各段等比放大。
**更正（2026-11-18 16:5x）**：在完整语料（24733 条）上 generic 占 **66.3%**，但把它的高频词
挖出来看全是语气词——这个(1033)/笑哭(964)/什么(892)/哈哈(857)/没有(849)…说明**它不是漏识别的人群，
而是本来就没有人群特征（纯情绪附和）**。所以"补 signals 降 generic"这条路到此为止：
只对**有信号**的段扩（memer 2512 / shallow 2132 / feeler 1020 / craft_learner 689 / tech_nerd 509），
不追 generic 占比。

## 五、本机训练常数（排期用）

16 层 @224 + grad-checkpoint：**≈6.55 秒/步**（100 步 655 秒，M1 Pro 32GB，rss 3.9GB）。
1600 步 ≈ 2.9 小时。全层 @256 会 OOM、全层 @128 会 nan，16 层是可行上限。
训练前必须卸 ollama 模型并停 8788 LoRA 服务（2.9GB 不参与训练），`train_run.sh` 用 trap 复原。

## 六、上线纪律

适配器由 `cph4/fleet/social/train/ACTIVE.json` 指针决定，**不按"最新一轮"自动抓**——
A/B 两轮都会产出 `best/`，自动抓会把对照实验当上线件。改指针 = 一次显式裁决，要写 why 与 eval。

## 七、验收只认两个数

1. 覆盖率：同一批 43 条视频里能出至少一条过闸评论的视频数（现役 35/43 = 81%）
2. 品味分中位（现役 80）
合格线：覆盖率 ≥40/43 **且** 中位不低于 80。只满足其一 = 放水或挑好看的，不算变好。
副判据（定位用，不做合格线）：单候选 PASS 率（现役 44%）、13 段分段评测、产出长度分布。

## 八、7x24 自驱闭环（CEO「自己找素材训练，不断迭代」「自己循环测试、自己判断」）

四个件，缺一个闭环就是断的：

| 件 | 正身 | 管什么 |
|---|---|---|
| 循环 | `Tools/fleet/social_24x7.py`（launchd `com.fluxgroup.social24x7`，30 分钟一轮） | 看 GPU/缺口 → 清洗 → 训练 → 评测 → 上线；单实例锁；训练期间只等不抢 |
| 闭环验收 | `Tools/fleet/e2e_gate.py` | 固定 43 题集真出稿→过闸→覆盖率与中位分→ACCEPT/REJECT/INCONCLUSIVE + 失败归因 |
| 换/回滚 | `Tools/fleet/lora_switch.sh` | 写 ACTIVE 指针→重启 8788→轮询就绪；没有它"回滚"是空话 |
| 换页看门狗 | `Tools/fleet/train_guard.py` | 换出>50/min 或 swap 涨>300MB 或可用<400MB 即撤并行那路 |

判词规矩：**训完不直接上线**，顺序是 造集→训练→链路自检（回归门）→切候选→闭环验收→ACCEPT 才留 /
REJECT 自动切回上一版。空闲也每 6 小时跑一次 E2E，专抓"服务还在、质量悄悄掉了"。

素材供给不由本循环做：`sociallearn`（20 分钟一轮）already 常驻采集，两边抢同一个浏览器 profile 只会互相打断。

踩过的两个坑（都已修）：①`voice_gate.py` 没有 `--self-test`，按统一参数接进回归链会永远判红 →
任何适配器都上不了线；改为探针（直接调 `vg.check` 验返回结构）。②撤线函数带写死的 `pkill` 模式，
撤第三路时把第二路一起打死 → 撤线只许认 label。


## 九、失败归因的键必须与闸的真实前缀一致（2026-11-18 实锚）

首跑 E2E 归因全 0（{'太长':0,'RISKY':0,...}），不是"没有失败"，而是**判据键名对不上**：
`social_comment_gen.gate` 返回的是"品味闸 RISKY(40)""与本视频领域无关""点名他人（@提及）"这类前缀，
归因表里却写着 RISKY/红线。修正后 43 条视频的真实归因：**品味闸 39 次（93%）+ 指控词 3 条**。

含义很明确：**失败不是长度/格式/服务问题，是生成文本本身质量不够**——所以下一步该改的是
"把标题里的信息喂进提示词"，而不是继续调 max_tokens 或换模型。同族纪律：归因器必须与
上游返回值的**真实字符串**对齐，否则 0 会被误读成"没问题"。
