# 本地适配器生产链的三处口径错配（2026-11-19 实锚）

CEO 问「训练应该不会有问题吧？无非就是去看别人的评论弹幕等」。
诚实结论：**输入面没问题**（弹幕 13812 条、评论 2334 条在采，弹幕在训练集里已按 35% 上限分层抽样），
问题全在"产出端"，共三处，每一处都能单独让训练白做。

## 一 产物：权重不入 git 又被清理扫走 → 现役基线蒸发

- 事实：`RUNS/20261118-113014/best`、`RUNS/20261118-163441/ckpt600` 都是**空目录**；
  全盘只剩一个可用适配器（`20261119-040930/adapter`，527MB，含逐步 checkpoint）。
- 后果：所谓"现役 35/43 覆盖率基线"不可复现，回滚目标不存在——任何"回滚"都会失败。
- 定的规矩：①训练结束必须 `materialize_best`（mlx 产出 `adapter/`，切换口径要 `best/`，
  两者不自动等价）；②权重归档到 `~/.fluxgroup/lora-archive/<run>-<seg>/`（仓外、不在清理范围）；
  ③任何时候只剩"一个可用件"就是资产缺口，要在屏上报，不能等到要回滚才发现。

## 二 服务选择：ACTIVE 指向失效时静默回退=线上挂未验收件

- 事实：06:02 训练产出 `adapter/`，切换代码要 `best/` → 报"适配器不存在"、切换失败、ACTIVE 没更新；
  8788 重启时按"最新一轮"**静默**挂上同一份未验收候选；07:04 定期 E2E 测出 25/43 REJECT，
  但那条定期 E2E 只报告不回滚 → 线上就这么漂了一夜。
- 判据：**配置指向失效时必须喊话，不许回退到"最新"**；静默回退等于让未验收件上线且无人知。
- 实现：`mlx_lora_server.sh` 解析不到 ACTIVE 时打印警告；新增 `mode=base` 明确表达
  "没有验收通过的适配器，只跑基座"；`lora_switch.sh` 必须 `pop("mode")`——
  否则以后每次切换都被 base 静默吃掉（这正是"配置写了不等于生效"的同族坑）。

## 三 验收：合格线在要求模型超过真人

同一 43 题、同一把闸（comment_taste + 编造闸）实测：

| 被测对象 | 覆盖率 | 品味中位 |
|---|---|---|
| 基座（--no-lora） | 26/43 | 81 |
| 唯一存续候选（craft_learner 段适配器） | 25/43 | 80 |
| 现役基线（权重已丢） | 35/43 仅存记录 | 80 |

决定性第四条：**原始真人评论 400 条过同一把品味闸，PASS 仅 13%（51 条），RISKY 85%**。
模型每候选通过率 ≈12%，与真人同档 → 模型"人味"已达标；而覆盖率合格线 40/43＝93%
要求它几乎每条视频都产出**超过真人**的评论。这解释了为什么两次训练都 REJECT：
不是模型变差，是尺子脱离了现实。

- 建议改法（待裁决）：绝对线作废，改**配对判据**——同一次运行里同批同闸测基座与候选，
  候选覆盖率 ≥ 基座 +3/43 且品味中位不降，两条同时成立才算变好。
- 另一处口径错配：**段专用适配器却用全量 43 题验收**（craft_learner 段适配器只为那一段优化，
  在全量上天然吃亏）→ 按段验收。
