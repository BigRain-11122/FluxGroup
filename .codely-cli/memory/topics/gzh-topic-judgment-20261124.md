# 选题判据：从「能写」到「能核」—— 2026-11-24

> 起因：CEO 否掉公众号选题 v1（原话「你的选题还不行」）。
> 正身=`cph4/fleet/social/gzh/TOPIC-SELECTION-SPEC-v1.md`，
> 数据=`TOPICS-v2.json`（20 条），闸=`Tools/fleet/gzh_topics_v2_check.py`（自检 8/8）。

## 一、核心判据（一句话）

**选题好不好，看的不是「能不能写」，是「读者能不能去核」。**

标题里没有可搜的具体对象（车型/机构/法规），`verifiable` 字段写得再漂亮也是
**假可核验**——读者不知道该去查什么，编辑也没法验尸。

## 二、v1 被否的六个原因（逐条有证据）

| # | 毛病 | 例子 | 后果 |
|---|---|---|---|
| 1 | **不点名对象** | 「同价位 5 台纯电 SUV」——哪 5 台？ | 假可核验 |
| 2 | **全是 evergreen 清单** | 17 条 0 条绑事件 | 像百科不像公众号 |
| 3 | **句式单一** | 大量「X 个 Y」「为什么 X」 | 42 号 5% 用疑问句，靠「具体名词+悬念」 |
| 4 | **无对立面** | 全是中性方法论 | 好选题是「谁不希望你知道」 |
| 5 | **无开篇具体物** | `scene` 字段不存在 | 必然写成「随着新能源市场的发展」 |
| 6 | **无一人称锚点** | 全第三人称 | 个人号更该有「我」 |

## 三、六条硬判据（v2 每条必须满足，闸可验）

1. **标题点名 ≥1 个可搜对象**（车型/机构/法规/硬参数）
2. **标题套三种句式之一**：A 具体动作+现场物 / B 数字规格+悬念 / C 断言+对比收口
3. **`opponent` 非空且 ≥6 字**：谁靠这个信息差赚钱
4. **`scene` 是具体物**：黑名单拦「很多/各种/随着/不断发展/越来越」
5. **`verify_before_write` 指向具体页面**（官网配置表/工信部公告/财报/法规原文）
6. **不含 `forbidden_promises`**（我实测/我拆了/我把车摆一起…）

## 四、闸自己犯的两次错（值得单独记）

### 错 1：判据拍脑袋 → 会误杀好标题

我最初定「标题必须点名 ≥2 个对象」。跑闸红了 16 条，其中大半是我的**判据错**不是数据错：
42 号车库的真实标题只点名 **1 个**对象——「探访小米龙甲电池诞生地」「3,000 TOPS 算力智驾芯片明年见」。

**教训：判据要从中位实测里取，不能从"我觉得应该"里取。** 改回 ≥1 后，
剩下的 8 条才是真问题（标题确实空泛），逐条换成真实车型才对。

### 错 2：禁承诺检查有假绿

```python
blob = json.dumps(doc)                      # ← 含 forbidden_promises 定义本身
for bad in FORBIDDEN:
    if bad in blob and bad not in json.dumps(doc["forbidden_promises"]):
        fails.append(...)                    # ← 于是正文里出现同词也放行
```
负控「把 promise 改成『我实测了 800 公里』」**判绿**了。

**正法**：先剔掉 `forbidden_promises` 字段再查：
```python
doc_wo = {k: v for k, v in doc.items() if k != "forbidden_promises"}
blob = json.dumps(doc_wo, ensure_ascii=False)
```
**教训：任何"黑名单里的词允许出现在黑名单定义里"的逻辑，都会退化成"哪都不拦"。**
