## §1 跨字段矛盾：先审计再修，别只修一类

批量生成时每个字段独立采样、互不校验，于是同一个人身上能同时出现
「35 岁男性穿靛蓝改良旗袍」「14 岁戴磁悬浮老花镜」。
**正确顺序 = 先跑矛盾全谱审计（只读），再一次性修完**，否则修了服装还要再来一轮眼镜。

实测（10091 份可解析档案）：
- 男-女性服饰 150 份（旗袍/连衣裙/高跟鞋）
- 女-男士领带 331 份 —— **判为风格不算矛盾**（中性风/中山装在硅基城成立），不动
- <40 岁戴老花镜 318 份 —— 老花约 40 岁起，故阈值取 40 不是 50
- <16 岁-衰老器具 0 份（拐杖/助听器对小孩是真实可能的，不当矛盾）
- <16 岁-重体力 0 份

修法＝按「，」切句段后逐段判定（比正则跨段替换稳），男性按年龄段换同性向服装，
<40 岁删老花镜整段；**先写回滚档** `state/persona-fix-backup.json`（cid → 原服装行）。
落地 464 份，复查全为 0。

坑：`老花呢中山装` 里的「老花」不是老花镜，关键词必须写全 `老花镜`。

## §3 口头禅复读：58% 的年轮用同一句开头

实测 23461 条年轮里 13664 条（58.2%）逐字含本卡口头禅；4184 人复用 ≥2 次，
最严重 6/6 圈全用同一句。

根因两处叠加：
1. 提示词明写「开场句优先取你『语言风格』里你自己的口头禅/行话/底色词」；
2. 人设的 `**语言**` 行带 `口头禅「…」`，整行注入提示词 = 每轮都在给它这句。

修法（零 LLM·确定性，已落地）：
- 已在本卡旧年轮里用过的口头禅 → **从注入的语言串里正则摘掉**（不给诱因比写禁令有效，
  9B 对「禁止 X」常复述 X），并改说「你惯用那句前几条用过了，这条不许再出现」；
- 未用过的保留，但改「最多一次、不要放在开头」；
- `diversity` 块删掉「开场句优先取口头禅」，改为「从此刻手上的一件具体事起句」。

近 7 天口径 28.2% vs 全史 58.2%（已进体检），阈值 35%。

## §4 禁即复述：把被禁开场逐句印进提示词 = 示范

`today_blk / recent_blk / city_phr_blk` 原先把「全城已用滥的开场」连引号原句印出来。
实锚：当日最高频开头 `今天先记一句：袖口被风…`（14 次）正是上一轮被印进禁令的串。
**改法＝只报条数与形状，绝不印原句**；逐字重复仍由闸按 opening12 精确判，拦截力不减。

## §5 天气分流是空转规则，已废止

原设计按 cid md5 让 2/3 席次「本轮不写天气」。实测当日 3691 条年轮：
允许组 1204 条风占比 72.8%、禁止组 2487 条 73.7% —— **分流对模型零效果**。
同时闸侧 `wx-skip-weather` 因为调用点写成 `ring_violations(line, sig)` 没传 cid，
`if cid and …` 恒假，从未生效（日志里偶发的命中来自别的路径）。
→ 分流撤销，天气统一为「至多一句、只说此刻亲历的冷热或天色、不得起句」；
并把硬约束段那句「风只在它真挡住你手上的活时才提一句…」整句删掉——
该段反复出现「风」字本身在给模型打底。

## §6 拒稿只顺延不动 last = 日记永久停摆

拒稿分支把 `next` 顺延 +1d，但不动 `last`。同一席天天被拒就天天顺延，
`next` 永远是「明天」，居民日记永久冻结：实测 813 人（8.1%）自 10-24 起再没写过，
最久 C-03802 停 32 天，而游标还写着 `next=2026-11-19`，看上去一切正常。

两道修：
1. `due_citizens` 自愈——`next` 在未来但 `last` 已 ≥7 天 → 立即视为 due（复活存量）；
2. `fallback_ring(cid, text)` 死信兜底——连拒 3 次（游标 `rf`）改用卡面
   「行为/职业」第一小句 + 确定性结尾落一条年轮（零编造、不过闸、不违反锚定律）。

## §8 提交链路假绿：孤儿锁 + 「不看返回码」

2026-11-18 16:0x 实锚：`life/BigLife/.git/index.lock` 从 15:56 残留（15:56:25），
此后 add/commit 全部 `fatal: Unable to create index.lock`，**而泵日志连续写着
`pump commit: ok`**——16 分钟的年轮写了没进库（302 个文件悬空）。
根因不是锁，是判活方式：`produce_pump` 用 `rl._run(...)` 忽略了 returncode，
只看「没抛异常」就记 ok；`evolve_citizen.commit_files` 则是 `return False` 静默，
四个调用点都没看返回值。

修法（已落地）：
- 泵：检查 add/commit 的 rc（commit rc=1=无改动可提交，属正常），失败打印
  stderr 摘要；若错误里含 `index.lock` 且锁龄 >10 分钟、无存活 git 进程 → 删锁重试一次。
- `commit_files` 失败改为 `print("COMMIT FAILED: ...")`，不再静默。

通用律：**任何「成功」日志必须以子进程返回码为判据，不能以「没抛异常」为判据**——
`_run` 这类包装不因 rc≠0 抛异常，是所有假绿的共同出生地。
清孤儿锁前先 `Get-CimInstance Win32_Process name='git.exe'` 按命令行匹配本仓，
fsmonitor--daemon 与别的仓的 fetch/merge 进程都不持本仓 index.lock。

## §9 风 73% 是天气如实，不要改

当日 `real_signals()["weather"]` = `cloud 13.2°C wind 13.6m/s`（7 级）。
实测允许/禁止写天气两组风占比 72.8%/73.7% → 差异为零，说明这是**数据驱动**而非提示词驱动：
大风天全城提风是生活真实。质量哨兵因此改为天气感知——
`wind>=8m/s` 时风覆盖率顶 = 55% +（wind-8）×5%，封顶 85%（晴天仍按 45%）。
判律：**当一个指标被真实世界数据顶上去时，改文案是错的，改阈值并写明依据才对**；
否则会像 10-16 到 10-18 那样反复改一段本来写对的话。
