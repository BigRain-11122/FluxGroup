# 用脚本生成施工图纸集 —— 方法论与坑录（2026-11-13）

## 一、产物与正身

- 图纸目录页：`house/rental-conversion/drawings/index.html`（11 张 A3，SVG + PNG 双份）
- 生成器：`Tools/house/gen_drawings.py`（唯一几何源，改一处全册同步）
- 预览页生成：`Tools/house/make_preview.py`
- 方案正文：`house/rental-conversion/PLAN-20261113-一套改两套可行性.md`

## 二、架构（可复用）

三层：

1. `Sheet` —— A3 横向 420×297mm，`MM=3`（1 纸面 mm = 3 px），负责图框、标题栏、纸面 mm 坐标的
   线/矩形/圆/多段线/文字/多行文字。
2. `Plan` —— 平面绘制器，把「实尺 mm」换算成「纸面 mm」：`k = 1/scale`（1:50 时 k=0.02），
   提供 line/rect/text/C/window/door 与窗、门的专用画法。
3. 各 `sheet_*()` —— 11 张图各自组图，共用同一个 `base()`（房间填色、外墙、内墙、新墙、窗、
   门、立管、烟道、标注）。

好处：A-01→A-08 的房间轮廓、墙线、门窗位置只写一次；改几何只改一处，不会出现「平面图和
给排水图对不上」。

## 三、四个当场踩到的坑

1. **raw `<path>` 的坐标必须乘纸面→px 因子。**
   `Sheet.L/R/T` 内部统一乘 `MM`，但门弧用裸 `<path>` 手写，若直接写 `Plan.x()` 返回的纸面 mm，
   弧线会缩到 1/3 并跑到图外——症状是图上凭空多一条斜线、所有门都没有弧。
   正法：`self.x(...)*MM`、`self.y(...)*MM`、`self.w(r)*MM`、`stroke-width` 同样乘。
2. **房间名与家具标签必压字。**
   房间名改成「房间内角 + 白色描边 halo」：`paint-order="stroke" stroke="#fff"
   stroke-width=字号×0.75`，先画白底再画字。家具标签按面积阈值过滤（<0.6㎡ 不标），
   窄长件（h > 2.2w）标签转 90°。否则床/橱柜/洁具会各自压住房间名。
3. **Playwright 禁 `file://`，目检必须走本地服务。**
   起 `python -m http.server` + 一个内嵌 `<img>` 的 `_preview.html`，再用
   `page.locator('.wrap').screenshot()` 截图；直接导航到 .svg 会 timeout。
4. **PNG 导出用元素截图，不是页面截图。**
   对每个 `.wrap` 元素截图，DPR 1.3 → 1638×1197，A3 观看/打印够用。

## 四、图面必备要素（缺一项就不像施工图）

- 标题栏：项目 / 图名 / 图号 / 比例 / 日期 / 设计 / 版本 / **阶段与免责**（依据挂牌图反推、未复尺、不得直接施工）
- 比例尺（0–1m–2m 三段）+ 指北针
- 图例（墙/新墙/窗/门/立管/给水/排水/烟道）
- 说明区：要点 + 硬约束 + 实测复核项
- 每张图一个明确意图（结构 / 拆改 / 布置 / 地面 / 天花 / 电气 / 给排水 / 立面大样 / 软装）

## 五、复算

```
python Tools/house/gen_drawings.py     # 生成 11 张 SVG + index.html
python Tools/house/make_preview.py     # 生成 _preview.html 供目检
```

改尺寸后必须重新跑两次并对至少 3 张（布置、给排水、立面）做目检再交付。

## 六、边界

这是「方案深化图」，不是报建施工图。几何由挂牌户型图反推（房间面积 + 尺寸链），
长宽 ±0.3m。开工前必须现场复尺，并核实：承重墙位置、立管管径、门洞位置、外墙能否开窗。
