# 「机制在，但从不工作」的三个实测形态（2026-11-16 换来的）

比"没实现"更危险：看板是绿的、阶段名在配置里、日志有记录，但实际一次都没跑。

## 形态一：slow 阶段被 deferred 卡死

`executor_guard` / `executor_revive` / `viz_audit` 起初都设 `slow=True`（每 5 分钟一跑）。
调度是 `slow_due = time.time() - prev["slow_ts"] > SLOW_EVERY(300)`，而 `slow_ts` 被旧轮次
占住时，整轮走 else 分支，把**所有** slow 阶段写成：

```
stages[name] = {"rc": None, "sec": 0, "tail": "deferred (runs every 300s)"}
```

结果：三个自愈阶段连续几天 deferred，机器从不被自动拉起，而所有面板显示"正常"。

- **判据**：查 `cph4/fleet/dispatcher/PULSE.json` 的 `stages.<name>.tail` 是否含 `deferred`，
  而不是查"阶段名在不在 STAGES 里"。
- **正法**：0.1 秒级的自愈阶段改成 `slow=False`（每轮串行跑），确定性优先；
  自愈动作要带冷却（避免每轮重启服务）。

## 形态二：一个阶段的长超时饿死整轮

`modelradar` 的 timeout 是 900s，某轮卡在拉模型上跑了 **656 秒**，整轮出不来，
排在它后面的所有阶段（含体检）永远轮不到。日志里它显示 `modelradar=-15/656.2s`（SIGTERM）。

- **判据**：单个阶段的 timeout 接近甚至超过整轮正常耗时，就是隐患；
  再算一遍"各阶段 timeout 之和 vs 整轮预算"。
- **正法**：timeout 按真实工作量定（digest 比对 + 本地 list 给 300s 足够），
  拉模型这类长动作拆成独立命令，不放在常驻节拍里。

## 形态三：探不到时不回写状态（假绿源头）

`executor_revive` 对 `offline` 只 `stuck.append(nid)`，**不写 `st[nid]`**。
旧 `healthy` 一直留在 state 里 → bm-c 的 8790 当场探不到，看板却显示 healthy 46 小时前。

- **判据**：状态机是否对每一种判定都回写（尤其是"探不到"这种没有动作的分支）。
- **正法**：探不到也写 `{"verdict": "offline", "ts": now}`；页面再把"healthy 但龄期 > 1h"
  降级成「healthy·陈旧」，两层一起才挡得住。

## 配套：并发 git 的卡死

一次 `git pull --rebase --autostash` 卡在中途（`git reflog` 里 HEAD@{0} 是 `start`、
没有对应 finish）会把本地提交挪出 HEAD——提交对象还在，但 `git log` 看不到。

- **识别**：`git status` 显示 `interactive rebase in progress`，或 `ls .git/rebase-merge`。
- **恢复**：`git rebase --abort`，回到 rebase 前状态（提交与工作区改动完整）。
- **预防**（待做）：脉的自动 git 操作只在工作区干净时 pull。

## 2026-11-18 自驱循环空转四形态（L1 迁入原文）
[2026-11-18 22:39:32] 自驱循环"看起来在转、实际空转"的四类形态与修法（2026-11-18 养号线实锚，可复用到任何定时循环）：①**子命令按想当然拼**——循环里 `human_corpus.py / comment_taste.py / segments.py` 全零参数调用，而三者都要求参数，argparse 直接 exit 2，于是每 30 分钟全红三小时、训练一次没跑；排查时先跑一遍工具的 `--help` 对齐真实 CLI，别先怀疑数据/模型。②**失败只记 rc**——日志里只有 `rc=2` 时根因被藏起来，必须把子进程最后一行输出带进台账。③**开闸按时间而非数据**——"冷却 5 小时到了就重训"会让同一份数据反复烧 2 小时 GPU（965 行→29/43、2655 行→25/43，两次都低于现役 35/43）；正法=同段被否过则要求语料真涨（否 1 次 ×1.10、否 2 次 ×1.25）才放行，并做双向负控。④**save() 是 "w" 的工具被当作增量用**——`human_corpus --from-dir` 会整份重写语料文件，扫到比累计少的目录就从 47963 行静默截短；正法=先并入既有文件再落盘（按内容哈希去重，幂等），并在注释里写明"要重建先删文件"。另：循环连续失败 N 次后"暂停"若只是 return 退出，会被 KeepAlive 立刻拉起重试，表现为无限重试而非停机——停机语义要么写锁文件要么写机读告警，别只靠进程退出。


## 2026-11-19 写了并行/轮换不等于生效（L1 迁入原文）
[2026-11-19 14:51:19] "写了并行/轮换"不等于生效的三个实锚（2026-11-19）：①**Pool 把整行 dict 塞进 IPC + 每行重读一次 spec** → 父进程 100% 卡在序列化、只有 1 个 worker 干活、整机 CPU 23%；正法＝只传文本、worker initializer 预热、回传小元组（48k 行 0.3 秒）。②**近重复分桶太宽**（只按段+长度档，generic 一桶上千行）＝单核 O(n²)，跑 2 分钟无产出；加"首 6 字"后每桶个位数。③**追加+截断保留最旧**（`merged[:80]`）→ 新源永远进不来，日志却写"新增 16 个源"；正法＝保留最新 + 日志报截断后总数。另两条同族：**9B(8.9GB) 是训练的毒丸**，哨兵必须在训练开始前就位（一次性实验尤其容易漏），实测只剩 4B 驻留才安全；**未跟踪的产物目录会被机队 clean 扫掉** → 训练器启动即"缺 train.jsonl"且不写日志，落盘后必须自验文件存在再起训。判据总则：利用率看产出/小时，不看 %；空了先问"是没活还是没排上"，不要为数字造假活。
