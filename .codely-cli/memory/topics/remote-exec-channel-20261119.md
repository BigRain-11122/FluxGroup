# 跨机执行通道：为什么一直走不通 + 正解 — 2026-11-19

> 索引自 `.codely-cli/memory.md`。本文件纠正 2026-11-11「8790 只有传家宝在听」的旧端口结论，并定下 Windows 机的正解通道。

## 1. 根因（不是工具坏了）

把**四件事全压在 git 上**：代码发布、消息队列、命令执行、回执。任何节点提交运行时文件就分叉 → `pull --ff-only` 必失败 → 拉不到新卡 → 执行不了。症状表现为"机队不通"，实为"git 被当成执行通道"。

## 2. 三条通道必须分清（这是本轮最重要的一条纪律）

| 用途 | 通道 | 特征 |
|---|---|---|
| 传数据/代码 | git（origin 快照） | 会分叉、有延迟、不该装运行时产物 |
| 传信号/唤醒 | FleetLink `/poke` | 单跳 ~14ms，`reason` 必须含 `enable-tasks` |
| 执行命令 | **SSH**（或"卡里 cmd"） | 真正能跑任意命令的面 |

任何一条被拿去兼任，都以分叉或静默失败收场。

## 3. 通道边界实测（2026-11-19，可能与更晚的现场不同）

- 公司生产力机（DASHENG / bm-a）：**8790 / 445 / 3389 / 4222** 可达。
- 小钢炮（BIGMONEY / bm-b）：**离线 4 天以上**。
- 传家宝（FLUXGROUP / bm-c）：**仅 445 / 3389**，8790 不通（**勘正** 2026-11-11 的旧结论）。
- **NATS 4222 上没有任何 FleetAgent 订阅** ⇒ 它只是总线，不是 exec 通道。别再拿它当命令入口。

## 4. 正解（已写工具，尚未在任何机器执行）

一次性启用 Windows 自带 **OpenSSH Server**，之后直接 `ssh <user>@<host> "任意命令"`，彻底摆脱"靠 git 绕"。工具=`Tools/fleet/enable-remote-exec.ps1`。

- 状态：**未执行**。属现场/远程桌面动作（需在机器本身跑一次）。
- 判据（装完怎么算通）：从主控 `ssh -o BatchMode=yes <user>@<host> "hostname; echo ok"` 直接返回机器名与 ok，而不是靠回执/心跳自述。

## 5. Windows 侧其它硬事实（供后续复用）

- 自包含远程命令=base64(UTF-16LE) 的 PowerShell，纯 ASCII，长度上限 8191，节点 id 由卡注入。
- 解释器绝对路径：Windows 上 `python`，macOS 上 `python3`（`/usr/bin/python3` 是系统 3.9，plist 里必须写绝对路径）。
- 无执行通道时只能做三件：写对方台账（FleetLink `/sync` union 追加 orders.md）、投它上线必消费的 outbox、把最小动作压成一行命令交出去。
