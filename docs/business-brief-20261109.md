## 三、钱与成本

- **收入**：仓内未见已成交/回款台账（推断：尚未产生实质收入）。
- **成本**：机队电费 + 云端 token + 人的时间（CEO 一人）。算力是最大可变成本。
- **算力策略**（cph4/local-first.md）：L1 规则零 token → L2 本地 LLM → L3 云端，铁律"先问 L1/L2"。
- **产能现状**：生产队列 1,654 张卡，590 DONE / 725 CANCELLED / 309 ARCHIVED / 19 UNVERIFIED / 6 FAILED / **1 OPEN**。
  大量历史卡是清理与返工；当前真正在跑的很少——产能没有压在"出货"上。

## 四、现在真正的三个瓶颈

1. **收款**：19.9 卖不了，因为商户号/支付资质未签（CEO 物理件）。这是从"能演示"到"有收入"的唯一硬闸。
2. **上架**：39 款游戏 0 上线，卡在隐私政策（机队可做）和跑包截图（需 CEO 放行）。前者不依赖任何人，是当下最该被清掉的活。
3. **产能错配**：大量自动化在维护自己（队列丢行、TTS 卡错机、模型雷达），而不是生产可卖物。
   725 张 CANCELLED 需要一次归因，否则"忙"会继续被当成"有产出"。

## 五、这台 Mac（bm-m）该干什么

| 能干 | 不该干 |
|---|---|
| 主控/调度/判读/一屏 | 渲染、训练、批量转码、回测重活 |
| 轻模型常驻（4B，≤5GB）+ 需要时 8B 单槽 | 常驻大模型跟办公抢内存 |
| 批量读文档/摘要（746 块已跑） | 当"全能大脑"做最终判断 |
| 把业务缺口转成可派卡、盯回执、催办 | 自己下场写产品/文案（越界） |
| 检索查证（repo_rag，带路径） | 代替 CEO 做取舍 |

实测边界（本机 32GB）：4B 24 tok/s / 8B 13 tok/s；8B@32k 占 7.7GB，装 8B 后全系统只剩约 2.6GB。
所以"质量与效率平衡"的正确姿势是：**4B 干粗活、8B 只做对话与判读、云端做综合与难题**。

## 六、这一轮本地模型到底做了什么

- repo_map：242 个文件、746 块，4B/1.7B 分块摘要（结构 100% 覆盖，内容分层）。
- agent 车道：8B 单槽 32k，冷启 81s / 热态 4s；工具调用、AI.md 三问、机制图八层复述均通过。
- repo_rag：815 块向量索引，五题事实命中率 0.07 → 0.49（仍是"查证工具"，不是"理解引擎"）。
- 结论：本地模型适合**抽取与初筛**，不适合**归纳与定夺**。

## 七、建议的下一步（业务优先，不是技术优先）

1. **36 款隐私政策 + 台账补登**：不依赖任何物理件。控制面该做的是**派卡给 bm-a 并盯回执**，不是本机自己写。
2. **19.9 材料包**：报价/成本/退款说明做成待签稿，CEO 一签就能开卖。
3. **725 张 CANCELLED 归因**：找出"为什么忙却没有可卖物"，把产能压回三条能变现的线。
4. 技术侧只做一件：等 bm-d 入网，把 35B 挂成局域网路由，本机彻底退回调度位。
