# 本地模型 Agent 的角色边界（2026-11-10）

> 问题：是否让 agent 用本地模型去做监控、派活、验收？
> 结论：**要，但只做「参谋」，不做「法官」**——决定权留在确定性脚本，模型只负责读懂、挑可疑、给理由。

## 一、为什么不让模型直接控盘

1. 不可复现：同一张卡两次判断可能不同，出了事故查不清；
2. 慢且贵（相对）：4B 一次判读 2–5 秒，监控要秒级；
3. 会编：模型说「完成」不代表盘上有文件——诚实律要求只认产物；
4. 权限风险：模型一旦能改状态，一次幻觉就能把假绿写进台账。

## 二、三个角色，三种权限

| 角色 | 谁做 | 权限 | 产出 |
|---|---|---|---|
| 监控 | patrol_seats / selfwatch / resilience（规则） | 只读+自愈 | 旗标、自愈记录 |
| 监控研判 | local_auditor / local_analyst（本地模型） | 只读 | PASS/SUSPECT/FAIL + 理由 |
| 派活 | master_agent（规则） | 写队列（单写手） | 派单结果 |
| 派活建议 | （下一步）local_planner（本地模型） | 只读 | 建议顺序与理由 |
| 验收 | verify_done / 回执核对（规则） | 写状态 | DONE/UNVERIFIED |
| 验收初审 | local_auditor（本地模型） | 只读 | 交付物是否满足验收条款 |

## 三、已落地：验收初审 local_auditor

- 每 10 分钟扫最多 8 张新完成卡；
- 本地交付物：读文件 + 验收条款 → 4B 判 PASS/SUSPECT/FAIL + 一句理由；
- 远端交付物（D:\ 等）：标 REMOTE，不误报 MISSING；
- 缺失文件：标 MISSING（确定性判断，不消耗模型）；
- 只写 state/local-audit.jsonl，**不改卡状态**；SUSPECT/FAIL 供日报与人工复核。

## 四、下一步（自动推进）

1. 派活建议器：读队列+能力台账，给「接下来 10 张该谁做」的只读建议，与 master_agent 结果做对照；
2. 监控研判：把巡视 RED/黄灯聚合成一段「最可能的原因」，减少人工看板时间；
3. 所有模型输出统一带证据指针（文件/行号），无证据不采信。

## 五、红线

模型不得写队列、不得改卡状态、不得决定付款/对外发送；一切落地动作仍由规则脚本执行并留痕。
