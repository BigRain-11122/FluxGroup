## 〇 一句话诊断（校准后不变）
**产能端过剩，"被真人触达"的下游为零。** 而头部的做法恰恰相反：**用极少的产能做极多的验证，只放大过关的那一个。**

## 三 跨线三条共性规律（治根）
1. **下游第一**：各线北极星必须含**一个外部可达指标**（发布数/上线数/到账额/可达 URL）。
2. **只放大过关的那一条**：未过市场测试**不得投产能**（头部砍款率 90%、点子淘汰制）。
3. **验证体量决定生死**：头部是"**少量产能 × 海量验证**"；我方现状是"海量产能 × 零验证"——**方向相反**。

## 五 v1.0 探针的两处假阳修正（**我自己工具的错，留痕**）
`Tools/benchmark-gap-probe.ps1` 首跑 8 条 wired 中 **2 条是假阳**：
1. **R-D1 报 `accessible_fronts=1` PASS**——实为 `BigDomain/tests/` 或沙盒内的 html 被计入。**"可访问前台"必须定义为"外部可达且有点击录屏"**，不能用"仓内有 html 文件"替代。**已改判为 `DEFINITION_GAP`**（口径未定义＝不得判 PASS）。
2. **R-F2 报 `layout_data_files=4` PASS**——实为 `world-state.json` 等**数据快照**被误认为"装配数据源"。**装配数据源须是装配器消费的 layout 件**（`ui-layout.json` 或等价），快照不算。**已改判为 `WEAK_SOURCE`**（须人工确认）。
3. 另：R-L1 报 `wired=6`，而 BigLife 自报判据件为 **3 仓**——差异来自我的解析器按 "wired" 字样计数（6 处提及）而非仓数。**已标注口径待对齐**。
> 教训与附录 A5 同型：**探针报 PASS 不等于达标**；口径未定义时正确输出是 `DATA_GAP`/`DEFINITION_GAP`，**不是 PASS**。
