# Local-First — 集团本地化算力战略（CPH4 Labs）

> CEO 令（2026-09-23 原话）：「各公司和集团做好本地化的策略，token 可以烧，但要同时建立本地化系统化能力，能自我运算，直到后面减少 token 的使用」

## 0. 战略三句话

1. **现在放开烧**：token 费用不是现阶段的约束——全速迭代优先，禁以省钱为由降速。
2. **同时建本地**：各公司与集团同步建设本地系统化算力（确定性自动化 + 本地 LLM），高频低险任务逐步自算。
3. **终点是自持**：token 用量随本地能力增长**结构性下降**——不靠省，靠替换。

## 1. 三层算力阶梯（任务路由原则）

| 层 | 载体 | 适用 | 现状与方向 |
|---|---|---|---|
| **L1 确定性自动化**（零 token） | 脚本/门禁/规则引擎 | 巡检、门禁、格式化、台账、心跳、审计 | 两公司已强（X026Gate/EncodingGate/NameCheck/smoke/门禁链/探针）——**最大化** |
| **L2 本地 LLM**（零 API token） | Ollama（bm-a=4070S 12GB·bm-b=3070·qwen2.5:7b 现役） | 高频低险：摘要/分类/初筛/复盘/代码一审/内容草稿 | 已有保温件与借算协议（fleet §5）——**成长层** |
| **L3 云端大模型**（token） | Codely API | 高险/复杂推理/跨域决策/立法 | **收缩层**：只做 L1/L2 干不了的 |

**路由铁律**：任何任务先问「L1 能不能？」再问「L2 能不能？」最后才用 L3。

## 2. 执行纪律

- **测量先行**（科学决策）：各公司先立 token 计量（轮账本记本轮用量，CLI 有数据则精确、无则粗估标注），再谈迁移——进化轮周报聚合集团用量趋势，季度评 L1/L2 覆盖清单（清单制，不设虚 KPI）。
- **本地能力清单**入 `cph4/README` 能力注册表：各机 Ollama 模型/显存/keep-warm 状态；借算走 fleet §5。
- **零负担接入**：本地 LLM 从轮内单步开始（摘要/初筛先跑通再扩），禁要求产品大改造。
- **GPU/共享机纪律照旧**：keepwarm.pause 释放阀、RAM<4GB 禁新开重活（fleet §10）。

## 3. 各公司落地路线（集团定方向，落地各公司自治）

- **BigMoney**：J13 本地 LLM 研究助理升格为本地化路线载体（qwen2.5:7b 承接轮报告摘要/策略代码一审/复盘初稿），令已发 fleet/orders。
- **Biggame**：Ollama 保温栈已有（OllamaServe/KeepWarm/GpuStackBoot）——ME 反思道、审查审计等高频低险任务渐进路由本地。
- **BigStream**：内容生产线按 L2 优先设计（草稿/标题/初筛本地生成；终稿与合规审查可留 L3）。
- **集团层**：进化轮的感知/摘要类步骤未来可路由 L2；治理与立法永远 L3+CEO。

## 4. 检验

- 集团 token 用量趋势进进化轮周报（升/降如实，禁粉饰）。
- 季度进化轮附「本地化覆盖清单」：哪些原 L3 任务已由 L1/L2 承接。
