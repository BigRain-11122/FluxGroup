# FLUX OS v2 — 集团顶层架构设计（2026-11-02）

> 性质：**顶层设计正典（单一入口）**。本件回答"集团由哪些模块组成、模块之间只怎么说话、业务与机队怎么装进这套模块"。
> 溯源：CEO 令 2026-11-02「从头开始，把集团和业务、机队等所有的都模块化设计一次」+「先调研，不要着急回答」。
> 体量纪律：本件只写**结构与判据**，不复制各领域法条；细节一律落到代码与 schema，不落成新规则。
> 一句话：**把"按公司切"改成"按能力切"；把"手写状态"改成"磁盘生成"；把"自研一切"改成"接标准"；把"13 条线"改成"3 条产品 + 能力库"。**

## 三、六条设计原则（后续一切结构由此推出）

1. **事实由磁盘生成，人只写意图**——状态文件一律是构建产物（generated），手写状态=无效。登记表由扫描器生成，与磁盘差集即告警。
2. **一个事实只有一个权威**——同一语义只允许一个文件/schema；其余是投影（可丢弃重算）。
3. **跨模块只有契约，没有 import**——模块间只能投递 6 种契约件；换实现不改别人。
4. **能力轴，不按公司轴**——业务线=配方（recipe）；公司=账本与品牌，不是技术边界。
5. **不自造轮子**——运行时用 dsh，持久化用 SQLite step journal，协议用 MCP/A2A/AG-UI，技能用 SKILL.md，视频用 Wan 2.2。
6. **默认放行，闸只留三类**——不可逆 / 对外发布 / 花钱超限；其余自动继续 + 事后复核（CEO 2026-11-01 最高规则）。

## 三定、CEO 定案 2026-11-02（三岔口全部取推荐项 A/A/A）

这三个选择一旦定下，后面所有组织、条线、子公司都以此为准，不再重新讨论：

| 定案 | 内容 | 直接后果 |
|---|---|---|
| **① 所有子公司保留，只分优先级** | 8 个载体全部保留；P0 内容 ＞ P1 游戏 ＞ P2 量化与前台 ＞ P3 城市与渠道 | 低优先级不关停、只排队；有书余算力就跑，不造活 |
| **② 机队干确定性重复活** | 配音、装配、质检、闸、批处理在本地；重 GPU 活按项目租或走云 | 不再为"满负荷"造活；内存不够就排队，不许硬扛 |
| **③ 治理砍成三类决策** | 机器判（有断言）／人判（有 SLA）／CEO 裁（方向·红线·花钱） | 委员会名义投票取消；只留"谁判的+依据+复核" |

**由此产生的四条硬约束（写进流程，不靠记）**
1. 开新线必须同时回答：谁买、谁判、哪台机器干、第一件产物是什么。四缺一，不开。
2. 任何线连续 7 天没有可核验产物，自动降级为"暂停"，不解释、不补文档。
3. 只有两条产品线可以占用生产机器；其余最多用夜间空档。
4. 对外的一切（发布、报价、签约、发言）只出草稿，签名权在 CEO。

## 四、全盘架构：5 层 · 17 模块

```
L0 决断层   K1 ORDER ──────────────────────────────┐  CEO 四输入面 → 令
                                                    │
L1 事实层   F1 CENSUS   F2 CONTRACT   F3 EVENT ◄────┘  磁盘事实 / schema / 事件流
                                                    │
L2 能力层   C1 SCOUT  C2 STUDIO  C3 GATE  C4 SHIP  C5 VAULT  C6 DEAL
                                                    │
L3 执行层   R1 ORCH   R2 NODE   R3 MODEL   R4 STORE ┘  卡→机→模型→盘
                                                    │
L4 观测层   O1 BRAIN  O2 AUDIT  O3 CITY             一屏 / 不变量 / 元宙
```

| 模块 | 唯一职责 | 输入 → 输出 | 状态正身 | 替换成本 |
|---|---|---|---|---|
| **K1 ORDER** | CEO 四输入面 → 令 | 口头/文字 → `orders/<id>.json` | `docs/orders.md`（人读）+ json（机读） | 不替换（宪法） |
| **F1 CENSUS** | 扫盘生成事实 | 磁盘 → `state/lines.json` `state/assets.json` | 生成物，不入 git | 低 |
| **F2 CONTRACT** | 6 契约的 schema 与校验 | 任意契约件 → pass/fail | `cph4/contracts/*.schema.json` | 低 |
| **F3 EVENT** | 追加事件、投影状态 | 事件 → `state/*.json`（投影） | `events/<node>/<date>.jsonl` | 低 |
| **C1 SCOUT** | 选题/竞品/需求 | 主题 → `research-card`（含机会/成本/判据） | 调研卡（git） | 中 |
| **C2 STUDIO** | 内容生产 | 配方+资产 → 母版 | 母版目录 + artifact 记录 | 高（但可换模型） |
| **C3 GATE** | 质检与放行 | 母版 → `verdict` | `verdicts/<id>.json` | 中 |
| **C4 SHIP** | 发布/合规/回填 | 母版+verdict → 已发布+数据 | `ship/<id>.json` | 中 |
| **C5 VAULT** | 资产总账 | 文件 → `artifact`（sha/许可/血缘） | `vault/index.jsonl` | 中 |
| **C6 DEAL** | 定价/报价/回款草稿 | 能力+成本 → 商务案 | `deals/<id>.json` | 低 |
| **R1 ORCH** | 卡→机→步 | recipe+state → 卡流 | SQLite（本地）+ 卡事件 | 高（用成熟件） |
| **R2 NODE** | 单机执行 | 卡 → 回执 | `receipts/` | 高（dsh 插件） |
| **R3 MODEL** | 模型路由与配额 | 请求 → 结果 | `events/model.jsonl` | 中 |
| **R4 STORE** | 三仓与对象 | 写 → 落位 | git / D盘 / 对象存储 | 低 |
| **O1 BRAIN** | 一屏决策 | state → 一页（3 个待决 + 3 个阻塞） | `state/brief.json` | 低 |
| **O2 AUDIT** | 不变量总闸 | 全仓 → 12 条断言 | `state/invariants.json` | 低 |
| **O3 CITY** | 元宙观测面 | state → 可看可操作 | 城市仓 | 中 |

**模块准入五问（不合格不叫模块）**：①输入什么文件 ②输出什么文件、在哪 ③坏了自己会不会被发现 ④谁能换掉它 ⑤关掉会缺哪张产物。

## 五、六个契约（模块间唯一语言，对齐 MCP/A2A）

| 契约 | 必填 | 对齐标准 | 一处权威 |
|---|---|---|---|
| **ORDER** | `id / ceo_verbatim / scope / affects[] / receipt_window / veto_window` | — | `orders.jsonl` |
| **CARD**（作业卡） | `id / line / stage / needs{profile} / deliverable{path,min_bytes,nonempty} / accept[] / idempotency_key / ttl` | A2A Task | 卡流 |
| **RECEIPT**（回执） | `card_id / rc / error_class / artifacts[] / host / seconds / stdout_tail` | A2A Task 终态 | `receipts/` |
| **ARTIFACT**（资产） | `sha256 / kind / path / bytes / license / provenance{line,stage,card,inputs[]} / gate_status` | — | `vault/index.jsonl` |
| **VERDICT**（闸判） | `gate / input_sha / checks[{name,value,threshold,pass}] / pass / tool_version / approved_by` | — | `verdicts/` |
| **RECIPE**（产品配方） | `product / chain[C*] / acceptance[] / channel / unit_economics / kill_criteria` | — | `products/<name>.yaml` |

**四条硬约束**
1. 卡不带 `line` → F2 拒收（现有 90/97 张卡即违规）。
2. 卡只声明**资源画像**（`gpu_vram_gb/cpu/io/model_slots`），**不写机器名**；由 R1 匹配（现有 `lane: bm-d` 即违规）。
3. 回执不带 `rc` → 不算收口；`rc≠0` 必须带 `error_class`。
4. 交付物没有 ARTIFACT 记录 → C3 一律判 fail（"无登记即不存在"）。

**十二条不变量（O2 `flux_check.py` 一跑全判，红即停）**

| # | 断言 | 现状对应 |
|---|---|---|
| I1 | 每张卡有 `line`，且该 line 在 `products/` 有 recipe | 90/97 张卡无 line |
| I2 | 卡内不含机器名与盘符绝对路径 | 卡里写死 `D:\` / `C:\` |
| I3 | 每份回执有 `rc`；`rc≠0` 必带 `error_class` | 25/106 无 rc |
| I4 | 每个交付物有 artifact 记录（sha256+bytes） | 资产索引仅 8 条 |
| I5 | 每个 artifact 有 provenance（line/stage/card/inputs） | 不存在 |
| I6 | `state/*.json` 不被 git 跟踪 | 现在全部入 git |
| I7 | 队列只有一个写入口（持有锁者） | 7 个脚本并发全量写 |
| I8 | 每个 GPU 任务租约带 `job_id` 且持有者一致 | owner 恒为 `gpu_lease` |
| I9 | 闸判带 `tool_version` + `input_sha` | verdict 无版本 |
| I10 | 发布件必含 AIGC 隐式标识字段 | 无 |
| I11 | 每条产品有 recipe 且带 `kill_criteria` | 无 |
| I12 | 每个脚本至少一个调用者，否则归档 | 3+ 孤儿脚本 |

## 七、生产管线（C2 STUDIO 的落地形态）

```
配方 → 角色圣经(C5) → 分镜/关键帧(轻档 Wan-5B/图模型) → 出片(重档 Wan-27B 或云) →
装配(--grade/EDL 重建) → 闸(C3: 机检 + 观众级) → 资产入账(C5) → 分发(C4: 标识+备案)
```

- **一致性四件套**：角色设定卡（正/侧/背 + 光位）→ 角色 LoRA（10-20 图）→ 主体参照（IP-Adapter/首帧）→ 固定 seed；缺一件不许开拍。
- **闸不是十个工具，是两层**：`不变量总闸`（结构对错）+ `领域闸`（画面对错：帧数/seam/freeze/OPPOSE/重复/静止）。领域闸必须是**可传参的同一执行器**，不是十个脚本。
- **观众级不可省**：静音看全片并复述主线；机器全绿而人一眼看出问题 = 闸失效（既有判例）。

## 八、机队与运行时（R1–R4）

**机器只声明能力，卡只声明需求**

| 机 | 画像 | 在体系里的角色 |
|---|---|---|
| 公司生产力（bm-a，32 核 / 27.5GB 空闲） | cpu-heavy / io / 轻 GPU | 装配、构建、批量转码、夜窗重活 |
| 小钢炮（bm-b，16 核 / 3.3GB 空闲） | cpu / 音频 / 回测 | 配音、回测、数据 |
| 传家宝（bm-c，3070 16GB / 内存不稳） | gpu-16G | 出图出片、LoRA/图标/归集与验收；内存 <8GB 时**不派**（硬画像） |
| 算力大脑（bm-d，3×V100 48G，未入网） | gpu-48G×3 | 入网即自动进池，不改任何业务代码 |
| MacBook Pro（bm-m，32GB） | 调度/判定/出包 | **只做编排、判定、观测**；重活不符画像 |

**R1 ORCH 的形态**：卡 = workflow；每步 = 带 `idempotency_key` 的 durable step，落本地 SQLite（WAL）；进程崩了重跑只回放已完成步。派单只有一条路径：`state` 投影 → 选卡 → 匹配画像 → 投递。**不再有 4 套派单脚本。**

**R2 NODE 的形态**：`dsh`（插件化）+ 一个集团插件（`claim / heartbeat / gpu_lease / receipt / artifact_register`）。执行器 PATH 与解释器差异写进画像（Mac 用 `python3`，Windows 用 `python`）。

**现状代码的取舍（实测结论，不是推倒重来）**

| 判定 | 内容 | 依据 |
|---|---|---|
| **保留（纯逻辑，值得进新基座）** | `run_stage()` 的 (rc, sec, tail)+`ok_rc` 步骤模型；`pull_if_clean/push_if_ahead` 的"手写脏件 vs 生成态脏件"分离与**永不 rebase** 铁律；swap 用 **pageouts 增速**判据；`route_decision/choose_lane/assign` 三个纯函数；`closer` 两条规则（**产物在盘才算 DONE**、心跳 600s 无回执退回）；`already_closed` 幂等判据；`run_job` 的"后台线程 + 每 45s BUSY"；`line_agents.arm_recurring` 的 every_h 语义 | 这些是不依赖文件形状的正确判断，换引擎照样成立 |
| **重写** | 编排（23 脚本串行 → 一张 DAG + 一次 SQLite 事务）；GPU 租约（见下）；状态投影（3 套 → 1 套生成物）；派单（4 套脚本 → 1 条路径）；git 同步（4 份实现 → 1 份） | 现状为胶水拼装，形状不成立 |
| **废弃** | `when_all` 的双重语义；`cwd` 空串即仓库根的隐式约定；`MASTER-TICK.json` 字符串选举；`MASTER-STATE/PULSE/SUPERVISOR` 三套互写；`/tmp` 自造锁；`shell=True` 执行层；`backlog_fill.py` 双份；`planner.py`/`steward.py`/`free_mem.py` 等**无人调用**的孤儿 | 实测：孤儿脚本 3 个以上；同名双份 1 组；4 份 git 同步 |

**必须一并修掉的四个硬缺陷（否则新架构照旧烂）**

| 缺陷 | 实测 | 正法 |
|---|---|---|
| **"单写手"是宣称，不是事实** | 7 个脚本对同一队列全量读改写、无锁 → lost update | 队列只由 R1 写；一切变更=事件追加；状态=投影（SQLite 单事务） |
| **纸闸** | `gpu_lease --if-held-ok` 默认返回 0（第二个任务直接开跑）、owner 是字面量、无续租、写入非原子；`mem_gate` 永远 `return 0` | 租约带 `job_id+pid+心跳续租`，`--strict` 为默认；内存闸返回**判定值并阻断**，否则删掉别假装有闸 |
| **看门狗自反馈环** | 串行阶段上限合计 900s > watchdog 420s → 健康但慢被 `-k`，子进程成孤儿继续写 | 心跳与周期解耦（每完成一阶段即刷新 mtime）；`-k` 杀进程组；DAG 单步超时 < 心跳阈值 |
| **密钥明文** | `com.fluxgroup.webai` 的 `WEB_PASSCODE`、`com.fluxgroup.gateway` 的 `ROUTER_TOKENS` 直接写在 plist | 移入 Keychain/`.env`（gitignored），plist 只留引用 |

**失败分类学（强制，替换自由文本）**

**rc 归一（先定义再判读）**：`0`=OK｜`2`=契约不合（E-CONTRACT）｜`124`=超时｜`126`=不可执行/模型不可用｜`127` 与 Windows `9009`=命令不存在（E-PATH）。**"有产物就算成功"不再成立**：产物存在只能证明"跑过"，成功只由 `rc==0 且 verdict.pass 且 artifact 已登记` 三者同时成立。

| 码 | 含义 | 自动动作 |
|---|---|---|
| `E-CONTRACT` | 卡/回执不合 schema | 拒收+退回制造者，不重试 |
| `E-PATH` | 路径不存在/跨机不可达 | 转投正确节点，不重试 |
| `E-MEM` | 内存低于地板 | 排队到夜窗，不重试 |
| `E-MODEL` | 模型/权重缺失或加载失败 | 降档重试 1 次 |
| `E-QUOTA` | 配额/额度 | 暂停该线，告警 |
| `E-TIMEOUT` | 超时 | 续跑（durable），最多 2 次 |
| `E-COMPLIANCE` | 标识/备案缺失 | 阻断发布，不可绕过 |
| `E-UNKNOWN` | 其余 | 进判断席 |

## 九、状态、记忆与法

**三仓分离（解决"状态噪音阻断派单"）**

| 仓 | 内容 | 写入频率 | 同步 |
|---|---|---|---|
| **法/代码仓**（本仓） | 法条、配方、契约 schema、工具代码 | 低频（人改） | git |
| **状态仓** | `events/*.jsonl`（追加）、本地 SQLite | 高频 | git 每小时批量 / NATS 加速 |
| **资产仓** | 母版、模型、音色、美术包 | 大文件 | D 盘 + 外置盘冷备 + 内容寻址 |

铁律：`state/*.json` **不入 git**（gitignore，由事件投影生成）。谁再手写状态文件，O2 直接判红。

**记忆（治理，不是检索）**：L0 硬法 ≤300 字 / L1 项目指针 / L2 主题文件 / L3 事件与台账。
每条记忆带 `status(candidate|confirmed|superseded|expired)` + `source` + `scope` + `expiry`；索引**生成**，不手写；冲突时"实况优先"自动降级旧条目。**单一写入口**，禁止多会话各自 append 造成冲突标记。

**法**：不新增法条。新机制先问"能否并入不变量或现有闸"，不能才立法；T0 变更仍归 CEO。

## 十、合规内建（C4 SHIP）

- **隐式标识（机器可读，原则上强制）**：输出文件元数据写 `AIGC` 字段 + 内容哈希 + 服务方编码；视频写 MP4 容器元数据，图片写 XMP。
- **显式标识**：成片是否加"AI 生成"字样 = **CEO 决定**（既有令：不加）；但平台上传声明位照实勾选。
- **微短剧**：备案后上线；算法不得诱导沉迷/过度消费。
- **日志**：无显式标识的输出，留存提供对象与时间 ≥6 个月。
- **红线不动**：零真人脸、品牌规避、儿童场景四查、密钥不入 git、真金永禁全自动。
