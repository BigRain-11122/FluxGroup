# GitHub 风向雷达（研究室常设职能）v1.0

> 溯源：CEO 令 2026-09-29 ~13:1x「研究室要全面理解城市和各子公司的业务，并持续提供创新，技术，工具等赋能，尤其要了解github的风向和技术。高频点赞的务必做好研究落实，」（ledger P-2026-09-29-06·registry O-2026-0929-002）。
> 性质：T2 立法·否决窗 7 天（至 2026-10-06）。本件 ≤60 行·季度法熵审视随周轮。

## 一 职能定谳（三面）

1. **业务理解底座**：研究室=全面理解城市+七司业务的常设持有者——锚件清单=AI.md（组织/机制总览）+FluxVerse BLUEPRINT/DESIGN/TECH+BigLife CODEX/SILICON-LIFE+BigMoney PLAN+fleet+BigStream PLAN+BigDomain BLUEPRINT+BigCompute BLUEPRINT+MiniGame 产品仓族+cph4/city-lab+README 注册表。**每轮研究必带司域映射一行**（发现→哪个司哪个业务面），零映射=未交付。
2. **持续赋能**：创新/技术/工具产出走既有落点强制律（接线单/采用登记/结论应用表）——闭环率=唯一 KPI（city-lab 同律），产出量=虚荣指标。
3. **风向雷达**：GitHub 风向与技术的集团横切面——高频点赞项目（trending/高星好评）务必研究落实（见 §三判据）。

## 二 寻源面（三源·礼貌节流律全程适用）

| 源 | 方法 | 频率 |
|---|---|---|
| GitHub trending | trending 页直读（daily/weekly·HTML 面不占 API 配额；被带偏即换源重试一次） | 每窗 |
| 高星好评工程 | search API（配额内）/git ls-remote（配额绕开正法）/star 增速榜外站 | 每窗 ≥1 次实搜 |
| 领域专项 | 各司业务面触发式（如治理域 O-2026-0929-001 三波在飞=专项先例） | 触发式 |

## 三 「高频点赞=务必研究落实」判据（CEO 原话即约束）

1. trending 榜内与七司业务**契合**的项目 → **必研究**：R- 切片或 OH 切片承载·五门评估（oss-harvest §四）·api.github.com 逐件直验（限流时 git ls-remote/raw 直读换源律）。
2. 契合且过五门 → **必落实**：接线单/采用登记（oss-harvest §五）/转目标司任务单——无落点=未交付。
3. 不契合 → **一句话判负留痕**（诚实律·禁止硬凑）。
4. 三红线不变：GPL/AGPL 禁入产品交付链（工具环境例外注记）/许可逐件验原文/外部工程资产不搬。
5. **即 hot 即报**：star 暴涨级/爆发性项目（日增千星族）→ 当窗即报夜轮/值守轮线，不等 72h 窗。

## 四 节律与台账

- **每窗（72h·OSS 轮）**：CPH4 切片必含风向面 ≥1（trending 扫描实录+候选判读）——OH-<date>-cph4.md 切片承载。
- **周轮**：风向简报一行入进化轮五议程（本周榜内契合件/已落实件/判负件计数）。
- **回访**：研究→落实→生效闭环率随周轮抽验（audit-office 同向无效功面咬合）。

## 五 边界与咬合（禁双建）

- 与 **P-2026-09-26-18 调研部建制**：彼=各司调研部自扫各自领域前沿；此=研究室集团横切风向面+跨司赋能。互引禁重复。
- 与 **O-2026-0929-001 治理域专项**：彼=专项执行波（R-20260929-gov-* 三件在飞）；此=常设职能立法。专项产出照走本雷达台账。
- 与 **oss-harvest.md**：风向雷达=其「寻源面」的常设化扩容；五门/落点/采用登记全复用不重建。
- 与 **research-protocol.md**：R- 件标准/源分级/结论应用表全适用。
