## 中心：智能体管理（AI 管 AI）

### 一、谁在管 · 三层身体（各司其职，不混用）

1. **主控脑** — Mac bm-m，`master_pulse` 常驻脉
   - 只出四样东西：卡、裁决、告警、一屏
   - 禁自己生产（出图/渲染/装配/回测一律派卡）
2. **执行机** — Windows bm-a / bm-b / bm-c / bm-d，`lane_agent` 车道
   - 从 origin 的 `lanes/<node>.json` 取卡，回执写 `queue-receipts/`
   - 一台机器多个槽位，GPU 活同刻只 1 张
3. **常驻轻量模型** — `qwen3.5:4b-mlx`（7.6GB，`num_ctx` 8192）
   - 只做分类/摘要/打分/抽取，结论一律规则复核
   - 4B 算术必错（已实测）→ **所有数字由规则算，不交模型**
   - 云端模型按日预算 ¥100 硬顶，走 `cloud_budget.py`
4. **不混用的理由**
   - 32GB 是模型与 CEO 办公应用共用的同一内存池
   - 主控越界当生产者 → 指挥部空转（已发生两次）

### 二、管什么 · 六个面（缺一面就有盲区）

1. **值守** — 进程活着≠在干活
   - `executor_guard` / `hb` / `qcheck` / `canary`（1–2 分钟）
2. **派单** — 每条线都要有明确下一步
   - `ceo_queue` / `night_plan` / `workgen` / `supply_target`
   - 软判据：**队列有变化，或明确报「无活可派」**——不许沉默
3. **监督** — 盯产出不盯心跳
   - `done_audit` / `asset_reach` / `deadline`
   - 四信号：产出年龄 + git 提交 + 远端回执 + 磁盘 mtime
4. **验收** — DONE ≠ APPROVED
   - `artifact_review` 三层审核 → 入档 `archive/` → 待入 `INTAKE-PENDING.jsonl`
   - 子仓没 clone 时**只记「待入」，绝不假装入库**
5. **自愈** — 问题必须有人收口
   - `self_improve`（码龄/空壳/依赖）+ `fork_close` + `node_closeout.ps1`
   - 告警必须有消费方，否则等于没告警
6. **汇报** — 只看三个文件，不看过程
   - `CEO-NEXT.md`（一条）/ `CEO-THREE.md`（每日≤3件）/ `COMMAND-BOARD.md`（三分钟）
   - 编号短句大白话，能扫读

### 三、凭什么管 · 真值规则（防「看起来正常」）

1. **回执不等于产出** — rc=0 也可能零产物（E-ARTIFACT，已多次实测）
2. **在线不等于在干活** — 心跳绿而队列空 = 停产
3. **完成不等于做对** — 空文件/坏 JSON/0 时长视频/拒答文本全算失败
4. **新鲜不等于有效** — mtime 未替换、lease 1e9 秒都能造假绿
5. **本地判定不了别机的盘** — Windows 路径/子仓/state 一律判「远端待查」，不判缺失
6. **假红与假绿同罪** — 报一次假高危，之后真高危没人信（已立法：散件检查只报新增，存量豁免）
7. **核验只认机器输出** — `root_cause_audit.py` / `demand_audit.py` / `regression.py`

### 四、按什么节奏管 · 频次分层（从代码生成，不手写）

1. **45 秒** — 队列/预算/市场（脉基础节拍）
2. **1–3 分钟** — 值守、派单、单卡执行
3. **5–15 分钟** — 备份、状态回推、字幕批处理
4. **30 分钟** — `ceo_pilot` 六源合一打分（同题不刷屏，标「仍等你」）
5. **1–6 小时** — 产出审核、回归用例
6. **每晚** — 夜窗串行（00–06 生产 / 06–07 交班）
7. **每日** — 情报核真（`fact_check`）、安全台账、灾备体检
8. **纪律**
   - 周期只写一处（`master_pulse.STAGES`），表由 `cadence_build.py` 生成
   - `cadence.py` 拦相位撞车与未接线——闸要能真的拦下人

### 五、怎么自我改进 · 闭环六步（一次到位）

1. **发现** — 校验器报「脉在跑但表里没登记」（覆盖差 = 只有部分真相）
2. **归因** — 症状归到根因账 6 条（R1 单一真相源 / R2 生成态混 git / R3 判据可骗 / R4 修复不生效 / R5 无人收口 / R6 跨机不可达）
3. **修复** — 改规则而不是补文档；规则只许变瘦
4. **生效** — 改码必须重载脉、部署必须重启、忽略规则必须 `git rm --cached`
5. **复验** — **验证失败分支有没有被执行**（大小写、被吞异常、参数位置都让修复形同不存在）
6. **入册** — 结论进 `ROOT-CAUSE-LEDGER` / `CEO-DEMAND-LEDGER` / `regression.py` 断言

> 关键：**维度缺失比任务缺失危险**——任务漏了校验器会抓，维度漏了没人问。

### 六、不能做什么 · 硬边界

1. 不代签、不代发、不代答创作者身份（平台账号与发言权在 CEO）
2. 不为「满负荷」造活；算力不足宁可排队或 ROUTED，不许 swap 假装在跑
3. 不以「等 CEO/等授权」为由停工——默认自动放行，闸只留不可逆/对外发布/花钱超限三类
4. 不碰 `.wxapkg` 解密、不套主号 cookie、不自动 `ollama pull`
5. 不改别人机器上的生产脚本换行/编码（无实测不动生产）

### 七、人的位置 · CEO 四输入面

1. **方向变更** — 改航道
2. **P1 新方向** — 署名立项
3. **红线裁决** — 不可逆/合规/花钱
4. **资源调配** — 机器与预算
5. 其余一切：按既有规则自行决策推进，CEO 巡视时提返工

## 一张纸看懂

```
CEO（定方向/裁红线/调资源）
   └─ 智能体管理层（规则 + 判断，不生产）
        ├─ 主控脉 master_pulse（93 阶段 / 92 条节奏）
        │    ├─ 值守 → 活着
        │    ├─ 派单 → 有活
        │    ├─ 监督 → 有产物
        │    ├─ 验收 → 做对了
        │    ├─ 自愈 → 收口了
        │    └─ 汇报 → 一屏三文件
        └─ 机队车道 lane_agent（bm-a/b/c/d，多槽）
             └─ 回执 + 产物 → 审核 → 入档/待入 → 账本
                              └─ 失败 → 根因账 → 规则变更 → 回归断言
```
