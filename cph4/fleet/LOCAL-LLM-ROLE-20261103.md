# 本地大模型怎么赋能机队（2026-11-03 实测决策）

> 问题：主控笔记本的本地模型，在机队里到底该干什么活、用哪个模型、怎么接。
> 本件只写实测数字与由此得出的分工；不采信榜单。
> **机器面**=`cph4/fleet/LOCAL-MODEL-POLICY.json`（职责映射/验收阈值/黄金集/自动拉档规则）；
> 每日由 `Tools/fleet/model_radar.py run` 扫描上游 + 实测复验，结论落 `state/model-radar.json`
> 与 `cph4/fleet/model-radar/LEDGER.jsonl`。改阈值/换档判据只改那份 JSON，不在本文件另立一套。

## 一、结论：按"信息形态"分三层，不按"模型强弱"分

| 层 | 用什么 | 什么时候用 | 本机实测 |
|---|---|---|---|
| L1 规则 | 代码判断 | 答案能从字段算出来 | 211 份真回执判「完成/未完成」，规则 100% 准确、0 秒 |
| L2 向量 | `nomic-embed-text` | 判断"是不是同一件事/像不像" | 20 对真卡：**19/20**，0.08s/对 |
| L3 生成 | `qwen3:4b-instruct` | 只能靠读文字回答（摘要/归因/写话） | 结构化 JSON 合法，**24.8 tok/s** |

**核心判据：能用规则就别用向量，能用向量就别用生成。** 上一轮实测 43 条判定里 19 条是本地模型自答、23 条被机制取代，委员会实际裁决 0 次 —— 大量"用模型"的场合其实是规则能算的。

## 二、模型与本机速度（同一台 M1 Pro / 32GB，可用内存仅 12.8GB）

| 模型 | 结构化 JSON | 解码速率（预热后 5 次中位） | 结论 |
|---|---|---|---|
| `qwen3:4b-instruct` | 合法 | **35.7 tok/s**（5 次 34.7–36.9） | 常驻 |
| `qwen3.5:4b` | 合法 | **34.7 tok/s**（5 次 33.3–35.0） | 与前者**基本同速** |
| `qwen3.5:35b-a3b` (21GB) | — | 驻留即 swap | 封存，只在 mem_gate 放行时按需 |

**方法论订正（重要）**：首版测出「qwen3.5:4b 慢 2.8 倍」是**错的**——那次把 0.93 秒的模型加载时间算进了墙钟。正确做法是先把模型预热进内存，再用 API 的 `eval_duration`/`eval_count` 只算解码段。预热后比值是 **1.03×**，两个模型同速。

**结论：选型不能按版本号，也不能按未预热的单次墙钟。** 两者同速时，按任务准确率与显存占用选。

## 三、引擎坑（决定能不能用结构化输出）

- 新版 Ollama 在 Apple Silicon 走 **MLX**，解码快很多。**2026-11-14 复测：MLX 在 0.40.16 上已遵守 `format`**
  （`format:"json"` 与带 enum 的 schema 都实测通过，`qwen3.5:9b-mlx`）。下面两条是 0.40.13 时代的结论，
  只在老版本成立，保留作历史。
- （历史）原结论：MLX 引擎会静默忽略 `format`（JSON schema）（ollama/ollama#17013）。
- （历史）当时的规则是"结构化输出一律用 GGUF"，但 2026-11-14 起 4B/9B 全是 MLX 常驻档，该规则已失效：
  真正要守的是**输出仍必须过契约校验**（必填键 + 枚举白名单 + 真实路径），不能只靠 `format` 兜底。

## 四、小模型在"判断相似"上是失败的（附对照）

同一批真卡（正例=同 cmd 的两张卡，负例=不同线不同 cmd），**同规模 n=30+30 对照**：

| 方法 | 召回 | 特异 | 合计 | 速度 |
|---|---|---|---|---|
| `qwen3:4b-instruct` | 8/30 | 30/30 | **38/60 (63%)** | 0.40s/对 |
| `nomic-embed-text`（阈值 0.61） | 28/30 | 27/30 | **55/60 (92%)** | **0.033s/对** |

分布看得很清楚：负例相似度 10/50/90 分位 = 0.520/0.561/0.623，正例 = 0.624/0.867/1.000，两堆在 0.62 附近才勉强分开，所以阈值 0.61 会放进来 3 个假阳。

**结论：语义匹配交向量，不交生成模型。** 小模型在这类任务上倾向一律答"不同"（30 个正例只认 8 个），特异度高是因为它几乎不肯定，不是因为它判得准。

## 五、可以真交给本地模型的五件事

1. **回执摘要**：把 N 份回执压成事实句（已验证能出事实级摘要）。
2. **失败归因**：读 `stderr_tail` 给出原因类别与一句处置建议（结论必须可复核，不许直接执行）。
3. **卡面质检**：派单前检查卡片是否缺 deliverable/accept/cmd 可疑（输出结构化 JSON）。
4. **拦话**：社媒代答闸 —— 涉及 AI 身份、编造经历、引战广告，一律判"不能代答"。
5. **文本抽取**：从非结构化日志里抽 BV 号、集数、路径这类字段。

## 六、禁止交给本地模型的三件事（都有实锚）

1. **写代码 / 改代码** —— 曾建议 Windows 机跑 `sysctl -p` 的幻觉，造成返工。
2. **给运维命令** —— 同上，且它不知道目标机环境。
3. **做事实判断与对外表述** —— 曾编造"不是 AI 做的"、引用不存在的交付文件。

## 七、已落地的工具

`Tools/fleet/semantic_dupes.py` —— 用向量找"同一件事被派了多张卡"，阈值 0.64（实测最佳）。
- 首跑即抓到一个真事故：**同一个配音质检活被派了 3 张卡**（两跑一待派）。
- 归一化要先剥标题的 `[线名（工序链）]` 前缀，否则模板化文本会把不同线的卡并簇（实测 0.64 下把配音质检和回测并到一起）。
- 剥离后分离干净：三张配音卡 0.81/0.83/0.996，与回测 0.52、与游戏 0.54。

## 九、机队全机模型雷达（CEO 2026-11-03 令：每台机空闲时搜最新、适配、测不过不换）

1. 每台在线机每天一张卡 `R-MODEL-RADAR-<NODE>-<YYYYMMDD>`（workgen R8 生成），命令：`python Tools/fleet/model_radar.py run --node <node> --idle-only --apply`。
2. 闲才跑：本机有生产卡在跑 / 可用内存低于地板 / bm-a 工作日 09-19 → 回执 `SKIPPED-IDLE` 并写明原因，不算失败；雷达自己的卡不算「本机忙」。
3. 换档判据只一处：`accept_upgrade`（质量更高且速度 ≥ 现役 90%，或质量持平且速度 ≥ 105%；质量更低一律不换）。测不过就保持原档。
4. 每机口径在 `LOCAL-MODEL-POLICY.json → nodes`：能装多大、跟哪些家族、闲时窗口、是否以实装为基线（`auto_baseline`）。未声明的机沿用全局段。
5. 回执落 `cph4/fleet/queue-receipts/model-radar-<node>-<date>.json`（git 受控，远端可验证），含 attention / discovered（上游最新家族）/ verdicts / applied.from-to-rollback。
6. 实测（2026-11-03 bm-a）：基线 qwen3:4b-instruct，解码 112.5 tok/s，黄金集 7/8；扫描可发现上游新家族（lfm3 / d3 等），但只报告、不自动拉。
