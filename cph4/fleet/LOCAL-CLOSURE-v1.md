# 本地闭环规划（LOCAL-CLOSURE-v1）· 2026-11-11

> 令源：CEO 2026-11-11「每个机器都要本地闭环，只有产出和统计、排单信息共享什么的上云，你帮我科学规划」。
> 机器面=`MODEL-COMPUTE.json`（端点阶梯，本机 order=0）+ `STATIONS.json` 的 `local_model`（每机档位）；体检=`Tools/fleet/local_loop_check.py`（自检 6/6）。
> 一句话：**执行、判断、排队、验收都在本机；出机器只出清单、度量、交接单。**

## 一、分层：什么必须在本地，什么才上云

| 层 | 内容 | 在哪 |
|---|---|---|
| 执行 | 跑命令、出产物 | **本机**（绝不外包） |
| 判断 | 自验（判据脚本）、判读（小模型）、写卡理由 | **本机**（小模型 + 确定性脚本） |
| 排队 | 自己队列的读写、自己建卡、自己领 | **本机分片** |
| 升级 | 长剧本/语感/审稿这类小模型做不好的 | 算力大脑（有网才用，没网排队） |
| 上云 | ①产物清单+哈希 ②统计度量 ③排单信息（谁有空、跨机交接单） | git 远端分片 |

**判断律**：能本机做完的绝不出机器；本机做不好的上升算力大脑；两头都不通就退规则结论，不停工、不编造。

## 二、每台机的本地模型档位（写进 STATIONS.local_model）

| 机器 | 本地模型 | 占用 | 用途 | 依据 |
|---|---|---|---|---|
| 公司生产力机 | 8B 级 Q4 | 8G 显存 / 10G 内存 | 写卡理由、判读、游戏素材核对 | 12G 显存 + 94G 内存，宽裕 |
| 传家宝 | 8B 级 Q4（用完即卸） | 8G / 10G | 出片间隙做判读，不与 KF/i2v 抢显存 | 16G(可用13.4) 要与 ComfyUI 共用 |
| 小钢炮 | 4B–8B 按需 | 6G / 8G | 声音类判读、字幕校对 | 8G 显存要留给 TTS |
| 算力大脑 | 32B 级 | 32G / 32G | 全队重活与 agent 算力（升级通道，不是依赖） | 3×V100 48G |
| MacBook | 4B + 向量 | 0 / 5G | 调度、账本、轻判读、断网兜底 | 32G 统一内存与办公共用 |

## 三、端点阶梯（代码已改，本地优先）

`local_model.endpoint()` 现在的顺序：**本机 127.0.0.1（order=0）→ 算力大脑（order=1）→ 主控 tailnet（order=2）**，带 30 秒健康缓存，探不通直接跳下一级。

`local_model.local_station()` 用 `FLEET_STATION` 环境变量或 hostname 自动认自己是谁；本机实测认到 `control`，阶梯返回 `['127.0.0.1', 'tailnet:11434']`，本机模型 8 个可用。

## 四、闭环五查（`local_loop_check.py`）

| 项 | 判据 | 为什么必须有 |
|---|---|---|
| L1 本地推理 | 本机 127.0.0.1 的模型服务能答 | 断网还能判断，否则一断网就停工 |
| L2 分片可写 | `rt/<工位>/` 能写能删 | 干完记不下来等于没干 |
| L3 队列可读 | 自己 `queue.jsonl` 可读 | 不知道下一步干什么 |
| L4 判据在盘 | 承接工序用到的判据脚本存在 | 没有判据的"自验"是假绿 |
| L5 产物可落 | `out/<工位>/` 可写 | 产物没地方落 = 白干 |

三态：PASS / FAIL / **SKIP**。**异地机器不许替它签字**——127.0.0.1 只有本机能验，所以 `--all` 里别的机器 L1 记 SKIP，必须在各自机器上跑。

## 五、现状（2026-11-11 实测）

1. MacBook：**五项全过，可独立闭环**（24 道工序，判据 drama_rules + voice_gate 齐）。
2. 三台执行机（公司生产力机 / 传家宝 / 小钢炮）：文件面通过，**本地模型是否存在无法从这台机远程验证**，必须在各自机器跑一次 `local_loop_check.py --station <自己>`。这是推广第一步。
3. **发现的真缺口**：`family_check` 判据脚本全仓不存在（原计划在 `Tools/family_compliance_check.py`，可能在吸嘟嘟子仓没同步）。已把 `T-TEXT-COMPLIANCE`、`T-3D-ADAPT` 的 judge 改回 `manual` 并写入 `judge_note`——**不许拿不存在的脚本当自验依据**。找回脚本后改回。
4. 算力大脑 url 为空（未入网），阶梯自动跳过，不影响本机闭环。

## 六、推广步骤（每机 20 分钟）

1. 在目标机装 Ollama（或同协议服务），按 `STATIONS.local_model` 拉一个 4B/8B 模型。**这一步是唯一硬门槛**。
2. 在该机跑：`python3 Tools/fleet/local_loop_check.py --station <自己>` → 五项全 PASS 才算闭环。
3. 起自驱：`python3 Tools/fleet/station_drive.py --station <自己> --loop 300`。
4. 断网演练：拔 tailnet 后再跑一次 2、3，仍能建卡/跑/验/记账 → 闭环成立。
5. 只把三样推上云：产物清单+哈希（回执已含）、统计（`metrics.jsonl`）、转移单（`HO-` 卡）。

## 七、和"算力大脑是能力中心"怎么并存（不矛盾）

1. 算力大脑是**升级通道与重活机**，不是每台机的必经之路——否则它一挂全队停摆。
2. 每台机先用本机小模型把活干完；干不了的（长剧本、语感、审稿）才排给它。
3. 它自己也闭环：本地跑 32B，不需要别人的模型。

## 八、验收判据

1. 每台机 `local_loop_check.py` 五项全 PASS（异地 SKIP 必须补成实测）。
2. 断网状态下 `station_drive.py --once` 能产出至少一张卡并写出带 sha256 的回执。
3. 全队上云流量只有三类：回执/清单、度量、交接单；不得出现"把执行或判据放云端"。
