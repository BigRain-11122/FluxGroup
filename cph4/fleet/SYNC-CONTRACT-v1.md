## 二、六条硬规则

1. **一个事实一处正身**。文件被谁拥有，只看路径前缀 + 本契约与 STATIONS；不许在别处再写一份。
2. **只在自己的条线写**。跨条线要改别人的东西，先发卡（见 §三），得到回执再动；
   紧急修复可以改，但必须在回执里写明"越界原因"。
3. **共享件只增不改**：`Tools/` 下的通用工具（采集/闸/审计/调度）谁都能用，
   但改动必须先跑自检并在提交信息里写影响面。
4. **数据不进同一条通道**：语料/产物用 git 传（正典在主分支）；
   大文件与环境、权重、Cookies **绝不进 git**（走各自磁盘 + 清单）。
5. **同步靠"正典 + 回执"，不靠印象**：跨机结论必须有 receipt 或 commit 作证据；
   没有证据的一律标 `UNVERIFIED`，不许当已办。
6. **让路优先于抢先**：多机同时要同一资源（浏览器/GPU/同端口）时，按 `res_alloc` 租约，
   不是谁先跑谁赢。

## 三、要别人判断时怎么问（今天立的第一版）

判据在我这儿拿不准的，不许自己猜也别硬删，**发卡问拥有者**：

- 卡文件：`cph4/fleet/ASK-<日期>-<主题>.jsonl`，一行一卡，字段：
  `_id` / `to`（机器 id）/ `ask` / `files`（要判的路径）/ `answer_schema` / `reply_to`
- 回执：`cph4/fleet/order-bus/receipts/<_id>.json`，字段按 `answer_schema`
  （`verdict` = `in-use|obsolete|keep|unsure` + 一句话理由 + 若还在用写出谁调用它）
- 逾期：超过 72 小时无回执 → 主控按 `unsure` 处理并记 `BLOCKED-JUDGE`，
  **不许默认当废弃删掉**。

## 四、共享什么、怎么共享（互相赋能的部分）

| 共享物 | 放哪 | 谁维护 | 怎么取 |
|---|---|---|---|
| 通用工具（采集/审计/闸/调度） | `Tools/`（本仓，所有人共用） | 主控，改动需自检 | 直接调，不复制 |
| 机器与条线定义 | `STATIONS.json` | 主控 | 读 |
| 席位的职责与判据 | `AGENT-TEAMS-v1.json` | 主控 | 读 |
| 车道与回执 | `cph4/fleet/lanes/` + `order-bus/receipts/` | 各机写自己的 | 读别人的、只写自己的 |
| 语料与产物清单 | 各条线的 `*MANIFEST*`/台账 | 拥有者 | 按清单取，不猜路径 |
| 全仓体检 | `cph4/fleet/REPO-AUDIT.{json,md}` | 主控（`Tools/repo_audit.py --scan`） | 任何机可重跑复算 |

**唯一不允许共享的**：登录态、Cookie、API key、权重文件。这些只在本机磁盘，永不进 git。
