# 方案快速转化 v1（2026-11-05）

> CEO 令：「颗粒度细一点，做好各个方案的快速转化，不要等很久，我很烦低效和卡点。」
> 正身=`Tools/fleet/plan_convert.py`。判据全机器可判。

## 一、转化是什么
一句话方案 → **当分钟**得到：一页规格（含可判验收）+ 四步产物 + 一张可执行卡（真活才排队）。

## 二、实测数字（2026-11-05 17:4x）
| 环节 | 时间 |
|---|---|
| 念头 → SPEC + 四步产物 + 卡 | **0.44s** |
| 主控接卡（脉 45s 一轮） | ≤45s（原 180s） |
| 短 CPU 卡在机器上排队（bm-m 1 槽时） | 3 分钟 → 见 §四 |

## 三、四步固定拆法（每步一件可验物，≤10 分钟）
| # | 阶段 | 产物 | 在哪跑 |
|---|---|---|---|
| 01 | 取证 | `step1-取证.json`（输入在不在盘/件数/指纹） | 当场 |
| 02 | 加工 | `step2-加工.json`；给了 `--tool` 才是真加工并排队 | 当场/机器 |
| 03 | 验收 | `step3-验收.json`（含 verify_done 真实回执） | 当场 |
| 04 | 交付 | `step4-交付.json`（可发物定义/谁签/缺什么） | 当场 |

## 四、已踩过的坑（都是实测）
1. **四步全排队 → 3 分钟**：3 秒的记账步骤去排 45 秒一轮的队。正法=记账步骤当场跑，只排队真加工。
2. **卡不钉机器 → 被别的机器抢跑 FAILED**：转化件在本机盘上，必须 `hard_nodes=[bm-m]`。
3. **通用命令被语义判重拦成 DUP-SKIP**：每步命令必须含本方案路径，不能复用通用命令。
4. **自派并行的尝试已撤回**：实测卡执行完不回账（RUNNING 悬挂），不如先修排队语义。

## 五、判据
- C1 每步有交付物路径；C2 每步 ≤10 分钟；C3 第一步产物当场存在且非空；
- C4 有 `--tool` 时真加工卡必须入队成功。
- 全绿 rc=0；任一不满足 rc=2 并写明哪条。

## 六、何时不该用
- 需要方向裁决（找 CEO）或物理件（商户号/装机）的方案：转化器只产出规格与卡，
  不会替 CEO 决策，也不会造假产物。
