如何用智能体管理

FluxGroup · 2026-11-07 · 操作图（节点=真实工具/阶段）
  • 智能体管理（AI 管 AI） 人定方向 · 规则定判断 · 智能体跑循环 · 磁盘定真伪
    • 一、谁在管三层身体不混用 越界当生产者，指挥部就空转（已发生两次）
      • 主控脑 Mac bm-m · master_pulse 常驻脉 只出卡/裁决/告警/一屏
        • 禁自己生产：出图/渲染/装配/回测一律派卡
        • 允许的亲自参与：本地模型分类·摘要·打分·一屏·账目核对（结论必规则复核）
      • 执行机 bm-a / bm-b / bm-c / bm-d · lane_agent
        • 从 origin 读 lanes/<node>.json 取卡，回执写 queue-receipts/ 这条通道绝不能进 .gitignore
        • 一台机多槽位；GPU 活同刻只 1 张
      • 常驻轻量模型 qwen3.5:4b-mlx · 7.6GB · num_ctx 8192 · 38–40 tok/s
        • 红线4B 算术必错 → 所有数字由规则算，不交模型
        • 8B 按需且必须先让 4B 让位；35B 禁常驻（24GB 即 swap）
        • 云端按日预算 ¥100 硬顶 · cloud_budget.py
        • 座位表：MODEL-MONITOR-MATRIX-v1.json（P0 抢 P2 · 同输入 15 分钟不重复调）
    • 二、管什么六个面，缺一面就有盲区
      • 值守 进程活着 ≠ 在干活 · executor_guard hb qcheck canary 1–2 分钟
      • 派单 ceo_queue night_plan workgen supply_target 软判据：有变化，或明确报「无活可派」
        • 不许沉默——沉默等于没人管
      • 监督 盯产出不盯心跳 · done_audit asset_reach deadline
        • 四信号：产出年龄 + git 提交 + 远端回执 + 磁盘 mtime
      • 验收 DONE ≠ APPROVED artifact_review 三层审 → 入档 archive/ → 待入 INTAKE-PENDING.jsonl
        • L1 结构审：路径/非空/可解析/无占位/媒体签名与时长
        • L2 一致性审：声称条目数 vs 实际 · mtime 防旧件冒充
        • L3 语义抽查：4B 只答是/否/不确定，不确定率>30% 判该批不适合模型审
        • 诚实线子仓未 clone 时只记「待入」，绝不假装入库
      • 自愈 self_improve（码龄/空壳/依赖） · fork_close · node_closeout.ps1
        • R5告警必须有消费方，否则等于没告警
      • 汇报 只看三个文件 CEO-NEXT.md（一条）· CEO-THREE.md（每日≤3件）· COMMAND-BOARD.md（3 分钟）
        • 编号短句大白话，能扫读；同题不刷屏，标「仍等你」
    • 三、凭什么管真值规则 · 防「看起来正常」
      • R3-1回执 ≠ 产出：rc=0 也可能零产物（E-ARTIFACT）
      • R3-2在线 ≠ 在干活：心跳绿而队列空 = 停产
      • R3-3完成 ≠ 做对：空文件/坏 JSON/0 时长/拒答文本全算失败
      • R3-4新鲜 ≠ 有效：mtime 未替换、lease 1e9 秒都能造假绿
      • R3-5本地判不了别机的盘：Windows 路径/子仓/state 一律「远端待查」，不判缺失
      • 铁律假红与假绿同罪——报一次假高危，真高危就没人信
        • 故散件检查只报新增、存量豁免；安全台账加白名单排除
      • 核验只认机器输出 root_cause_audit.py · demand_audit.py · regression.py · fact_check.py
    • 四、按什么节奏管频次分层 · 从代码生成，不手写 93 阶段 / 92 条节奏 · 周期只写 master_pulse.STAGES 一处
      • 45s队列 / 预算 / 市场（脉基础节拍）
      • 1–3m值守、派单、单卡执行、契约检查
      • 5–15m备份、状态回推、字幕批处理、机群巡检
      • 30mceo_pilot 六源合一打分（监督/派发/侦察/找工具/验收/审查）
      • 1–6h产出审核、回归用例集
      • 每晚夜窗 00–06 生产 · 06–07 交班
      • 每日情报核真、安全台账、灾备体检、模型雷达
      • 纪律cadence_build.py 生成 → cadence.py 拦相位撞车与未接线
        • 闸要能真的拦下人：首跑就抓到 T32 与 T26 撞相位，3600→4100
    • 五、怎么自我改进闭环六步 · 一次到位
      • 1 发现校验器报「脉在跑但表里没登记」——覆盖差 = 只有部分真相
      • 2 归因症状归到根因账 6 条（R1–R6）
        • R1 单一真相源缺失 · R2 生成态混进代码 git · R3 判据可被「看起来」骗
        • R4 修复不配套生效 · R5 无人收口 · R6 跨机不可达
      • 3 修复改规则而不是补文档；规则只许变瘦
      • 4 生效改码必重载脉 · 部署必重启 · 忽略规则必 git rm --cached
      • 5 复验验证失败分支有没有被执行（大小写 · 被吞异常 · 参数位置）
        • 实例：Diverging vs diverg 让整段合并逻辑从未执行过
      • 6 入册结论进根因账 / 需求账 / regression.py 断言（12 条已固化踩过的坑）
      • 方法论维度缺失比任务缺失危险——任务漏了校验器会抓，维度漏了没人问
    • 六、不能做什么硬边界
      • 不代签、不代发、不代答创作者身份（账号与发言权在 CEO）
      • 不为「满负荷」造活；算力不足宁可排队或 ROUTED，不许 swap 假装在跑
      • 不以「等 CEO/等授权」为由停工——闸只留不可逆/对外发布/花钱超限三类
      • 不碰 .wxapkg 解密、不套主号 cookie、不自动 ollama pull
      • 不动别机生产脚本的换行/编码（无实测不上生产）
    • 七、人的位置CEO 四输入面
      • ① 方向变更 → 改航道
      • ② P1 新方向 → 署名立项
      • ③ 红线裁决 → 不可逆 / 合规 / 花钱
      • ④ 资源调配 → 机器与预算
      • 其余一切按既有规则自行决策推进，CEO 巡视时提返工
