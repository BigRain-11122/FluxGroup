# 常驻与按需拉起（RESIDENT-vs-ONDEMAND）· 2026-11-11

> 令源：CEO 2026-11-11「常驻和短暂拉起可以分开的，你好好规划，看一下我的各种业务和需求」。
> 原则：**常驻只留"小、稳、不占卡"的东西；吃 GPU/吃内存/吃 CPU 的一律按需拉起，干完就退。**

## 一、三条判据（按这个分，不按名字分）

1. **占不占 GPU**：占卡的一律按需；常驻里不允许出现 GPU 进程。
2. **失败影响面**：它挂了会不会让整条链停？会 → 常驻；不会 → 按需。
3. **空闲代价**：空转时吃多少内存/CPU？> 500MB 或 > 5% CPU → 按需。

## 二、现有 44 项的分类（Mac 主控）

### A 常驻（必须一直在，共 6 类）

### D 明确不常驻（这次要停掉的老习惯）

1. 8 个看护器同时常驻（watchdog / serviceguard / selfwatch / resilience / toolwatch / loadwatch / modelwatch / usefulload）——合并成 2 个：一个看进程、一个看产物。
2. 各类审计/巡检/分诊的常驻循环（auditor / patrol_seats / selfdrive / repo_deep / local_worker 等）——改成**夜窗批处理**，白天不跑。
3. 本地 35B 常驻——已封存，任何情况不常驻。
4. 收件口/素材共享（往外置盘写字节的）——已退役。

## 四、拉起机制（技术口径）

1. **常驻**：launchd `KeepAlive`（Mac）/ 计划任务"持续运行"（Windows），必须带 `RunAtLoad` 与失败重启上限。
2. **按需**：由卡或事件触发 `launchctl kickstart` / `schtasks /Run`；进程自己带**租约**（最长运行时间），到期自杀，不留孤儿。
3. **GPU 独占**：任何 GPU 活先取租约（`gpu_lease`），拿不到就排队；同一时刻只有一张卡在跑。
4. **模型装卸**：常驻 4B + 向量；9B/14B 按需加载，`keep_alive=0`，用完即卸。
5. **夜窗**：02:00–06:00 只跑批处理（审计、回测、素材批），白天不跑机制活。

## 五、资源红线（常驻部分）

1. 常驻总内存 ≤ 6G（不含模型），模型常驻 ≤ 5G。
2. 常驻 CPU 合计 ≤ 2 核。
3. 常驻里不允许出现：GPU 进程、>8G 模型、循环审计。
4. 任一常驻服务失败三次 → 停止重启并上报，不无限拉起。

## 六、验收（怎么算分对了）

1. 空闲时：Mac 上只有 6 类常驻，GPU 空闲、内存占用 < 12G。
2. 干活时：对应按需进程出现；活干完 30 分钟内进程退出、显存释放。
3. 一个业务停掉，不影响其他业务（互相不占对方资源）。
4. 任一按需进程超过租约仍在跑 → 判缺陷并记录。
