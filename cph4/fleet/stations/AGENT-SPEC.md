# 每机智能体（STATION-AGENT）· 2026-11-11

> 令源：CEO 2026-11-11「每台机器都要有自己的智能体，他们可以链接主控的算力，去巡查和验收」。
> 实现：`Tools/fleet/station_agent.py`（一机一端，读自己岗位书）。自检 7/7。

## 一、一机一体的意思

1. 每台机常驻一个自己的智能体，只巡自己的领域，读自己的岗位书（`stations/<id>/CHARTER.md`）。
2. 它不做执行、不改卡状态；它产出**发现**与**建议**，落地动作仍由规则脚本或人做。
3. 它的判断可调用主控的本地模型（8792 网关），不需要每台机自己装大模型。

## 二、它能做什么（只有三类）

1. **巡查**：队列积压、阻塞无原因、在跑无回执、DONE 但产物缺失、重复 id、磁盘余量、岗位书缺失。
2. **初审**：对上述发现给一句"先处理哪件、为什么"的建议（可选，需模型令牌）。
3. **上报**：写自己的 `rt/<station>/state.json` 与 `log/<日期>.jsonl`；主控与其他工位只读。

## 三、它不能做什么（写死在代码里）

1. 不写别人的分片，不跨工位读写。
2. 不改卡的 state / owner / 交付判据。
3. 不自证完成——它给的是初审，最终验收仍在人工/独立工位。
4. 拿不到模型不报错，退化为规则结论并记 `model=unavailable`。

## 四、各工位的巡查重点（同一运行时，不同侧重）

| 工位 | 巡查重点 | 建议给谁 |
|---|---|---|
| delivery | 材料四件套缺件、包体不存在、构建产物为空 | 主控（派修） |
| visual | 关键帧尺寸不符、抽卡超限、产物与参考不一致 | 主控（退卡重出） |
| audio | 有台词无配音、响度越线、采样率不对 | 主控（退卡重配） |
| brain | 回测不可复现、报告三项指标缺、任务超时 | 主控（重排） |
| control | 分片读不到、回执与产物哈希不符、账本缺口 | CEO（一屏） |

## 五、怎么部署到一台机

1. macOS（主控）：`launchd` 常驻，参数 `--station control --loop 300`。
2. Windows（其余四台）：计划任务每 5 分钟跑一次 `--station <id> --once`，静默链（VBS）包装。
3. 环境变量：`FLUX_LLM_TOKEN`（主控网关令牌）；没有就纯规则跑。
4. 开工第一条命令：`python3 Tools/fleet/station_status.py --remote`，确认自己的分片有活。

## 六、模型接入（走主控，不各自装）

1. 端点：`http://100.75.133.10:8792/api/generate`（主控网关）。
2. 只允许白名单模型（4B 主力）；上下文 8192、并发 2、死线 120 秒，由网关强制。
3. 主控本机优先，机队借用排在其后；拿不到就排队，不许自行换成本地大模型。
4. 模型输出只作建议，必须能被规则复核。

## 七、验收口径（怎么算它工作正常）

1. 每 5 分钟至少一条 `state.json` 更新。
2. 发现都有 code + subject + detail，能被人直接处理。
3. 连续 24 小时零发现 = 要么真干净，要么巡查失效——需人工抽查一次。
