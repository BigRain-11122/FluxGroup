## P-01 · 漫剧 KF｜超高比例静默截断导致画风随机漂移
- **现象**：1236 镜里 992 镜（80%）实际 prompt 超模型上限；输出画风在赛璐璐/线稿/彩页/JoJo 肌理间乱跳，场景后半句被吃掉（"交易大厅"画成街巷）。
- **根因**：SD1.5 CLIP 文本编码器硬上限 77 token，超限**静默丢弃尾部**；而 STYLE 段排在最后，第一个被截——风格词全丢=画风随机。
- **修法**：加预算层 `expand_c`：IDS_C 压缩锚（每人物 10-12 词）+ STYLE_C 常量化（13 词）+ 组装顺序 CORE→STYLE→SCENE，只有 SCENE 允许截尾；改完先跑全 1236 镜模拟再烧。
- **前后量化**：全 1236 镜 max 71 tok（零超限）；扩样 6/6 漂移 → 首验画风统一。

## P-02 · 漫剧 KF｜锚注入的字面匹配漏形态 → 全池 51% 零锚
- **现象**：631/1236 镜零锚（随机人物），66 镜部分锚；EP025 出现中文 ids 触发 KeyError 把烧线卡死 11 小时。
- **根因**：注入用 `replace(token+' ')` 只命中单形态，而实际词面有三种（全名 `Chang Hong`、带撇号 `MC's`、纯描述方言 `young man in white shirt`），且未知 token 直接 KeyError。
- **修法**：全名→token 归一（长在前防子串）+ 正则覆盖"token 后跟空格/撇号/标点/结尾"+ 未知 token 跳过 + 零锚兜底尾部 append；改锚逻辑必跑 60 JSON 全量模拟，不许抽检带全盘。
- **前后量化**：零锚 631 → 0，全量模拟命中率 100%；教训成本 11 小时烧线。

## P-03 · 文本线｜提示词写禁语 = 磁吸
- **现象**：写进 prompt 的"不要出现争取早日上线"，8/8 条生成里都出现了。
- **根因**：负向指令在生成模型里提高该串的激活（先复述再否定），约束写成否定式等于给模型喂样本。
- **修法**：prompt 保持**纯正向**描述，禁语全部下沉到机检闸（G1-G18）拦。
- **前后量化**：禁语复发 8/8 → 0（改后线）。

## P-04 · 文本线｜给例句 = 逐字照抄
- **现象**：示范"好例"之后，生成把好例原句直接搬进回复。
- **根因**：少样本示例被模型当可复制模板，尤其在短文本任务里示例的权重高于抽象约束。
- **修法**：只给约束（长度窗/语气/忌项/结构），不给例句；用闸做质量兜底。
- **前后量化**：逐字照抄 100% 命中（G18 ≥8 字连续） → 换约束式后 0。

## P-05 · 文本线｜打分函数 Goodhart（奖励什么就学什么）
- **现象**：奖语气词 → 满屏"吧啊哈哈"；奖工艺自述 → 句句"熬到凌晨两点"；奖锚词复述 → 全是"X 确实挺 Y"的空话。
- **根因**：代理指标一旦进选择器就被优化，模型学的是打分器不是任务。
- **修法**：减法打分（只罚模板/空话/复读/长度越界，不奖励任何词）+ 跨条新颖度 + 4 候选择优。
- **前后量化**：同 10 条评论：v1 4/10 → 定稿 8/10（跳 2 条），且零磁吸词。

## P-06 · MV 图像｜意象对但渲染层字面漂移
- **现象**：纸飞机被渲成真客机（舷窗+金属漆）；歌词"直升机"被拍成真直升机同框。
- **根因**：词面只写名词不给材质/大小，模型用先验补全（plane→客机）；意象指令没落到渲染层。
- **修法**：词面加固小感（hand-folded / thin notebook-paper / palm-sized）+ 帧批多模态复扫；意象转化按 LYRIC-IMAGERY-LAW 三档判定。
- **前后量化**：首次 8 分俗度 → 加固后重摇过闸；KN05 真机镜头直接删除改光柱意象。

## P-07 · 通用｜prompt bloat 退化线
- **现象**：单 prompt 塞到 3000 token 量级后，指令遵守明显退化（关键约束被忽略），格式类任务差异可达 40%，指令类 10-100%。
- **根因**：长上下文里关键约束的注意力权重被稀释；无结构长文让模型把指令当背景。
- **修法**：分片（一个 prompt 一件事）+ 结构化格式（键值/分段标题）+ 关键约束前置。
- **量化**：外部研究复现（arXiv 2411.10541 / SAMMO），本产线以 CORE 前置 + 分段实践对应。

## P-08 · 漫剧 KF｜组合镜在压缩锚下恒塌缩
- **现象**：三人共举图表/父子同桌/双人对视等组合镜，压缩锚路线 6 靶全灭（缺人、性别翻、主体塌缩）。
- **根因**：压缩锚丢的是**关系信息**（谁和谁、几个、在做什么），只保留个体外观。
- **修法**：组合镜必须走 custom 路线：显式 `N people in one frame` + 逐人全锚 + 关系动词；不能依赖压缩锚。
- **前后量化**：压缩锚 0/6 → custom 4/6 达标（另 2 个 16-seed 不可达，记残）。

## P-09 · 漫剧 KF｜底模分布边界不是 prompt 能修的
- **现象**：50 岁中年男主，8 变体 + 显式年龄锚（early fifties / silver-gray temples / deep expression lines）全部输出年轻脸。
- **根因**：底模训练分布年龄偏窄，文本条件无法越过分布边界；压缩锚只是加剧。
- **修法**：换底模 / LoRA（v1.1 升级面）；文本层判负，不再烧。
- **量化**：8/8 失败 → 停止文本尝试，省下后续烧批。

## P-10 · MV i2v｜低清先验律
- **现象**：新镜型直接烧 768P 正片，运动崩坏后整条重烧。
- **根因**：运动/主体/崩坏类缺陷与分辨率无关，低清即可暴露；正片单价高。
- **修法**：先 480P 短验（2-3 分钟）确认运动与主体，再烧 768P；重烧失败件先 480P 复验修法。
- **量化**：单条验证 2-3 min vs 正片 20+ min。

## P-11 · 通用｜同构批的一致性靠 seed 与常量化
- **现象**：同批镜头风格/人物漂移，逐条调 prompt 越调越乱。
- **根因**：每镜独立随机 + 风格词自由书写 = 方差叠加。
- **修法**：STYLE_C 常量化 + 固定 seed 基（`92000000 + ep*100 + n + k*1000`），变体只改温度/微措辞。
- **量化**：跨镜一致性由"看运气"变为可复现；批内返工率显著下降。

## P-12 · 文本工程｜折行/字幕的空间约束是求解顺序问题
- **现象**：55% 早切导致 5-7 字碎行与孤字（60 集 14 处孤字），后又出现 47 处行首标点。
- **根因**：先按比例切、再补规则，两个守卫互相回滚；二次折行把已含换行的段再切=错位。
- **修法**：贪心填满（行宽≤上限）+ 双守卫有界迭代（先灭孤尾→再禁则→收进不得再造孤尾）+ 拍平式二次折行；改完全量模拟回归。
- **量化**：孤字 14→0、行首标点 47→0、worst 字幕 17.00 / 字卡 10.00 全绿。

## P-13 · 声音车道｜GPU 批被文本模型抢资源，单句从 5s 掉到 84s
- **现象**：IndexTTS 批量配音跑到 EP006 时单句生成时间从 ~5s 飙到 77–84s（rtf 15–20），显存占用从 5.1GB 涨到 7.9GB，系统可用内存掉到 1.7GB。
- **根因**：Ollama 保活任务（MiniGameOllamaServe / KeepWarm）在 GPU 批运行期间把 4B 文本模型重新钉回常驻（keep_alive=-1），与配音模型共占 8G 卡；同时 llama-server 占 3.6GB 内存，触发页面交换。**槽位策略写了"互斥"，但消费方没读策略**——保活任务是独立腿，不知道有人在用卡。
- **修法**：GPU 批开跑前必须做三步：①建 `Tools\Ollama\keepwarm.pause` 阀 ②`Disable-ScheduledTask` 两条保活任务 ③杀 llama-server 并 `ollama stop`；批完成后再按相反顺序恢复（删除阀 + Enable 任务）。仅建阀不够——sentinel 只在识别到"GPU 批进程"时尊重阀，任务腿仍会重钉。
- **前后量化**：单句 77–84s → **5–7s**（rtf 20.4 → 1.3–1.4）；可用内存 1.7GB → 6.3GB；显存 7.9GB → 6.5GB。
- **派生纪律**：长批的"恢复义务"必须写进链路尾步或独立收尾任务，否则 Ollama 会长期缺席（历史判例：收官忘恢复）。

## P-14 · 产线复用｜试点脚本的"手写程序"假设会把批量跑到 KeyError
- **现象**：混音器对 3 集试点手写了 `BED_PROG` / `SFX_PROG`（每集的环境音床与音效时间表）。批量跑 EP004-060 时在 `BED_PROG[ep]` 抛 `KeyError: 'EP004'`，57 集**一条都没混出来**；而守望链仍写 `CHAIN COMPLETE`（只看退出码不看产物数）。
- **根因**：试点脚本把"逐集手工编排"当成常量，通用化时没人补程序面；链的完成判据是"跑过了"而不是"产物达量"。
- **修法**：①通用化必须带**程序合成**——按台词/场景关键词选音床（大厅/街/夜/雨/采访/机房/人群/室内），音效稀疏（≤7 条/集，含开场 title）；②链的完成判据改成**产物数阈**（mix 文件 <55 或 remux 成功 <55 → exit 非零，不许写 done）。
- **量化**：修前 0/57 集；修后 3 集试跑 16s（≈5s/集），对话 RMS -20.6dB / 环境 -32dB / 音效 -33.8dB，峰值 0.891 合规。

## P-15 · 资源阀｜一次性建阀不够，TTL 会把阀吃掉
- **现象**：GPU 批跑到第 2 小时速度骤降 15 倍（4s → 60-87s/句），显存 7.0GB 里又出现文本模型。
- **根因**：哨兵的 stale-valve TTL=12h 且"无 GPU 任务"即删阀；批跑过夜后阀被清，哨兵下一拍把 4B 钉回常驻，与配音模型共卡。
- **修法**：批期间用 **every:5m 的续阀任务**（touch mtime + 顺手杀 llama-server），链完成 json 出现后自动停手；不是"建一次就完事"。
- **量化**：续阀后单句回到 4-5s（rtf 1.5），显存 7.0GB（仅配音模型）。
