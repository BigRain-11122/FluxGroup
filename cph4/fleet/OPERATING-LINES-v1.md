## 二、三档验收强度（这是"转验收"的实质）

1. **自验**（默认）：机内判据过了即 DONE。判据分两种——确定性脚本（path/hash/drama_rules/voice_gate）与**专家团评审**（skill 判据 + 席位投票 + 确定性否决，`JUDGE-PANELS-v1.json` / `panel_review.py`）。**没有人判这一档**；发送/注册/备案属权限不属判断。
2. **抽验**（常态）：主控按 `sample_per_day` 抽最近的 DONE 件，重算哈希比对。适用于所有机。
3. **全检**（惩罚态）：同一台机连续 3 次抽验失败 → 取消自验资格，主控全检，连续 10 件通过才恢复。

抽验四项判据（配置在 `ACCEPTANCE-v1.json`）：
- A1 产物在盘且非空
- A2 重算 sha256 与回执一致（**回执没写哈希直接算不过**）
- A3 人判件不许标 DONE
- A4 回执与产物时间差不超 10 分钟

## 三、主控巡查做什么（`master_patrol.py`，自检 8/8）

一轮五件事：
1. **机器**：状态、席位、能接类型、背几道工序、队列 O/R/D/B、最后回执多久前。
2. **任务面**：59 道工序的承接方与产物契约覆盖率。
3. **抽验**：按比例抽 DONE 回执，重算哈希，不合格立刻记台账。
4. **停摆**：有回执但产物没变的假完成复发。
5. **出手清单**：机器不可用、有卡没人干、无承接工序、无产物契约、24h 无回执、抽验失败。

节奏建议：**每天两次**（开工前、收工后）。中间不插手——这就是"偶尔检查"。

## 四、日常与介入的分界（写死，避免又变成主控派活）

| 事 | 谁决定 | 主控做什么 |
|---|---|---|
| 今天先干哪三件 | 机器值班长席位 | 不看 |
| 卡怎么拆、命令怎么写 | 机器自己 | 不写 |
| 产物合不合规格 | 机器判据 + 抽验 | 抽样复算 |
| 跨机依赖卡住 | 上游机写 HO- 单 | 对方 24h 不动才介入 |
| 工序没人承接 | 无人能决定 | 改 TAXONOMY（`fleet_cmd assign`） |
| 机器坏了 | 机器自报 BLOCKED | 判断修/改派/停线 |
| 规则要不要改 | 复盘席提案 | 批准 + 回归验证 |
| 对外/花钱/不可逆 | 永远 CEO | 只备料 |
