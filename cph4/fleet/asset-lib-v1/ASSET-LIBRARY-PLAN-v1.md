# AI 内容资产库：调研结论与建库规划 v1（2026-11-03）

CEO 令：「做 AI 相关的 MV、短剧、漫剧、动画、有声小说、漫画等需要的大量自由特色资产库，
你好好去调研和规划，现在先准备资产，不做生产，要大量高质量的，不是垃圾库」。

## 一、调研结论：资产库就是这条业务的核心竞争力

三条行业事实（不是我猜的）：

1. **角色一致性是第一名痛点**：调研口径里 76% 的创作者把它列为首要挑战。现有最优方案
   （角色 LoRA + ID 模块 + ControlNet + IP-Adapter）一致性可达 95%，**剩下 5% 在连续剪辑里
   仍会被观众抓到**——所以资产库不是"有就行"，参考包干不干净直接决定崩不崩。
2. **头部把「资产层」单独拎出来**：剧本分镜 + 角色 LoRA + 场景模板库 属于资产层，
   做过 10 部剧的团队与新手的差别不在提示词，在资产库厚度；一部新剧的边际成本随库变厚下降。
3. **镜头上限逼出快切**：实测一部 8 分钟 AI 短剧 117 个镜头，平均 4.1 秒、中位 3.2 秒。
   所以资产库必须按"2–8 秒可切镜"的颗粒度建，而不是按"一张一张图"建。
   另外人工精修占 40% 工时（修手/修脸/服装/五官）→ 库要预留"补丁包"位。

**推论（这是本规划的总原则）**：资产库的敌人不是"不够多"，是"多但不能用"。
所以建库顺序是 **先定类与规格 → 再定准入闸 → 最后才谈数量**。

## 二、结构：四层十类（照 CHAR 库的成熟分法）

| 层 | 类 | 解决什么 |
|---|---|---|
| 身份层 | `characters` 角色包 | 脸/体态/身份串/LoRA，跨镜同一个人 |
| 外观层 | `props` 道具锚点、`characters/outfits` 服装变体 | 同一角色换装不崩、关键物件当锚 |
| 场景层 | `scenes` 场景模板、`motions` 动作/镜头片段、`transitions` 转场 | 底、节奏、接得上 |
| 风格层 | `styles` 画风/调色、`typography` 字体版式 | 一部片看起来是一部片 |
| 声音层 | `voices` 音色、`audio-sfx` 音效、`audio-bgm` 配乐 | 有声小说与漫剧的角色区分 |

数量目标不写死在本文，唯一来源：`cph4/fleet/asset-lib-v1/LIBRARY-TARGETS.json`
（P0=能开一部片、P1=能开 5 部不同题材、P2=题材全覆盖）。

## 三、"高质量"怎么变成可机判（这是本规划的关键）

每类资产四条机器判据，缺一条就不算入库：

| 判据 | 怎么判 | 工具 |
|---|---|---|
| 数量 | 该类比当前档目标差多少 | `asset_library_check.py` |
| 规格 | 短边/时长/音轨/alpha 是否达标（抽样） | 同上 |
| 授权 | 目录级或条目级 `RIGHTS.json`，license 在白名单；真人必须有 consent | 同上 + `asset_dataset_audit.py` |
| 凑数 | 近似重复率（dHash）、同脸换背景 | `asset_dataset_audit.py`（face 模式） |

人判的那一半（机器判不了，别假装能判）：
- 角色：5 条训练集未出现的提示词出图，同一人且"一眼不像 AI"
- 声音：盲听 5 条，答不出"这是合成音"
- 场景/道具：能否在 3 个不同风格下复用而不违和

## 四、三期推进（每期都有可验收产物，不靠"写文档"）

### 第 1 期 P0：能开一部片（目标见 targets 的 p0）
- 8 个角色包（含参考包 6 张 + 服装 2 套 + 表情 4 个 + 关键道具 1 个）
- 12 个场景模板（竖屏 1080×1920 至少一半）
- 20 个道具、15 个动作片段、10 个转场、3 个风格包
- 6 个音色、40 个音效、10 段配乐、4 套字体版式
- 验收：`asset_library_check --tier p0` 的 10 类全 OK，且抽检通过

### 第 2 期 P1：能开 5 部不同题材
- 覆盖都市/古装/玄幻/末世/悬疑五类题材的场景与道具
- 音色扩到 20（年龄 20–60、南北口音、粗细声线都要有）
- 验收：同上的 p1 档全 OK + 任意两部片之间不撞场景

### 第 3 期 P2：题材全覆盖 + 特色化
- 角色 100+，且刻意避开"标准 AI 脸"分布
- 风格包 25（含漫画分格、网点、古风线稿等）
- 验收：p2 档全 OK；且抽检里"一眼 AI"的比例 < 20%

## 五、垃圾库长什么样（反向清单，建库时逐条自检）

1. 几千张图但没有一条有授权 → 不是资产，是负债。
2. 同一个角色只有正面平光 3 张 → 一转侧脸就崩。
3. 场景全是"白底棚拍感" → 拼起来像 PPT。
4. 音色全是标准朗读 → 一开口就是播音腔。
5. 每类数量都很大但规格不一（1080/720/540 混） → 剪辑时无法批处理。
6. 没有命名与索引 → 找素材的时间超过做片的时间。
7. 大量近似重复（换背景/换尺寸当新资产） → 库越厚，选择越慢。

## 七、与现有工具的关系（不重复造）

- 台账与入库：`Tools/fleet/vault.py`（文件按指纹取名，台账 `cph4/fleet/vault/index.jsonl` 是权威）
- 数据集准入：`Tools/fleet/asset_dataset_audit.py`（face / voice，含 rights 门）
- 语料工程：`Tools/fleet/voice_corpus_prep.py`（纯 CPU，可分片并行）
- 库体检：`Tools/fleet/asset_library_check.py`（数量/规格/授权/缺口）
- 工序：`cph4/fleet/ri/content/lines/asset.json`（internal=true，不设市场门）

## 八、失效条件（到了就停）

1. 某类连续两周数量不涨且缺口没解释 → 该类判定"做不出来"，改来源或改规格，不加卡。
2. 抽检"一眼 AI"比例超过 30% → 停建该批，先查数据集（不是加训练步数）。
3. 授权不全的资产超过库存 10% → 停止入库，先清账，否则库里混进侵权件会整批不可用。
4. 库体检连续 3 次 EMPTY/GAPS 而补料侧没有任何投料动作 → 这是流程缺陷，先修投料口，别再派人。
