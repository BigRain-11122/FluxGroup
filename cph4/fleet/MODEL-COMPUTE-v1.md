# 算力大脑 = 机队本地模型能力中心（2026-11-11 定案）

> 令源：CEO 2026-11-11「算力大脑还没装备好，他要承担机队的本地化模型大部分的算力…他是整个机队的本地化能力中心，机队自己机器能做的先做，不能的马上让算力大脑赋能解决，尤其是整个机队的 agent 自动化要求的算力，主控只做轻量赋能」。
> 机器面=`cph4/fleet/MODEL-COMPUTE.json`（端点阶梯，运行时读它）；端点选择已落代码=`Tools/fleet/local_model.py::endpoint()`。
> 本件讲**为什么这么分、装备缺什么、怎么验收**；数字只在 JSON 里。

## 一、定位一句话

**机队先自己做（确定性脚本），做不了的立刻问算力大脑；主控只在算力大脑不可用时兜底 2B/4B。**

这修正了此前"模型算力在 MacBook"的默认假设：主控的 32G 统一内存要和 CEO 的办公应用共用，把它当模型农场是错的。

## 二、硬件实况（决定它能干什么，不能靠希望）

1. **CPU：双路 E5-2695v2 / 24 核 48 线程 / 无 AVX2** —— CPU 侧推理基本废掉。tokenize、采样、embedding 这类"看起来轻"的活也必须走 GPU，否则会拖成瓶颈。
2. **GPU：3× Tesla V100 16G = 48G，Volta(SM70)** —— 支持 FP16 与 INT8(DP4A)，**不支持 bf16**、**没有 INT4 张量核**。所以默认 FP16；量化只在显存不够时用，别指望 INT4 提速。
3. **GPU：3× P104-100 8G，Pascal** —— 只适合小模型和向量，不接主力。
4. **内存 256G，系统盘 512G 不够** —— 模型库要加 1–2T 盘，这是装备第一优先级。
5. **未入网**：tailnet IP 未分配，`MODEL-COMPUTE.json` 里 url 留空（阶梯自动跳过，不会去探一个不存在的地址）。

## 三、能跑什么（按卡分工，不做跨卡并行）

V100 之间走 PCIe、无 NVLink，跨卡张量并行会被通信拖死。所以**一卡一角色**：

| 卡 | 角色 | 型号档 | 显存 | 承接 |
|---|---|---|---|---|
| V100-0 | triage | 8B 级 | ~6G | 分类、抽取、短判定（量大、要求快） |
| V100-1 | creative | 32B 级（FP16 放不下就 Q4） | ~20G | 剧本、台词、文案——语感靠这个档 |
| V100-2 | review | 32B 级 或 14B×2 | ~16G | 审稿、判据复核、争议判断 |
| P104 | embed / 小模型 | 0.6B–3B | ~2G | 向量、去重、语义检索 |

并发按座位各 1–2，总量见 JSON 的 budget。**不做 70B**：Q4 约 40G，塞进去就没有余量给 KV cache，且 Volta 上速度不划算。

## 四、谁用它（这就是"agent 自驱"的算力基座）

1. **每台机的自驱循环**（`station_drive.py`）判"该不该建卡、产物够不够"——要模型就找它。
2. **每台机的监理**（`station_agent.py`）triage 发现项、写人话原因——要模型就找它。
3. **内容产线**：剧本/镜表/文案/评论草稿/报告/配方/报价——批量文本一律它出，主控只改不写。
4. **夜间批处理**：批量摘要、批量打标、跨片检索、回测辅助解释。
5. **主控保留**：2B/4B 做本机摘要与短判定、离线兜底、断网时不停摆。

## 五、运行时怎么选（已落代码，不是纸面）

`local_model.endpoint()` 的阶梯：**显式 `OLLAMA_URL` > `MODEL-COMPUTE.gateways` 按 order 探活 > 本机 11434**，带 30 秒健康缓存，探不通不重试、直接退下一级。

现状（2026-11-11 实测）：`gateways()` 只返回主控一条（算力大脑 url 为空=未装备），`generate()` 正常返回，说明阶梯不会因"机器没到"而卡死。

**已知缺口**：约 20 个旧工具直接读 `OLLAMA_URL` 环境变量、绕过了阶梯。算力大脑上线当天，要么把它们的调用改成 `local_model`，要么在启动脚本里统一 export `OLLAMA_URL=http://<brain>:11434`——后者一行搞定，先做后者。

## 六、装备清单（按优先级，缺一件都上不了线）

1. **盘**：加 1–2T 放模型库（现在 512G 装不下 32B 级）。
2. **入网**：tailnet 上线、分配 IP、写进 `MODEL-COMPUTE.json` 的 url。
3. **驱动/CUDA**：V100 需匹配的 NVIDIA 驱动 + CUDA 12.x；`nvidia-smi` 三卡都认到。
4. **服务**：单机 `ollama serve` 或 `llama.cpp server`（Volta 上 llama.cpp CUDA 更稳）；监听 11434，仅 tailnet 可达，不暴露公网。
5. **模型**：按 §三 四张卡各拉一个，拉完做一次 p50 与并发实测，写进验收。
6. **验收**：探活通过 → 至少一个模型加载完成 → 单请求 p50 < 8s → 才把 order=1 激活。

## 七、切换与回退

1. **切**：填 url + 探活通过，30 秒内全机队自动开始用它，不用改任何业务代码。
2. **退**：连续 2 次探活失败 → 阶梯自动降到主控轻量档；此时**只做摘要/分类**，批量生成排队等它回来（不许拿 4B 硬顶长篇）。
3. **指标**：每个座位的 p50、失败率、显存占用写进 `cph4/fleet/dispatcher/local-model.jsonl`，按周看。

## 八、和自驱契约的关系

`AUTONOMY-V3.md` 里"要模型找主控 8792 网关"一句作废，改为：**要模型找算力大脑**；主控 8792 只保留轻量兜底与离线应急。其余边界（不对外、不自封人判、不造活）不变。
