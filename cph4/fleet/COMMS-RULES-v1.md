# 通信规则 v1（2026-11-02）

> 目的：让"机器活着""在干活""出了东西"三件事分开可见，不再用一个心跳冒充全部。
> 一条原则：**谁写什么只有一处；每一种沉默都有名字。**

## 一、四个信号，各管一件事

| 信号 | 谁写 | 写在 | 说明什么 | 多久算沉默 |
|---|---|---|---|---|
| **心跳** | 机器 | `MASTER-STATE.lanes[n].hb_age_s` | 机器活着、内存、显卡 | >300 秒 |
| **上报** | 执行器 | `lanes/<node>.json` 的 mtime | 执行器在跑、在领活 | 有活时 >15 分钟 |
| **认领** | 中枢 | 队列 `state=RUNNING` + owner | 这张卡归谁 | 卡在 5 分钟内没被领 |
| **回执** | 执行器 | `queue-receipts/<卡>-<机>.json` | 产物落地了 | 有活时 >1 小时无回执 |

**规则一**：这四个不许互相代替。心跳新 ≠ 在干活；在干活 ≠ 出东西。

## 二、谁可以写哪个文件（唯一写手）

1. **队列**：只有中枢 `master_agent` 写；其他人改行必须走 `merge_jsonl`（按 id 合并，加锁）。
2. **车道文件**：只有中枢写 `lanes/<node>.json`；机器只读。
3. **回执**：只有执行器写 `queue-receipts/`。
4. **状态**：只有脉冲写 `PULSE.json` 与 `MASTER-STATE.json`。
5. **记忆**：任何会话可写 `CODELY.md`；脉冲每轮单独提交一次（`memory: autosave`），不挡同步。

## 三、同步规则

1. 脉冲每 60 秒一次：先提交状态，再拉，再推；**永不 rebase**。
2. 手写代码（`Tools/` 等）脏就不同步——这是保护，不是故障；提交后自动恢复。
3. 记忆文件与运行态不算手写代码，单独提交，不再挡同步（此前 322/386 轮就卡在这）。
4. 连续 3 轮同步失败 → 报红并写进一屏。

## 四、静默律

1. 机队一切动作静默：不弹窗、不响铃、不自动打开播放器。
2. 需要人来的只有两类：物理件、抽查。
3. 报错也不打扰人：落 `INCIDENT-LEDGER` 与一屏，不弹窗。

## 五、每天一屏（机器出，人只看）

1. 一屏五列：节点 / 机器活 / 在干活 / 上报年龄 / 最近回执。
2. 不一致的节点必须打名字：离机、心跳沉默、忙但不上报、空转有活、无回执。
3. 工具：`Tools/fleet/comms_check.py`（只读，随时可跑，退出码 2 = 有不一致）。

## 六、判定口诀（排障顺序）

1. 先看心跳：沉默 → 机器问题。
2. 心跳新但上报旧 → 执行器问题。
3. 上报新但队列没认领 → 中枢问题。
4. 认领了没回执 → 卡的问题（路径、内存、模型）。
5. 回执有、产物不在 → 交付面的假绿。
