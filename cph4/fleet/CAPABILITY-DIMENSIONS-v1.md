# 管理体系维度盘点（2026-11-07）

一句话：**我的颗粒度够细（86 个阶段），但广度上缺四块**——产物好不好、允许坏多少、花了多少、会不会出事。这四块都属于"没有度量就没有管理"。

对照来源（均为真实查阅，非印象）：
1. LangChain《How to Monitor AI Agents in Production》：agent 要盯 tool call 失败率、按工具统计运行数，且"故障常藏在 HTTP 200 背后"。
2. StackAI《AI Agent Observability》：golden signals + agent 专项（质量 rubric、成本、安全）；LLM 成本必须当一等信号。
3. Atlan《AI Agent Observability 2026》：四层=实时指标/持续评测/告警/实验闭环。
4. Google SRE Workbook：SLI→SLO→错误预算；快燃 10-15×/5 分钟、慢燃 6×/1 小时两档告警。

## 四块必须补的（按价值排序）

### 1. 允许失败率 + 燃尽告警（第 7、8 项）
现在的问题是"要么绿要么红"，没有中间态。成熟做法是给每类任务定 SLO（如派卡成功率 ≥95%/7 天），算出错误预算，用快燃/慢燃两档告警。
**为什么重要**：没有错误预算，一次偶发失败就会触发停线（我们干过），而系统性劣化反而没人管（因为每轮都"绿"）。

### 2. 产物质量评分（第 9 项）
现在只判"有没有产物"。要加 rubric：完整性（字段齐）、可复现（命令+输入）、证据（指针可点）、新鲜度（非旧文件冒充）。
**为什么重要**：rc=0 且文件存在，仍可能是垃圾——这正是外部调研说的"故障藏在 200 背后"。

### 3. 成本归因（第 10 项）
按线/按任务累计：云端 token、本地机时、GPU 分钟。产出"每万次派单成本""哪条线最贵"。
**为什么重要**：现在只知道"日预算 100 元"，不知道钱花在哪条线，也就无法判断该砍哪条。

### 4. 安全与供应链台账（第 11、12 项）
把红线变成计数：越权动作次数、PII 命中、AGPL 依赖数、素材授权缺失数。全部可告警。
**为什么重要**：红线写在文档里 = 没人检查；变成指标才会每天算。

## 落地计划（本轮先做前三块）

1. 写 `cph4/fleet/SERVICE-LEVEL-v1.json`：每类任务的 SLI 定义 + SLO 目标 + 窗口。
2. 写 `Tools/fleet/slo_budget.py`：从回执算 SLI、剩余错误预算、快燃/慢燃状态。
3. 写 `Tools/fleet/quality_score.py`：产出 rubric 打分（规则为主，4B 只写一句理由）。
4. 写 `Tools/fleet/cost_attrib.py`：按线/任务累计成本，出"最贵 TOP5"。
5. 三个都接脉（每日或每小时），并在一屏留一行。
6. 安全与供应链台账本轮先出清单（第 11、12 项），下一轮做扫描器。

## 一条自我提醒

**维度缺失比任务缺失更危险**：任务漏了会被校验器抓到，维度漏了没人会问。所以这份盘点应该每季度重跑一次，而不是只做一次。
