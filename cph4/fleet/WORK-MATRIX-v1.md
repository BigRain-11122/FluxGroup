# 工作归属矩阵 v1 · 复盘与规划（2026-11-11）

> 令源：CEO 2026-11-11「各个机器负责的子公司和业务工作颗粒度不够细，好好复盘，然后再规划」。
> 机器面=`cph4/fleet/TAXONOMY-v1.json`（任务类型字典）+ `Tools/fleet/work_matrix.py`（校验器，自检 7/7）。
> 本件是人读面：复盘结论、分工矩阵、阶段计划。阈值与资源下限只在 TAXONOMY 里。

## 一、复盘：颗粒度到底断在哪（实测，不是印象）

| # | 事实 | 数字 | 说明 |
|---|---|---|---|
| 1 | 卡片声明的工序 | **0** 张有 task_type，**6/2250** 有 stage（0.3%） | 派单不知道这张卡是哪道工序 |
| 2 | 派单资源词表 | `needs` 只有 cpu(1753)/gpu(46)/空(451)，`heavy` 真值 28 | 一台机能干什么，系统只知道"吃不吃显卡" |
| 3 | 产品工序与机器能力 | 59 道工序 vs 28 个能力词，交集 **4**（7%） | 工序名（镜表/海选/口型）没有一个能反查到机器 |
| 4 | 工序归属字段 | 59 道工序里带 owner_station 的 **0** 道 | 只有一个"产品级"归属，跨机链条表达不出来 |
| 5 | 负载分布（估算工时） | 主控台 28 道/1100 分/12 产品；交付工厂 14/765/6；视觉 6/750/3；声音 8/310/5；大脑 2/180/1 | **最忙的机器只有 4 槽且 CEO 在用，最闲的机器 8 槽却没入网** |

结论一句话：**归属只做到"产品归哪台机"，没做到"这道工序归哪台机、用什么工具、什么时段、谁来判"**。所以派单只能按机器名硬指派，同一台机背 12 个产品，而 8 槽的大脑空转。

## 二、规划：加一层，按"能力"分工而不是按"产品"分工

四层，一层一正身：

1. **子公司（org）** → `LINE-REGISTRY.org`（内容/策略/游戏）
2. **业务线（line）** → `LINE-REGISTRY`（15 条）
3. **产品（product）与工序（stage）** → `PRODUCTS.json`（16 个 / 59 道）
4. **任务类型（task_type）** ← **本次新增，缺的就是这层** → `TAXONOMY-v1.json`（45 个）
5. **任务卡** → 必须带 `product_id + stage + task_type`，派单只认能力匹配

能力三分（分工只看类型，不看产品）：

- **模型型**：要本地大模型出文本（剧本/镜表/选题/文案/草稿/报告/配方）。只有主控台有模型，所以现在全压在它身上。
- **工具型**：确定性脚本，吃显存或吃核（KF/i2v/口型/混音/打包/构建/切图/索引/清单）。按硬件与时段分。
- **人判型**：CEO 物理件（发送/备案/商务/发布决定）。`T-OPS-CEO`，永不派机。

## 五、阶段计划（今天做了什么、下一步靠什么）

1. **今天已做**：建 TAXONOMY（45 类型 + 16 产品 59 工序全映射）、加 shifts、建校验器、下沉 3 道工具型工序。校验实况：**errors 0，warnings 15**（全是"有活没人干"——视觉/声音/大脑三台不在线）。
2. **阶段二（一周内）**：给交付工厂夜窗装 4B（94G 内存、12G 显存，夜窗足够），把 6 类批量文本（选题/文案/评论草稿/报告/配方/报价）下沉。测算：主控 **25 道/1025 分 → 18 道/755 分**，交付工厂 17/840 → 24/1110 分（8 槽 × 12 小时夜窗完全吃得下）。
3. **阶段三（算力大脑入网后）**：成为本地模型中心——承接全队 triage/creative/review/embed 四类推理、批量文本、回测与夜间批处理，8 槽不再空转；主控退回轻量兜底。装备清单与验收见 `MODEL-COMPUTE-v1.md` §六。
4. **不改的东西**：产品清单与工序名仍以 `PRODUCTS.json` 为正身；能力只在 TAXONOMY 声明，STATIONS 不再重复写能力词。

## 六、派单的新判据（三条，写进卡规则）

1. 卡必须带 `product_id + stage + task_type`；三者缺一，派单器直接拒收（现在 0% 的卡带 task_type）。
2. 机器承接 = `TAXONOMY.task_types[task_type].stations` 命中本机 **且** 本机硬件达标 **且** 当前在 `shifts` 时段内；不命中就是 `UNSERVICEABLE` 报警，不许按机器名硬塞。
3. 派单前跑 `python3 Tools/fleet/work_matrix.py`：有 ERROR 不许开派，有 BOTTLENECK 只许派给在线机并把缺口写进日报。
