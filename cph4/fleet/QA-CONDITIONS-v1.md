# 工况测试策略与结果（QA-CONDITIONS-v1）· 2026-11-11

> 令源：CEO 2026-11-11「你要用不同的工况去测试，并假定自己是机队某一台机器，好好写好策略，一个个测试发现问题解决问题」。
> 台架=`Tools/fleet/station_qa.py`（12 工况，可 `--station` 扮演任意一台机）；沙箱隔离，每例独立临时根目录。
> 结论先给：**12/12 全过，其中 4 个是台架抓出来的真 bug，已修**。

## 一、策略：每台机在坏情况下"应该怎样"

先定行为，再写用例——不是先写代码再补测试。

| # | 工况 | 应该的行为 |
|---|---|---|
| Q1 | 冷启动：空分片、无产物 | 只为「有命令且非权限」的工序建卡；其余如实报缺口（AUTHORITY / TOOL-PENDING），不造活 |
| Q2 | 队列坏行：中间插坏 JSON | 跳过坏行不丢整份，后续读写照常 |
| Q3 | 磁盘告急：free < `min_free_gb` | 直接 BLOCKED，不建卡不跑，不形成失败循环 |
| Q4 | 模型全挂：端点全不可用 | 评审团全 ABSTAIN → REVISE；不是 PASS，也不崩 |
| Q5 | 产物过期：mtime 超 `refresh_h` | 应重建卡；同工序当天只建一次 |
| Q6 | 重复在飞：已有 OPEN 卡 | 不重复建卡 |
| Q7 | 回执重名：同 id 二次写 | 两份文件，历史不覆盖 |
| Q8 | 并发写片：两线程同时 upsert | 两张卡都在（写锁生效） |
| Q9 | 交接断头：目标机不存在/离线 | 只写 HO- 卡或返回同机提示，不崩 |
| Q10 | 面板缺席：task_type 无 panel | BLOCK（宁可拦不许放） |
| Q11 | 产物存在但是空文件 | 不许判 DONE（size>0 才算） |
| Q12 | 权限件：CEO 发送 | 不建卡、不判完成、不代发 |

## 二、抓到的 4 个真 bug（都已修）

| 来源 | 症状 | 根因 | 修法 |
|---|---|---|---|
| Q1 / Q12 | 权限件（发送/注册/备案）在自驱报告里**完全不可见** | `plan()` 先判「本机是否为承接方」，而权限件的承接方是空列表 → 直接 `continue` | 改成先判「无承接方」：`human` 件报 AUTHORITY，其余报 NO-OWNER，都进报告 |
| Q5 | 产物过期了却**不重建卡** | 新鲜度取的是**目录自身 mtime**，而目录 mtime 只在增删文件时变，文件改写不更新 | 新增 `_newest_mtime()`，目录取内部最新文件时间 |
| Q8 | 两线程并发 upsert，**只剩一张卡**（丢写） | 锁只包了"写"，读-改-写整体没锁 → 经典 RMW 竞态 | `upsert` 整段加锁；锁改为同线程可重入（避免嵌套死锁） |
| Q3 | 磁盘告急没触发 | 用例阈值写错（free 正好等于水位），不是代码问题 | 台架改成 free < 水位，并把用例断言收紧 |

## 三、五台机都跑了一遍

`--station visual|delivery|audio|brain|control` 各自 12/12。同一套行为对五台机一致，说明逻辑没有绑在某台机的特殊性上。

回归：`station_drive` 11/11、`station_shards` 7/7、其余 10 套自检全绿（改动只碰了这两处）。

## 四、要特别说明的两点

1. **Q8 这一类问题只有并发测试才抓得到**。之前所有自检都是单线程顺序跑，看起来全绿；真实机队里自驱循环、命令面、巡查可能同时动同一份分片——这是最危险的一类假绿。
2. **Q5 这一类是"语义错但测试也看不出来"**：产物明明过期，系统认为新鲜，于是永远不重做。这种错不会报错，只会静默少干活。

## 五、下一步该加的工况（还没做）

1. **时钟跳变**：回执/租约用本地时间，跨时区或改系统时间时的行为未测。
2. **git 同步失败**：分片能写但推不上去（网络断/冲突）时的退避与告警未测。
3. **卡在 RUNNING 但进程被杀**：进程重启后如何回收（现在靠 station_agent 的 stall 判据，未纳入台架）。
4. **产物被外部进程改写**：抽验能抓到哈希不一致，但自驱不会主动复检。

不只测"坏了怎样"，还测"现在这套东西接不接得上"：

| 组 | 项 | 结果 |
|---|---|---|
| 链条 | 59 道工序全落三桶 ／ task_type 都在册 ／ 每类型有承接方 ／ 硬件达标 ／ 判据有落点 ／ 评审团无幽灵席位且至少一席本方 | 6/6 |
| 通路 | 端点阶梯可解析 ／ 席位 cls 都能映射 ／ 交接目标在册 ／ 命令面与自驱同源分片 | 4/4 |
| 策略 | 三桶互斥 ／ 频率预算不超载（主控 178/300 次、66/90 分） ／ 每机至少一席（39 席） | 3/3 |

**本轮被它抓到的三处真问题**：评审团 15 处"只有外邀席位没有本方视角"（已补本方 GATE/LEAD）、量化回测漏配面板（已建）、正典 6 个指针还指着已归档的旧路径（已改指 `docs/_archive-20261111/`）。

## 七、机队预演（fleet_rehearsal.py，10/10）

在沙箱里用真配置 + 模拟时钟让五台机跑若干轮，**不碰真机队**：

| 场景 | 断言 | 结果 |
|---|---|---|
| R1 首次上场 | 只建有命令的工序；权限件不建卡 | visual 建 1 张并 DONE，control 0 张 |
| R2 某机离线 | 离线机不建卡，工序不被别机抢 | 离线 visual 建 0 张 |
| R3 模型全挂 | 面板全 ABSTAIN → REVISE | 卡状态 REVISE，无 DONE |
| R4 命令失败 | 卡 FAILED，不写 DONE | FAILED（rc=3） |
| R5 磁盘告急 | blocked，不建卡不跑 | blocked 且队列空 |
| R6 同日两轮 | 不重复建卡、不重复跑 | 两轮都是 1 张 |
| R7 跨天 | 产物过期 → 重建并重跑 | 次日重建并 DONE |
| R8 两机并发 | 各写自己分片 | visual 1 音频 1，互不覆盖 |
| R9 交接链路 | A 完成后 B 分片出现 HO- 卡 | audio 收到 HO-P1-sound |
| R10 抽验失败 | 回执哈希被改 → 抽验 FAIL | A2 哈希不一致 |

**预演抓到并修掉的 5 个真缺陷**：
1. **离线/被暂停的机器照样自己开干**——状态从来没进自驱判定（只有磁盘判据）。已加状态闸：非 ready 不建卡不跑，手工演练须显式 `--force`。
2. **缺抽验配置时巡查静默零抽验**——看起来"巡过了"，其实什么都没抽。已改为报错并计入异常。
3. **目录型产物没有哈希**——抽验只能说"不可验"，等于验收失效。已加目录指纹（相对路径+大小+文件哈希）。
4. **卡没写 judge 就一律 PENDING_HUMAN**——而 fleet_cmd/handoff 生成的卡不一定带 judge。已改为回退到任务类型的判据。
5. **`--now` 时钟契约不一致**（float vs datetime），预演时才暴露。
