# 2026-11-15 竞品拆解晨报：社交自动化 Agent

本周生产最需改进的“真空点”是**会话状态机**。调研档案显示，社区方案如 Chatwoot 虽功能完备（会话状态机、人工接管、SLA），但因许可限制无法直接移植代码，却揭示了我们要重写的逻辑结构。目前每条评论独立处理会导致同用户多轮提问被重复回；我们需在`Tools/fleet/social_threads.py`中照抄其实务模型：定义 `open / waiting / resolved / snoozed / handoff` 五种状态，强制转移写入本地表（防调用方滥用），且 `handoff` 后机器禁止再发，仅凭人工复述可交还。

当前决策轮次（R-20261028）显示系统曾因文件损坏重启，但核心逻辑已修复；相比之下，社交模块缺乏“未回积压”概念，无超过 X 小时自动标记 Overdue 的机制。

需补充：CEO 对外发送权确认流程是否覆盖 SLA 触发场景，以确保 `resolved` 状态下的草稿流转符合合规要求。
