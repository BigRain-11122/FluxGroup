
## I-20261102-01 主控被自己的状态文件拖死（结构性）

- **现象**：11-01 23:30 → 11-02 07:30 约 8 小时，主控脉对外无法同步（push 全部 rejected），bm-a 夜班判「主控真空」并接管；1912 轮脉冲中 1036 轮 `skipped:dirty`。
- **根因**（三层，逐层验证）：
  1. 每 60 秒把 PULSE/SUPERVISOR/BRAIN/DIGEST 等报告提交进 git → 24h 内 461 次提交中 63% 是状态噪音；
  2. 只要有任一 tracked 文件脏，`git pull` 即被阻塞；`CODELY.md` 未提交 → 永久 `non-fast-forward`；
  3. 出问题后我用 rebase 收口，rebase 在共享工作树上必然冲突（UU on PRODUCTION-QUEUE），冲突又冻结同步。
- **正法**：
  - 报告类状态**移出版本控制**（16 个文件 + PATROL-FLEET 目录，已 gitignore），git 只留派单通道（lanes/队列/backlog/MASTER-STATE）与产物；
  - 同步改 `pull --ff-only`，分叉只报 DIVERGED 不自动合并；仅生成态脏时用 autostash，手写代码脏则拒绝同步；
  - 报告快照改为 30 分钟一次，时钟读 git 历史。
- **实测**：改造后近 30 分钟提交 4 次（此前约每 3 分钟一次），push ok。
- **附带教训**：改完 pulse 必须真跑一轮（`--no-pull` 冒烟）再 kickstart；本轮 `cold` 未定义导致循环崩溃 2.5 小时（已加 try 保护，状态提交异常不再打断心跳）。

## I-20261102-02 bm-b 内存枯竭导致「活着但不干活」

- **现象**：bm-b lane 文件每分钟更新（agent 活着），但 `ram 0.0/1.0 GB`，最近一次产出回执停在 11-01 20:45（约 14 小时无产出）；TTS 卡重试 23 次零回执。
- **处置**：取消盲重试（判无效产出）；派诊断卡 + 救援卡（free_mem --apply）；救援卡因 free<0.2GB 仍无法执行。
- **待物理介入**：需重启 bm-b 或关闭占内存进程（无远程执行通道，只能靠本机计划任务或人工）。
- **制度修正**：救援卡（rescue=true）不受 1GB 内存底线限制（0.2GB），避免「内存不足连释放内存的脚本都跑不了」的死循环；`rescue/accept/line` 字段已加入入队白名单（此前被丢，卡到了执行机也没有救援属性）。
