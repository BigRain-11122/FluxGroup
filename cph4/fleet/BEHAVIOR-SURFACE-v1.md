> CEO 2026-11-23：「你现在的主要还是训练符合各个平台的用户行为，行为面要扩大 不要只是评论」
> 机读正身 = `BEHAVIOR-SURFACE-v1.json`（本件是人读摘要，两者冲突以 JSON 为准）。

## 一、为什么"只有评论"不行

机器人的破绽不在**动作种类少**，而在**分布错**：

- 真人的一次会话是 看 → 划走 → 搜一个词 → 拖回去 → 点不感兴趣 → 偶尔赞 → 极少说话；
- 机器人是 赞 → 评论 → 赞 → 评论，**没有负反馈、没有搜索、没有进度操作**。

所以每新增一个动作，必须同时给两个数：**占比上界**和**与别的动作的先后关系**。
只说"支持点赞"不算支持行为面。

## 二、动作词表（跨平台统一）

| 动作 | 含义 | 说明 |
|---|---|---|
| read | 观看/阅读 | 进详情 + 停留 + 滚动 + 看完比例 |
| search | 主动搜索 | 真人常用的入口，机器味最重的缺口 |
| progress | 进度/倍速/暂停/关弹幕 | 从头 1.0x 播完是不存在的 |
| uninterest | 不感兴趣 | **最强真人指纹**，机器人几乎不做 |
| like / coin / fav / follow | 互动四件套 | 各有配额 |
| danmaku / comment | 说话类 | 占比必须远低于点赞 |
| share / space / live | 传播/主页/直播 | 低频、留痕，量极小 |
| swipe_away | 划走 | 抖音的常态行为 |
| note_detail | 笔记详情 | 小红书必须进详情才算看过 |
| article_more / zaikan | 展开全文 / 在看 | 公众号专有 |

## 五、下一步（按投入产出）

1. **B站 search + progress + uninterest**——零额外账号风险，直接把"只有点赞评论"这个最大机器味补掉。
2. **小红书 note_detail + like + collect**——小红书语料断供，先把详情页行为跑通才有料。
3. **抖音 swipe_away**——抖音不划走就不是抖音。

## 六、不许做的事

- 不许用服务端直连采平台内容（实测必被拦：公众号"环境异常"、小红书 300012、知乎 `/account/unhuman`）。
- 不许跨平台导流（主页留联系方式 / 私信 / 加 V）——平台红线，永久封禁级。
- 不许给"未登录/无账号"的平台排班（自检会红）。
- 不许为了跑满 24 小时而给没实现动作的平台加权重：权重代表**能干多少活**，不是排班填空。
