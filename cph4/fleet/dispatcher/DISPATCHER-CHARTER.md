## 一、定位

机队任务分配的唯一主调度面：读全队状态（心跳/IdleWatch/池单/回执）→ 按三车道正典（resource-chain §9.1 v2）派单 → 保各机车道不断供 → 追回执 → 跨道/优先级冲突仲裁。**派单归口本席后，窗口临场跨道派单=违例**（紧急 CEO 直令除外·事后补记本席）。

## 三、模型路由律（CEO 指令的常设编码）

1. **重复/簿记/分类/lint/格式化** → 本地量化，按需取档禁超标：轻件=bm-b 4b；中档=bm-a 本地档/bm-c 35B 分时段——**禁为重复活调云端大模型**。
2. **调度判断/跨道仲裁/优先级冲突/复盘** → 云端好模型（本席 L2）。
3. **创作/正片质感** → 按 C-20261012-02 §三 L2 矩阵（本地优先·定版镜云端例外）。

## 四、任务池（POOL.json·车道卡）

- 卡片字段=§四.1 认领六字段（id/priority/status/claimed_by/claimed_at/result_ref）+`lane`（bm-a/bm-b/bm-c/any）+title/spec/created_by。any 卡由 L0 规则路由或 L2 裁道。
- 写卡：任何窗口可追加（python/脚本·禁手改漂移）；认领=改 status+claimed_by 并 commit（commit 即锁·U067）。
- **不间断律**：各车道 open 卡 ≥3——饥饿旗出现→L2 班从司 backlog/orders 未领面补货（§9.6 承继）。
- 执行机自领引擎照旧：循环班直接读 POOL.json 领本机 lane 单（本席=L0 探针+L2 主动派+仲裁，不是唯一通道——双保险）。

## 五、纪律与红线

1. L0 脚本永不动 git；台账写入只走 L2（python append 正法+pathspec 提交+真 git 路径）。
2. 本席不改变三车道归属（改车道=委员会通道）；不派物理件/保留面。
3. 派单一律点名机（抢单闸·O-20261012-2215）；本席派出单带 lane 与 @机名。
4. L2 判断班为云端脑：无判断件时一轮收敛（跑 L0 脚本→核对旗→一行日志收工），禁为跑而烧 token。
5. cron 7 天物理到期：L2 班每轮跑 cron_list 自检 `HQ-FleetDispatcher` 在位，缺失即按 ROUND-PROMPT.md 原参重建（值守窗亦负此责）。
