# 执行映射 v1（谁做、拿什么证据、多久一次）

> 目的：让 AI 不用猜"这条我能不能自己做"。每条宪法条款对应一个执行者、证据与频率。

## 一、执行者定义

| 代号 | 含义 | 权限 |
|---|---|---|
| **M** | 机器/脚本 | 只读判定、写回执、写审计；不改契约、不发布 |
| **P** | 代审（制作人 AI） | 签 G1–G3；可提修订；不可改宪法 |
| **C** | CEO | 方向、价格、平台、G4、宪法 |

## 二、逐条映射

| 条款 | 内容 | 执行者 | 证据 | 频率 | 工具 |
|---|---|---|---|---|---|
| C-01 | 身份 | C | 人工 | 年 | — |
| C-02 | 交付/RC | M + P | 8 闸回执 + 物料清单 | 每次构建 | `receipt.py` + gate-runner |
| C-03 | 类别/资源 | M | lint 报告 | 每契约 | `contract_lint.py` |
| C-04 | 体验法则 | M + P | 范围检查 + 10 秒片段 | 每原型 | linter + 人眼 |
| C-05 | 质量/假绿 | M + P | 闸回执（PASS/FAIL/NOT_RUN） | 每次构建 | gate-runner |
| C-06 | 生产节奏 | M + P | 构建回执 + 队列 | 每日 | scheduler |
| C-07 | 商业化 | M + P | 代码扫描（广告/服务器）+ 合同 | 每 RC | `gds.py` + 人工确认 |
| C-08 | 组织/权限 | C + P | 门报告 | 每门 | — |
| C-09 | 边界 | M | lint + 代码扫描 | 每契约/RC | linter + grep |
| C-10 | 试验/量产门 | M + C | 试验结果 JSON + 决策 | 4 款后 | `experiment_eval.py` |
| C-11 | 失效/停线 | M + P | 月度损益 + 退款/销量 | 每月 | P&L 表 |
| C-12 | 单位经济 | M + C | 计算器输出 + 实收 | 每月 | `unit_econ.py` |
| C-13 | IAA 护栏 | M + P | 配置检查 + 运行日志 | 每 RC | 静态扫描 + 真机 |
| C-14 | 变更控制 | C | 版本记录 | 每月 | registrar |
| — | 立项评审（G-A/G-B/G-C） | M + P | `panels/<ID>.yaml` + lint 输出 | 每门 | `panel_lint.py`（机制=`GREENLIGHT-PANEL-v1.md`） |

## 三、AI 可自主做的事（不问）

- 跑 lint、跑 8 闸、写回执、标 NOT_RUN。
- 生成构建、跑冒烟、出日报。
- 发现违约（广告/服务器/换皮）立即停并报告。
- 计算经济模型、生成候选机会卡。
- 在契约范围内改代码/资产；越界即停。

## 四、AI 必须升级的事

- 改宪法/类别/项目契约。
- 宣布 PASS 但没有证据。
- 发布/定价/平台选择。
- 插队、砍项目、改目标。
- 退款 >20%、连续两款 <400、现金不足。

## 五、落地顺序

1. G1/G2/G7/G8 脚本化（编译/出包/资产/物料）。
2. G3–G6 接真机/机器人；没有证据固定 NOT_RUN。
3. `experiment_eval.py` 接四款试验数据。
4. 月度 P&L 模板。
5. 愿望单/退款/实收的手工回填表（平台无 API 时）。
