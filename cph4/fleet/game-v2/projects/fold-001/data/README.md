## 2 顶层结构

```json
{ "schema_version": 1, "count": 100, "garments": [ { … }, … ] }
```

根是**对象**不是数组——Unity 的 `JsonUtility` 不能反序列化顶层数组；多包 3 个字段也能顺带校验 `count` 与 `garments` 长度是否一致。

## 3 字段 schema

| 字段 | 类型 | 取值 | 说明 |
|---|---|---|---|
| `id` | string | `"G001"`–`"G100"` | 稳定主键，不复用、不改号。图鉴格序 = id 序 |
| `name` | string | 中文，100 个互不重复 | 图鉴 / 结算显示名。取自内容包 §2 原名 |
| `category` | string | `T恤 / 衬衫 / 裤 / 裙 / 毛衣 / 外套 / 毛巾 / 袜子 / 床品` | 分布 12 / 12 / 12 / 11 / 10 / 10 / 11 / 11 / 11 |
| `fold_family` | string | `对折 / 三折 / 卷 / 立式 / 挂` | 规则集与折序；家族内规则固定（内容包 §3），换家族 = 换玩法，不是调参 |
| `folds` | array | 1–3 条，每条 `{axis, at, dir}` | 折线表，**顺序 = 执行顺序** |
| `slots` | int | 1–2 | 占几个格位（抽屉 6 格位 / 挂杆 6 挂位 / 顶箱 4 大格位） |
| `difficulty` | int | 1–5 | 只由折数 / 提示通道 / 空间余量 / 材质四旋钮决定，**不靠调判定阈值**（D-010：恒 92% / 80%） |
| `material` | string | `棉 / 麻 / 丝 / 羊毛 / 绒 / 混纺` | 丝 / 绒（及纱）类需先垫衬纸，占位与摩擦参数不同 |
| `room_ids` | array[int] | 长度 1，值 1–25 | 所属房间；每房恰好 4 件 |
| `codex` | string | ≤20 字 | 图鉴一句话，写"物件本身"，不写任务、不写奖励 |

### 3.1 `folds[]` 三条字段的语义

| 字段 | 含义 |
|---|---|
| `axis` | 折线走向。`"x"` = 折线水平（把上/下的一半折过去）；`"y"` = 折线竖直（把左/右的一半折过去） |
| `at` | 折线位置，0–1。`x` 轴从左 0 → 右 1；`y` 轴从上 0 → 下 1 |
| `dir` | 被折起的那半往哪边走。`axis:"x"` 只能配 `up / down`；`axis:"y"` 只能配 `left / right`（自检强校验这对配对） |

折序是玩法的一部分：三折家族固定"先下摆上折 1/3，再压领口"，反了层序就错；立式家族固定"左右各内收一次，再上折成 6cm 文件状"。引擎侧不要自己重排 `folds`。

### 3.2 两处口径说明（免得下一个人以为是 bug）

1. **`slots` 上限 2**：内容包 §2 里被套 / 薄被 / 夏凉被 / 被子收纳袋标了 4 格位、粗针毛衣 / 厚帽衫 / 冲锋衣 / 床单标了 3。本数据契约 `slots ∈ {1,2}`，故一律记为 2；"大格位"的换算交给容器侧（顶箱 4 大格位 = 2×2 格位），不在衣物表里翻倍。要恢复 3–4 必须先改契约，不能在 JSON 里偷偷写。
2. **`slots` 与折数的关系**：`slots` 只描述占位，不描述折数；`folds` 长度才是折数（1–3 条是本表上限，段进到"卷 4 折 / 挂 7 件"那种由引擎在家族规则里叠加，不写进单件数据）。

## 4 家族与难度分布

| 家族 | 件数 | 难度带（实际） | 规则要点（内容包 §3） |
|---|---:|---|---|
| 对折 | 27 | 1–4（1:11 / 2:10 / 3:5 / 4:1） | 沿肩线 / 中线折；袖子先内收成矩形；厚料折完压 0.2s 排气 |
| 三折 | 25 | 1–5（1:1 / 2:4 / 3:12 / 4:6 / 5:2） | 下摆 1/3 上折 → 压领口（折序固定）；每折落在"当前层的边"上 |
| 卷 | 21 | 1–5（1:1 / 2:5 / 3:12 / 4:2 / 5:1） | 从下摆起卷、半径递减；卷尾塞进侧缝；易勾料先裹衬纸 |
| 立式 | 13 | 1–5（1:4 / 2:3 / 3:4 / 5:2） | 折成 6cm 宽"文件"状；光滑面朝外，抽一件不带出邻件 |
| 挂 | 14 | 2–5（2:1 / 3:2 / 4:6 / 5:5） | 衣架穿入、肩线对齐；按长度排序；挂位会溢出 → 唯一要决策的家族 |

家族内的高难度都挂在"材质"这条旋钮上，不是加规则：真丝衬衫（对折/4）、羊绒衫与粗针毛衣（三折/5）、纱裙（卷/5）、皮衣（挂/5）。所以同一家族里既有 1 级也有 5 级，是设计意图不是漏填。

难度分布（自检锁定）：**1–2 级 40 件 / 3 级 35 件 / 4–5 级 25 件**，直方图 17 / 23 / 35 / 15 / 10。
早期房间只放 1–2 级（房 1 均 1.00）、中段进入 3 级（房 9–12）、后段 4–5 级（房 16/18 均 4.50、房 25 均 4.25），与"折数 2→6 / 提示全亮→无 / 余量 2 格→0"的段进同向。

## 7 如何新增一件

1. **取号**：用 `G101`（顺延，不回填空号）。id 一旦进存档就不能改，图鉴按 id 排序，插入会给老存档错位。
2. **写一条**：

```json
{
  "id": "G101", "name": "无袖连衣裙", "category": "裙", "fold_family": "挂",
  "folds": [{ "axis": "x", "at": 0.82, "dir": "up" }],
  "slots": 1, "difficulty": 3, "material": "混纺", "room_ids": [17],
  "codex": "肩线窄，挂起来才不塌。"
}
```

3. **同时改三处计数**：`count` 改成新长度；类别配额（现为 12/12/12/11/10/10/11/11/11，加一件就破平衡，需同步在另一类别减一件，或明确改口径并更新本表）；难度三档 40/35/25 的配额。
4. **房间保持 4 件**：`room_ids` 加进去后该房会变 5 件，必须把房里另一件挪走或换房。房间是"4 格主件"的计数单位，5 件会让抽屉装不下。
5. **`codex` ≤20 字**，写物件本身（材质、磨损、谁的、什么时候的），不写"完成任务""收集"这类系统语。
6. **跑自检**：`python check_garments.py`，必须 `ALL PASS`。脚本会挡掉：字段缺失 / 多余字段、`dir` 与 `axis` 不配对、`at` 越界、房间不满 4 件、类别或难度配额被破坏、出现运营钩子词与失败态词。

改已有条目同理：只改内容不改 id；改 `folds` 等于改手感，动之前先看该家族的折序规则（§3.1）。

## 8 Unity 怎么读

### 8.1 结论：用 `StreamingAssets`，不用 `Resources`

| | `Resources/` | `StreamingAssets/` ✅ |
|---|---|---|
| 打包 | 全量编进包体，启动索引常驻 | 原样拷进包体，不进索引、不占常驻内存 |
| 改数据 | 必须重编（哪怕只改一个数字） | 换文件即可，Steam 侧可做数据热修 / 灰度 |
| 定位 | `Resources.Load<TextAsset>("garments")`，路径隐式 | 显式路径，`data/garments.json` 一眼能找到 |
| 尺寸 | 适合极小的配置 | 适合 100 条这种会长的内容表 |

本项目 Steam Win64，`System.IO` 直接可读，没有 WebGL 的异步限制；替 47KB 的 JSON 走 `Resources` 只会换来"改一个字要重编"。

放置路径：

```text
Assets/StreamingAssets/data/garments.json
```

### 8.2 反序列化（推荐 Newtonsoft）

包：`com.unity.nuget.newtonsoft-json`（Unity 官方分发）。**不要用 `JsonUtility`**：它对顶层数组、字段默认值、未知字段都挑剔，且字段一改名老存档就静默变 null。

```csharp
using System;
using System.IO;
using System.Text;
using Newtonsoft.Json;

[Serializable] public class FoldStep {
    public string axis;   // "x" | "y"
    public float  at;     // 0..1
    public string dir;    // up/down/left/right
}

[Serializable] public class Garment {
    public string     id;            // G001..G100，主键
    public string     name;
    public string     category;
    public string     fold_family;   // 对折/三折/卷/立式/挂
    public FoldStep[] folds;
    public int        slots;         // 1..2
    public int        difficulty;    // 1..5
    public string     material;
    public int[]      room_ids;      // 长度 1
    public string     codex;
}

[Serializable] public class GarmentDb {
    public int        schema_version;
    public int        count;
    public Garment[]  garments;
}

public static class GarmentData {
    public static GarmentDb Load() {
        string path = Path.Combine(Application.streamingAssetsPath, "data/garments.json");
        string json = File.ReadAllText(path, new UTF8Encoding(false));   // 文件本身就是无 BOM
        var db = JsonConvert.DeserializeObject<GarmentDb>(json);
        if (db == null || db.garments == null || db.garments.Length != db.count)
            throw new InvalidDataException("garments.json 损坏：count 与条目数不一致");
        return db;   // 常驻内存约几十 KB，按 id 建 Dictionary 索引即可
    }
}
```

### 8.3 接进玩法的三条约定

1. **只按 `id` 索引**，`name` / `category` / `fold_family` 是中文串，只用于显示与选规则表；存档里存的也是 `id`（`profile.items` 的键），绝不用名称。
2. **`fold_family` 是 switch 的键**，五个值对应五套规则与提示曲线（§4 表）；出现未知家族直接抛错，不要 fallback 到对折——静默降级会让 92% 判定和折序全错。
3. **`slots` 交给容器装箱**：抽屉 6 格位 / 挂杆 6 挂位 / 顶箱 4 大格位的容量在容器侧配置（内容包 §0），衣物表只报自己占几格；`slots` 总和超容量就是这一格的空间压力，不要在这张表里改数字来"调难度"。

### 8.4 已知坑

- 换行与 BOM：文件是 UTF-8 无 BOM + LF。用 Excel 或记事本另存会带 BOM，`JsonConvert` 会在首个字符处报 `Unexpected character`；提交前跑一次 `check_garments.py` 就能拦住（脚本第一项就是查 BOM）。
- 中文不要转 `\uXXXX`：`ensure_ascii` 关掉更利于 diff 与人工校对；Unity 侧按 UTF-8 读即可。
- 压缩包：Steam 构建时 `StreamingAssets` 不压缩是默认行为，别开 LZ4 全量压缩去省那 47KB。
- 三端壳（微信 / 车机）不复用本表的 100 条，各自契约的件数是 3 / 5，读自己的小表。
