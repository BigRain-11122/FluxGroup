## 测试 1 · 表演+运镜（微表情三层 + 缓推）· 本地 H3 480p

- **被测词条**：`performance.micro-expression` + `camera.slow-push-in` + `structure.h3-integrated-multimodal`
- **素材**：mv0001 V7.22e 第 6.0 秒关键帧（女主近景，台灯夜景段）
- **环境**：本地 ComfyUI + H3 i2v 480p int4（`Tools/promptlib_test_h3.py`）
- **产出**：`cph4/fleet/prompt-library/tests/out/p1_perf_pushin.mp4`
  （864×480 / 124 帧 / 5.17s / 24fps / 130s 出片）
- **对照帧**：`tests/out/p1-compare.png`（0.2s / 2.0s / 3.8s 三帧）

### 结果

| 检查项 | 期望 | 实测 | 判 |
|---|---|---|---|
| 人脸一致性 | 同一个人，不崩 | 三帧同一张脸，五官/发型/项链位置一致 | **PASS** |
| 崩坏（多手/多指/文字） | 0 | 无 | **PASS** |
| 推轨（不是变焦） | 缓慢靠近，背景透视变化 | 半身到近景确有推近，幅度偏小 | **PASS（弱）** |
| 微表情三层（渴望→抑制→眨眼泄露） | 三层可读 | **读不出来**：全程低头，只有一次眨眼 | **FAIL** |
| 时长/帧数 | 5s 级 | 5.17s / 124 帧 | **PASS** |

### 根因（重要）

提交时本地 lint 报 **14 条**，两条致命：

1. `[LEN-I2V] 196 words (>90 i2v budget)` —— 提示词**超预算一倍多**。段落一多，模型只抓得住第一句（"slow push-in"），后面的表演描写被稀释。
2. `[NEG] no` × 11 —— 本地 H3 的 lint **不接受 `no xxx` 负向清单**，会判为噪声。官方云端示例里那种二十条 `no extra fingers` 的写法，本地版不吃。

### 结论（已写回词条）

- **本地 i2v 预算：≤90 词**；想写三层表演，必须把三层压缩进一句，不能分三句。
- **本地禁用负向清单**；换成正向约束（"face stays identical, hands stay still, one person only"）。
- 云端与本地不是同一套语感——云端吃长结构，本地吃短句。

## 测试 2 · 同 KF，压到 90 词重跑（本地 H3 480p）

### 结论（已写回词条 verified 字段）

- `structure.h3-integrated-multimodal` → **verified=true**（本地接受该结构，锁脸成立）
- `camera.slow-push-in` → **verified=true**（90 词版本推轨明确可读）
- `performance.micro-expression` → **verified=false**：本地 H3 在 5 秒/480p 下演不出"渴望→抑制→泄露"三层。
  下一步试法：①时长拉到 8-10s；②改成 **ECU 只拍眼与唇**（不给整脸）；③三层压成一动作（"她眨眼时下唇轻颤"）。

### 由此新增的本地写法规矩

1. **≤90 词**（超出即稀释，第一条指令吃掉全部注意力）。
2. **禁 `no xxx`**：本地 lint 判负向为噪声，改用正向描述（same face / one person / hands still）。
3. 表演想读出层次，**必须给特写 + 至少 8 秒**；5 秒内只能承载一个动作。

## 测试 3 · 导演解法：三镜一拍（5s × 3 剪成一条表演）

**思路**：一条 5 秒长镜演不出"渴望→抑制→泄露"（测试 1/2 已证），那就把表演交给**剪辑**——
三镜各演一个拍子，观众自己补完情绪链。这也是低预算片子的标准解法。

| 镜 | 拍子 | 提示词要点 | 实测 |
|---|---|---|---|
| S1 眼 | **反应**：有人在画外叩玻璃，她抬眼 | locked 85mm + 画外触发 + 瞳孔/下眼睑 + 一次慢眨眼 | **读出**：低头→抬眼看→落回，能读到"注意到" |
| S2 手 | **接触**：指尖按上冷玻璃、下滑、留印、呼气起雾 | locked 85mm + 接触 + 物理证据（印子/起雾） | **强**：手贴上玻璃并下滑，印子可见 |
| S3 唇 | **抑制与泄露**：抿唇、吞咽、下颌轻颤、张唇呼气 | locked 85mm + 抑制 + 微泄露 | 仍在渲染（本地单条 10 分钟+，异常慢） |

- S1：`tests/out/p3_three_shot/S1_ecu_eyes.mp4`（对照 `s1-compare.png`）
- S2：`tests/out/p3_three_shot/S2_ecu_fingertip.mp4`（对照 `s2-compare.png`）
- 已剪：`tests/out/p3_performance_cut.mp4`（10.33s，S1+S2）

### 三条硬发现（已写进词条）

1. **源帧决定景别上限**：源图是胸像，提示词要"极特写"，模型只回落到中近景。
   想做 ECU，必须先有一张 ECU 源帧——这条以前没人写，白试了三轮。
2. **物理触发 > 抽象情绪**：写"她注意到"演不出来；写"画外有人叩玻璃，她抬眼"就有了。
3. **一镜一拍**：5 秒只够一个动作 + 一个反应；三层必须拆三镜，靠剪辑连接。

### 结论

- 新增词条 `directing.low-budget-performance`（verified=true）与 `camera.source-frame-ceiling`（verified=true），存 `seeds/directing-v1.jsonl`。
- 现条件下的最优表演配方 = **锁定机位 + 局部细节 + 物理触发 + 一镜一拍 + 剪辑连接**。

### S3 补记（2026-11-05 21:4x）

第一次跑 S3（"抿唇+吞咽+下颌颤+张唇"四件事塞一句）**23 分钟没出片**，GPU 满载 11.7/12.3GB。
处置：①掐客户端进程；②`POST /interrupt` 无效（队列仍 running=1）；③**重启 ComfyUI** 清队列与显存；
④把提示词压到 **22 词、只留一个事件**（抿唇→吞咽→呼气，去掉"下颌颤"）。

重跑结果：**300 秒出片**，动作读出（抿唇、低头、抬眼），三镜剪成 **15.5 秒**表演段：
`tests/out/p3_performance_cut.mp4`

### 由此新增的操作规矩（本地 H3）

1. **一条提示词只许一个事件**。四件事塞一句 → 采样时间暴涨且动作互相抵消。
2. **单条 >10 分钟 = 异常**，标准时长 130–300 秒；超时先查显存与队列，不要干等。
3. **`/interrupt` 不一定生效**：队列 `running` 不清就重启 ComfyUI，重启是干净解。
4. 重启后第一条会慢些（加载模型），从第二条恢复正常。
