# 竞品拆解方法论 v1（RECON-METHOD）

> 配套：`CHARTER-v1.md`（边界与红线）、`Tools/recon/drama_recon.py`、`Tools/recon/apk_recon.py`
> 原则：**先量化，后解读**。任何"节奏好/上头"的判断，必须能落到本文件定义的某个指标上。

## 零、抄什么 / 不抄什么（CEO 已授权"抄"，此处定义可抄边界）

| 层 | 判定 | 说明 |
|---|---|---|
| 结构层（集数、钩子位置、反转间隔、关卡节奏、数值曲线） | ✅ 可抄可复刻 | 这是"骨架"，法律与工艺上都站得住 |
| 手法层（镜头语言、字幕样式、音效点位、UI 布局范式） | ✅ 可抄 | 表达手法不专有；避免逐帧复制 |
| 参数层（按钮尺寸、动效时长、包体预算、加载时长） | ✅ 可抄 | 直接进我方规格表 |
| 资产层（美术、音乐、字体、剧本原文、代码） | ❌ 禁 | 侵权高风险，且会让产品"像别人" |
| 标识层（角色形象、品牌、专有名词） | ❌ 禁 | 商标/形象权 |

## 一、内容拆解组（短剧 / 漫剧）

### 1.1 取源
- 通道：YouTube 公开短剧/漫剧频道（免登录，`yt-dlp` 可下）；公开的官方预告/花絮亦可。
- 命令：`yt-dlp -f "bv*[height<=480]+ba/b[height<=480]" --write-info-json -o "media/recon/raw/%(id)s_%(title).60s.%(ext)s" <url>`
- 记录：标题、时长、发布日、播放/点赞、频道、是否 AI 生成、平台来源。

### 1.2 九个量化面

| # | 面 | 指标 | 工具/做法 |
|---|---|---|---|
| C1 | 题材与人设 | 身份反差类型、爽点类型、关系链（几人几角） | 人工标注（前 5 分钟） |
| C2 | 开场钩子 | 冲突建立时间（秒）、首句台词、首个反转时间 | 转写 + 时间戳 |
| C3 | 集结构 | 单集时长、集数、每集末钩类型、付费点位置（若有） | 章节/转写分段 |
| C4 | 节奏 | 镜头时长中位数/P90、对白密度（字/分钟）、静场占比 | `drama_recon.py` 场景切分 |
| C5 | 反转节拍 | 反转次数、间隔分布、铺垫-爆点距离 | 人工 + 转写对齐 |
| C6 | 台词模板 | 高频句式（打脸/质问/宣言）、金句位置 | 转写 + 词频 |
| C7 | 镜头语言 | 景别分布（特写/中景/全景）、机位、运镜次数 | 抽帧 + 人工 |
| C8 | 包装 | 字幕字号/位置/描边、花字、封面帧、片头时长 | 抽帧测量（像素） |
| C9 | 声音 | BGM 段落、音效点位、响度 LUFS | `ffmpeg loudnorm` + 波形 |

### 1.3 最小可用产出（一张卡的格式）

```
对象：<剧名>｜来源：<URL>｜时长：<mm:ss>｜类型：真人/AI漫剧
C2 钩子：第 X 秒出现"<冲突>"，首句台词"…"
C3 结构：共 N 集/单集 X 分；集末钩=悬念/反转/威胁；付费点=第 N 集末
C4 节奏：镜头中位 X.Xs（P90 X.Xs），对白 X 字/分，静场 X%
C5 反转：共 N 次，间隔 X-X 分钟；第 1 次在第 X 分（黄金 90 秒内/外）
C6 台词：高频模板 3 条（原文引用 ≤20 字/条）
C9 声音：BGM 段落 X 处，音效 X 处/分钟，整体响度 X LUFS
AI 痕迹（若 AI）：口型/手部/一致性/背景文字 四类问题计数
可抄结论：3 条参数级建议（写明用在哪条产线）
不可抄/风险：1 条
```

### 1.4 AI 漫剧专项检查（我们重点）
- 人物一致性：同角色跨镜脸相似度（人工 5 级）与换装/换角度失败率。
- 口型：是否对嘴、是否用"侧脸/遮嘴/画外音"规避。
- 手部与道具：每 10 分钟可见错误数。
- 背景文字：是否出现乱码/伪文字（AI 特征）。
- 镜头运动：是否 i2v 常见"匀速漂移"，还是做了变速/切点设计。
- 音频：是否 AI 配音（音色重复、韵律平），口型与配音是否同一轨。

## 二、游戏拆解组（小游戏）

### 2.1 取源（合规优先）
1. **公开 APK**（应用宝/豌豆荚/APKPure/TapTap 有安卓版的款）——用于包体与 UI 结构分析。
2. **GitHub 高星开源复刻/同类实现**——用于工程实现与性能参考（承"先找现成轮子"律）。
3. **公开录屏/官方演示**——用于核心循环与商业化点位（无法拿包时）。
4. 不碰：微信 `.wxapkg` 解密、付费包、需要登录态的私有分发。

### 2.2 九个量化面

| # | 面 | 指标 | 做法 |
|---|---|---|---|
| G1 | 包体 | 总大小、`lib/` 占比、`assets/` 占比、首包/分包、纹理格式 | `apk_recon.py`（zip 结构 + 体积归因） |
| G2 | 引擎 | Unity(il2cpp/mono)/Cocos/Laya/Egret/自研 H5；引擎版本线索 | 特征文件（`libunity.so`、`libil2cpp.so`、`cocos2djs`、`*.wasm`） |
| G3 | 资源 | 图集数量与单图尺寸、音频格式与码率、字体、Spine/龙骨 | 解包目录统计 |
| G4 | UI | 画布基准分辨率、适配策略、按钮最小热区、字号档位、动效时长 | 截图测量 + 资源命名 |
| G5 | 核心循环 | 30 秒 / 3 分钟 / 30 分钟三层动作与反馈 | 录屏 + 试玩/拆包逻辑 |
| G6 | 数值 | 开局资源、产出/消耗比、难度拐点、失败惩罚 | 试玩记录表 |
| G7 | 商业化 | IAA/IAP 结构、激励视频点位与频次、插屏间隔、首充设计 | 试玩 + 权限/SDK 扫描 |
| G8 | 留存钩 | 签到、任务、排行榜、皮肤、离线收益、社交裂变 | 功能清单 |
| G9 | 性能 | 冷启动时长、内存峰值、安装后体积、帧率档位 | `adb` 实测（有设备时） |

### 2.3 最小可用产出

```
对象：<游戏名>｜平台：微信/抖音/安卓｜包体：X MB（lib X%/assets X%）
G2 引擎：Unity 20XX + il2cpp；纹理 ASTC/ETC2；音频 OGG
G4 UI：基准 750x1334 竖屏；主按钮 ≥88px 高；主色 #XXXXXX；点击动效 0.15s
G5 循环：30s=点击产出→升级；3min=过关→开箱；30min=看广告翻倍→冲榜
G6 数值：首关 45s；第 10 关难度拐点 +X%；离线收益上限 X 小时
G7 商业化：激励视频 4 处（复活/翻倍/免费领/加速），插屏每 X 关 1 次
G8 留存：7 日签到 + 每日 3 任务 + 周榜
可抄结论：3 条（用在哪款）
不可抄/风险：1 条
```

## 四、质量闸（缺一不算交付）

1. 每条量化结论附**测量方法**（脚本名/命令），可复跑。
2. 视频类结论必须基于**全片**，禁止只看前 3 分钟。
3. 游戏类包体结论必须有**体积归因表**，不能只写总大小。
4. 每张卡必须有"可抄 3 条 / 不可抄 1 条"，否则退回。
5. 样本与卡片对得上号（文件名含 ID），禁止无源结论。
