# 多平台训练与人群风格排布 v1

> CEO 2026-11-23：「各大平台的训练和用户群行为、风格理解等，要科学排布」。
> 本件定的是**排布**：哪个平台什么时候训、训什么、拿什么判、什么情况不许训。

## 一、三条排布原则（先给理由，再给表）

### 原则 1：共享骨架，平台专属外壳
| 层 | 归属 | 现状 |
|---|---|---|
| 基座模型（qwen3.5-4b-4bit）、训练/评测流水线、五维质量框架、判词功率（n≥30）、拟人节律 | **共享** | 已具备 |
| 语料池、人群分段表、判据阈值、金标评测集、LoRA 适配器 | **平台专属** | B站已有，其余缺 |

理由：平台语体差异是结构性的（B站中位 **10 字**、78% 不写句号、48% 带表情；知乎是长逻辑；小红书是 emoji+种草），
**混训会把风格拉平**——已有实锚：「共用弹幕模板＝一个人开两个号的最大破绽」「亲笔样句只进 acct1 提示词、不进共享语料，否则新号被训成老号口吻」。

### 原则 2：单卡只做时间片，一周一个主平台
本机只有一块 GPU。**训练与出稿叠跑实测 25.7 → 2.1 tok/s（12 倍）**，所以不是"并行"，是"轮换"。
非主平台这一周只做**采集**（走 CPU/网络），不占训练档。

### 原则 3：进训练要过三道门
1. 自有语料 ≥ **2000 行**（`use=train`）
2. 该平台**段表齐全**且每段 ≥60 行（低于 60 的段只采不训——实测 beginner 51/student 48/… 这类段训了也是噪声）
3. **金标评测集 ≥30 条**（n<10 结论是噪声，n=10 仍会翻盘：同一权重相隔 20 分钟 79.9 vs 55.9）

## 三、周排布（时间片，按门放行）

| 周 | 主训练平台 | 并行（只采集，CPU） | 验收 |
|---|---|---|---|
| 本周 | **B站**（在跑 music_seeker 段） | — | 本轮跑完 → n≥30 评测出判词 |
| 次周 | 抖音（若接口扩到 ≥2000） | 小红书设备端 D0–D2 | 抖音段表首版 + 金标 30 |
| 第三周 | 小红书（若 ≥2000 且段表齐） | 知乎设备端 | 小红书 emoji/长度带实测 |
| 候补 | 知乎 / 微博 / 公众号 | 按采集进度 | 达门才排 |

**月度节奏**：每平台每月 1–2 轮训练；每轮必须「训练→n≥30 评测→判词入台账」三件齐，缺一件判本轮作废（不许只训不判）。

## 四、平台专属要建什么（清单，不是口号）

1. **段表**：抖音（短、梗密）、小红书（种草/测评/emoji 密度）、知乎（长逻辑分层）、微博（热搜话题）、公众号（留言短评）。每份必须**判据式、不写例句**（写例句＝被逐字照抄）。
2. **判据阈值**：`SEG_TUNE` 按平台一份——同一把尺子量跨平台必然误杀（玩梗/浅层本就该 6–12 字无主干）。
3. **金标集**：每平台 30 条「给了上下文就能答」的题，自带证据；测的是照做与拒答，不考它认不认识我们的项目。
4. **适配器**：一平台一件 LoRA，同平台不并存两件（否则判词归属不清）。

## 五、判词纪律（跨平台统一，不许各自发明）

1. **n≥30 或三次取中位**；板上一律标 n。
2. **PASS 率 + 均分一起看**：只看 PASS 会选错点（实测 iter100 76.8 vs iter300 72.5，末点更差）。
3. **分段判据**：每段单独判，禁止用总均分掩盖某段退化（实测 beginner -22.6、tech_nerd -14.4 被总均分盖住）。
4. **判词必须落台账**，含 why/next/landed（`evolve_audit` 的 EV01）。

## 六、P0 数据契约（当前技术债，必须先补）

**问题**：现有语料字段是 `id/author/text/thread/ts`——**没有 platform/kind**。多平台一旦接线，语料会混成一锅，分平台训练与分平台评测都做不了。

**要求**：所有采集出口必带 `platform`（bilibili/xiaohongshu/zhihu/weibo/douyin/wechat）与 `kind`（comment/danmaku/article/note），并保留 `evidence`（ui.xml 或接口原始响应）。
**验收**：
```bash
# 每行都必须有这两个字段，且平台取值在枚举内
python3 - <<'PY'
import json,glob
OK={"bilibili","xiaohongshu","zhihu","weibo","douyin","wechat"}
bad=0;n=0
for f in glob.glob("cph4/fleet/social/raw/*.jsonl"):
    for ln in open(f,encoding="utf-8"):
        n+=1
        try: r=json.loads(ln)
        except Exception: bad+=1; continue
        if r.get("platform") not in OK or not r.get("kind"): bad+=1
print(f"行 {n} 不合规 {bad}")
PY
```
存量 B站 41k 行进迁移时可批量补 `platform=bilibili,kind=comment|danmaku`（按文件名可判，不需要重采）。

## 七、kill criteria（防止为了"覆盖平台"造空活）

1. 某平台 **7 天语料零增长** → 降到候补，不再排训练档。
2. 段样本 <60 且连续两周补不上 → 该段不训，只做画像。
3. 判词 PASS 率连续两轮低于基座 → 下架该适配器，回到人工抽检。
4. 只有"要覆盖"的想法、没有可用语料的平台，**一律不进排布**（无产物契约不建卡）。
