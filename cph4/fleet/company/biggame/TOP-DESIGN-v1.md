# Biggame · 公司级顶层设计 v1（2026-11-03）

> 顺序位 #3。理由：最接近能卖（吸嘟嘟已有可构建包），差的是四道产品闸。
> 认知基座已在 `cph4/fleet/ri/game/CANON-v1.md`（市场/铁律/判据/失效条件），本件不复制，只答公司级 8 问。

## 1. 卖什么

轻量 2D 家庭小游戏：单局 60–90 秒、无失败态、无广告，付费点是"本局生成的家庭明信片"。
另有一条 B 端形态：车机家庭游戏可演示包（吸嘟嘟），只做演示，不进量产。

## 2. 谁买

C 端：微信小游戏里的亲子家庭（家长付费 28/58 元买明信片与家庭包）。
B 端：车机 OEM（演示与联合测试）。**商务、账号、版号、软著、ICP 全在 CEO 手上**，本司只出材料与包。

## 3. 第一件产物

`吸嘟嘟V0.10.18`（215MB / 519 文件，Windows 可执行包，2026-11-03 凌晨构建成功）。
但**它还不是可交付物**：四道产品闸（真包实跑 / 首启 30 秒 / 性能档 / 可玩性盲评）一次没跑过。
下一件产物必须是"带四闸回执的包"，不是"又构建了一次的包"。

## 4. 谁判

机器：`game_pack_scan.py`（包在盘且能双击运行）、asset-audit（命名/切图/alpha/导入设置）、
2D 硬约束扫描（无 3D 场景/模型/相机）、单局时长实测（60–90s）、失败态扫描（0 处）。
人判：可玩性盲评（≥3 人，48h 内给结论）；CEO 定是否对外演示。

## 5. 哪台机干

构建与实跑 = Windows 侧（bm-a 或 CEO 工作机）；本机（bm-m）负责出包、质检、素材与文档。
本机看不到 Windows 产物 → 包的证据必须以回执形式回到总控仓，否则等于没有。

## 6. 钱与合规

- 零买量：增长靠内容分发与家长口碑（67% 新增用户来自投放，我们明确不走这条路）。
- 48 包商用 gate 未过前 **不得对外演示**任何 Unity 资产画面。
- 儿童场景四条（AIGC 标识/零真人脸/品牌规避/儿童合规）由 `family_compliance_check.py` 守。
- 定价只许 买断 28 / 家庭包 58 / 皮肤 6–18；禁关卡钥匙、体力、抽卡、广告。

## 7. 停线条件

沿用 CANON §八，加一条公司级：
- 单款 30 天做不出可玩包 → 换题，不延期。
- 开始投流 → 立即停（模式跑偏）。
- 出现失败态或广告打断 → 返工，不谈判。
- **连续 7 天无"带闸回执的产物" → 整条线挂起**（构建次数不算产物）。
