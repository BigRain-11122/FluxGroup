# LOCAL-MODEL-MATRIX v1 — 机队本地模型矩阵与云端兜底线（2026-10-21）

> 令源：CEO 2026-10-21 原话「我希望本地算力之后满负荷运转开展业务，搞不过来的时候在我的额度范围内，你调用云端模型接入，然后你推荐一下本地适配的模型，最好用你 QWEN 最新的」。
> 性质=接管准备件（规划态·装机动作候接管令）。模型版本=2026-10-21 web 实测检索（来源附文末），**装机前必再跑一次新鲜度闸**（BRIEF §二.12 行情/版本类当日源律）。

## 一、选型总原则

1. **全 Qwen 开源系**（Apache-2.0 商用可，红线合规=CC 授权链无风险）；按卡适配，不按"最大最好"。
2. **MoE 优先**：30B-A3B 总参 30.5B 激活仅 3.3B——推理计算量≈32B Dense 的 1/10，这正是消费级卡跑"32B 级能力"的唯一现实路线，也是修旧事故（35B-A3B 全专家 CPU 卸载=398 token 跑 5 分钟）的正解方向：**部分卸载+高主频 RAM**。
3. 每型号上线前先过吞吐 bench（≥20 字/秒才准接产线活），诚实读数入台账——沿 V100-P0「31.6 字/秒 PASS」判例法。

## 三、云端兜底线（额度内·现行 T0 口径继承）

**触发判据（"搞不过来"的可执行定义）**——本地队列积压 >2h 或 本地吞吐 bench 不达标 或 该能力本地无模型位，三选一才升云，且每次留痕（谁批/为什么/花了多少）：

| 场景 | 云端接入（千问系 API） | 备注 |
|---|---|---|
| 深判/架构裁决/复杂推理 | Qwen3.5-Plus / Qwen-Max 级 | 现行"本地先试硬前置"律保留：30B-A3B 产出+自评分不够才升 |
| 长上下文 >32K 单请求 | Qwen-Long 级 | bm-a 旧病（71K token 撑爆 16K ctx）的合法出口 |
| 多模态重判读 | Qwen-VL-Max | bm-d VL 卡排满时的溢出位 |
| 视频/图像生成（TJGenerators 族） | 按波≤8·逐案 | 生成面仍默认本地 bm-c/bm-d，例外=CEO 亲批流程不变 |

**并发帽维持**：全队云端并行 <8（每机 ≤2）。**"在我的额度范围内"执行面**=云端调用走千问积分计费，席每月对账一次消耗入 SLI-8 线（周趋势可见）。

## 五、装机顺序（接管令后执行·先易后难）

1. bm-a：llama.cpp/ollama 装 Qwen3-30B-A3B Q4_K_M（ModelScope 镜像源=国内直连快）→ 部分卸载调参 → 吞吐 bench（目标 ≥20 字/秒·如实报）→ :8091 起服务。**旧 35B-A3B 端点直接换掉**（qwen3.6-35b-a3b 为旧代口径）。
2. bm-b：Qwen3-8B-Q4 全驻，替换 qwen2.5:7b 位（bili-ops 提示词随 v3 定稿重校）。
3. bm-c：Qwen-Image-2.1-Turbo 试烧（POOL-0021 卡位=此件，与既有开卡合流）。
4. bm-d（到位后）：vLLM 版本兼容性预研（V100 compute 7.0 支持矩阵）→ 双实例 GPTQ 部署 → VL-30B 卡3 → 吞吐+判图双 bench。
5. 全机：模型登记进 resource-chain §9.1 车道表 + 本件版本注记（每周保鲜审）。
