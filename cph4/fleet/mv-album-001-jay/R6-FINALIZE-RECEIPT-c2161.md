## 二、R6-1 落地参数（已试三版择优）

```
eq=saturation=0.18:contrast=0.98:brightness=0.015,
colorbalance=rs=0.10:gs=0.03:bs=-0.10,gblur=sigma=0.7
```

- 窗口：64.000–70.080s。
- **否决了 R6 原写法的 `unsharp=...:0.6`**：`unsharp` 正参数量是「锐化」，与 R6 要的「轻虚化」方向相反（实测板 `BFLY-VARIANTS-c2161.jpg` 第 4 格边缘更硬）。改 `gblur=sigma=0.7`。
- **否决了纯灰阶（sat 0.16 无染色）**：全片主调是暖金，灰阶插段会读成「另一条调色链」，违「全片单一视觉语言」。改暖染（`colorbalance` 提 R 压 B），板对比见 `BFLY-WARM-VS-GREY-c2161.jpg` 中格 vs 右格。
- 验收帧：66.0 / 67.0 / 69.0s 原生帧——翼面花纹不可辨、动作保留。

## 三、R6-3 落地参数

```
# 第一遍 172.000-179.000 原样
# 第二遍 179.000-186.000 推近 1.34 倍后再统一调
crop=1003:573:170:97,scale=1344:768:flags=lanczos
eq=brightness=0.0118:contrast=1.02:saturation=0.98,noise=alls=6:allf=t+u
```

- **复读判定必须在原片帧序列上切片统计**：把窗口切出来再重编码会因 x264 相邻帧预测差异把「逐帧同哈希」抹平（本轮首测误得 dup=2，正解=全片 framemd5 取 4128–4464 帧，得 **81**）。
- **亮度是自校准出来的，不是抄的**：punch-in 裁掉了画面边缘的亮部，窗口均值自己掉了 2.7 code（39.88 → 37.15）。脚本按整码步迭代（8-bit `eq` 的 brightness 量化到整 code，<1/255 的增量静默无效——0.0039/0.0078 两档实测输出完全不变），到 0.0118 落地 +3 code → 40.14。
- 帧数守恒：两遍各 7.000s × 24fps，合计 336 帧，与源窗一致，**时间轴零位移**。
