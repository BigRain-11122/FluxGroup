# 视频生成路由律 v1 · 本地优先（2026-11-25 CEO 令）

> CEO 原话：「本地烧视频的能力不是有吗？以后优先本地，实在不行再上云」
> 效力：**覆盖 2026-10-09「云端视频解禁令=正式镜头主力上云」**。那条作废。
> 适用范围：MV / 漫剧 / 短剧 / 短视频，一切**图生视频、文生视频**生成。

## 一、默认路径（不经批准，直接走）

```
本地 ComfyUI :8189  →  wf_h3_i2v_768p_int8.json  →  MiniMax-H3 (fl2va, int8)
                    1344×768 · 24fps · 107帧(4.46s) 或 192帧(8s, 首尾帧)
                    单镜约 650s（10.8 分钟）· 0 积分
```

实测口径（`v2-reburn/progress-bmc.jsonl` 13 个成功样本）：
- 每镜耗时 **362–707s，均值 650s**
- 折算 **146s 算力 / 1s 成片**
- 分辨率 1344×768（768P int8），与云端 768P 同档
- 单卡串行，一个 runner；多批必须**接力**（判例：重复 runner 会把镜头排成串）

## 二、上云白名单（只有这四条，「实在不行」的具体定义）

| # | 条件 | 举例 |
|---|---|---|
| 1 | **本地不可用** | ComfyUI 挂死 / 显存不足且释放无效 / 模型权重缺失 |
| 2 | **本地能力边界外** | 单镜 >15s（H3 训练上限 362 帧）；需 2K+ 分辨率；需真实口型同步 |
| 3 | **死线压过成本** | 有明确交付时点，且本地排队算不完（须写明算式：镜数 × 650s vs 剩余时间） |
| 4 | **CEO 点名** | 明确要求走云端某模型 |

**不构成上云理由**：本地排队久、想快点看、想省电、想并行、模型"可能更好"。

## 三、记账（上云即记）

即使命中白名单，也必须落三样：
1. `attribution`（谁批的、命中哪条白名单）
2. 积分预估（H3 768P ≈ **70 积分/秒**）
3. 回执写入 `cph4/fleet/cloudF-queue-bmc.jsonl`

> 对比口径：一条 4.46s 镜 —— 本地 0 积分 / 10.8 分钟；云端 ≈ 312 积分 / 数分钟。
> **本地慢 10 分钟，省 312 积分**。除非命中第 3 条，否则不换。

## 四、能力边界（写死，防止"以为本地能"）

| 本地能做 | 本地不能做 |
|---|---|
| 1344×768 单镜 4.46s / 8s（首尾帧） | 单镜 >15s（362 帧上限） |
| 首尾帧约束（fl2va，`last_frame` 可选） | 2K / 4K 原生输出（只能后处理放大） |
| 4 步 turbo，int8 量化 | 真实口型同步（有口型先验，提示词层不可治） |
| 串行排队，无人值守 | 多镜并行（单卡，起第二个 runner 会互相排队） |
