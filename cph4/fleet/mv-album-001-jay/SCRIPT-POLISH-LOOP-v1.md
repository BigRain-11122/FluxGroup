# 剧本/分镜持续打磨环 v1（2026-10-20·CEO 令「剧本分镜叙事要不断更新和打磨」）

> 一句话：**剧本不是定稿件，是活件。** 每次生产推进、每条新判例、每次看片反馈，都必须回到剧本/分镜并产生一个可追溯的版本增量。

## 一、五个触发器（任一发生就开一轮打磨）

| 触发 | 动作 | 时限 |
|---|---|---|
| ① 新调研结论落地（官方文档/拉片/受众） | 逐条问：改哪一镜、改成什么 | 当窗 |
| ② KF/i2v 烧出后看到实际问题 | 缺陷回写剧本（不是只在 QC 记一笔） | 24h |
| ③ 装配/看片反馈（含 CEO 一句点评） | 拆成"出生站"级别的修法 | 当窗 |
| ④ 姊妹曲暴露出同型缺陷 | 横向回写其它三曲 | 48h |
| ⑤ 每完成一曲（收口） | 全片复盘：哪三处最好、哪三处最弱、下一曲怎么改 | 收口时 |

## 二、版本规则（防"改了但没人知道"）

- **版本号只增不减**：`剧本 v3 → v3.1 → v3.2`；分镜同类（`v2.5 → v2.6`）。
- 每个增量**必须写清四件事**：改了什么 / 为什么改 / 依据（调研或实测）/ 影响面（哪几镜、要不要重烧）。
- **禁静默改写**：改了不记录=违例；记录在 `SCRIPT-REVISION-LEDGER.md`。
- 分镜以**状态机脚本为正身**（`*-shots-v2.py`），md 是衍生物；改 md 不改 py = 无效改动。

## 三、打磨的两种，别搞混

| 类型 | 允许 | 判据 |
|---|---|---|
| **增量打磨** | 加物证、加动作、改时序、改光句、改镜长 | 场次结构与立意不变 |
| **结构改版** | 换叙事结构、删场、换立意 | 必须写明"为什么旧结构不成立" + 导演席签 |

**默认只做增量。** 推翻结构=要证据，不是灵感。

## 四、每轮打磨的固定动作（四步）

1. **读三家**：剧本 → 分镜状态机 → QC 对应节（不许只看剧本改剧本）。
2. **列三条**：这轮最多改三处，改多了等于没改（观众感知不到，生产也验不出来）。
3. **写落点**：每处写"哪一镜/哪一拍/哪一句词"，不写"整体提升氛围"这种空话。
4. **记账**：写进 LEDGER，标注是否需要重烧/重签。

## 五、与生产的关系（不互相卡）

- **在产件不回改**：已烧/已装配的镜，改动进"下一版候选清单"，不阻塞当前出片。
- **未烧件优先改**：KF 未烧、i2v 未烧的镜，改完直接生效。
- **改 prompt 需重签**：KF 包改动一律走导演席重签（`KF-PACK v1.x`）；i2v 包随批重出。

## 六、节奏

- 每曲至少 **3 轮**增量打磨：开工前（立意/结构）、首批烧制后（实测修正）、装配前（节奏与可读性）。
- 每周一次横向对齐：四曲互看，把 A 曲的毛病提前打到 B 曲上。
