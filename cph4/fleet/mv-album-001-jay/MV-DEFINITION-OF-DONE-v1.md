# MV 定版判据 v1（Definition of Done）· 2026-11-05

> 立此件缘由：mv0001《爱在西元前》从 10-08 到今天一个月，走了 v5.6→v5.8→v5.10→v5.11→v7.08→v7.13→v7.17→v7.18→v7.19→v7.20→v7.21 十余版仍未定版。
> CEO 追问「到底有没有建立正确的机制」——本件回答：此前**没有**，现在补上。
> 适用范围：41 曲全产线（不只 mv0001）。

## 一、为什么一个月定不下来（结构性缺陷，不是执行不力）

1. **没有定版定义**：什么算「完成」从未写成可判定条件，于是每轮都是「再改一点」，改完又发现新的。
2. **闸只查技术、不查创作契约**：交付闸查重复镜/静止/闪烁，**没有一条断言**检查调色双基准、镜长、字幕规格。
   实证：V7.21 机器面全绿（dup 0 / static 0 / seams 0），但同时「全片一个暖调」——闸看不见。
3. **改片与签片同一席**：导演席既改又签，等于自审自签，问题自然反复。
4. **CEO 的批评没有变成断言**：10-19 的邝盛方案、10-24 的转场红线都落了文档，但没有一条落进机器判据，所以下一版照错。
5. **版本号不表达收敛**：修复轮也算新版本，十余个版本号里没有一次「过判据」的语义，看着像一直在动，其实没有向定版靠。
6. **最后一公里无人认领**：V7.19-V7.21 出了片、过了闸，卡在「没人签」三天。

## 二、定版定义（六条，全绿才叫定版）

> 每条都给判据与判定方式；G1-G4 机器判，G5-G6 人判但必须留证据文件。

| 门 | 判据 | 判定方式 |
|---|---|---|
| **G1 结构** | 帧数/时长/镜数断言成立；接缝 0、闪烁 0、死停 0（≥0.25s） | `Tools/mv_delivery_gate.py` |
| **G2 重复/静止** | 未申报重复镜 0；近静止镜 0（fps 归一后）；设计复现全部在白名单 | 同上（带 `--whitelist` + canon 卡窗） |
| **G3 转场语法** | OPPOSE=0；硬切 ≥4 类；无白闪/放大/抖动/贴纸；叠化 ≤3 次 | `Tools/mv_transition_audit.py` |
| **G4 创作契约（新增·此前的空白）** | ① **调色三层**：现代博物馆/阅读段 R−B ≤ +5 且饱和 ≤ 基线 80%；台灯夜景段（INT*）色相按物理正确保留、只要求饱和 ≤ 基线 85%；古代段 R−B ≥ +15。② **镜长**：主歌段 ≤3.4s。③ **字幕**：字块 bbox 不与人脸框/主体框重叠，字号与安全区合 TYPOGRAPHY-SPEC。 | `Tools/mv_contract_check.py`（已建，G4①②；③待建） |
| **G5 导演盲审** | 联系表全片逐格过 + 三律（高级/去俗/去 AI 感）逐条留证；自己挑不出毛病 | `canon/DIRECTOR-REVIEW-<版本>.md`，**须与改片席不同人** |
| **G6 交付就绪** | 成片地址 + 平台声明位清单 + 片尾出处卡 + 母版/代理档齐 | `PUBLISH-PACK-<版本>.md` |

## 三、版本号收敛规则

1. 未过 G1-G4 的改动一律叫**修复轮**，不升版本号（记 R1/R2/R3）。
2. 过 G1-G6 才 +1 版本，且该版本冻结。
3. 定版后只接受被点名的问题；**禁顺手优化**（反反复复的主要来源）。

## 四、分权

- 改片席（剪辑/调色/装配）与签片席（导演）**不得同一人**。
- 主控只负责：发卡、监督、裁决；不亲自改片。
- 同一缺陷**二犯即停线**复盘，写进本节即为过失留档。

## 五、CEO 批评 → 断言的转化规则

每收到一条 CEO 批评，24 小时内必须落成一条**可执行断言**（进 G1-G4 任一门的脚本），
否则视为未闭环。断言须自带正反样例（应通过/应拒绝各一）。

## 八、回归守护（防"做对的能力被下一次重构丢掉"）

1. 建立 `canon/REGRESSION-LEDGER.json`：每条已修能力 = 一条断言 + 一个样例 + 首次修复日期。
2. **任何重建前先跑 ledger，全绿才开工**；重建后复跑，绿了才算完成。
3. 首批必须登记的（都是这个月真丢过或真修过的）：
   - 古今分色：现代段 R−B ≤ +5（10-24 修好 → 11-02 丢失）
   - 重复镜白名单：未申报 = 0
   - 帧数断言 5623 / 时长 234.29s±0.05
   - 接缝 0 / 闪烁 0 / 死停 ≥0.25s = 0
   - D4 火光判例（最暗角判别式）

## 九、卡与看板（自动化，不靠人盯）

1. 每段一张卡，卡模板**单一源**（`ri/content/lines/*.json`），卡面参数带全（如 `--whitelist`、全部 canon 卡窗）。
2. 同一卡同参数**连续 3 次确定性 FAIL → 自动停派**并转 NEED-JUDGMENT，禁无限重试（本月实证：每天 3 次×370s 全白跑）。
3. 看板只显示三样：产物 mtime、闸 verdict、停滞小时数；**超 24h 标红，超 48h 升级**。
4. 卡的回执必须落盘（`deliverable_exists` 为真），否则视为未跑。

## 十、十条铁律（每条都可检查）

1. **重建优于补丁**：成片上打补丁一律不批（10-23 已实证制造 20 处碎片）。
2. **先归因再动手**：说不清是"看不清"还是"做错了"就不许重烧。
3. **批评 24h 变断言**，否则算未闭环。
4. **新判据必过正反样例**（应通过/应拒绝各一）。
5. **阈值只在一处**：要改数就改这一份，禁止别处另立。
6. **重建前跑回归**，绿了才开工。
7. **改签不同席**。
8. **版本号只表达收敛**，修复轮不升版本。
9. **同病二犯停线**复盘，记过失。
10. **出片 6h 内必须有人签或升级**，不许出了片没人管。

## 十一、不停顿守则（No-Stall·CEO 2026-11-05「不签也不能停顿」）

> 病根：把"质量门"和"推进"绑在一起，于是"没过门"就变成"停住等"。3 天没改善就是这么来的。
> 正解：**门只决定能不能发布，不决定能不能继续做。**

1. **门是发布门，不是工作门**：G1-G4 任何一门 FAIL，同一班内必须自动产出下一张修复卡并开工；FAIL 而不出卡 = 停摆，按事故计。
2. **时间盒**：每轮修复 ≤6 小时；到点必出新版本，绿不绿都出（记 R1/R2/R3…）。禁止"等改到完美再出片"。
3. **并行线程**：同时至少两条互不阻塞的修复线（调色 / 字幕与剪辑 / 重复镜与微停），一条卡住不拖另一条。
4. **收敛判据**：每轮缺陷数必须单调下降；连续两轮不降 = 方法错，停手换法，不许硬磨。
5. **接受阈值**：定版允许携带 ≤3 项非阻断缺陷（写进 `KNOWN-GAPS.md` 随片公开），否则永远定不了版；阻断级（结构/重复/卡顿/明显穿帮）一律不可携带。
6. **单段标定优先**：参数类修改先在 1-2 个镜段上验（约整片成本 1/30），验准了再一次整片重建；禁"改一次整片重烧一次"。
7. **签核不阻塞生产**：未签版本照常进入下一轮；签核只影响"能否对外发布"。
8. **看板口径**：只显示「当前版本 / 缺陷数趋势 / 下一版 ETA」，不出现"等签核"。
