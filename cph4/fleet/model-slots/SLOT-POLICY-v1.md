# 机队模型槽位策略 v1（SLOT-POLICY）

> **立据（CEO 令 2026-10-27）**：「委员会牵头，联合实验室，把机队每个机器的大模型都要针对本机配置做完美的适配，不断打磨工作流和任务负载，并不断迭代更新，不要只理规则不干活 要实际产出」
> 牵头：决策委员会 T1；技术承接：CPH4 Labs（联合实验室）；执行：各机位

## 一、原则（四条，别的不写）

1. **先量后配**：任何模型入册必须有本机实测三数——生成速率（tok/s）、驻留显存（MB）、首载时间。看排行榜不认。
2. **槽位互斥**：文本 / 图像 / 音频 三条重载车道**互斥占用显存**，靠 profile 切换，不靠"应该能挤下"。
3. **禁默认常驻大模型**：14B 级别在 8G 机上 4.4 tok/s、占 7.9GB，只能离线批量用完即卸（keep_alive ≤10m），禁当常驻件。
4. **让路优先**：CEO 用机/他机重活时切 `idle`（这是既有让路律的模型面延伸，不是新令）。

## 二、标准 profile 集（全机队同名，便于调度席程序化调用）

| Profile | 语义 | 谁可调用 |
|---|---|---|
| `text-fast` | 交互式文本（本机最优质量/速度档） | 循环班/哨兵/在线回复 |
| `text-quality` | 大模型离线批量（慢、独占） | 批处理作业 |
| `image` | 图像车道（卸文本→ComfyUI/SD） | KF/素材批 |
| `audio` | 音频车道（卸文本→TTS/声线） | 配音批 |
| `idle` | 全卸留桌面基线 | 让路/保底/交接 |

**调度纪律**：批开始前切 profile、批结束回 `idle` 或上一 profile；**跨机作业不得假设对端槽位状态**，派工单必须写明期望 profile。

## 三、预检闸（每次切换都跑，不许人工判断）

- 允许加载条件：`空闲显存 ≥ 模型驻留 + 1.0GB`；不满足=拒绝并报告，不许"先跑跑看"。
- 加载后校验：`实际占用 ≤ 卡容量 98%`；超 95% 打 WARN（将发生 CPU 卸载，速率掉一个数量级）。
- 卸载校验：`回落到桌面基线 ±200MB`（本机基线须记录在机位档案里；基线异常升高=有残进程，先查再动）。

## 四、每机必交件（MACHINE-PROFILE-<机位>.md）

模板要素（缺一不算交件）：
1. 硬件：CPU/核数/RAM/GPU 型号+显存+驱动+功耗墙；
2. 显存底数：空载基线 / 各常驻模型实测占用；
3. 模型实测表：模型 · 首载 · tok/s · 驻留显存 · 一句话结论；
4. 槽位表：本机实际可用的 profile 及显存需求；
5. 任务→槽位映射：本机跑哪些活、用哪个槽、为什么；
6. 迭代记录：最近一次实测日期与变化（速率变化 >20% 必须复测并改档案）。

## 五、迭代机制（这是"不断打磨"的落点）

- **周度复测**：各机每周一跑 `Tools/model_slot_bench.py --weekly`（S4U 任务，静默链），覆盖 `bench-<机位>.json`；速率漂移 >20% → 触发档案更新 + 槽位重议。
- **任务负载打磨**：每月一次「任务→槽位」复核——把跑了整月还在 `text-quality` 上做的交互型任务挪回 `text-fast`，把永远跑在 `text-fast` 上的批量任务挪去 `text-quality`。
- **入册门槛**：新模型必须带**本机实测 + 一个真实任务的 A/B 结果**（例：同一批 10 条评论，过闸率/时延对比），否则不入册。
- **台账**：`cph4/fleet/model-slots/LEDGER.md` 追加行（日期/机位/变更/前后数字），只增不改。
