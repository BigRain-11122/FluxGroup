# 机器自驱契约 v3（AUTONOMY-V3）· 2026-11-11

> 令源：CEO 2026-11-11「机 队机器要有完全的自驱力，而不是什么都等主控，主控只是搜集了解和分发，还有模型赋能，机器没活自己找，自己全链路解决，自己搞定一切」。
> 执行体=`Tools/fleet/station_drive.py`（自检 11/11）；能力口径=`TAXONOMY-v1.json`；分片=`Tools/fleet/station_shards.py`。
> 旧机制（主控造卡→supply_batch→各机 claim）降级为**兜底通道**，不再是主路径。

## 一、一句话

**机器自己找活、自己干完、自己验、自己记账；主控只做四件事：搜集、了解、分发、模型赋能。**

## 二、六步循环（每台机独立跑，不需要人点）

1. **SENSE**：读自己的领域——`TAXONOMY` 里以本工位为承接方的工序，逐个看产物在不在、过没过保质期（`refresh_h`）。
2. **SUPPLY**：缺就自己建卡写进自己的分片。卡必带 `product_id + stage + task_type`；同一工序同一天只建一次；已有未结卡就不重复建。
3. **CLAIM**：自己领，自己写 `owner/claimed_at`。没有"等派单"这一步。
4. **RUN**：跑卡上的 `cmd`，日志与 `_run.json` 落在 `cph4/fleet/out/<产品>/<工序>/`。
5. **VERIFY**：按 `judge` 自验。确定性判据（path/hash/drama_rules/voice_gate/family_check/game_submit_pack）过了才判 `DONE`；`manual/human` 一律 `PENDING_HUMAN`，不许自封。
6. **RECORD + HANDOFF**：写回执（含 sha256、字节数、耗时、判据结论），并把下一道工序需要的东西**直接写进目标工位分片**——跨机交接不过主控。

## 三、只有三件事找主控

1. **要模型**：找**算力大脑**（机队本地模型中心，端点见 `MODEL-COMPUTE.json`，order=1）；它不可用时才退到主控 2B/4B 轻量档；都不行就退化为规则结论，不停工。
2. **跨机目标不在线**：写 `BLOCKED` + 原因，并通知（不自己改别人的卡状态）。
3. **对外 / 花钱 / 不可逆**：发布、发送、注册、下单、备案，一律停手报 CEO——这条永久有效。

## 四、主控的新职责（收窄，不是消失）

1. **搜集**：读五份分片与回执，汇总"谁在干什么、卡在哪"。
2. **了解**：一屏 + 度量（产出年龄、返工率、缺口）。
3. **分发**：只处理跨机依赖与无主工序（没有任何工位承接的任务类型）。
4. **模型赋能（轻量）**：只在算力大脑不可用时提供 2B/4B 兜底；批量生成与长文本一律走算力大脑，不许压在主控。
5. **异常裁决**：同一错误两次以上、判据冲突、红线问题。
6. **不再做的事**：给每台机造具体卡、替机器决定今天干什么。

## 五、边界（硬，违反即事故）

1. **不对外**：不登录、不发送、不发布、不注册、不代 CEO 说话。
2. **不自封人判**：人判型停在 `PENDING_HUMAN`；没写判据的卡不许判 `DONE`（自检里就是这一条）。
3. **不造活**：产物路径没契约（`PRODUCTS.outputs` 没写）的工序，只报 `UNKNOWN-OUTPUT`，不建卡。
4. **不假跑**：卡没有 `cmd` 时判 `NEED-CMD`，不写"已完成"。
5. **不改别人的分片**：跨机只做 handoff 追加。

## 六、"自己找活"的顺序（没活时按这个找，不许空转）

1. 自己领域里**产物缺失**的工序（最高优先）。
2. 自己领域里**过了保质期**的周期产物（数据/草稿/报告/索引/复盘）。
3. 上游交给自己的交接单（`HO-` 开头）。
4. 自己能力内的**资产补库**（音色/图标/索引进新）——必须落产物，不许以"我检查过了"交差。
5. 以上都没有：写一条 `NO-WORK` 记时，不假装忙。

## 七、现状（2026-11-11 实测，不夸大）

- 自检 **11/11**：缺产物建卡、不重复建、新鲜不建、过期重建、path 判据 DONE、人判 PENDING_HUMAN、无判据不许自证、产物缺失 FAILED、无 cmd NEED-CMD。
- 主控台 `--dry` 实况：**would_create 0**（今天草稿包与复盘都新鲜），**23/25 道工序没有产物契约**。
  也就是说自驱真能跑通的目前只有 `PROD-ACCOUNT-GROWTH` 的「草稿/复盘」两道——这不是坏消息，这是**推广清单**：把 23 道工序的产物路径写进 `PRODUCTS.outputs`，每补一道，那台机就多一道能自己干的活。

## 八、推广步骤（每台机三步，一天能铺完）

1. **补契约**：给该工位承接的工序写 `PRODUCTS.outputs`（产物路径）+ `PRODUCTS.commands`（执行命令）。
2. **起循环**：`python3 Tools/fleet/station_drive.py --station <工位> --loop 300`（Windows 用计划任务每次 `--once`）。
3. **验一轮**：`--dry` 应显示 `would_create` 只含真缺口；`--once` 后回执里 `verdict=DONE` 的必须带 `sha256` 与字节数。

## 九、与旧规则的冲突处理（已定，不再讨论）

1. 旧 `station_agent.py`「只报不修、不改卡状态、不自证完成」**保留**——它是**监理**，看的是"该做的没做"。
2. 新 `station_drive.py` 是**工人**，可以干活、可以自验；两者分工：监理不许代替工人干活，工人不许给自己发"合格证"以外的权力（人判型仍归人）。
3. 主控脉里的 `supply` 系列降为兜底：只在"没有任何工位能承接"或"机器连续两轮 NO-WORK 但队列有活"时出手。
