## 一、A 级：Thomas-Krenn（整机厂 QA 签署）与手册互相印证的三条

来源：`thomas-krenn.com/en/wiki/Supermicro_X9DRi-F_Motherboard`（该页 2022-09 最后编辑，访问量 5 万+）

1. **PCIe 槽按 CPU 分区**（与手册 p15/p44 一致，且说得更明确）：
   > "The PCIe root complex is located within the CPU. PCIe slots 1, 2, and 3 are controlled by CPU1. PCIe slots 4, 5, and 6 by CPU2. **To enable the use of all PCIe slots, two CPUs must be installed.**"
   → 结论：**三张 V100 必须双 CPU**，这不是我们的推断，是厂商写明的。
2. **SATA / SCU 的 RAID 禁区**（手册只列了端口，没说这个坑）：
   - SATA2 与 SATA3 端口**不要放进同一个 RAID**；
   - 两个 4×SATA2 控制器**只有一个能用于 RAID 模式**；两个都开 RAID 时装系统容易出问题。
3. **BMC 固件不能降级**（这条很关键，手册没写）：
   > "A 3.xx firmware version **may not be reflashed to an underlying (2.xx / 1.xx) version. This can damage the IPMI modules.**"
   → 我们要刷的是 3.62（3.xx），**刷上去就别想退回 2.xx**；另外刷的时候若取消"preserve configuration"，BMC 会恢复出厂、IP 要用 IPMICFG 重配。
4. 他们出厂前的 BIOS 设置：`Quiet Boot = Disable`、`Load Onboard LAN1/LAN2 Option ROM = Enabled`（后者影响网络启动/部分 PXE 场景）。
5. 硬件版本 1.11A；BIOS ≥1.0a 才显示 "X9DR3-F" 这个名字。

> 注：该页说"32GB 内存条目前不可得"是 2013 年的口径，**已过时**——后来有 32GB RDIMM/LRDIMM，手册写明的上限仍是 RDIMM 512GB / LRDIMM 1TB。

## 二、B 级：X9 的远程画面（iKVM）在现代电脑上打不开

来源：Netrouting 知识库《Fix the Java Console on Older Supermicro IPMI》＋ Supermicro IPMIView 手册（本地 `IPMIView_User_Guide.pdf`）

**现象**：浏览器点 Remote Console 没反应 / 提示 Java 不安全 / 空白窗口。
**原因**：X9 的 BMC（WPCM450）用的是老式 Java 插件/JNLP 启动方式，现代 Chrome/Edge/Safari 已彻底不支持 Java 插件；JRE 11+ 又禁用了旧算法。

**现实可行做法（按省事程度排序）**
1. **直接用 IPMIView**（`管理软件/IPMIView_2.25.0_…_Windows.exe`，自带 JRE）——不需要装 Java、不需要老浏览器。这也是 Supermicro 自己手册推荐的路径（IPMIView 手册明确支持 WPCM450 的 X9 板）。
2. 非要用网页版：JRE **8（32 位更稳）** + 老浏览器；或改 `java.security` 放开旧算法（麻烦且降安全性，不建议）。
3. **空白画面 / 鼠标错位**：先把 BMC 刷到 3.62；控制台里把 Mouse Mode 设 Absolute；再点 Web 界面的 `Maintenance > iKVM Reset`（IPMI 手册 2.11.3）。

## 三、C 级：Tesla V100 在老平台上的三个共识

来源：NVIDIA 开发者论坛、ReBarUEFI issue #381、多篇同题博文（同一现象被反复复现）

1. **插上 V100 显示器没画面是正常的**：Tesla 系列（P4/P40/P100/V100/A2/T4）没有视频输出，画面必须走主板 VGA 或 BMC KVM。
2. **Above 4G Decoding 是前提**：V100 的 BAR1 很大（16GB 版 16GiB、32GB 版 32GiB），固件得能把这么大的地址窗口映射到 4G 以上。
3. **典型症状与判据**：
   - Windows：设备管理器里报 **Code 12（资源不足）**；
   - Linux：`dmesg` 里 `bridge window ... can't assign; no space`。
   → 这两种都指向 MMIO/BAR 空间分配，不是卡坏。X9DR3-F 的 BIOS 里 **有** Above 4G Decoding 开关（手册 p89），所以**不需要**去做 DSDT 补丁 / ReBarUEFI 那类改造（那是给没暴露该选项的消费级板用的）。

## 四、风扇吵：官方其实有开关（这条回到 A 级）

手册 p80 的 BIOS 项 **Energy Performance** 直接影响风扇策略：
> "This setting allows the user to adjust the fan speed based on performance (maximum cooling) or energy efficiency (maximum energy savings)."

选项：**Performance / Balanced Performance / Balanced Energy / Energy Efficient**。
- 放在机房里按默认（偏 Performance）无妨；**放在桌边/卧室调试就选 Balanced Energy 或 Energy Efficient**，噪音下降明显。
- 另外手册 p17 写明本板支持 "firmware thermal management via IPMI 2.0 + Low noise fan speed control"——即阈值也能从 IPMI 侧调（社区做法是用 ipmitool/IPMICFG 改风扇阈值，属 D 级经验，改前先记录原值）。

## 五、常见"我以为坏了"清单（C 级，多条复现）

| 现象 | 实际原因 | 处置 |
|---|---|---|
| 插 V100 后显示器黑屏 | Tesla 无视频输出 | 接主板 VGA 或 BMC KVM |
| 装完系统看不到显卡 | BIOS Above 4G 未开 / 驱动未装 | 开 4G，装 NVIDIA 数据中心驱动（非 GeForce 驱动） |
| 只装一颗 CPU 时后半排槽不工作 | PCIe 4/5/6 归 CPU2 | 装第二颗 CPU（T-K 明文） |
| 想退回旧 BMC 固件 | 3.xx 不可回刷 2.xx，可能损坏 BMC | 别退；要退只能换 BMC 或联系厂商 |
| 两个 SATA 控制器都开 RAID 后装不上系统 | 只有一个可用于 RAID（T-K） | 只用一个控制器组 RAID |

## 六、我不采信 / 需要实测才能用的说法

1. 论坛里"X9 全系可以用 ipmitool 改风扇阈值到很低的转速"——不同 BMC 固件版本 raw 命令不同，**刷 3.62 后必须重新验证**，否则可能把风扇锁死在低速导致过热。
2. "X9DR3-F 支持 32GB 单条"——取决于是 RDIMM/LRDIMM 与具体批次，手册只给了容量上限，**没有给单条容量清单**，需查 Supermicro 的 Tested Memory List。
3. 任何"改 BIOS 微码/解锁 Resizable BAR"的教程——本板有原生 4G 开关，先用手册给的正规项，别刷非官方 BIOS。
