# CPU 产能台账与排产规则（2026-11-01 主控大脑）

CEO 令：**CPU 也要满负荷，机队可以去做金融公司要的、音色库一类的活；既不能闲置，也不能无效产出。**

本文件回答三件事：有多少 CPU、现在在干什么、下一步该排什么。排产逻辑已落到
`cph4/fleet/work-bank/<node>-cpu-bank.json`（机器读）+ `Tools/fleet/workgen.py`（每轮自动补料）。

## 一、CPU 产能与角色

| 机 | 核/内存 | 角色 | CPU 允许时段 | 现在在跑 |
|---|---|---|---|---|
| bm-a | 高核 / 94GB | 公司生产力 + 夜间重 CPU | 夜间可满载，白天只接 day_ok，留 ~10% 余量 | MV 交付闸（CPU+OpenCV） |
| bm-b | 中核 / 24GB | cpu-sound + 回测节点 | 全天（除 TTS 抢核时让路） | 短剧 TTS EP004–060 → 队列里排着金融回测 |
| bm-c | 24 核 / 24GB | GPU 生产 + CPU 语料腿 | 内存 <8GB 只接只读/轻 CPU | 音色库候选发现 |
| bm-m | 10 核 / 32GB | 主控，只做轻活 | 全天轻量 | 主控脉 + 本地 4B 判读 |
| bm-d | 256GB / 48GB VRAM | 算力大脑（未入网） | 入网后承接回测重批 | — |

**结构性事实**：机队总 CPU 远大于 GPU 产能。GPU 只有 bm-a/bm-c 可用且出片慢；
CPU 侧的活（回测、语料、质检、闸）才是能真正吃满的空闲算力。

## 二、CPU 上该干的活（按「能不能变成钱/能不能变成可发的东西」排序）

1. **金融（bigmoney，bm-b）**：ETF 复合因子回测、权益档单列、股票面新赛道。
   产出判据=年化/夏普/最大回撤三数，**不是台账条目、不是波次登记**。
2. **音色库（voice bank，bm-c 采集 + bm-b 训练）**：候选发现 → 分片下载 → 降噪/ASR → shard。
   整线此前卡在「没有 BV 清单」，已补上 `Tools/voicebank/vb_discover.py`（关键词→候选清单）。
3. **短剧（bm-b）**：TTS 批量合成、逐集质检、混音 remux。
4. **MV 闸（bm-a 夜窗）**：交付闸 / 转场审计 / 稳定性闸，全是 CPU+OpenCV 重活。
5. **机队自检类（任意机）**：证据扫描、索引、盘点——只作为补位，不占主要产能。

## 三、排产规则（防止「闲置」与「无效产出」两头出错）

1. **每机常备 ≥3 张 CPU 卡**（`workgen` FLOOR=3）：任何机器报空闲即自动补料，不等人工。
2. **每张卡必须有 deliverable + accept**：没有产物的卡不入队（`SPEC-REQUIRED`）。
3. **产物已在盘 = 该活已做完**：bank 卡与 READY 卡都会按磁盘事实收口，不再重复派（防无效产出）。
4. **轻 CPU 不吃重内存门槛**：只用脚本不吃模型的活，内存底线降到 1GB；此前 bm-c 剩
   2.0GB 就被判「容量不足」而闲置，属门槛误伤，已修。
5. **重活只在允许时段**：bm-a 白天不接重 CPU；bm-c 内存 <8GB 不接出片。
6. **同一线同日只派一张生产卡**：避免自己跟自己抢核。

## 四、当前的缺口（不是算力，是数据与决策）

1. **音色库 BV 清单**：已有发现工具，但首批「12 席 × 关键词」需要定案（本盘已定：
   v01 播客/有声书、v02 课堂/讲解、v03 评书/说书；后续按 60 席矩阵扩）。
2. **ASR 权重**（faster-whisper-small）在 bm-c 缺失且网络受限：一条命令补齐或从 bm-b 拷贝。
3. **量化仓不在 Mac**：金融卡只能在 bm-b/bm-d 执行，Mac 侧只做派单与结果判读。

## 五、验收口径（怎么算这轮 CPU 没白跑）

- 每条线出的是**可核验文件**，不是「已完成」三个字。
- 金融卡看三数（年化/夏普/回撤）；音色卡看候选数与可用性判定；TTS 卡看可发布集数；
  MV 卡看 OPPOSE/seam/freeze 三个零。
- 任一卡连续两次失败 → 判「无效产出」，改卡或撤销，不许挂着占位。
