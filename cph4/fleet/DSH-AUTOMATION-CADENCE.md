## 一、节奏总表

| 频率 | 轮次 | 目标（一句话） | 完成判据 |
|---|---|---|---|
| 20 min | 机队回收 | 分叉自愈、僵尸卡收口、节点戳在动 | 三台机「能领卡」或「有物理阻塞」 |
| 45 min | 供给补位 | bm-a/b/bm-c 每条车道 OPEN ≥3 | 无空车道，新卡带 deliverable+ok_rc |
| 2 h | 返工清零 | FAILED/UNVERIFIED/返工≥3 逐张根因 | 失败有根因，误判清零 |
| 3 h | 业务推进 | 最老 ACTIVE 线出 1 件真交付物 | 落盘 + 进 git + 回执 rc=0 + DONE |
| 6 h | 质量验收 | 假 DONE 降级、抽检产物真伪 | 账上 DONE 与盘上产物一致 |
| 每天 08:30 | 晨间议会 | 今日三件事 + 三张点名卡 | 三卡当天可验收 |
| 每天 20:30 | 夜间产线 | GPU/重活开窗，bm-c 出图、bm-a 渲染、bm-b 回测 | 一夜 ≥2 条线各 1 件可验收物 |
| 每天 23:40 | 挂起线处置 | >72h 无产物的线：出最小件或判 DEAD | 每条线有产物路径或死因 |
| 周日 20:00 | 周复盘 | 砍三条最贵重复劳动，更新缺口 | 至少 1 条已落地的删除/自动化 |

## 二、所有轮次共同铁律

1. **不把计划当产出**：交付物必须落盘、非空、进 git、有回执。
2. **不问、不候**：能自己定的按现有方向定；缺物理件（装机/账号/支付）记一行 BLOCKERS 后继续。
3. **改工具优先于重派**：同一断点出现两次，改判据/改脚本，而不是再派一张同样的卡。
4. **三件套验收**：deliverable 在盘 + 回执 rc∈ok_rc + 队列 DONE，缺一件算没完成。
5. **不碰云端 API**（T0 云道停用令）；不删数据；不动 CEO 物理件域。
6. **同卡连续 3 次失败**转 BLOCKED 并写「最小解锁动作」，不许无限重试。

## 三、与你（CEO）的接口

- 需要你出手的只有四类：装机接线、账号/资质、大额花钱、去留裁决。其余自决。
- 每轮只在「有结论」时回报；没有结论就是没做完，继续做。
