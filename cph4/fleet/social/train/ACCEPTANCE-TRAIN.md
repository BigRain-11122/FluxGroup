# 训练验收口径（2026-11-18 立，写在结果之前）

CEO 判词：「你训练好了再说，现在远远不够」。所以验收不看 val loss、不看"感觉变好"，
只看两个能复算的数，且必须在**同一批视频、同一把闸**下比：

## 主判据（产线级）

1. **覆盖率**：同一批 43 条视频里，能产出至少一条过闸评论的视频数。
   现役基线 = 35/43 = 81%（2026-11-18 13:2x 实测，适配器 RUNS/20261118-113014/best）。
2. **品味分中位**：现役基线 = 80（最低 67 / 最高 103）。

**合格线**：覆盖率提升 ≥15%（即 ≥40/43），且品味分中位不低于 80。
只满足其一不算变好——覆盖率靠放水、分数靠挑好看的都能"达成"，必须同时成立。

## 副判据（定位问题，不做合格线）

3. 单候选通过率：`train_eval` 在同一评测题上的 PASS 率（现役 44%，基座 33%）。
4. 分段评测：13 段里哪些段退化（现役已知退化段 beginner −22.6 / tech_nerd −14.4 / feeler −8）。
5. 长度分布：产出长度是否落在语料 P75（42 字）附近——现役失败原因里"太长"占四分之一。

## 实验设计（一次只动一个变量）

- **Run A**：数据与模板完全不动，只把 400 → 1600 iter（965 行 ≈ 0.4 epoch → 1.6 epoch，
  原跑明显欠训）。
- **Run B**：同样 1018 行、同样步数，只把三条指令模板统一加上「8-35 字，一到两句话」
  （原模板只有一条写了字数，模型只在遇到那条时才收口）。
- 两次都用 `--num-layers 16 --max-seq-length 224 --grad-checkpoint`（硬件上限，实测全层会 nan/OOM）。

## 上线纪律

适配器由 `cph4/fleet/social/train/ACTIVE.json` 指针决定，不按"最新一轮"自动抓——
A/B 两轮都会产出 best 目录，自动抓会把对照实验当上线件。

## 2026-11-19 标定复盘：现在的合格线在要求模型超过真人

三条同题同闸的实测（43 题固定集，同一把 comment_taste + 编造闸）：

| 被测对象 | 覆盖率 | 品味中位 |
|---|---|---|
| 基座（--no-lora，26/43） | 26/43 | 81 |
| 唯一存续候选（20261119-040930 craft_learner 段） | 25/43 | 80 |
| 现役基线（113014/best） | 35/43 记为基线，但**权重已丢失**（目录空），不可复现 | 80 |

决定性的第四条：**原始真人评论 400 条过同一把品味闸，PASS 只有 13%（51 条），RISKY 85%。**
而模型每候选通过率约 12%，与真人同档——也就是说"模型已经到人味水平"，
但覆盖率合格线 40/43=93% 要求它在几乎每条视频上都产出**超过真人**的评论。

结论与改法（待 CEO 裁决）：
1. **绝对线作废**：40/43 是从 35/43 推出的 +15%，而 35/43 那版权重已不存在，基线不可复现。
2. **改配对判据**：同一次运行里同时测（a）基座（b）候选，要求候选覆盖率 ≥ 基座 + 3/43
   且中位不低于基座，两条件同时成立才算变好。这样判据与"看得见的现实"同尺，
   且不需要一个已丢失的历史基线。
3. **段专用适配器要按段验收**：craft_learner 段适配器用全量 43 题验收属口径错配——
   它只为那一段优化，天然在全量上吃亏。
4. **产物保全**：权重不进 git 又会被清理，已完成 `~/.fluxgroup/lora-archive/` 归档
   + 训练结束自动 materialize_best（best/ 落位）+ 归档副本；8788 的适配器解析
   在 ACTIVE 指向失效时**必须报错并在日志喊话**，不许静默挂最新一轮。

## 2026-11-19 对照实验定案：数据切法不是变量，扩语料优先

同段（craft_learner）同 900 步，只变 `--min-human`：
- h5（670 行）：val 最低 **3.368 @400 步**，末点 3.619
- h8（369 行）：val 最低 **3.412 @300 步**，末点 3.985
- 差值 0.044 < 0.05 → 按预设判据 **B：无差别，数据切法不是变量**

两臂都在 300-400 步见底后回升 = 过拟合，说明 900 步对这两份数据都太多。
**定案三条**：①单段训练默认上限 500 步、按 val 见底即停；②选点取 val 最低那一步（不取末点）；
③同段被否后不再重复训练，先补该段语料（`gate_segments` 的数据增长闸执行）。

全文与逐点日志：`cph4/fleet/social/train/AB-RESULT-20261119.md`

## 2026-11-19 7×24 训练循环（train_forever.py）判据

CEO 令「确保能7x24不断的训练，颗粒度做细做全，要有人味」。落地为"按段轮转 + 段内验收"，
阈值首版如下，**尚未跨段标定**（只有 shallow 一组对照），后续每段跑过两轮后回来复核：

| 判据 | 值 | 为什么是这个值 | 标定状态 |
|---|---|---|---|
| 段内可用语料下限 | 200 行 | 低于此只学会抄碎片（475 行时已有增益，180 行以下多为模板句） | 待标定 |
| 同段冷却 | 6 小时 | 一天最多 4 次，避免对着同一批语料反复过拟合（A/B 已证 900 步必回升） | 待标定 |
| 被否后重训闸 | 语料涨 ≥15% | 同段被否后再训同一批数据只是重复消耗，必须先用新语料换信息量 | 待标定 |
| 留档增益 | 段内均分 ≥ 基座 +5 | 低于 5 分落在评测噪声内（3 条/段，单条波动约 ±10 分） | 待标定 |
| PASS 约束 | 不降 | 均分涨而 PASS 降＝挑好看的样本，不是真变好 | — |
| **人味约束** | human 维度不降 2 分 | 总分可被语感/格式刷高，人味掉了就是 AI 腔回来（CEO「要有人味」） | 待标定 |

队列与证据：
- 队列板 `cph4/fleet/social/TRAIN-LOOP.md`（每段：可用行数、可否训、判据、补料缺口）
- 台账 `cph4/fleet/social/train/TRAIN-LOOP-LEDGER.jsonl`（每轮：段/行数/val 最低点/步/基座与候选均分/人味Δ/判词）
- 权重归档 `~/.fluxgroup/lora-archive/`（不进 git）
- 7×24 触发：launchd `com.fluxgroup.trainloop`，每 300 秒判一次队列；训练中由 `TRAIN-RUNLOCK` 挡住重复实例

诚实边界：**训练不会凭空 7×24**——没料时循环只输出补料清单（各段差多少行），
不重复训同一批语料冒充产能。真正的吞吐瓶颈在采集侧（8 个段低于 200 行）。
