# 简介 v2：设计师语言（2026-11-24）

> CEO 否掉 v1：「简介写的太 low」。
> v1 病根：用了**内容运营话术**——「聊」「只讲能核对的」「每篇给一条改法」。
> 这是卖课号/资讯号的语言，不是设计师的。

## 一、先诊断：v1 为什么 low

```
❌ 汽车 HMI 视觉设计师。聊汽车设计、智能座舱与未来出行——只讲能核对的，每篇给一条改法。
```

| 病 | 说明 |
|---|---|
| **「聊」** | 媒体腔。设计师不说自己「聊」，说「做」/「看」/「记录」 |
| **「只讲能核对的」** | 承诺式，像卖课。真正的专业不需要声明自己专业 |
| **「每篇给一条改法」** | 服务话术。读者不是客户 |
| **三个领域并列** | 罗列 = 没有主张。好简介只给一个判断 |

**设计师语言的三个特征**：**断言**（陈述立场）、**克制**（不解释自己）、**有画面**（具体意象）。

## 二、五个版本

### A 版｜呼应名字（首推，18 字）

```
汽车 HMI 视觉设计师。在量产之前，先看见。
```

- **为什么好**：「在量产之前，先看见」——一句话说清这个号**存在的理由**（比发布早 3 年看见），且**直接呼应「未量产」**。
- 关键词：汽车 HMI + 视觉设计。

### B 版｜有立场（22 字）

```
设计汽车界面。相信形状先于功能，也相信车还没定型。
```

- **为什么好**：「形状先于功能」是**设计主张**（不是罗列），后半句呼应「未量产」。
- 关键词：汽车界面设计。

### C 版｜极简（10 字）

```
汽车正在被重新设计。
```

- **为什么好**：最短、最有力。一句话就是全部主张。
- 风险：没有任何关键词，搜不到；显得空。

### D 版｜专业（24 字）

```
汽车 HMI 视觉设计。观察人与机器之间的那层界面。
```

- **为什么好**：「人与机器之间的那层界面」——**HMI 的本质**，一句定义，有学术感。
- 关键词：汽车 HMI + 视觉设计。

### E 版｜有画面（26 字）

```
做汽车 HMI 视觉设计。看形状如何从油泥长成屏幕。
```

- **为什么好**：「从油泥长成屏幕」——**传统工艺 → 数字界面**的画面，专业且独特。
- 风险：偏造型，可能被理解成只写外观。

## 四、推荐：**A 版**

```
汽车 HMI 视觉设计师。在量产之前，先看见。
```

理由：
1. **一句话说清存在理由**（比发布早 3 年看见），不罗列、不承诺。
2. **直接呼应名字「未量产」**——名字和简介是一个整体。
3. **18 字**，克制。
4. 保留两个核心关键词（汽车 HMI / 视觉设计），搜索能命中。

**如果要更硬核、更有立场**：选 **B**（形状先于功能）。

## 五、备选：如果 A 还不够

**「在量产之前，先看见。」** 单独用（去掉前半句身份）——
更纯粹的断言，但会失去「HMI 视觉设计师」这个身份信息。
