## 二、这轮补的三个东西

### 1. 标题闸 `gzh_title.py`（12/12）

**先纠正我自己的过度承诺**：原计划「从选题自动生成 10 个候选标题」，
做出来是 **1–4 条机械变体**。原因是诚实的——填不满强行凑数产出就是模板腔
（CEO 反复否掉的「草率 / 太俗」）。所以这个工具**不做创意生成**，只做卡形式 + 给诊断。

| 维度 | 判据 | 依据 |
|---|---|---|
| H1 长度 | 16–32 字（硬闸） | 9 篇实测中位 26 |
| H2 点名对象 | ≥1 个可搜对象（硬闸） | 真实标题平均只点名 1 个 |
| H3 无禁词 | AI 腔 / 标题党 / 禁承诺 / 抽象词（硬闸） | 选题库单一事实源 |
| B1 含数字型号 | 加分 | 9 篇里 6 篇有 |
| B2 三种句式 | 加分（动作+现场物 / 数字+悬念 / 断言+对比） | 从真实标题归纳 |
| B3 甜区长度 | 加分（20–28） | 最接近中位 26 |
| M1 问号结尾 | 减分 | 9 篇里只有 2 篇 |

**坑**：句式判定一开始把 `V8` 的 `V` 当电压单位，
「享界 V8 不只有第二排？…」被误判成「数字规格」。改成**单位必须紧跟数字**才对。

### 2. 事实核查 `gzh_fact_check.py`（6/6）

和 `gzh_logic_check` 的 L5 分工不同，两个都要跑：
**L5** 只看句内 25 字窗口；**本工具**做全文清点，多出三件事：

| 能力 | 判据 |
|---|---|
| 无源 | 同句与左右各 1 句都没有来源词 → **FAIL** |
| 疑似编造 | 末位非零的长数字（3127、587.32）且无源 → **WARN** |
| 同指标两值 | 同白名单指标在不同句子给出不同值 → **INFO** |

**三条边界（写清楚，免得以后误用）**：

- **不追踪** 个/项/层/次 —— 那是在数场景里的事物（「点了三层菜单」），不是对外部事实的主张。
- 4 位整数**不等于**假精度：`3000 元`、`7500 元` 是取整，可疑的是末位非零的 `7541`。
  这条是自检逼出来的——初版把 3000 也判成假精度。
- 冲突只在不同句子间比：同句两值通常是两台车对比。
  这条同样是自检逼出来的——初版按「同单位不同值」一刀切，把电池 60.5 vs 48 度误报。

### 3. 大纲闸 `gzh_outline.py`（7/7）

不写内容，只给骨架。章节不发明结构，直接从选题库 `promise` 拆——
`promise` 本身就是用「+」分隔的三段，天然对应三章。

校验五条：章节 2–5 个 / 小标题不许问号（实测 5%）/ 每章必须有「论点」「依据」行 /
字数预算合计偏离目标 ≤10% / 依据不许出现禁承诺。

**坑**：字数合计一开始把开头「目标 3600 字」也算进去，得出 7200 判红。
改成**只数小标题里的「约 N 字」**。

## 三、采集：按来源分层，垃圾源默认不跑

**CEO 令 2026-11-25**：「采集要去专业网站 官方网站 科学网站等等，其次是平台自产内容和头部公众号，
务必避开垃圾信息源浪费时间」。

所以源分三层，**大众媒体默认关闭**：

| 层 | 内容 | 现役源 | 状态 |
|---|---|---|---|
| **T1** 一手事实 | 官方/标准/统计/科学 | 工信部首页 · 中汽协首页 · 统计局最新发布 · arXiv API · 巨潮公告 API | 5/5 通 |
| **T2** 平台自产/头部垂类 | 车家号作者页 · 头部公众号 | 车家号能力已验证，但缺稳定作者 URL 清单 | 暂缺 |
| **T3** 大众媒体 | 科技媒体 RSS | IT之家 · 爱范儿 · 钛媒体 · 少数派 | 默认关闭，`--with-t3` 才跑 |

**新增能力（都能离线自检）**：
- `parse_links()` 通用栏目页解析：官方站几乎没 RSS，但列表是稳定 HTML；
  相对路径必须解析成绝对链接（官方站大量用 `/xwfb/...`）。
- `src_arxiv()`：官方 API，摘要里自带方法与数字，是最适合当素材的科学源。
- `src_cninfo()`：巨潮公告 API，按公司名精确取（比亚迪/长城/长安/上汽/广汽/赛力斯/宁德时代）。
  **只记索引不解析 PDF**——正文抓不动就不假装抽出了数据，它的价值是给写稿指原路。
- 一手索引豁免「低信息量」闸：索引给的是出处，不是正文。

**实测产出（T1，limit=3）**：工信部智能网联汽车大会、中汽协 R744 制冷剂示范、
统计局社零 416464 亿 + 规上工业 4.8%、arXiv UIAnchor 31.5%、比亚迪 2026年10月产销快报链接。

**已死的源（别再试）**：C-NCAP 域名解析失败、中汽中心 301、
Semantic Scholar 429、充电联盟 429、36kr `/feed` 改 HTML（200 但 0 item）。

### 采集的两个已修 bug（保留记录，别回退）

**① 侧边栏污染**：进链接抓正文后，三篇完全不同文章的「观点」抽出同一句
「世界粮食计划署：三大关键贸易通道受阻…」——页面推荐位被当正文抓了。
修法两道：`html_to_text` 丢掉「无句末标点且 <45 字」的块；`extract` 要求观点与标题有二元词交集。

**② 三个源静默死掉**：36kr/geekpark/huxiu 返回 HTTP 200 但 0 个 `<item>`，旧代码还记成源成功。
修法：`src_rss`/`src_html_list` 解析到 0 条一律抛错。

## 六、训练侧（2026-11-25 补）

`Tools/fleet/gzh_trainset.py`（自检 8/8）：把 `ARTICLES.jsonl` 拆成四任务数据集，
并把 `GZH-TRAIN-SPEC-v1.md` 的三条语料门槛做成机检。

| 门槛 | 现状 | 判定 |
|---|---|---|
| 总篇数 ≥200 | 19 | FAIL |
| 单作者 ≥10 篇 | 42号车库 11 | PASS |
| 作者数 ≥5 | 4 | FAIL |

数据集产出（19 篇 → ）：标题 15 / 开篇 13 / 骨架 8 / 收尾 15，`train_ready=false`。
**train_ready=false 时不许开训**——训了会学成复读机或方向错。

阈值全部按实测定：开篇 100–350 字（实测 min 127 / 中位 201 / max 536，
原来拍的 80–200 会把中位样本全丢掉）；小标题 2–6 个（实测集合
{0,3,4,5,11,24,31,40}，>6 是 Q&A 体不入骨架集）。

**扩语料的两条实测结论**：
1. 车家号作者页是**无限滚动**，`?page=N` 返回同一批内容；滚动能加载内容但
   唯一文章链接不增（102 个锚点里仅 49 个带标题，滚到底仍 49）。
2. 作者主页链接是 `/Authors/<id>`（**大写 A**），文章页可从 `/Authors/` 反查作者；
   推荐位只暴露 `/info/`，所以扩作者要两跳（文章 → 推荐文 → 该文作者）。
   单作者簇经两跳扩到 49 条后饱和，再扩必须换作者的入口。

**降级 21 / 死 8 的教训（别再逐个试）**：
- 车企官网首页几乎全是 SPA，静态 HTML 无可解析链接；**改走 /news 才拿到**（比亚迪 8 条、吉利 5 条）。
- 站酷/蔚来属于偶发（重探会活），已按最新探活改回可用。
- Material / DesignSystems / 站酷 首页能开但列表解析不出 → degraded，需专门适配。
- AutomotiveNews 403 / Autocar 202 / Behance 403 / Dribbble 202 / SAE 202 / 乘联会 403 / UI中国 403 / 普象 10KB 壳 → 死。

**这轮修的两个抽取缺陷**：
1. **英文源等于白抓**：观点/方法信号词全是中文，英文文章永远抽不到。
   补英文信号词 + 大小写不敏感。
2. **英文稿抽不出观点**：设计/学术英文稿很少出现 because/how-to，改按**段落级相关性**
   （正文段落会重述主题，侧边栏标题块不会），并加「导语兜底」取首个实质段落。
   效果：设计类落地率从 1/13 提到 14/18。
