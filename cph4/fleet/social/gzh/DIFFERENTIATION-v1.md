# 差异化定位 v1（2026-11-24）

> CEO 令：「你可以研究头部公众号 做好相关训练，但我的号要有自己的思考和定位，要有差异化」

## 一、先承认：学头部只能学到「及格线」

研究 42 号车库 11 篇后，它的强项是**能进现场**：

| 42 号做的 | 需要的资源 | 我有没有 |
|---|---|---|
| 探访小米电池工厂 | 媒体资质 + 差旅 | ❌ |
| 对话陶吉（11278 字） | 高管人脉 | ❌ |
| 上市前拆车 | 实车 + 场地 | ❌ |
| 3,000 TOPS 芯片独家 | 供应链信源 | ❌ |

**抄它的写法 = 写一堆我兑现不了的承诺。**

而且，就算我抄会了它的结构（断言式小标题、具体数字、开篇场景），
那也只是**及格线**——一个"像 42 号但不是 42 号"的号，凭什么被记住？

## 二、头部号的能力矩阵（找空位）

| 类型 | 代表 | 强在 | 弱在 |
|---|---|---|---|
| **媒体** | 42 号车库、晚点 | 现场、人脉、时效 | **不懂实现**（不会做界面） |
| **车评人** | 38 号、大家车 | 驾驶感受、口碑 | **不懂设计**（审美是主观的） |
| **技术号** | 机器之心、量子位 | 论文、算法 | **不懂产品**（不关心用户） |
| **设计号** | Dezeen、造物 | 审美、案例 | **不懂汽车**（不碰工业约束） |
| **厂商号** | 各家官方 | 一手参数 | **不敢说不好** |

**空位在哪？**

```
       懂实现（会做）
            │
   技术号 ──┼── 【空位】
            │
不懂汽车 ───┼─── 懂汽车
            │
   设计号 ──┼── 媒体 / 车评人
            │
       不懂实现（只会说）
```

**没有人同时占据「懂实现 + 懂设计 + 懂汽车」这个三角中心。**

## 三、我的差异化：三角中心

### 我的独特组合

| 资产 | 别人通常没有 |
|---|---|
| **专职汽车 HMI 视觉设计** | 媒体人不会做界面，设计师不碰汽车 |
| **做过车机游戏（Unity）** | 设计师不懂渲染，工程师不懂审美 |
| **美工出身（视觉审美）** | 工程师看不出「廉价感」 |
| **多线业务（FluxGroup）** | 纯设计师不懂商业 |
| **硅基智能体世界观** | 行业内几乎没人往这个方向想 |

**这五样凑在一起的人，行业里几乎没有。**

### 差异化一句话

> **别人告诉你「这车有什么」，我告诉你「为什么做成了这样，以及本该怎么改」。**

拆开看三层：
1. **有什么**（媒体能做）→ 我不做，那是资讯
2. **为什么做成这样**（懂实现才能说）→ **我的第一层**
3. **本该怎么改**（懂设计才能说）→ **我的第二层**

**第二层是护城河**：只有真做过的人，才知道「为什么不能那样改」（成本/工艺/法规/时间）。

## 四、三个差异化支柱（每个都要能落地）

### 支柱 1：从「界面」看「能力」

别人测「这个功能有没有」，我测「这个功能为什么难用」。

| 别人写 | 我写 |
|---|---|
| 「支持语音控制空调」 | 「说『有点冷』它开 22 度，但没问副驾——意图理解的边界在哪」 |
| 「15.6 寸大屏」 | 「15.6 寸屏上，最常用的三个功能被放在了第几层」 |
| 「支持 OTA」 | 「OTA 三年，为什么有的车越升越难用」 |

**判据**：每篇至少一个「为什么不能更简单」的解释。

### 支柱 2：从「成本」看「设计」

别人的「减配」是骂，我的「减配」是算账。

| 别人写 | 我写 |
|---|---|
| 「减配了，太坑」 | 「这一项减配省了 200 块，但让售后成本涨了 3 倍——这笔账怎么算的」 |
| 「用料扎实」 | 「这块皮的成本差 3 倍，但触感差异 80% 来自缝线密度，不是皮本身」 |

**判据**：每个批评配一个「如果我是产品经理，我会怎么权衡」。

### 支柱 3：从「智能体」看「未来」

别人写「未来出行」，我写「智能体正在获得身体」。

| 别人写 | 我写 |
|---|---|
| 「自动驾驶更安全了」 | 「让车自己开，本质是让智能体接管『判断权』——它凭什么被信任」 |
| 「座舱更智能」 | 「座舱是智能体的感知器官：它看得见你，才谈得上懂你」 |

**判据**：每篇结尾回到「人与机器的关系」，不做技术堆砌。

## 五、为什这三个支柱别人抄不走

| 支柱 | 抄袭门槛 |
|---|---|
| 从界面看能力 | 需要**真做过 HMI**（知道设计约束） |
| 从成本看设计 | 需要**懂供应链与商业**（知道钱怎么花） |
| 从智能体看未来 | 需要**有世界观**（不是学得来的） |

**三条都是「履历型壁垒」，不是「写作技巧型壁垒」。**

## 六、训练方案（学方法，不学腔调）

### 6.1 从头部学什么（只学这三样）

| 学 | 不学 |
|---|---|
| **结构**：开篇场景 → 3 个小标题 → 每段一个判断 | 不学它的选题（我做不了现场） |
| **密度**：每 300 字一个可核验细节 | 不学它的长度（11278 字的对话我没有素材） |
| **克制**：断言式，不煽情，不升华 | 不学它的信源依赖（独家消息我没有） |

### 6.2 训练数据怎么用

现有 12876 条训练集是**评论语料**（B 站风格），不适合长文。

**公众号要单独训**：
1. **样本**：19 篇已采文章（11 篇 42 号）+ 后续补充
2. **只训「结构与密度」**，不训「腔调」
3. **调性用 prompt 控制**（三条铁律 + 三支柱），不靠模型记忆

**为什么**：腔调靠模型学 = 学成四不像；腔调靠 prompt 约束 = 可控可改。

### 6.3 训练判据（怎么算训好了）

| 判据 | 怎么验 |
|---|---|
| 结构对 | 生成的稿子有「场景 → 3 小标题 → 每段一个判断」 |
| 密度够 | 每 300 字至少 1 个数字/型号/法规条款 |
| 三支柱至少命中一个 | 「为什么难用」/「成本账」/「智能体视角」 |
| 去 AI 味 | `deai_check` 一级词 0 命中 |
