> CEO 令：「给我调研，先把公众号形象打造起来，人设立起来，选题类型也是」。

## 一、调研结论（先看证据，再看人设）

### 1.1 主对标的真实写法（42 号车库 11 篇实测）

| 维度 | 实测 |
|---|---|
| 开篇 | 具体场合 + 具体人 + 冲突（「在享界 V8 的发布会上，余承东凭借 L3『争议发言』再次成为主角」） |
| 人称 | **我 93 次 / 你 47 次 / 我们 18 次**——强一人称 + 对话感 |
| 小标题 | 全是**断言式**（「毛利率涨了，利润却掉了四成」），不是疑问句 |
| 可信度 | 靠**具体数字**（11 月 9 日、一千张 A100、4,200 座超充站） |
| 能力 | 探访工厂、对话高管、上市前拆车——**个人号做不到** |

**结论**：它的护城河是「能进现场」，个人号复制不了，只能换一条护城河。

### 1.2 行业硬数据（可当弹药，全部公开可查）

- **JD Power 2025 中国智能座舱**：车型平均 **622/1000** 分，优秀接近 700
- **Cariad 中国调研**：**63% 车主**反映座舱功能「用不上或不好用」
- **JD Power**：**56.5% 用户**因可靠性顾虑**减少使用** AI 车控
- 用户最看重「智能避堵导航 4.27/5」，最不看重「AI 作图写诗 3.87/5」
- **英国《汽车快报》实测**：97% 的 2023 年后新车用触屏；**关闭车道保持辅助平均耗时 13.6 秒**，个别车型超 20 秒
  → 60km/h 下低头 13.6 秒 = **盲开 227 米**
- 智能座舱渗透率 48.8% → 2025 超 75%，2030 市场 1600 亿

### 1.3 赛道空白（最关键）

搜「智能座舱评测」返回的全是：行业白皮书、厂商官网自吹、券商研报。
**没有一个「消费者视角的车机评测」个人号在占位。**

### 1.4 平台规则（2026，决定怎么写）

- **完读率第一权重（35%）**，超过分享（30%）→ 开头 3 秒定生死
- **2026-03 新增「非真人自动化创作」专项条款** → AI 生成/改写被识别即限流，严重封号
- **2026-05-13 个人号「一号一人」** → 只能一个人运营，不能矩阵

## 二、人设定义（五要素）

> **一句话：一个做车机的人，替每天要在屏幕上点二十次的车主，去较真。**

| 要素 | 内容 |
|---|---|
| **是谁** | 做车机内容的人（Unity 渲染 / 交互设计出身），**不装媒体、不装车评人** |
| **为谁说话** | 每天开车要在屏幕上点二十次的车主，不是参数党 |
| **立场** | 屏幕不是越大越好，功能不是越多越好——**能用几次、几次能成**，才是标准 |
| **性格** | 较真、具体、不留情面但不刻薄（对事不对人，也不做人身攻击） |
| **独家资质** | 别人说「我觉得不好用」，我能说「**为什么做不好用**」——因为我自己做过 |

### 护城河（三条，缺一条人设就立不住）

1. **视角**：传统车评看马力/底盘/空间；我只看**人机交互**——同质化最重、最容易被吹牛、最影响日常。
2. **资质**：做过车机游戏与 UI，**能拆解「为什么难用」**，不是纯吐槽。
3. **弹药**：JD Power / Cariad / 汽车快报 / 工信部公告，**第三方硬数据对照厂商宣传**。

### 人设禁区（写了就崩）

- 不装「我开过 500 台车」——实测做不了，说了就是假。
- 不做「某品牌黑/粉」——只对具体交互较真。
- 不追热点发布会通稿——个人号没资质，也没必要。
- 不做人身攻击、不影射具体工程师。

## 四、视觉系统

| 项 | 规范 |
|---|---|
| **头像** | 300×300，深色底（#1A1A1A）+ 白色线条**一个手指点屏幕**的抽象图；右下角小字 ID。不用车模、不用渐变 |
| **主色** | 深灰 #1A1A1A + 强调色橙 #FF6B35（用于「13.6 秒」「63%」这类关键数字） |
| **首图** | 1280×720，**左文右图**：左侧一句大断言（≤12 字），右侧一张界面截图局部 |
| **正文排版** | 16px / 行高 1.75 / 段间距 1em；**每 3–4 段一个断言式小标题** |
| **配图规范** | 界面截图必须**局部放大**（原图没人看得清），关键按钮加红框 |
| **禁用** | 不用表情包、不用花字、不用「震惊体」 |

## 五、语言规范（可直接当写作检查表）

1. **开篇 30 字内**：一个具体场景或一个具体数字，**不许**「随着…的发展」。
2. **人称**：「我」为主，「你」保持高频（目标每千字 ≥10 次），「我们」少用。
3. **小标题**：断言式短句，**不用疑问句**（42 号实测 5%）。
4. **数字**：每个结论配一个可查数字，并注明来源与时间。
5. **去 AI 味**：过 `Tools/fleet/deai_check.py`，一级词 0 命中。
6. **完读率**：开头 3 行必须给出「这篇文章能帮你省什么」的明确承诺。

## 六、选题类型（按人设重定，4 类）

| 类型 | 说明 | 现有 20 条映射 |
|---|---|---|
| **T1 界面拆解类** | 从官方截图/发布会视频拆交互逻辑：点几次、看几层、信息过载在哪 | 新增（现有 20 条全缺） |
| **T2 宣传对照类** | 厂商宣传 vs 第三方数据/实际表现 | T12 L2/L3、T14 城市 NOA、T15 续航 |
| **T3 交互拆解类** | 为什么这么设计、代价是什么 | T13 芯片、T06 标配 |
| **T4 购车决策类** | 座舱权重该给多少 | T01–T11（保留，但加座舱视角） |

**关键变化**：现有 20 条偏「车」的整体决策，人设要求**加一条 T1 界面拆解类**。

**为什么不是「实测」**：`forbidden_promises` 明确禁止「我实测」，个人号也没有实车。
但**界面拆解不需要实车**——官方发布会视频、官网截图、店内实拍都能看出来
「要点几层」「信息塞了几项」。这是**设计视角**，正是做过车机的人独有的能力，
也是唯一不用造假就能立住的差异化。
