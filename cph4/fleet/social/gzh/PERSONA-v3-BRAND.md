# 公众号定位 v3：个人品牌资产（2026-11-24）

> CEO 补充：「我可以去专门搞汽车智能化的公众号，宽泛一点，以后也有助于我打造自己人设和求职」。
> 这一条把**目标函数**换了：不是做流量号，是做**个人品牌资产**。

## 一、目标校准（v2 → v3 的根本差别）

| 维度 | v2（内容号思维，错） | v3（个人品牌思维，正） |
|---|---|---|
| **KPI** | 阅读量 / 粉丝数 / 变现 | **被谁认识 / 能证明什么 / 带来什么机会** |
| **成功长什么样** | 10 万+ | 猎头/同行/车企设计负责人**主动找过来** |
| 选题标准 | 什么有流量 | **什么能证明我的判断力和专业度** |
| 内容形态 | 追热点、快 | **体系化、可长期沉淀、可当作品集** |
| 频率 | 越高越好 | **质量优先，宁可一周一篇** |

**一句话**：流量是副产品，**「这个人懂行」才是主产品**。

## 二、T 型定位（宽 × 深）

```
                    ← 横向：汽车智能化全栈（覆盖面 / 被搜到）→
  ┌──────────────────────────────────────────────────────────┐
  │  座舱 HMI · 智能驾驶 · 电子电气架构 · AI 上车 · 芯片      │
  └──────────────────────────────────────────────────────────┘
                              │
                              ▼  纵向：HMI 视觉设计（差异化 / 别人写不了）
                       层级·留白·配色·动效·字体·质感
```

- **横向宽**：覆盖汽车智能化全栈，任何热点都能接，不怕没题。
- **纵向深**：每个话题都用**视觉设计视角**切入——这是我独有、且是正职的能力。

**为什么这个结构是对的**：
- 只做 HMI 视觉 → 太窄，圈外人不看，找工作的选择面也窄
- 只做智能化泛评 → 和一堆媒体号同质，凭什么是我
- **宽覆盖 + 深切口** → 既被搜到，又只此一家

## 三、人设（v3）

> **一个汽车 HMI 视觉设计师，用设计的眼睛看汽车智能化——别人告诉你「有什么功能」，我告诉你「为什么这个功能用起来是这样」。**

### 三种可写的文章（对应求职三块能力证明）

| 类型 | 证明什么 | 例 |
|---|---|---|
| **A 拆解型** | 专业深度 | 「同一个功能，为什么新势力要三层、传统车企要五层」 |
| **B 判断型** | 行业判断力 | 「2026 年座舱竞争已经不在功能，在信息架构」 |
| **C 方法型** | 可复用能力 | 「我评估一块车机屏的 7 个维度」（可被同行引用） |

**关键**：C 类（方法型）是**求职最强弹药**——它证明的不是"我会用"，而是"**我有方法论**"。

### 立场（形成辨识度，也是面试谈资）

1. 汽车智能化的竞争，**已经从「有没有」进入「好不好用」**，而好不好用是设计问题。
2. **功能同质化是必然**，差异化只能来自交互与视觉。
3. 一块屏的体验，**70% 取决于信息架构，不是 UI 皮肤**。

### 禁区

- 不聊动力/底盘/空间（不是车评人）。
- 不做品牌黑/粉（只对具体设计较真）。
- 不空口说「丑」——**必须给改法**。
- 不追发布会通稿（个人号没资质，也没必要）。

## 五、简介（v3，3 选 1）

**A 版（专业 + 求职导向）**
> 汽车 HMI 视觉设计师。用设计的眼睛看汽车智能化：座舱、智驾、架构、AI 上车。
> 别人讲有什么功能，我讲为什么用起来是这样。

**B 版（硬核）**
> 做汽车座舱视觉的。拆智能化，给方法论。
> 每篇一个判断，配一条可执行的改法。

**C 版（极简）**
> 汽车 HMI 视觉设计。看智能化，只聊体验从哪来。

## 六、视觉系统 v3（专业、克制）

| 项 | 规范 |
|---|---|
| **头像** | 300×300，纯黑底 + 极细 8pt 网格 + 一个橙色高亮像素块。**设计师的头像应该是克制本身** |
| **主色** | 黑 #000 / 白 #FFF / 橙 #FF5A1F |
| **首图** | 1280×720，界面局部放大 + 红框标注 + 一句断言（≤14 字） |
| **正文** | 16px / 行高 1.75 / 每段 ≤4 行 / 每 3–4 段一个断言式小标题 |
| **配图** | 截图必须局部放大到能看清字；标注带编号 ①②③ 对应正文 |
| **禁用** | 表情包、花字、渐变背景、无标注整屏截图 |

## 七、选题体系 v3（6 类，宽覆盖）

| 类 | 名称 | 覆盖 | 视觉切口 |
|---|---|---|---|
| **S1** | 智能座舱 | HMI、屏幕、语音、HUD | 层级/留白/配色/动效 |
| **S2** | 智能驾驶 | NOA、传感器、算力 | 可视化/接管提示/信任感设计 |
| **S3** | 电子电气架构 | 域控、中央计算、OTA | 为什么架构决定体验上限 |
| **S4** | AI 上车 | 大模型、Agent、座舱智能体 | 对话设计/意图理解/反馈 |
| **S5** | 行业与竞争 | 谁在赢、价格战、渗透率 | 设计与商业的关系 |
| **S6** | 方法论 | 我如何评估一块屏 | **求职最强弹药** |

**配比建议**：S1 40% / S2 20% / S3 10% / S4 15% / S5 10% / S6 5%
（S6 少而精，每篇都是作品集级别）
