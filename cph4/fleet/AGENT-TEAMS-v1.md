# 每机智能体团队（AGENT-TEAMS-v1）· 2026-11-11

> 令源：CEO 2026-11-11「每个机器都要有自己的智能体专家团队，非常细分，排好各自的模块，走主控和算力大脑的本地大模型能力，要打通通路」。
> 机器面=`cph4/fleet/AGENT-TEAMS-v1.json`（**39 席**）；运行器=`Tools/fleet/agent_team.py`（自检 12/12）；通路=`local_model.endpoint()` 的 本机(0)→算力大脑(1)→主控(2) 阶梯。

## 一、一句话

**每台机有一支自己的专家队，每席只管一段；全部经同一条本地模型通路，不各接一套。**

## 二、团队编制（39 席）

| 工位 | 席位数 | 专家席 |
|---|---|---|
| 主控台 | 8 | 值班长 · 监察 · 记账 · 闸审 · 语感编辑 · 合规官 · 材料官 · 调度 |
| 公司生产力机 | 8 | 值班长 · 监察 · 提审专家 · 图形规格官 · 构建官 · 车机适配官 · 准入官 · 记账 |
| 传家宝 | 9 | 值班长 · 监察 · 镜头顾问 · 关键帧审片 · i2v 提示词官 · 一致性检查 · 剪辑节奏 · 字幕校对 · 记账 |
| 小钢炮 | 7 | 值班长 · 监察 · 选角 · 音色一致性 · 混音师 · 配乐 · 记账 |
| 算力大脑 | 7 | 值班长 · 监察 · 量化研究员 · 回测审计 · 批处理 · 模型运维 · 记账 |

设计原则：
1. **一席一事**：每席只写一句职责，写不成一句就是拆得不够细。
2. **每席带判据**：输出是 JSON 就规定必须有哪些键；是正文就规定字数上限。没有判据的席位不许进编制。
3. **不写模型名**：席位只声明难度档 `cls`（triage/review/creative/deep），模型由通路决定——这样换机器、换模型都不用改席位。

## 三、通路（这是"打通"的具体含义）

```
席位 --cls--> local_model.generate()
                    |
                    +-- 0 本机 127.0.0.1（每台机自己的模型，本地闭环）
                    +-- 1 算力大脑（重活/32B 级，未入网时跳过）
                    +-- 2 主控（轻量兜底，仅 2B/4B）
                    +-- 全不通 -> 返回空，席位标 degraded=true
```

三条硬规矩：
1. **不许绕通路**：任何席位都不许直连某个模型的地址，一律经 `local_model.generate`。
2. **模型不可用不编**：`degraded=true` + `ok=false`，交回规则或人；输出全空也判不合格。
3. **每次调用留痕**：`rt/<工位>/team.jsonl` 记座位、cls、端点、耗时、是否降级。

## 四、怎么用（三个命令）

```bash
python3 Tools/fleet/agent_team.py --station visual --list     # 看这台的编制
python3 Tools/fleet/agent_team.py --station visual --run V-KF --input "首帧：..." 
python3 Tools/fleet/agent_team.py --probe                     # 通路体检（端点+席位能否落地模型）
```

## 五、现状（2026-11-11 实测）

1. 席位表自检 **12/12**：五台机都有团队、id 不重复、cls 合法、json 席位有 keys、text 席位有上限；judge 的四种反例（空输出/缺键/全空/超长）全部拦住，并能在噪声文本里取出 JSON。
2. 通路体检（主控台）：本机端点可用（8 个模型），tailnet 端点不通（预期，服务暂停）；8 席全部能落到已装模型 → **通路可用**。
3. 实跑一席：`C-INSPECT` 拿真实队列状态，1.9 秒返回合法 JSON，正确指出"1 张 BLOCKED 缺 cookie"，无编造。
4. 其余四台机：**必须在各自机器上跑一次 `--probe`**，因为本机端口只有本机能验（与闭环体检同一原则）。

## 六、还没做的（诚实清单）

1. 席位**没有自动排班**：现在要人工 `--run`。下一步把 `station_drive` 的判断环节切到席位（LEAD 决定先干什么、INSPECT 挑异常），这才是"团队自己上班"。
2. 席位间**没有串起来**：目前各席独立，尚未实现"INSPECT 发现 → LEAD 排优先级 → 具体席执行 → BOOK 记账"的流水。
3. 算力大脑的 `deep` 席（量化研究员/回测审计）现在只能落到本机 8B，等它入网才会真正变强。

## 七、频率与额度（AGENT-CAPACITY-v1，2026-11-11 补）

第一版把 39 席全算在主控头上，实测 **1464 次/天、超额度 5 倍**——那是不科学。改成**按机器分账**后：

| 机器 | 模型 | 调用 天/额度 | 模型时间 天/额度 | 结论 |
|---|---|---|---|---|
| MacBook 主控台 | 4B | 178 / 300 | 66.2 / 90 分钟 | OK（59%） |
| 公司生产力机 | 8B | 184 / 600 | 109.7 / 180 分钟 | OK（31%） |
| 传家宝 | 8B（用完即卸） | 172 / 400 | 97.8 / 120 分钟 | OK（82%，最紧） |
| 小钢炮 | 4-8B | 146 / 300 | 69.8 / 90 分钟 | OK（49%） |
| 算力大脑 | 32B | 272 / 3000 | 305 / 720 分钟 | OK（9%） |

三条让它"高频但不过载"的做法：

1. **上限与预期分开算**：`per_day` 是硬上限，预算按 `expected` 算——事件型席位的预期=当天真实事件数（配置里 `events_per_day`），不是上限。所以监察可以 5 分钟一响应，但一天只真跑 40 次左右。
2. **零模型席位不占模型额度**：记账（`*-BOOK`）只跑脚本，`est_tokens=0`，可以 15 分钟一次而不花一分算力。
3. **事件门**：输入指纹（队列状态+产物 mtime+回执数）不变就跳过。实测连续两轮 tick：第一轮放行 C-LEAD/C-INSPECT，第二轮 4 个席位全部被拦。

超载时的降级顺序（写死在配置）：**降频（间隔×2）→ 深度席移到算力大脑 → 大脑不可用只留 INSPECT/LEAD/GATE → 全停告警**。永不允许把执行机的批量活压回主控。

用法：
```bash
python3 Tools/fleet/agent_schedule.py --plan     # 看排班与额度
python3 Tools/fleet/agent_schedule.py --check    # 超预算返回 1（可接主控脉当闸）
python3 Tools/fleet/agent_schedule.py --tick --station visual --max-runs 3
```
