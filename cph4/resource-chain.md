## §一 集团调度（原 cph4/scheduling.md v1.0 全文）


> CEO 令（2026-09-23 原话）：「建立集团顶层机制，所有子公司合理分配算力和时间，调度科学，缺资源可以汇报给ceo。云端算力目前无限，最大化并行利用，做好技术基建，尤其是本地化的能力！」

### 0. 三原则

1. **云端无限，并行优先**：当前云端 API 算力无上限——「排队等云端」是伪约束；任务默认并行开跑，禁串行化等待（一台机器忙≠集团忙）。
2. **本地是基建**：本地算力=基建能力（`local-first.md` L1/L2 阶梯），建设优先级高于省钱；**只有本地任务需要调度**（显存/RAM/物理核有限），云端任务不需要。
3. **调度=机制约定，非调度守护进程**：不建中央调度器——调度以「规则 + 心跳台账 + 裁决」落地，防官僚层。

### 1. 算力与时间分配规则（科学调度）

- **配置分配表**：机器群按配置归属各子公司+空余算力可借池——配置面= `fleet-allocations.md`（CEO 令 2026-09-23「机器群根据配置合理分给各子公司+空余可借+云算力未指令前并行全量」·本文件姊妹件）。
- **verdict 驱动放置**：开工前读全机队心跳 verdict（fleet/machines、FleetStatus 范式）——GPU 空闲 ≥6GB（GPU_ML_READY 档）才开 LLM 重活；RAM<4GB 禁新开重活；CPU 并行合计 ≤ 物理核-2（既有 fleet §10 律，全集团适用）。
- **双通道并行律**：云端（L3）与本地（L1/L2）不互斥——同一循环内「云端推理 + 本地渲染/生成」并行开跑（BigStream m2-local-stack 四工位 PoC 为范式）。
- **节律互不抢占**：各司 OS 循环（10min tick）独立运转；共享机时段冲突=心跳 verdict 协商，后到让路。
- **拆批默认并行**：可拆批任务（回测批/素材批/渲染批）默认拆并行（BigMoney worker 上限 `min(12, 空闲GB/0.5)` 为范式）；机器闲置且有 open 任务单=可认领（跨公司借算合法，fleet §5）。

### 2. 缺资源汇报通道（escalation → CEO）

- **常规**：各司资源缺口（显存不足/缺权重/需装机/需组网/需账号）→ 记 `HQ-FEEDBACK.md`（标 `P0-Resource`）或本司任务单 → **周进化轮收取汇总进周报「资源缺口清单」** → CEO 一句话裁决。
- **紧急**：P0 缺口阻塞主线 → 当下任一会话直接呈报 CEO + 台账留档，**不等周日**。
- CEO 物理件域照旧：装机授权 / 账号域 / 大额采购 / Tailscale 组网。

### 3. 本地化基建（尤其项）

- 各司按 `local-first.md` 阶梯建设 L1/L2；**集团共享能力一处建**（禁双建律）：本地 LLM 栈（Ollama 模型库+keepwarm）、TTS/STT/FFmpeg 工具链、AIGC 管线——建在谁的域，`cph4/README` 注册表登记托管方，他司引用复用（借算或远程调用）。
- **模型资产统一登记**（防各司乱拉权重占盘）：现役 bm-a=qwen2.5:7b（Biggame 系保温）+ qwen2.5:14b（BigStream m2 计划）——新权重入列先登记。
- 测量照旧：token 计量（BigMoney 已开）各司跟进，进化轮周报聚合集团趋势。

### 4. 与既有法的关系

- 本机制 = `governance.md` §6 资源协同条款的执行细则（溯源：CEO 令 2026-09-23「建立集团顶层机制…调度科学」）。
- 原「不建中央调度器」细化为：**不建调度守护进程；调度=机制约定**——顶层机制即本文件。

### 二、空余算力可借池律

1. **主归属优先**：配置内任务 P0——主归属公司的循环/任务单永远优先使用本机（保主）。
2. **空余进池**：机器空闲（verdict 绿灯：RAM 空闲≥4GB / GPU 显存≥6GB / CPU 余量）= 进入**可借池**，任何子公司可按**被借方机队协议**认领调用（BigMoney=fleet §5 范式：任务单认领+git 回流+批末清临时件）；跨司借算工单五字段规范=`cph4/fleet-protocol.md` §三.2（2026-09-24 扩法）。
3. **verdict 驱动**：借算前必读心跳台账（governance §6 资源互见）；满负荷机不借，禁硬抢。
4. **禁双建禁双开工**（governance §6 第 3/4 条）在算力面同样适用——同能力双公司各建=违规。

### 三、云算力默认态（CEO 令原文立法）

- **默认=并行全量调用**：一切云端 API 任务默认并行开跑、全量利用（scheduling.md §0.1 同源）；「排队等云端」「为省而串行」=伪约束，禁。
- **CEO 指令=唯一变更通道**：限流/收缩/指定通道/暂停，均以 CEO 明令为界（local-first.md L3 收缩层的例外开关）——AI 不得自行对云算力设限。
- 云端与本地双通道并行律（scheduling.md §1）不受影响：云任务全开≠本地任务让路。

### 六、物尽其用律（统一调度执法面）

1. **三级调度决策面**（统一调度的正典结构）：机内自调度（主归属 mandate 自治）→ 跨机借池（§二 verdict 驱动·认领制）→ CEO 资源调配（四输入面）——统一调度=聚合可见+池化促配+审计点名，**非搬任务守护进程**（scheduling.md「调度=机制约定非守护进程」律不变）。
2. **闲置点名律**：主归属机连续两夜 GREEN-IDLE（无在途任务+资源大量空闲）→ 夜报点名主归属公司：派活 / 进借池供他司认领 / 显式声明待机理由（声明态豁免——如 BigDomain 待机属已声明）；点名响应窗 48h。
3. **过载保护律**：YELLOW-HEAVY → 按 fleet §10 共享机纪律让路（keepwarm.pause 释放阀）；P0 任务被卡=P0-Resource 通道呈报（倾斜态期优先配给城建）。
4. **失联律**：OFFLINE 机器认领制任务单超时释放保护；夜轮点名直至回归。
5. **判据与回访**：物尽其用 KPI=夜轮闲置点名次数趋势（下降=分配趋于合理）+借池认领次数（上升=池化生效）；两周后进化轮回访本律。
6. **扩容采购判据线**（2026-09-24 CEO 快速调查令「看，再看一些排期啊之类的，还有任务的完成情况，是否需要去增加算力，比如说机器啊之类的」·T2 否决窗 7 天）：**默认态=不扩容**——三面实证（09-24 21:0x 双源心跳）：真瓶颈=承建单执行体串行（同仓单执行体纪律·加机不加速）+物理件链（商户号/备案·加机不解决）；已购能力未吃满（bm-c VRAM 13.4GB 闲置+P-49 装机未收口+P-54 极限令计量未满一周）；云端无限并行默认态（§三）可分流重活。**触发任一判据才呈购买卡**（测量先行律·判据未到禁先购）：A) P-49/P-54 收口满负荷一周后，本地 LLM 生成队列连续 3 天积压（夜轮 GREEN-IDLE 归零+等待>2×批周期）→ 增 GPU 机一台（显存 16GB+ 档）；B) ComfyUI 产线日需求>单机吞吐（BG-C 补装后两周计量）→ 增美术 GPU 机；C) 回测/纸盘 walk-forward 并行需求超 bm-b/c CPU 余量（09-24 实测 bm-c CPU 8%·远未到）→ 先借池后购。

### 8. 工程规模治理（防「工程不受控的庞大」·新面）

1. **WIP 上限律**：在途项目数有上限——U177 实证（MiniGame 17 款在途 0 款上线=轮均稀释）；**各司自定 WIP cap**（MiniGame 建议 M5 演化日复审定值），超限=禁开新线（先收线或上线一件）。
2. **入口窄化律**：新文件/新流程/新工具入户口三问——①能否并入既有件？②复用谁（查注册表）？③一年后还活着吗？——治理层 v2 薄卡/登记处同源；新法默认 T2+否决窗+季度法熵复审（本机制自身即示范：扩法不建新件）。
3. **范围蔓延闸**：工单执行中禁 scope creep（「顺手重构禁令」的工程面形态）——需求外发现=另立提案单，禁顺手做。
4. **体量水位**（工程文件面）：单文档水位=治理面 L0 薄卡 ≤200 行/25KB（govscale 验收线）；commit ≤500 字符（versioning §4.3）；代码仓重量入 selfaudit 面。
5. **流程瘦身日**：季度法熵审视扩面——除法条合并/退役外附流程三问（哪步可并？哪步机器可代？哪步一年内真用过？）——「三不搬律」管入口、本律管存量（城市治理律同源）。
