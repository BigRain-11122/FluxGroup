# 造闸六问（gate-rigor）

## 为什么存在

2026-11-03 音色闸第一版把阈值拍了出来（44.1k / SNR≥30 / 底噪≤-55）。
拿本机 10 条真实云端 TTS 一验：**10/10 全判负**——好素材全被挡，闸等于废。
同类病在 ai_smell_gate 首版也发生过（32 张真人全判可疑）。
病根不是不会写代码，是**写闸前没有人追问**。本技能就是那套追问。

## 六问（每一问都必须能在文件里指出位置）

1. **标定依据**：这个数字从哪来？必须给出样本与分位（例：10 条真实素材，p10/p50/p90）。
   没有标定来源的数字 = 拍的，不许进判决，只能作提示。
2. **负控/反例**：有没有一组"应该被拒绝"的样例？闸只验"通过侧"等于没验。
   实现方式：`--selftest` 或固定反例目录，且必须真的跑过一次。
3. **能力边界**：这个闸判不了什么？写不清边界的闸会被当成万能闸用。
   本机没有的仪器（人脸嵌入模型、盲听听审）要明写"判不了，交人眼"。
4. **唯一判据**：同一判据只能有一处定义。若主流程与自检各写一份，修一处等于没修。
5. **失效条件**：什么时候这条标准不算数（不适用场景要列举，否则会被机械套用）。
6. **验证记录**：正反两组样例的实测结果，含数字。没有记录等于"据说能跑"。

## 标准动作

```bash
python Tools/gate_rigor_check.py --dir cph4/fleet --glob "*LAW*.md"
python Tools/gate_rigor_check.py --all          # 扫默认标准位置
```

新写或大改一份标准/闸之后，必须复跑并把 GAP 清零；GAP 不是"闸坏了"，是"这份标准还答不出六问之一"。

## 三条实现纪律

- **测不准就不判**：连续语音上 SNR 会被系统性低估，降为报告项，宁缺勿假。
- **强弱证据分离**：弱证据（暗光小脸镜的对称性）只提示，不进判决；否则闸变噪音，最后没人看。
- **阈值只写一次**：常量集中在文件顶部或策略 JSON，禁两处各写一份。

## 自检（改闸后逐条过）

1. 我的每个阈值能指到"哪批数据、哪个分位"吗？指不到就降级为提示项。
2. `--selftest` 或反例集跑过没有？应拒绝的样例是否真的红了？
3. 文件里有没有一段明写"这个闸判不了什么"？
4. 同一判据是否只在一处定义（主流程与自检共用同一函数）？
5. 有没有列"失效条件/不适用场景"？
6. 正反验证结果是否带数字写进了文档（不是只写在会话里）？

## 反面案例（真实发生过，别再犯）

- 拍阈值 → 10/10 好素材判负 → 闸废；
- 撞型判定只写在主流程 → 自检单跑判不出 → 负控第一次跑就红；
- 闸上线后只报"跑了 rc=0" → 判的是另一个文件/另一条线的产物 → 假绿。
