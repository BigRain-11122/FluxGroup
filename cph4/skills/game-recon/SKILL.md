# 游戏拆解技能（GAME-RECON）

## 何时用
- 要扒榜单（微信/抖音小游戏畅销榜、人气榜）前 N 名。
- 自家某款被说"包体大/UI 丑/留不住/变现弱"，需要外部基准。
- 立项前做品类与商业化基线。

## 边界（硬）
- 只用**公开 APK**、公开录屏、GitHub 开源实现。
- **不做**：`.wxapkg` 解密、破解付费/DRM、绕过登录、批量爬取私有接口。
- 反编译结果只用于理解实现与性能，**代码/资源零搬运**；商标与角色形象零复用。
- 原始 APK 只落 `media/recon/apk/`，30 天后清；结论先落卡再清样本。

## 取源（实测可用路径）
1. **应用宝**：搜索页 → 取 `appdetail` 链接 → 详情页 HTML 内嵌 `imtt2.dd.qq.com/...apk` 直链（2026-10-23 实测可用）。
2. **官方/官网 APK**：有则优先（版本新、干净）。
3. **GitHub 高星同类实现**：学工程与性能，不学美术。
4. 无包时：公开录屏 + 官方演示，只做 G5/G7/G8（循环/商业化/留存），G1-G3 标"未验证"。

## 执行五步
1. **拿包**：落 `media/recon/apk/<代号>.apk`，记录来源 URL 与抓取日。
2. **静态拆**：`python Tools/recon/apk_recon.py <apk>` → 体积归因、引擎、ABI、最大的文件、SDK 痕迹。
3. **深拆（按需）**：jadx 看包名/入口/关键类名；apktool 看资源命名与布局；Il2CppDumper/AssetRipper 看 Unity 资源结构。只读结论，不落地代码。
4. **动态看**：装真机（adb）测冷启动、内存峰值、首屏时长；录屏标注 30s/3min/30min 三层动作与广告点位。
5. **成卡**：按 `METHOD-v1.md §2.3` 九面输出，必含"可抄 3 条 + 风险 1 条"。

## 判读口径
- 包体：`lib` 占比 >55% = 引擎/多 ABI 膨胀；`assets` >60% = 资源重；两者都低 = 逻辑重或分包。
- Unity 判定：`libunity.so` + `assets/bin/Data` + `global-metadata.dat`（il2cpp）。
- 商业化：激励视频 ≥4 处且与"复活/翻倍/免费领/加速"绑定 = 标准 IAA 结构；插屏间隔 <3 关 = 激进。
- UI：主按钮热区 <88px（@750 宽基准）= 误触风险；动效 >0.3s = 拖沓。

## 横向产出（优先于单款）
- UI 规格基线表（主色/热区/字号/动效）
- 包体预算表（lib/assets/res 占比 + 纹理格式）
- 商业化点位表（位置×频次×触发）
- 同厂换皮对照（识别最小改造成本）

## 反模式
- 只写"包体 200MB"不给归因。
- 把反编译出的类名/资源名当自家实现方案照搬。
- 用一款的结论推全体（必须至少 3 款交叉）。
