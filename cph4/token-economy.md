> 溯源：CEO 令 2026-09-24「集团层面建立起token节省顶层机制和设计，着重搭建本地系统和能力，子公司分自己业务板块合理优化机制适配」+ 2026-09-23 令「token 可以烧，但要同时建立本地化系统化能力，能自我运算，直到后面减少 token 的使用」（local-first.md 同源战略）。**→2026-09-24 ~15:30 CEO 锚定语（统摄）**：「对 先干能本地干的事，节省token，沉淀本地能力，对外支出只在必要的时候去」——展开见 §〇.1 三增补。

## 〇、一句话

**Token 是集团的水电与口粮：放开烧（速度优先）+ 计量可见（每轮一行）+ 本地替换（结构性下降）——省 token 靠换机制，不靠省着用。**

## 〇.1 顶层锚定语三增补（CEO 令 2026-09-24 ~15:30 原话——五律的统摄锚·T2 随本件否决窗）

1. **工作选择律**（「先干能本地干的事」）：同等价值的工作，本地可完成者优先排——设计/规格/沙箱/本地工具先于需外部资源的工作；工作队列排序时显式适用。范例=服务器线（本地测好=对外支出的前置门·P-53）。
2. **能力沉淀律**（「沉淀本地能力」）：产出优先沉淀为**可复用本地资产**（池/工具/模板/规格/门禁）——pool_gen「一次生成永久消费」范式升格为通用律；同等消耗下，留下资产的路径优先；结构性替换律的资产面表述。
3. **对外支出必要性闸**（「对外支出只在必要的时候去」——速度优先律边界澄清）：**本地消耗**（Ollama/本地算力/本地栈）=可烧（是电费非支出·速度优先不变）；**对外支出**（云端 API 调用/资本采购）=必要性闸——本地不可行或不可等时才启用，L3 留痕律即其执法面；资本采购另叠「验证前置」（服务器案范式·先测后买）。

## 二、机制五律（集团法）

1. **计量先行律**：一切优化先计量。各司 OS 循环轮账本带一行标准 token 面：`tokens: local=<次数> api=<次数> api_reason=<一句话|->`（本地按次计、API 有 CLI 数据精确无则粗估标注）；周轮周报聚合三面趋势各一行，升/降如实（禁粉饰）。
2. **路由三问律**（local-first §1 铁律的执法化）：任何**新增** LLM/生成触点先过三问——L1 确定性可解？L2 本地够用？必须 L3？——接线位=各司提案/立项门+CPH4 提案审核面。**存量不追杀**（grandfather），随迭代自然迁移。
3. **L3 留痕律**：云端 API/纯生成调用在本司轮账本留一行原因（谁/为何/粗估）；不建中央台账（调度=机制约定非守护进程同源），审计=周轮抽验。
4. **结构性替换律**：禁「省着用」式优化（砍任务/降频/憋需求）；只认结构性替换（L3 任务→L1 脚本/L2 本地模型承接）。落地证据=季度「本地化覆盖清单」进周轮（local-first §4 续用）。
5. **速度优先律**（CEO 原话锚定「token 可以烧」）：token 费用不是现阶段约束——禁以省钱为由降速/停轮/砍 P0；优化永不伤害主归属任务与资源倾斜态 P0。

### 3.4 上下文管家模式（L2→L3 桥·2026-09-24 CEO 参考方案适配「把豆包改成你」·T2+否决窗 7 天）

> 溯源：CEO 令 2026-09-24 午后——外部参考方案（豆包版）适配本集团：**方案中的「豆包」位=集团 API 劳动力（各司 L3 循环）**；机器判定与三方案取舍如下。

- **机器判定（CEO 已裁）**：**不加显卡**——bm-a 现卡 4070S 12GB 够用（7B Q4 轻松/14B Q4 勉强/32B 跑不动）；3090 24GB 方案否（样板代码非 token 大头·ROI 低·样板生成线未开）；WMI 读数 4GB=已知 bug·实况 12GB（nvidia-smi/实况为准——fleet-allocations bm-a 行注记）。
- **根因判定**：token 大头=**冗余上下文入 prompt**（references/记忆/台账全量塞入），非算力不足——集团三源同证：F-07/F-10 记忆膨胀案+BS-F-02 空转重读链+commit 500 帽立法。**不改裁剪，加什么卡都白搭**（CEO 原话锚定）。
- **管家模式（方案①·结构性替换律新形态：L2 服务 L3 而非替代 L3）**：凡 L3 轮次前——本地快线 7b（现役 11434）先读全量 references/memory/正典 → 裁剪·摘要·按任务 ID 选篇 → 产 **≤2KB 精简上下文包** → L3 mandate 只挂精简包+当前任务单；**L3 只做决策与创作**（读日志/错误分类/上下文裁剪/下一步排序=禁 L3·轻活下沉 L1/L2）。
- **脚本产出纪律（方案③·零成本先行·见效最快）**：喂 LLM 的脚本输出**只有结论行**（progress/state/心跳类数据禁全量打印进 prompt）；references/正典**按任务 ID 只载相关篇**（禁全量挂载）。各司适配面首件即查此条。
- **目标带**：同源方案锚=input/轮 15k→4-5k（省 60-70%）——我方不承诺未测数字，**判据=轮账本 tokens 行前后对照**（计量先行律）：P-48 pilot 实测 input 降 ≥50% 且任务判据不降=成立线。
- **落点**：P-48 pilot@BigMoney（最重烧点+计量已开=对照最清晰）→ 成立后随 P-31 两周回执窗推广六司；治理层 v2（文档层瘦身）与本节（运行时裁剪）=上下文面两把刀，互补不重复。
