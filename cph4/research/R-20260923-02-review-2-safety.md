3. 冷启动预算 — **PASS**：定标按章程授权完成校准（暂定 2k→02b 路一定稿「注入≤2k+首读≤2k」=4k，02c §四），批3 附「自动注入实测 <2k tok」硬验收。

## ② 安全与故障域专项审查

**2-1 影子读切换判据不充分（02c 批1「双源对比一夜全等」）**。「全等」必须定义为**令级内容寻址集合相等**：以 O-id+quote 前 30 字为键（P-10 修法范式）对六字段（id/ts/quote/落点/状态/溯源）逐字段比较，外加**探针发射对等**（两源各跑一轮，脉冲序列去重后相等）——不是行数、不是字节相等（行数游标已实证漏 4/7；PS 5.1 GBK/UTF-8 编码差制造假阴假阳，对比前须归一化）。**漏比四样必翻车**：①窗内**真实新令**（只比迁移存量=拿静止数据验动系统，必须含 ≥1 条双源同收的现写令）；②**状态流转**（executed→done 字段更新，只比插入不比更新）；③**双发去重语义**（17:30 行双发实证，两源去重策略不同=假不等）；④**编码与空白归一**。「夜轮/CityWatch 零红」是必要非充分：jsonl 静默丢半行=零红但已漏令。
**2-2 生成器单点=诚实律违规面（02c 风险 4 对策不完整）**。「生成器进 selfaudit 门禁」只检测不解决且检测面错位（selfaudit 扫 commit 宣称，不扫视图新鲜度）。CEO 直读的尾部视图停在旧时刻而人不知=**假实况**，正撞诚实律 10.2「新鲜验证」。要求：视图强制带生成水印（generated_at+末令 O-id+源 head hash），夜轮机判「视图末令 O-id < jsonl 末令 O-id」即红+点名；另须定**视图落位路径**——建议 docs/orders.md 原路径即生成视图落位，否则 AI.md/夜轮 prompt 引用全部断链（见①-7）。
**2-3 jsonl 损坏/半行自愈路径缺失（02c 全文未提·安全域最大缺口）**。写侧：CEO 5+ 并行窗+探针+生成器同窗写 registry/*.jsonl，scan 双写者无锁竞写已实证（17:37/17:42），Windows 追加无原子保证=半行必然发生；读侧：坏行会让朴素解析吞掉整文件。集团已有现成范式（FluxVerse scan v0.3：坏 JSON 当场进 quarantine 隔离+state 走 .new→verify PASS 才原子晋升正本，实证 healed 2 恢复 PASS）——要求 registry：追加单写者锁+读侧逐行校验坏行隔离（不吞整文件）+夜轮点名+修复回填路径。方案补齐此节才够批1 动工标准。
**2-4 敏感面：CEO 原话全文进 orders.jsonl**。内容面不变（docs/orders.md 现状已逐字存原话，AI.md:71 立法「CEO 原话入 orders.md」），变的是**可导出性与可转发性**：一令一行结构化后，一句 jq/grep 即全量导出「原话×落点×状态」且可被任意脚本 join；更大的新面是**顺带转发**——探针/生成器/派生件天然消费 jsonl，原话被顺手带进 world-events/城市/产品面的概率大增（现状光脉冲只带 zone；游标键 quote 前 30 字已是既有最小暴露面，不再扩大即可）。要求新规入批1 立法：quote 全文**止步 HQ registry**，派生视图（CEO 直读件除外）/事件流/跨仓转发一律只带 O-id+落点+状态。
**2-5 密钥红线：需要新禁令（02c 未提）**。既有律仍是底（governance §7 密钥禁入 git+已入视为泄露须轮换；versioning.md:81 scan P0 模式=AWS key/GitHub PAT/私钥块→记档+轮换；RULES.md §3 .env 律；Biggame U014 物理件律），但 jsonl 化开了三个新口：①CEO 令原文可能夹带授权码/物理件（quote 字段逐字捕获）；②溯源/落点字段可能嵌带 token 的 URL；③结构化字段被探针转出 HQ 仓。要求：secret-scan 显式覆盖 registry/**；「令内夹带密钥/物理件=字段截断+台账记档+CEO 补件」处置律；转发侧继承 2-4 禁令。
**2-6 回滚的确切 git 操作（02c §三）**。每批一 revert 只在**窗内零新写**时为真。批1 确切 runbook：①把 jsonl 窗内增量**回填 md 正史**→②探针/夜轮切回旧源→③revert 切源 commit→④再 revert 迁移 commit（versioning.md:86 追加式不变）；顺序错了=丢史+探针读已死 jsonl=漏感重演（P-10 同型）。批2 org.yaml 同理：窗内新开线登记进 org.yaml 后直接 revert 批2=登记与视图双失，须先誊回散文。并须注明：治理件大回滚=CEO 一句话（versioning.md:87），「任何一批可独立 revert」不得读成 AI 可自决回滚。
**2-7 24h 观察窗判据不可机器判定（02c 批间纪律「探针/轮次零红」）**。「零红」现无单一机器信号源：夜报是散文、脉冲在 world-events、selfaudit 扫 commit 宣称，三处口径不一。要求落地一个 checker 合成布尔：夜轮 log 正常收尾+夜报无红标 pattern+探针脉冲数=窗内令数+selfaudit FAIL=0+2-2 水印不滞后→才自动放行下一批。另 24h 窗**测不到周轮**（evolution-tick 是周节奏，其 prompt 恰读批2/批3 要改的 governance §2 登记簿与根 CODELY.md 感知面）：批1 后与批3 后的**首个周轮必须强制首检**，不能只按 24h 机械放行。

## ③ 新增风险（02c §五清单之外）

1. **周轮感知输入被批3 削薄**：evolution-tick-prompt.txt:1 规定「读根 CODELY.md 与 gaming/CODELY.md 找七类信号」——索引卡化后周轮只读 200 行索引、主题文件无人读，漂移感知面变薄；批3 交付物须含周轮 prompt 同步改（读主题文件指引）。
2. **编码律风险未提**：生成器/对比器/探针全在 PS 5.1 下处理中文（集团已吃 GBK 亏，night-round.ps1 头部 ASCII 律为证）——读写 registry/视图必须显式 -Encoding UTF8，方案未立此条。
3. **归档轮转×游标×retention 三角**：orders 30 天窗转 registry/archive/（02c §二）——①orders_hq 内容寻址游标在轮转后不得重复触发（「已发不重发」时序未定）；②registry/archive/ 未登记进 retention.md 四级保留制，有被资源清理机制误伤丢史的风险（防误伤五闸须新增此类）。
4. **溯源双写漂移**：commit 信息=溯源载体 vs jsonl 溯源字段（02c §一）两处可能改一漏一——须定「溯源字段由 commit hash 单向派生、禁手写」。
5. **B/C 机源龄校验缺失**：registry 集中后 fleet B/C 双源机消费依赖 HQ 仓 pull 时序，消费侧无「源龄」自校验=远端机版假实况源（与 2-2 同类，发生在别的机器上）。
6. **批4 的 24h 窗测不到自领链路**：DevLoop/周轮自领是慢节奏，批4 观察窗应挂周轮节点判（≥7 天）而非机械 24h。
7. **orders.md 法条措辞漂移**：AI.md:15 称其为「唯一审计面」——jsonl 化后「唯一事实源=registry、orders.md=审计视图」，法条措辞须同步改，否则「唯一」二字成为新的文档漂移源（周轮点名对象）。
