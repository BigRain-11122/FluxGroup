## 一、OS/驱动面（Q1）——定谳：Windows 原生+双卡 TCC+R580 数据中心线钉死
- Windows 原生成立〔验证·A〕：①llama.cpp 官方 release 现发「Windows x64 (CUDA 12)=CUDA 12.4 DLLs」「Windows x64 (CUDA 13)=CUDA 13.4 DLLs」双预编译 zip（b11581/82·2026-10-13）——DLL 随包免装 Toolkit 免自编，sm750+ 在官方预编译圈内（M+A）；②kit 先例全兑现：andrewleech/v100-llm-kit=「Prebuilt binaries, serve scripts, docs for Windows…wiring for Claude Code」+docs/01-hardware（驱动+TCC/MCDM）+scripts/windows serve 脚本——T10 走官方预编译更简，kit 作 serve 脚本/接线范式抄改；③三机全 Windows=RDP+PowerShell+wget 式更新（release URL 按 b 号可拉），运维一致性；④Linux 唯一增益=vLLM 原生 TP2/NCCL→以 WSL2 后备处理（§二路径B），不破三机统一运维面。
- TCC 双卡〔验证·B〕：`nvidia-smi -g <PCI总线ID> -dm 1`（0=WDDM）或控制面板 CUDA-vs-TCC 页，重启生效；Tesla 数据中心卡在支持圈、消费卡/接显示的卡不可切（NVIDIA 论坛·LeaderGPU/immers）。T7910 无 iGPU→双卡全 TCC 后本地控制台落微软基础显示，远程一律 RDP〔推算·D 日核〕。
- 驱动钉死〔验证·A/B〕：R580=长期支持分支（NVIDIA 2026-09 驱动表：LTS 至 2028-06〔C〕·M 锚安全窗 2028-10；R595=production 至 2027-03·Turing 同在圈内）；Turing=CUDA 13 存活下限（A·沿波2），580 兼容 CUDA 12.x/13.x 应用（minor-version compat）。D 日钉=R580 数据中心 Windows 线在案版 580.88→582.78 取最新 580.xx（docs.nvidia.com/datacenter/tesla 版注·A）+核 Tesla T10 在支持产品列表（中国市场卡·D 日闸〔未验〕）。锁更纪律：系统设备安装设置禁 WU 自动装驱动；驱动版本+llama b 号双钉 fleet manifest；升级只走季度评审→本机金丝雀→35 字/秒+ECC/Retired Pages 回归门→机队推广（spec §6 环境冻结同执法）；18 个月折旧窗<LTS 窗→残值≈0 立账成立。

## 二、双卡配方面（Q2）——定谳：官方预编译主径；-sm tensor 优先/layer 兜底；Q4_K_M 定案；-np 8×8K
- 拆分模式（官方 multi-gpu.md 原文·A）：`layer`（默认）=流水线并行·KV 随层分布·「兼容最广+prefill 快+容忍慢互连」；`tensor`=张量并行（权重+KV 全拆·EXPERIMENTAL）·「优先 token 生成速度·多 NVIDIA 卡+CUDA 后端性能应良好」；`row`=**官方已弃用**（原文 Deprecated·Avoid in new deployments）→ 本稿不采。带宽同卡取舍：decode 是带宽瓶颈，layer 双卡轮流激活≈单卡带宽；tensor 双卡逐层同算+跨卡规约→近 2× 上限（anyei fork 同模型 2×tensor+MTP ~165 t/s vs 单卡 98.8-100.9=1.65× 实锚〔验证·B·V100 NVLink 下〕）。
- NCCL/P2P（A）：NCCL 构建期默认开但「不随 CUDA 分发」；Windows 无官方 NCCL→预编译包落「NCCL is unavailable, multi GPU performance will be suboptimal」一次性告警，规约走 PCIe 3.0 x16（T7910=2×x16 C612）——A3B 激活小可承受〔推算〕；`GGML_CUDA_P2P=1`（Tesla 支持圈）D 日试开，不稳即撤（IOMMU 坑·官方原文）。
- tensor 闸（A）：失败名单=DeepSeek2/GLM-DSA/Kimi-Linear/Minimax-M2 等 MoE 混合+Mamba 系——**Qwen 系不在名单**（qwen3next 架构 D 日载入确认〔未验〕）；报「SPLIT_MODE_TENSOR not implemented for architecture」即退 layer。tensor 硬条件：-fa（auto 默认）+KV 不可量化（f16 默认合）+--fit 不支持→-c 必须手动。OOM 阶梯（官方）：-c↓→-np↓→-ngl↓。候选加速器：`--spec-type draft-mtp`（MTP 投机·Qwen3.6 若带 MTP 头）D 日选配〔未验〕。
- 启动命令（win-cuda-12 zip 解包即用）：
```powershell
llama-server.exe -m Qwen3.6-35B-A3B-UD-Q4_K_M.gguf -ngl all -sm tensor -c 65536 -np 8 --numa distribute `
  --host 0.0.0.0 --port 8080 --api-key-file C:\srv\llama\keys.txt --alias qwen3.6-35b-a3b --metrics
# tensor 架构/FA 报错→改 -sm layer 同参；NCCL 告警可忍；P2P 不稳→撤 GGML_CUDA_P2P
```
- ctx/槽预算：-c=槽间总量（非统一 KV 模式按 -np 均分=8×8K；统一共享池动态分·A）；65536→KV 1.25G（0.625G/32K 线性·M）+权重拆卡≈11.1G/卡+buffer→约 13-14G/卡，16G 有余量〔推算〕；长卷宗轮换 -np 4 -c 131072。验收以 /v1/chat/completions timings.predicted_per_second+实际字符数双记录（A），中文≈1 字/token 级〔推算〕。
- 量化档定案：UD-Q4_K_M 22.12G（M）双卡全驻留无压力→**维持**（CEO 优先级=装得下>质量>速度·spec 裁决①）；IQ4_XS（kit 同款模型实配档·A）≈-2.5G，仅作 tensor 手动模式显存挤时降档备选（质量下让·K 量化在老卡 dequant 更快〔推算〕）。
- 路径B（后备·验收失败才启用）：vLLM TP2 `vllm serve <Qwen3.6-35B-A3B-GPTQ-Int4> --tensor-parallel-size 2 --max-model-len 16384`（TP=单节点卡数·A）；Turing sm75≥vLLM 最低 CC 7.0·fp16-only·INT4 走 weight-only Marlin 内核〔验证·B·vLLM 量化硬件兼容表〕；**vLLM Windows 不原生→WSL2+Docker+NVIDIA Container Toolkit**（B），WSL2 TP2 有历史坑（vllm#5161）+GPTQ-Int4 权重档需另寻/自转〔未验〕→运维面重=定后备；预期批吞吐更高〔推算〕。

## 三、接线面（Q3）——定谳：llama-server 服务化（WinSW）+局域网 OpenAI 端点+三 key+三层自愈
- 服务化（WinSW v3·A）：llama-service.xml=<id>llama-t7910</id>+<executable>C:\srv\llama\llama-server.exe</executable>+<arguments>（§二 命令）</arguments>+<onfailure action="restart" delay="10 sec"/>+<resetfailure>1 hour</resetfailure>+<log mode="roll"/>；改名 exe 与 xml 同目录→`llama-service.exe install`+`start`；startmode=Automatic 默认=开机自启。**Ollama 全线不装**（M·R-doc§五弃用→统一 llama-server）——本盒即机队 llama-server 服务化样板。
- 端点〔验证·A〕：--host 0.0.0.0 --port 8080（官方默认 9931 已显式改）；OpenAI 面=/v1/chat/completions·/v1/completions·/v1/embeddings·/v1/responses·/v1/models+Anthropic /v1/messages（Claude Code 直连·kit 05-claude-code 先例 A）；--jinja 默认启用（模板取 GGUF 元数据）→盲评/工具调用开箱。鉴权=Bearer：--api-key-file 一行一 key→三机各发独立 key（审计面·A）；防火墙：New-NetFirewallRule 8080/TCP 入站限三机 IP 段〔B〕。
- 消费方接线：三机 coding 面（Cline/Continue/Claude Code 等 OpenAI 客户端）base_url=http://<T7910-LAN-IP>:8080/v1+各自 key，--alias 统一 model 字段「qwen3.6-35b-a3b」；盲评批=异步 8 并发满槽+GET /slots?fail_on_no_slot=1 探容量（A）；委员会=同端点并发+温度梯度；路由律照执法（35B 只养代码代理+盲评/导演席两硬线·分类/lint 走 bm-b 4b·M）。
- 副业编排：faster-whisper（CTranslate2·CUDA/cuDNN/cuBLAS·int8 GPU 与 CPU 皆可·「up to 4× faster」A/B）显存 1-2G 级〔推算〕→与主活共存常驻试运行（占每卡 ~2.5G 余量边界→D 日显存水位实测）；RIFE/ESRGAN（PyTorch cu126 轮子=whisper/RIFE 环境锚·M）重显存批任务→夜窗 `sc stop llama-t7910`→跑批→`sc start`（或 D 日验证 --sleep-idle-seconds 空闲睡眠是否释放 VRAM·未验）；超限分流 bm-a/bm-c 消费机 GPU。
- 监控自愈三层：①WinSW onfailure=崩溃 10 秒自拉；②计划任务 60s 看门狗：/health 非 200×2→Restart-Service（挂死兜底；/health 公开无鉴权·503=加载中 200=就绪·A）；③GPU 面：nvidia-smi --query-gpu 温度/功耗/显存 csv 日志+`nvidia-smi -q -d ECC` Retired Pages/ECC 零错日检（spec §5/§7 双源律）→ECC 增长停机复验·>85°C 告警（导风罩改造后目标均温 ≤75°C·M）。每次服务变更重跑 24h+35 字/秒验收门。

## 四、结论面（含 CEO 追加令两答）
- 一句话定谳：Windows 原生+TCC+R580（582.78 级）；官方 win-cuda-12 预编译+`-sm tensor` 优先/layer 兜底+Q4_K_M 22.12G+-np 8×8K；WinSW 服务化+三 key 局域网 OpenAI 端点+三层自愈。预期双卡单流 40-70 字/秒〔推算：T10≈T4 级 320GB/s（M）×tensor 1.65×锚=58 中位；spec 推测带 40-80；27B Q6 双卡 36-46 实测锚〕→≥35 大概率过，D 日实测定谳。
- 宿主适配增量（同蓝图换宿主）：①2×V100 16G：换二进制源=andrewleech kit 预编译（同款 35B-A3B IQ4_XS+MoE 专家 CPU 卸载开箱·A）或 sm_70 自编；驱动窗=570-580（kit 钉 R570 573.96·Volta 止于 580）；vLLM→1Cat fork/源码 CUDA 12.6；环境永锁 CUDA 12.x——增量≈换包+锁环境两动作，得 HBM2 900GB/s（单卡 98.8-100.9 双源·双卡 tensor+MTP ~165）。②3090 24G 单卡：-sm none -ngl all+IQ4_XS 全驻留（spec：挤进 21.7G/32K·-np 余量≈0→-np 2-4）；驱动走 GeForce 同 580 线——增量≈量化档+无双卡拆分，外加图像视频车道解锁。③纯 CPU（双 E5-2680v4·DDR4 八通道）：-ngl 0 --cpu-moe（A·官方参数）+AVX2 硬线（M）→估 15-35 字/秒〔推算〕=P0 bm-a 夜窗同款血脉，用途=灾备+夜窗全显存让渡副业。
- 若推翻则推荐什么：判=T10 双卡主案维持（生态安全档·室内塔式·整机 ¥4800-7350 最低·sm75 支持圈最长）；推翻触发=①双卡 tensor 实测 <35 字/秒 ②T10 现货涨破 ¥1400（spec §4 触发线）→**首选切 2×V100 16G 成套速度备选**（¥900-1300/张·B 级实测吞吐在案；代价=kit/自编线+CUDA 12.x 永锁+580 窗口 2028）；两者皆失→蹲 3090 ≤¥4200（sm86 双车道·单卡容量边界）。理性排序=T10（稳·省·全官方圈）>V100（快·三税）>3090（全能但贵且挤）。
