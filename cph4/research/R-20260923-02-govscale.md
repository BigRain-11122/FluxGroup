## 一、问题定义（两个子问题，一件事）

1. **扩展性问题**：每开一条线/加一个功能要改 5-6 个核心文档（governance §2 / BRAND §8 / architecture / AI.md / 线 README / fleet-allocations…）——「改出来问题」的根源=**组织事实散落在多个散文文件里，每处都要手工同步**。
2. **Token 经济学问题**：治理面全散文+只增不减。新会话冷启动要吞根 CODELY.md 记忆（自动注入）+按 AI.md 指引读核心文档；且**同一 CEO 令被复述 3-4 遍**（orders 行+ledger 行+commit 信息+记忆条）。成本随「子公司数 × 天数」线性膨胀。

- 单令复述系数、冷启动逐项成本、30/90 天外推 → 波A 实测填（本目录 R-20260923-02a）。

## 三、研究两波（并行·各自落件本目录）

### 波A 内部审计（量化·R-20260923-02a-internal-audit.md）
1. 治理面文件清单化：chars/lines/est tokens（含根与线/产品仓 CODELY.md 记忆面=自动注入成本最高面）。
2. 单令复述系数：抽样 3 条今日 CEO 令，数其在 orders/ledger/记忆/changelog/commit 各复述几遍、共多少字节。
3. 冷启动成本：新会话实际注入+指引阅读总量（分仓根/产品仓两场景）。
4. 增长外推：当前斜率下 30/90 天体量预测。
5. Top-10 膨胀源排序 + 结构化注册表候选清单（哪些文档应转为机器可读登记处）。

### 波B 外部对标（方法·R-20260923-02b-external-patterns.md）
1. Agent 组织 context 工程业界实践（AGENTS.md/CLAUDE.md 分层与体量指引、长上下文 compaction、记忆系统设计）。
2. 单一事实源+派生视图范式（docs-as-code / 软件目录 / 事件溯源+投影——「组织即代码」的工程先例）。
3. 文本体量治理先例（水位线/滚动归档/size lint 门禁）。
4. 大型多 agent 组织保持单 agent 上下文薄的先例。
每条对标必须映射到 §四 验收线；查证不到=存疑即标。

## 四、方案验收线（方案件必须全过·专家审核按此打分）

1. **单一事实源**：一个事实只登记一次（登记处=结构化注册表），其余全是派生视图或指针——禁多文件复述。
2. **机器优先**：登记处机器可读（YAML/JSONL 等，探针可直接消费），人读视图按需生成。
3. **冷启动预算**：新会话治理面冷启动 ≤ 研究定标值（暂定 2k token，波A/波B 校准后定稿）。
4. **开线成本**：开子公司 #5/#6 触碰核心文档 ≤2 处（1 行登记+自动 changelog）。
5. **体量三律**：水位线+滚动归档+lint 门禁（接 selfaudit/周轮，超线自动点名）。
6. **迁移禁 big-bang**：pilot 单件（候选=orders.md）→专家审核→分批 rollout，每批独立 commit 可回滚。
7. **运转不中断**：进化轮/夜轮/探针/三司机队协议消费面平滑切换（探针从散文解析改读注册表=顺带收益）。

## 五、专家审核协议（CEO 令「方案要专家审核」）

1. 三视角**独立**评审件（并行独立会话，互不见稿）：①架构与扩展性 ②安全与故障域（含探针/轮次/协议迁移风险） ③各司接入成本（三司机队视角：改了以后每司多花/少花多少）。
2. 评审判据=§四验收线全过+迁移风险清单+回滚预案+冷启动改造前后实测对比。
3. 评审件落本目录（R-…-review-{1,2,3}.md）；不过=返工，禁带病落地。
4. **CEO 终审一句话放行** → 分批落地。
