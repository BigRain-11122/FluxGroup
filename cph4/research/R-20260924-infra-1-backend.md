> 第1路调研波 · CPH4 Labs · 2026-09-24 · 议题：红线修正案方案A（微信平台托管）vs 方案B（自建后端）
> 证据纪律：本地=文件指针；Web=URL+信息日期；三态标注【确认/推测/待证】；裁决权留 CEO（governance §4·红线增废=CEO 保留类）。

## §0 一页决策卡

**建议（非裁决）**：裁 **方案A**。证据链：①一期 9 件中无任何一件存在「平台托管不可承载、必须自建」的需求（§2）；②微信官方对云托管的自述即「无需服务器、无需运维管理」——与修正案A「平台托管」语义完全同构（§3.1）；③弹幕本体寄宿平台侧，回流接收端云托管网关即可承载，不构成自建理由（§5.2）；④方案B 在 Phase 1 零新增能力，却新增 ICP 备案+等保+7×24 运维三类负担，其中安全值守是「一人 CEO+AI 机队」模式的结构性最弱项（§4.3）；⑤支付合规全部是平台轨道问题（虚拟支付强制律/iOS 签约制/版号门槛），自建后端无一能绕过、反而更差（§3.2/§4.4）。同时建议预设「转B触发判据」（§6），避免未来二次立法成本。

## §3 方案A 深挖（微信平台托管：云开发 TCB + 云托管 CloudBase Run）

### 3.1 能力边界【确认·官方文档，抓取 2026-09-24】
- 官方定位原文：「开发者**无需搭建服务器**，可免鉴权直接使用平台提供的 API 进行业务开发」（developers.weixin.qq.com/minigame/dev/wxcloud/basis/getting-started.html）——与修正案A「平台托管」语义同构；平台运营规范专设「微信云开发服务规范」（§17）与「微信云托管服务规范」（§19）条款，两产品均为平台正名服务。
- 云开发能力清单（官方「能力概览」节）：云数据库（文档型）/云存储（CDN 加速）/云函数/工作流/静态网站（自定义域名）/内容管理 CMS/**云后台（含后台管理、支付管理）**/云模板/免登录鉴权/**云调用（云函数内免鉴权调用小程序开放接口）**/**微信支付（云函数内原生调用微信支付接口·免鉴权免签名免 access_token）**/环境共享（一套后端环境服务多个小程序/小游戏/公众号——适配 BigDomain 前台+FluxVerse 参观端多端架构）。
- 实时能力实证：官方案例「**通过实时数据推送承载千人活动**」——大厅聊天 Phase 1 规模（私域百人级）在原生能力射程内【确认】；公测后万人级需升云托管 WebSocket+广播扇出架构【推测】，仍在 A 框架内。
- 云托管（CloudBase Run，cloud.weixin.qq.com 官网，抓取 2026-09-24）：任意语言（Java/PHP/Node/Python/Go/.NET）；原生网关支持**微信私有协议/HTTPS/WebSocket**；天然鉴权（免 access_token 与证书维护）；极致弹性（按量计费精确到 100 毫秒，**可配置常驻不销毁**——消除冷启动）；可用性承诺 **99.99%**；防 DDoS/防 DNS 劫持/防数据爬取；配套 MySQL 数据库。

### 3.2 支付与代币合规（19.9 的合规路径）【确认·官方运营规范原文，抓取 2026-09-24】
出处=`developers.weixin.qq.com/minigame/product/`（《微信小程序平台运营规范》·含《小游戏特别规范》·页脚版权 2012-2026=现行维护版）：
- **虚拟支付强制律**（运营规范 §5.13/§14.7 原文）：小程序内提供的虚拟商品——「包括虚拟代币、解锁功能、订阅内容、付费功能、打赏、购买虚拟礼物等」——购买和支付**均需接入小程序虚拟支付；不得引导至 app、公众号、h5、个人号、网站完成支付**。→ 我们月卡/算力包/代币/围观付费若在微信端内销售，全部落入虚拟支付轨道；「线下人工收款/外链收款」明确违规（§0 降级面引用据此）。
- **小游戏虚拟道具支付=版号门槛**（小游戏特别规范 §3.1 原文）：「仅有获得网络出版服务工作主管部门审批通过、依法可以上网出版的游戏，方可提供小游戏虚拟道具支付功能」——**小游戏类目内购需游戏版号**【确认规则；办理周期/成本待证】。
- **iOS 现行规则**（§3.3 原文）：「在iOS系统下，如小游戏需要实现虚拟道具购买服务，可在『MP-虚拟支付-iOS资金概况』完成签约……如未开通，则不能展现任何充值、商城等相关的功能、页面、按钮，即使实际不可使用。无论是否完成签约，小游戏不得通过引导至外部网站或APP等来实现支付功能。」→ **iOS 已有明文签约制开放路径**【确认】；苹果分成比例/费率未在规范中载明【待证】。
- **不得变相支付**（§3.2 原文）：不得提供或以任何方式（包括线下充值、福利道具）变相提供与腾讯规则不一致的其它支付方式。
- **三条合规轨道判读**【推测·基于上述规则】：①小游戏内卖虚拟道具/代币=虚拟支付+版号（重轨，与 B 无关）；②大厅/服务面若以非游戏类目小程序形态承载，「AI 算力验证服务」能否按真实服务走标准微信支付=灰区【待证·须类目与商户资质复核】；③直播间购物车（视频号小店）=平台电商轨道（BigDomain §四入城门票漏斗）——但须守小游戏特别规范 §7.1.1-7.1.3（小游戏内版本服务与优惠不得低于任何其他渠道、不得引导用户去外部获得完整服务）。三轨全部在平台内，**无一需要自建后端**。
- **代币**：纯内循环、不提现、不发币（原案正典）与平台「虚拟币不得提现/涉赌」边界同向【确认·集团立法+平台规则同向】；运营规范 §2.5.2 禁随机抽取诱导投入、§6.1.5 禁彩票预测服务——与集团非投顾护栏（BigDomain §五.1/2）同源【确认】；行为挖矿型免费发放的平台细则【待证】。
- **商户号=CEO 物理件**（BigDomain §十.2·master-plan §九.2）：营业执照+经营类目+结算账户；现行费率【待证·pay.weixin.qq.com】。

### 3.3 计价与并发
- **云托管按量价目**【确认=官网现行展示口径，抓取 2026-09-24；页面版权标注 2018-2021，是否为 2026 执行价待证】：试用赠送 **400 元免费额度（3个月）**；CPU 0.055 元/(核·时)（免费 720 核时）；内存 0.032 元/(GB·时)（1440 GB时）；构建 0.05 元/分钟；公网流量 0.8 元/GB；数据库算力 0.342 元/(个·时)；CDN 0.18 元/GB。官网宣称「成本比传统服务器节省 30% 以上」。
- **例算**【推测】：0.5 核+1GB 常驻服务≈20+23≈43 元/月+流量；弹性缩容到 0 的按需服务更低于此。Phase 1 私域百人级月成本预计百元以内。
- **云开发（TCB）套餐价/免费额度现行数字**【待证】——官方落地页无套餐价目；2022 年免费额度缩减事件有社区广泛记录（细节待证）；按量模式自动扩容不受固定并发上限约束【确认·官方「按量计费，先使用后付费」】。
- **并发判读**【推测】：瓶颈不在算力（弹性扩缩），在实时推送连接数与广播扇出设计——千级官方案例已实证，万级需云托管自管扇出。

### 3.4 风险清单
- 平台依赖：单一生态绑定，计价/规则变更无议价权（免费额度缩减先例【待证细节】；运营规范 §3.6 载明腾讯保留调整支付金额上限与关闭支付能力的权利）【确认条款+推测影响】。
- iOS 分成不确定性：签约制已开但苹果抽成比例未载明，影响 19.9 毛利【待证】。
- 迁移成本：云开发 API 非通用，日后转 B 有重写成本（缓解：业务逻辑薄+数据 json 化+逻辑层与微信能力解耦）【推测】。
- 语义风险已消解：修正案文本「允许托管后端」已完成语义迁移（零服务器→零自有服务器资产+零系统运维），立法无含糊【确认·推导】。

## §4 方案B 深挖（自建后端：国内 VPS/PaaS）

### 4.1 能力【确认·常识面】
任意技术栈/完全控制/跨平台统一账号/自定义协议（WebSocket/长连接/队列）——技术上限高于 A，但 Phase 1 无一项需求触及此上限（§2）。

### 4.2 合规成本【法规级确认·执行数字待证】
- ICP 备案：国内服务器+域名对外提供 web 服务必须备案（接入商强制执行，未备案域名不得开通 web 访问）【确认·备案制度】；周期约 1-4 周、上线后 30 日内公安备案【待证·以工信部/接入商现行为准，beian.miit.gov.cn】。
- 等保 2.0：涉用户数据+支付+UGC 的商业系统建议二级备案+测评，测评费万元级/年【待证·各地有差异】；延后等保=监管风险自担。
- 网络安全法要求网络日志留存不少于 6 个月【待证·条款复核】；数据泄露主体责任直接落在集团自身。

### 4.3 运维负担判读（一人 CEO+AI 机队模式）【推测·基于治理结构】
- 金钱成本低（轻量服务器百元/年级促销价【待证】）——**真实成本不在钱**。
- 真实成本=①7×24 安全响应（入侵/泄露/DDoS 超基础防护阈值）无人肉值守；②证书/备份/监控/告警/系统更新长尾；③合规主体直接暴露（备案/等保/日志）全落集团自身。
- 对照治理事实：集团现行工程纪律=「静默律+本机轮询公开 API+watch 门禁自愈」（FluxVerse TECH）——B 引入的常驻公网资产与现行全套纪律冲突，需新立整套服务器治理条款（备份/密钥轮换/入侵响应/变更管理），立法与维护成本本身即是负担。

### 4.4 风险清单【确认】
- **支付规则零豁免**：虚拟支付强制律、iOS 签约制、版号门槛全部约束「小游戏/小程序」这个前端形态本身，与后端在哪无关——B 无一能绕过，还失去云函数原生调微信支付的免鉴权通道。
- 支付接口合规责任全自担（商户对接+风控+对账+差错处理）。
- 单点风险：单 VPS 无多活预算→可用性低于云托管 99.99% 官方承诺。

## §5 混合案评估（如实·禁为创新而创新）

### 5.1 A 主 B 备（唯一值得保留的混合形态）
Phase 1-2 全量走 A；B 不立项、不预购、不预留架构耦合。唯一价值=预设触发判据（§6）防二次立法。如实判：**现阶段不存在需要 B 参与的混合案**——任何「同时上 A+B」的双轨设计都是为创新而创新，本简报否决。

### 5.2 弹幕回流定性结论（本路唯一负责面）【确认】
弹幕的产生、存储、分发全部在抖音/视频号/B 站平台侧，我们不是弹幕系统运营者，只是回流读取方。回流只有两种形态：①平台官方事件推送（webhook/MQ）→需公网接收端点→**云托管 HTTPS 网关即可，零自建**；②平台无官方推送时的长连接客户端→需常驻进程→**云托管「常驻不销毁」容器可承载，仍零自建**（能力出处 §3.1）。结论：弹幕回流不构成任何自建后端理由；若某平台既无官方推送又禁止第三方接入，该平台回流不可行→降级人工/本地脚本，而不是建服务器。三平台 API 现状/配额/接入流程细节归第 5 路调研员简报，本件不越界。

**建议裁 A**（一句话裁法：「公共商业平台允许托管后端，内部面零服务器不变」）。同时立法三条转B触发判据，任一满足才重新评估 B：
