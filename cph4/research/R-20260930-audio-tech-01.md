## 1. 微信小游戏音频技术面

### 1.1 两套音频 API 与官方定位【确认】
微信小游戏提供两套音频 API（官方指南原文）：
- **InnerAudio**（`wx.createInnerAudioContext`）：播放简便快捷、**支持流式播放**，但性能低于 WebAudio；官方定位：**适用于播放较大音频文件，比如背景音乐**。全局配置走 `wx.setInnerAudioOption`。
- **WebAudio**（`wx.createWebAudioContext`，或 `wx.createInnerAudioContext({useWebAudioImplement:true})`）：**播放性能好、能力丰富，但占用内存较大，建议短音频、播放频繁的音效使用**。解码走 `decodeAudioData`（异步）。

> 信源（微信官方·小游戏音频指南）：https://developers.weixin.qq.com/minigame/dev/guide/base-ability/audio.html

### 1.2 音频格式支持表（InnerAudioContext·官方表）【确认】

| 格式 | iOS | Android |
|---|---|---|
| mp3 | √ | √ |
| aac | √ | √ |
| m4a | √ | √ |
| wav | √ | √ |
| **ogg** | **×** | √ |
| flac | × | √ |
| ape / amr / wma / mp4 | × | √ |
| aiff | √ | × |
| caf | √ | × |

- **结论：双端通吃只有 mp3、aac、m4a、wav 四种；ogg（Vorbis 容器）在 iOS 的 InnerAudio 路径上不可用。**
- 旧版官方教程口径（供参考，以新文档为准）：「目前两个平台完全支持的音频格式有 mp3、aac、wav，其他格式存在系统差异，不保证支持」【待证（旧教程页）】https://mp.weixin.qq.com/debug/minigame/dev/tutorial/ability/audio.html

> 信源（微信官方·InnerAudioContext API）：https://developers.weixin.qq.com/minigame/dev/api/media/audio/InnerAudioContext.html

### 1.3 Unity/团结引擎转换后的音频解码路径【确认】
微信官方《Unity/团结引擎适配·音频视频适配》页：
- **UnityAudio 已自动适配微信小游戏，优先建议用 UnityAudio（即直接用 AudioSource 组件）；也支持 FMOD 插件**。
- **转换插件的自动路由：长音频播放使用 InnerAudio；短音频播放使用 WebAudio；插件按音频文件大小自动适配**（官方未公布大小阈值的字节量 → 阈值具体值【待证，需真机/插件源码验证】）。
- **官方推荐音频格式：mp3 或 aac，「在双端有较好的兼容」**。
- FMOD 路径全部走 WebAudio → 官方明示**不推荐 BGM 等大文件用 FMOD 播放（会占用很大内存）**。

> 信源（微信官方·Unity/团结引擎转换音频视频适配）：https://developers.weixin.qq.com/minigame/dev/guide/game-engine/unity-webgl-transform/Design/AudioAndVideo

### 1.4 已知坑清单（逐条官方证据）

**（1）autoplay / 首交互解锁【确认·Unity 官方 + 团结镜像同文】**
- 浏览器安全策略：用户未通过鼠标点击/触摸/按键交互前，不允许音频播放；官方建议用**加载屏让用户先交互、在主内容开始前启动音频**。
  - https://docs.unity3d.com/2022.3/Documentation/Manual/webgl-audio.html
  - 团结引擎镜像：https://docs.unity.cn/cn/tuanjiemanual/Manual/webgl-audio.html
- Unity 官方文档同时引用 Chrome Autoplay policy（自动播放策略会阻止页面加载后自动播 BGM）。
- 微信侧：小游戏由用户点击启动，通常自然满足首交互；但**基础库 2.25.3+ 创建 WebAudioContext 后需要主动调用一次 `resume()`**（微信官方注意事项）。
  - https://developers.weixin.qq.com/minigame/dev/guide/base-ability/audio.html

**（2）iOS 静音键（Ring/Silent Switch）【确认】**
- InnerAudio 的 `obeyMuteSwitch` 默认 **true**（遵循系统静音开关）；**2.3.0 起该属性不生效，统一用 `wx.setInnerAudioOption` 设置**。
  - https://developers.weixin.qq.com/minigame/dev/api/media/audio/InnerAudioContext.html
- Unity 官方（Web 平台）：**Load Type = Decompress On Load 的剪辑走浏览器 `AudioBufferSourceNode`，iOS 设备处于静音模式时可能完全无声**（WebKit 对该节点类型的分类与 `MediaElementSourceNode` 不同）；官方给出的解法：**若要保证静音模式下也能出声，把 Load Type 设为 Compressed In Memory**。（注：该节为 Unity 较新文档新增，团结 1.10 镜像暂未收录，但引擎管线相同；微信内实际表现仍以真机为准 → 微信内该结论【待证】）
  - https://docs.unity3d.com/2022.3/Documentation/Manual/webgl-audio.html

**（3）切后台 / 回前台行为【确认】**
- 微信官方示例代码：`wx.onHide` → WebAudio `suspend()`；`wx.onShow` → `resume()`；被电话等中断用 `wx.onAudioInterruptionBegin/End` 恢复；InnerAudio 在 `onShow` 时重新 play。
- **iOS 17.5+：小游戏退后台后 WebAudio 无法恢复播放，需销毁后重新创建**（官方注意事项，含官方示例代码）；**iOS 高性能模式**下有专门的重建逻辑。
  - https://developers.weixin.qq.com/minigame/dev/guide/base-ability/audio.html
- 转换插件 QA：**iOS 17.5 以上退后台返回后音效无法继续播放 → 官方答复「尝试更新最新的插件版本」**（兼容仍在进行中）。
- 转换插件 QA：iOS 偶现报错 `operateAudio:fail jsapi has no permission`——退后台时可能出现，官方答复「没有实际影响，可以忽略」。
  - https://developers.weixin.qq.com/minigame/dev/guide/game-engine/unity-webgl-transform/Design/AudioAndVideo

**（4）解码延迟【确认】**
- WebAudio 路径：需 `wx.request` 拉 ArrayBuffer → `decodeAudioData`（异步）→ 首次播放存在"网络 + 解码"双重延迟（官方示例代码即此流程）。
- Unity 官方对 CompressedInMemory 的定性：**"压缩音频可能造成延迟，且播放精度较低"**；DecompressOnLoad「低延迟、更灵活」。
  - https://docs.unity3d.com/2022.3/Documentation/Manual/webgl-audio.html

**（5）并发限制与卡顿【确认】**
- **Android 上 InnerAudio 最多同时播放 10 个音频，超出部分做有损处理**（开发者无感知，但应避免同时播放过多）。
- 转换插件 QA：**同时播放的音频数量过多可能造成游戏卡顿，官方建议限制同时播放的音频数量**。
  - https://developers.weixin.qq.com/minigame/dev/guide/base-ability/audio.html 、 https://developers.weixin.qq.com/minigame/dev/guide/game-engine/unity-webgl-transform/Design/AudioAndVideo

**（6）循环播放相关的坑【确认】**
- Unity WebGL 构建**把 AudioClip 转码为 AAC**；AAC 是授权格式，Unity 依赖宿主平台编码器转码，**编码器可能改动开头 1024 个样本，导致循环点出现可听毛刺**。官方缓解方案：源文件用 WAV、开头补 ≥1024 样本静音、编辑 smpl chunk 让循环点从静音之后开始。
  - https://docs.unity3d.com/2022.3/Documentation/Manual/webgl-audio.html
- 微信已知问题：**部分音频文件在安卓无法循环播放**（已知问题，8.0.51 客户端已修复）；**音频在 PC 端无法循环播放完整音频**（已知问题，更新最新 Unity 导出插件）。
  - https://developers.weixin.qq.com/minigame/dev/guide/game-engine/unity-webgl-transform/Design/AudioAndVideo

**（7）采样率运行时偏差【确认】**
- WebGL 上音频经浏览器 `decodeAudioData` 解码，**运行时采样率可能与序列化数据（44100Hz）不同**（浏览器会对齐 BaseAudioContext 采样率，一般跟随设备音频驱动）；官方建议：运行时校验 `AudioClip.frequency`，seek 操作用 `AudioSource.time`。
  - https://docs.unity3d.com/2022.3/Documentation/Manual/webgl-audio.html

**（8）其他官方注意事项【确认】**
- iOS 高性能模式不支持 `useWebAudioImplement`；iOS 长音频不支持设置 `playbackRate`。
- 实例管理最佳实践：相同音效应**复用已有 InnerAudioContext 实例**（而非新建）；不再使用的及时 `destroy()`。
  - https://developers.weixin.qq.com/minigame/dev/guide/base-ability/audio.html

## 2. Unity 官方 WebGL 音频最佳实践

### 2.1 WebGL 音频架构与能力边界【确认】
- WebGL 不支持 FMOD 依赖的线程 → **Unity 在 WebGL 用基于内部 Web Audio API 的自研实现**，浏览器负责播放与混音；**仅支持基础功能**（官方原文 "supports limited audio functionality, which only includes the basic features"）。
- 类支持状态：AudioSource（部分 API）、AudioListener（全部）、AudioClip（部分 API）、**AudioMixer（部分）**、`SystemInfo.supportsAudio` 恒为 true、**Microphone 不支持**。
- **AudioMixer 仅支持音量（`AudioMixer.SetFloat`）**——官方原文「Volume is the only property you can change on Unity WebGL. Other properties and sound effects aren't supported」。→ **所有混音/效果（EQ、压缩器、混响、低通等）在 WebGL/微信小游戏端全部失效，响度与音色必须在音频文件阶段定稿**。
- AudioSource 其他限制：**pitch 仅支持正值**；`AudioClip.Create` 不支持动态流式（`Stream` 参数必须为 false）；`SetData/GetData` 仅对 DecompressOnLoad 的压缩音频可用。
- 信源：https://docs.unity3d.com/2022.3/Documentation/Manual/webgl-audio.html ；团结引擎镜像（Version 1.10 / 2022.3，内容同源）：https://docs.unity.cn/cn/tuanjiemanual/Manual/webgl-audio.html

### 2.2 构建时格式：WebGL 统一转码 AAC【确认】
- Unity 2022.3 官方原文：**"Unity WebGL imports AudioClip files in the Advanced Audio Coding (AAC) Format, which is supported by most browsers."**（团结 1.10 镜像同句，未翻译）。含义：**导入时的 Compression Format（PCM/ADPCM/Vorbis）选择不会以原格式进入 WebGL 包体——构建管线把音频转码为 AAC**（AAC 为授权格式，转码依赖宿主机编码器；Linux 构建机需安装 ffmpeg）。
- 与微信兼容性核对：AAC 恰好落在微信 InnerAudio 双端支持表内（§1.2）→ **Unity WebGL→微信小游戏的音频产物天然满足微信官方"推荐 mp3 或 aac"的口径**；"BGM 用 Vorbis 在 iOS 不可播"的担忧不成立于转换后的产物（产物是 AAC，不是 Ogg）。ogg/Vorbis 只在**绕过引擎管线、直接用 `wx.createInnerAudioContext` 播 .ogg 文件**时才会踩 iOS 不支持的坑。
- 官方文档未逐项说明 PCM/ADPCM/Vorbis 三种导入格式在 WebGL 转码后的差异表现 → 导入格式对 WebGL 端最终音质/体积的净影响【待证，建议用构建产物实测核对】。
- 循环毛刺风险见 §1.4-（6）。

### 2.3 Load Type 在 WebGL 的支持与官方推荐【确认】
- **WebGL 压缩音频只支持两种 Load Type：CompressedInMemory 与 DecompressOnLoad**（官方原文 "To use compressed audio with WebGL in Unity, set the AudioClip loadType to one of the following options: CompressedInMemory, DecompressOnLoad"）。
- **Streaming 在 WebGL 不可用**：官方 WebGL 页未将其列入可选项；且 `AudioClip.Create` 注明「Browsers don't support dynamic streaming, so to use AudioClip.Create, set the Stream to false」。通用文档还注明 Streaming 剪辑即使不加载音频数据也有约 200KB 开销（供其他平台参考）。
- 官方推荐语义（WebGL 页原文）：
  | Load Type | 官方描述 | 官方推荐用途 |
  |---|---|---|
  | CompressedInMemory | 磁盘压缩、载入内存后**保持压缩**，播放时解压；**省内存**，但"压缩音频可能造成延迟、精度较低" | **"best practice … for audio that's unaffected by precision, for example, background music"**（对精度不敏感的音频，例如背景音乐） |
  | DecompressOnLoad | 磁盘压缩、**加载时即解压**；内存占用大（通用文档：Vorbis 约 10 倍、ADPCM 约 3.5 倍于压缩态），**低延迟、更灵活** | **"for audio that's affected by precision, for example, character dialog or sound effects"**（对精度敏感的音频，例如角色对白或音效） |
- 通用平台文档补充（同样官方）：Decompress On Load **"用于较小的压缩音效"（don't use this option for large files）**——即它对小体积 SFX 是推荐值，对大文件（BGM/长语音）会爆内存。
  - https://docs.unity3d.com/2022.3/Documentation/Manual/webgl-audio.html 、 https://docs.unity.cn/cn/tuanjiemanual/Manual/webgl-audio.html 、 https://docs.unity3d.com/2022.3/Documentation/Manual/class-AudioClip.html
- **冲突点（必须在规范中写明）**：DecompressOnLoad 在 Web 平台受 iOS 静音模式影响（§1.4-2）——官方为"静音模式下仍出声"给出的方案恰是 SFX 走 CompressedInMemory，与"SFX 低延迟用 DecompressOnLoad"互相牵制；微信小游戏实际取舍见 §6。

### 2.4 AudioClip.loadInBackground【确认（通用行为）；WebGL 专项行为无官方文档】
- 官方定义（2022.3 ScriptReference）：启用后 AudioClip **在后台线程异步加载**而非主线程；适合**大量/大文件**加载，防止掉帧；Inspector 只读设置，运行时不可改（可用 `AudioImporter.loadInBackground` 预设）。https://docs.unity3d.com/2022.3/Documentation/ScriptReference/AudioClip-loadInBackground.html
- Manual（class-AudioClip）：默认关闭（保证场景开始播放时所有剪辑已加载完成）；开启后**对仍在加载中的剪辑的 Play 请求会推迟到加载完成**；加载状态用 `AudioClip.loadState` 查询。https://docs.unity3d.com/2022.3/Documentation/Manual/class-AudioClip.html
- WebGL 特例：官方 WebGL 页对 loadInBackground **无专项说明**（文档缺失本身是确认事实）；WebGL 无真实线程、浏览器 `decodeAudioData` 本身异步，故该开关在 WebGL 上的实际效果主要是**引擎内资源加载时序**（是否阻塞启动/是否推迟首播）【待证：无官方专项文档，以真机为准】。
- 相关默认值：Preload Audio Data 默认开启（场景加载后预载）；关闭则首播/`LoadAudioData` 时才加载【确认·class-AudioClip】。

### 2.5 导入侧官方参数备忘（跨平台通用，供生产批使用）【确认】
- 源文件可导入格式：.aif / .wav / .mp3 / .ogg（+tracker 模块 .xm .mod .it .s3m）；声道支持 mono/stereo/多声道（最多 8 声道）。
- Compression Format 语义（选项随构建目标而变）：PCM=短音效最佳（大体积）；**ADPCM=噪声类、大批量播放音（脚步/打击/武器）的推荐格式，体积约 PCM 的 1/3.5，CPU 远低于 MP3/Vorbis**；Vorbis/MP3=中等长度音效与音乐（Quality 滑杆可调）。
- Sample Rate Setting：PCM 与 ADPCM 支持自动/手动降采样（Vorbis 不适用该设置）。
- Force To Mono：下混后自动峰值归一化（下混通常变安静，归一化给后续 AudioSource volume 留 headroom）。
- Quality 不适用于 PCM/ADPCM。
- 信源：https://docs.unity3d.com/2022.3/Documentation/Manual/class-AudioClip.html

## 3. 包体预算：微信 4MB 主包限制下的音频策略

- 转换工具语境补充【确认】：Unity/团结转换产物中，"首资源包"= `*.webgl.data.unityweb.bin.txt`（Unity builtin＋勾选导出的场景＋**Resources 资源**）；wasm 代码＋首包资源 < 20MB 时可整体"小游戏包内"加载、免部署服务器，否则走 CDN。资源服务器注意：并发下载数 10、**官方建议单文件 2~5MB 以内**、txt 开 brotli/gzip 压缩率极高。https://developers.weixin.qq.com/minigame/dev/guide/game-engine/unity-webgl-transform/Design/DataCDN.html
  - 该页另有"小游戏总包体不能超过20MB"表述，与代码包页 30M 不一致，疑为旧口径未同步更新 →【待证，以开发者工具实际上传校验为准】
- **微信小游戏环境不支持加载本地 Bundle**：AA/AB 包、Instant Game 三种方案最终都采用"上传 CDN、运行时异步下载"【确认】。资源按需加载概述：https://developers.weixin.qq.com/minigame/dev/guide/game-engine/unity-webgl-transform/Design/ResourcesLoading.html
- Instant Game 的懒加载资源类型**包含音频资源**（纹理、模型、骨骼动画、音频资源）【确认·同上页对照表】
- 官方对"原生 APP 未做按需加载的轻度休闲游戏"的建议：快速适配＋首场景启动优化＋**关卡分包加载**；建议用 Unity Instant Game 缩短转化周期【确认·同上页】
- 代码包文件定位（官方）：只应放"首次加载需要的文件"；内容较大或需动态替换的文件，推荐启动后下载到本地【确认·文件系统页】
- 转换插件已对 AssetBundle **自动缓存**，无需再自建本地文件缓存/版本更新【确认·资源按需加载概述】

### 3.2 音频压缩当量估算（算术＋官方比值）
44.1kHz / 16bit 基准（1 分钟时长）：
| 格式/配置 | 码率 | 每分钟体积 | 备注 |
|---|---|---|---|
| PCM 立体声 | 176.4 KB/s | ≈10.1 MiB | 1 首立体声 BGM ≈ 吃掉 2.5 个主包 |
| PCM 单声道 | 88.2 KB/s | ≈5.0 MiB | |
| ADPCM（单声道） | — | ≈PCM 的 1/3.5（**官方比值**【确认】class-AudioClip："The compression ratio is 3.5 times smaller than PCM"） | CPU 远低于 MP3/Vorbis【确认】 |
| Vorbis/AAC/MP3 @128kbps | 16 KB/s | ≈0.92 MiB | Unity WebGL 构建即 AAC |
| Vorbis/AAC @64kbps（单声道语音/简单音效够用） | 8 KB/s | ≈0.46 MiB | |
| PCM 22050Hz 单声道（UI click 级） | 22.05 KB/s | ≈1.26 MiB | 0.2s 的 click ≈ 4.4 KB |

**结论（算术推演）：在 4MB 主包语境下，未压缩音频基本不可行；有损压缩约为 PCM 体积的 1/10~1/20。**

### 3.3 放主包 / 放分包 / 走 CDN 的取舍
| 路线 | 优点 | 代价/风险 | 音频适用性 |
|---|---|---|---|
| 主包（≤4MB） | 零网络依赖、离线可用 | 空间极其紧张（引擎胶水代码＋首屏资源优先） | 只放启动即用的极小 UI 音效；业界实测文章将音频压缩列为主包瘦身手段之一【待证】https://blog.csdn.net/weixin_32631179/article/details/161375991 |
| 分包 | 微信负责缓存、离线可复用；`preDownloadSubpackage` 可提前拉 | 计入总包 30M；Unity/团结转换链路对"本地 Bundle 加载"不支持（转换工具的主分包机制针对 wasm/首资源包） | 适合"关卡/玩法包"内中等音频；腾讯云社区观点："若仍超限，优先选择分包加载而非远程资源（微信会缓存分包节省流量）"【待证】https://cloud.tencent.com/developer/article/1640755 |
| CDN 远程 | 无总量压力；BGM 天然适合 InnerAudio 流式播放【确认·音频指南】 | 首次依赖网络/弱网体验；需域名白名单与缓存头治理 | **BGM/长音频/大音效的默认路线**；本地缓存上限 200MB 对休闲游戏音频总量足够【确认】 |

**对吸嘟嘟的分工建议**：主包＝少量启动 UI 音（百 KB 级）；玩法 SFX＝AB/AA 包随关卡按需（CDN）；BGM＝CDN＋InnerAudio 流式（插件对长音频自动走 InnerAudio【确认】）。BGM **不要放 Resources 目录**——Resources 资源会被打进"首资源包"【确认·DataCDN 页】。

### 4.2 对内部标准的逐项复核
**先辨析一个层级问题**：Sony/GANG/AES 的数字是**整局游戏混音（≥30 分钟代表性玩法）**或**流媒体节目**的目标；我们内部标准（SFX -16 / BGM -18 / ≤-3 dBTP）是**单条素材交付**规范。两者不是同一层面，不能拿 -23 直接改素材标准；素材级响度业界**没有单一权威值**，只有惯例区间（SFX/对白素材约 -16~-23、音乐素材 -14~-18、SFX 比 BGM 响 2~4 LU 以在混音中占前）。

| 内部标准 | 外部证据对照 | 判定 |
|---|---|---|
| 交互音效 -16 LUFS | 与 GANG"便携设备 -16"一致；与 AES"不超过 -16"上限一致；高于索尼便携 -18（更响）；处于 SFX 素材惯例区间（-16~-23）的响端 | **成立·保留**。移动/休闲在嘈杂外放环境普遍取偏响端，有依据；属主流上沿而非离群 |
| BGM -18 LUFS | 恰等于索尼便携基准 -18；比流媒体音乐交付（-14）与 CLL 音乐素材建议（-14）低 4 LU，为游戏内混音留衰减余量；与 SFX 形成 2 LU 相对差 | **成立·保留**。比 BGM 更响才属异常 |
| 真峰值 ≤ -3 dBTP | 主流标准全部为 -1（AES/Sony/EBU/GANG），A/85 为 -2；我们**保守 2 dB** | **成立·保留，但需注明理由**：素材级语义下，-3 dBTP 为"叠加＋编码重采样过冲"留双倍余量；且**微信小游戏端 AudioMixer 仅支持音量、压缩/限幅器全部失效（§2.1【确认】）**——素材 headroom 是小游戏端唯一防线，-3 dBTP 反而比照抄 -1 dBTP 更稳。若 Win64 未来接总线限幅器，可放宽至 -1 dBTP |

### 4.3 定谳
-16/-18/-3 dBTP **方向正确，无外部证据要求推翻**；规范文本应补三点：①此为素材级交付标准，与整局混音标准分层；②SFX 与 BGM 保持既定相对差；③因 WebGL 端无总线动态处理，素材真峰值纪律在小游戏端不可放宽。

## 5. 单声道 vs 立体声：UI 音效/SFX 的取舍依据

### 5.1 一手（官方）证据
- Unity 提供 **Force To Mono** 导入选项：下混后自动**峰值归一化**（下混通常变安静，归一化为后续 AudioSource volume 调整留 headroom）【确认】https://docs.unity3d.com/2022.3/Documentation/Manual/class-AudioClip.html
- Unity 支持 mono/stereo/最多 8 声道素材导入；旧版官方文档明确"mono 与多声道素材均可被 3D 定位"——即"立体声不能 3D"不是引擎硬限制，而是质量/资源取舍【确认（旧版文档）】https://docs.unity3d.com/355/Documentation/Components/class-AudioClip.html
- 微信侧内存压力：WebAudio"占用内存较大"（官方对短音频路线的定性）＋Android InnerAudio 并发 ≤10【确认】→ 音频内存需要省着用。

### 5.2 二手最佳实践（社区一致口径）
- 3D/空间化 SFX 用 mono："Most SFX are positional (3D). **Mono is required for Unity's spatial audio. Halves RAM usage. Stereo SFX sound wrong when spatialized.**"【待证】https://gamedevcheatsheet.com/audio-settings
- UI 音效用 mono："UI sounds are non-spatial. **Mono saves memory and there is no stereo benefit for a button click.**"【待证】同上
- 移动游戏大多数 SFX 转 mono、内存近减半【待证】https://dev.to/gameoptim/how-can-you-optimize-audio-resources-in-unity-without-hurting-performance-or-sound-quality-3bg
- 立体声素材双声道自同一世界点发出（3D 定位下无意义）【待证】https://medium.com/@truongpham/optimize-unity-game-performance-optimizing-audio-checklist-4dd0fff93be7
- BGM/音乐保持立体声（"Music is typically stereo. Forcing to mono would destroy the mix."）【待证】gamedevcheatsheet

### 5.3 取舍汇总（尺寸/兼容/听感）
- **尺寸**：PCM/ADPCM 下立体声=单声道 2 倍（算术事实）；有损编码（Vorbis/AAC joint-stereo）立体声开销约 1.2~1.5 倍、低于 2 倍【待证：随编码器实现浮动，无单一权威数值】。
- **兼容**：单声道是所有编解码器/播放路径的基本形态，微信双端（InnerAudio/WebAudio）均无 mono 兼容性问题；立体声在 iOS/Android 解码差异只取决于容器格式（§1.2）而非声道数。
- **听感**：UI/交互音效设计上是点声源、中心成像，立体声宽度收益主要出现在耳机场景；外放场景（不少机型仍为单扬声器或对称双扬）收益有限【待证】；3D 空间音效用立体声素材会在空间化时产生相位/定位异常（上引二手最佳实践）。
- **结论**：**UI 音效=单声道；交互/玩法 SFX（含 3D 定位）=单声道；BGM=立体声；2D 环境氛围音=可立体声；需要 3D 定位的环境音=单声道**。生产批统一在源文件阶段做单声道（或导入时 Force To Mono＋Normalize），禁止"伪立体声"（L=R 复制）素材入库。

## 6. 对吸嘟嘟的落地建议（现有导入矩阵逐条复核）

现有矩阵：**BGM = Vorbis + CompressedInMemory + loadInBackground ｜ SFX = PCM + DecompressOnLoad**（吸嘟嘟音频生产批现行标准）

### 6.1 BGM = Vorbis + CompressedInMemory + loadInBackground

**（1）Vorbis（导入格式）→ 定谳：保留，附 2 条注意事项**
- Win64：Vorbis 为官方通用推荐格式之一（"中等长度音效与音乐"），无问题【确认】。
- 微信小游戏：**WebGL 构建把 AudioClip 统一转码为 AAC**【确认】，产物恰好落在微信双端支持表（aac：iOS√/Android√）内——"Vorbis 在 iOS 播不了"的坑**不成立**于引擎管线产物，仅成立于"绕过引擎、直接 `wx.createInnerAudioContext` 播 .ogg 文件"的路线（ogg：iOS×/Android√）【确认·格式表】。
- 注意事项 A（循环）：AAC 编码器可能改动开头 1024 样本 → 无缝循环 BGM 有接缝风险。官方缓解：**源文件用 WAV、开头补 ≥1024 样本静音、编辑 smpl chunk 让循环点从静音后开始**【确认】。生产批 BGM 源一律 WAV 交付、循环点在 DAW 内定稿。
- 注意事项 B（备用路线）：若日后有"外挂 BGM 文件 + wx API 直播"的需求，文件格式必须 mp3/aac/m4a/wav（微信官方也只推荐 mp3/aac【确认】）。

**（2）CompressedInMemory（Load Type）→ 定谳：保留（微信端为官方明示推荐值；Win64 为可优化项）**
- Unity 官方 WebGL 页明示：CompressedInMemory 用于"对精度不敏感的音频，**例如背景音乐**"【确认】——现行设置与官方推荐完全一致。
- 微信端长音频由插件自动路由到 InnerAudio 流式播放【确认】，与 CompressedInMemory 语义契合。
- Streaming：**微信端不可用**（WebGL 不支持动态流式【确认】）；Win64 上 Streaming 是社区对 BGM 的常规推荐（省 RAM、几乎不占内存），但桌面内存宽松、非必需【待证·gamedevcheatsheet】。→ 建议：为 Win64 建平台 override，仅当内存剖析显示压力时才把 BGM override 成 Streaming；默认双平台统一 CompressedInMemory，降低管理成本。

**（3）loadInBackground → 定谳：保留，附真机验证项**
- 官方语义：后台异步加载防主线程掉帧，适合大文件；代价是**未加载完成的剪辑 Play 请求会被推迟**【确认】。BGM 属大文件，适用。
- 真机验证项（见 6.4-6/7）：微信端"首帧 → BGM 首响"延迟链路；SFX 类**不要**勾 loadInBackground（官方推荐 SFX 即时可用，社区口径同向【待证】）。

### 6.2 SFX = PCM + DecompressOnLoad

**（1）PCM（导入格式）→ 定谳：保留（为 Win64 保留），但须认知修正**
- **认知修正（本调研最重要发现之一）**：WebGL 构建统一转码 AAC【确认】→ **PCM 导入设置对微信端产物不生效**，微信端 SFX 的实际体积/音质由 AAC 转码决定（转码码率官方未文档化【待证，构建产物实测】）。现行 SFX=PCM 的真实收益只在 Win64（原生 PCM 零解码、低延迟、最高质量）。
- 推论：微信端 SFX 体积控制必须做在**源文件**层面（单声道、22050/44100kHz 按需、时长裁剪去首尾静音），而不是指望导入格式。
- 备选：若 Win64 端 SFX 库膨胀，ADPCM 为官方推荐的"大批量/噪声类"SFX 格式（体积≈PCM 1/3.5、CPU 远低于 Vorbis/MP3【确认】）；当前项目规模无切换必要。

**（2）DecompressOnLoad（Load Type）→ 定谳：保留，附 1 个 P0 必测项**
- Unity 官方 WebGL 页明示：DecompressOnLoad 用于"对精度敏感的音频，**例如角色对白或音效**"【确认】——现行设置与官方推荐一致。
- **P0 必测项（写入真机验收矩阵）**：**iOS 静音键（Ring/Silent Switch）开启时的出声行为**。Unity 官方 Web 行为：DecompressOnLoad 剪辑经 `AudioBufferSourceNode` 播放，**iOS 静音模式下可能完全无声**；官方解法是改 CompressedInMemory【确认·Unity 官方】。微信端短音频走 WebAudio（decodeAudioData→BufferSource），属同一节点类型；且官方 WebAudio 注意事项未提供静音键配置项（obeyMuteSwitch/setInnerAudioOption 均为 InnerAudio 侧配置）→ **WebAudio 路径静音键行为无可配置项、以真机为准【待证】**。
  - 若产品要求静音键下仍出声：方案 A = SFX 改 CompressedInMemory（Unity 官方解法，代价：延迟与精度）；方案 B = 关键提示音走 InnerAudio＋`wx.setInnerAudioOption({obeyMuteSwitch:false})`。需产品拍板；本调研只要求把"**iOS 静音键 ON → SFX 可能全静音**"作为已知风险写进规范。

### 6.3 新增规范条目建议（供生产批直接采纳）
1. **声道纪律**：UI/交互/玩法 SFX 一律单声道源文件（或 Force To Mono＋Normalize）；BGM 立体声；禁止 L=R 伪立体声入库（§5）。
2. **响度纪律**：维持素材级 -16 LUFS（SFX）/-18 LUFS（BGM）/≤-3 dBTP（§4.3）；每条素材元数据记录 Integrated LUFS 与 dBTP 实测值；WebGL 端 AudioMixer 仅音量可调、无总线动态处理【确认】，素材响度纪律不可放宽。
3. **循环纪律**：无缝循环素材按官方缓解法处理源文件；**吸嘟嘟核心的"吸尘持续音"为循环接缝最高风险项**，微信双端真机回验必做；同时跟进微信已知问题（安卓循环已修复于 8.0.51；PC 端循环需最新插件）【确认】。
4. **并发纪律**：同时播放 ≤10（Android InnerAudio 上限；WebAudio 过多会卡顿【确认】）；相同音效复用实例、闲置及时 destroy【确认】。
5. **生命周期**：接 `wx.onShow/onHide` 与 `onAudioInterruptionBegin/End`；iOS 17.5+ WebAudio 重建依赖插件版本——**转换插件保持最新**【确认】。
6. **包体分工**：主包只放启动 UI 音（百 KB 级）；BGM/大音效走 AB/AA＋CDN（微信不支持本地 Bundle 加载，最终都走 CDN【确认】）；**BGM 严禁放 Resources**（会被打进首资源包【确认】）；单音频文件 ≤5MB（官方单文件建议 2~5MB【确认】）。
7. **采样率**：全库统一一种采样率（44.1kHz 或 48kHz 任选其一，UI click 可 22050），不混用；WebGL 运行时采样率由 BaseAudioContext 决定、可能≠源【确认】，seek 用 `AudioSource.time`，必要时运行时校验 `AudioClip.frequency`。
8. **平台 override**：导入矩阵用 Unity 平台 override 分别配置 WebGL（微信）与 Standalone（Win64）；两平台策略不同时（如 BGM Streaming）只在 Win64 侧改。
9. **交付源格式**：SFX/UI 用 WAV 源；BGM 用 WAV 源（循环接缝可控）；避免 MP3 源（二次压缩＋编码器 padding 影响 UI 响应与无缝循环【待证】）。
