## 一、Q1 答面（VFX Graph WebGL 支持度·承重闸=判负）
- 硬门槛【确认·A·https://docs.unity3d.com/Packages/com.unity.visualeffectgraph@14.0/manual/System-Requirements.html】：官方原文「the minimum hardware requirements are: Support for compute shaders…Support for Shader Storage Buffer Objects (SSBOs)」——compute shader+SSBO=VFX Graph 最低硬件要求。
- compute 平台表【确认·A·https://docs.unity3d.com/2022.3/Documentation/Manual/class-ComputeShader.html】：官方原文「Platforms where compute shaders work: Windows…DirectX 11 or 12…macOS and iOS using Metal…Vulkan…OpenGL 4.3…OpenGL ES 3.1 on Android…Modern consoles」——**表内无 WebGL**；且 WebGL 2.0 仅≈OpenGL ES 3.0（【确认·A·webgl-graphics.html】原文「WebGL 2.0 roughly matches OpenGL ES 3.0 functionality」）＜GLES 3.1 compute 门槛。
- 加重证据【确认·A·System-Requirements 页·双 A 源互证：docs.unity3d.com 本波直读+docs.unity.cn 主会话直读】：官方原文「The Visual Effect Graph does not support Open GL ES」「isn't out of preview for URP…only supports some of the platforms that URP supports…only supports unlit particles」「isn't out of preview for mobile platforms」。
- **承重闸定谳：VFX Graph 在 WebGL 不可用（三链 A 级直读闭环）→ 3D 事件演出载体正式排除 VFX Graph**。对照组【确认·A·https://docs.unity3d.com/2022.3/Documentation/Manual/Built-inParticleSystem.html】：官方原文「allows you to create effects for every platform that Unity supports」=全平台可用；量级对比 Built-in「Thousands」vs VFX「Millions」【确认·A·ChoosingYourParticleSystem.html】——事件演出量级（脉冲/光点/光带）无缺口。装机验证兜底：官方在册运行时探针「Compute shader support can be queried runtime using SystemInfo.supportsComputeShaders」【确认·A·class-ComputeShader.html】→ 团结引擎 WebGL 实测 supportsComputeShaders==false 留证项并入任务单（止损令指令）。
## 二、Q2 答面（ParticleSystem/移动光点/Timeline）
- CPU 模拟本质【确认·A·Built-inParticleSystem.html】：官方原文「The Built-in Particle System simulates particle behavior on the CPU」；叠加 WebGL 官方口径【确认·A·webgl-performance.html】「The JavaScript language does not support multi-threading or SIMD」「WebGL performance is close to native apps on the GPU…On the CPU, Emscripten translates your code into WebAssembly」→ 粒子模拟成本落 CPU 瓶颈面，Max Particles 预算必须收紧。
- Prewarm【确认·A·PartSysMainModule.html】：官方原文「the system is initialized as though it had already completed a full cycle (only works if Looping is also enabled)」→ 循环待机演出（常驻灯带）开 Prewarm=出场即满态；一次性脉冲（非 Looping）不适用。
- Max Particles【确认·A·同页】：官方原文「The maximum number of particles in the system at once. If the limit is reached, some particles are removed.」→ 超预算=静默删粒（演出走样），预算须显式设；Ring Buffer 模式=到 Max 才回收最旧（同屏量恒定·官方在册机制）。
- Simulation Space 建议【确认·A·同页】：官方用法原文「…tend to leave trails that persist in the world space even if the object producing them moves around」→ **移动光点拖尾过江=World（或 Custom）**：本体随 Transform 位移、拖尾留世界空间。
- 拖尾载体【确认·A·PartSysTrailsModule.html】：Trails 官方定位「useful for a variety of effects, such as bullets, smoke, and magic visuals」；顶点量旋钮=Ratio（有拖尾粒子占比）+Minimum Vertex Distance（原文「the distance a particle must travel before its Trail receives a new vertex」）+Lifetime；World Space 强制拖尾落世界；Ribbon 模式=连粒子成带（街带光流可复用）；拖尾性能官方无数字⬜。
- 池化官方口径【确认·A·https://docs.unity3d.com/2022.3/Documentation/ScriptReference/Pool.ObjectPool_1.html】：官方原文「Object Pooling is a way to optimize your projects and lower the burden that is placed on the CPU when having to rapidly create and destroy new objects」，且**官方示例即 ParticleSystem 池**：stopAction=Callback→OnParticleSystemStopped→pool.Release——高频一次性脉冲（commit 光点过江）复用正法在册。
- Culling/一次性清理【确认·A·PartSysMainModule.html】：官方原文「Culling when offscreen is most efficient」（复杂系统慎用 Pause And Catch-up——官方原文可致「performance spikes」）；Stop Action=Destroy/Disable/Callback 支持一次性演出自动回收。
- Timeline 可用性【确认·A·https://docs.unity3d.com/Packages/com.unity.timeline@1.7/manual/index.html】：Requirements 仅列「2019.1 and later」编辑器版本，**无任何平台限制记载**；包内容含 Player 运行时源码（原文「This is the source for what is available in the Player」）→ 据此推断 WebGL 可用🟡；Timeline 开销官方无数字⬜。结论：一次性事件演出维持**脚本 Transform 驱动为主**（沿袭 2D 定谳·CPU 足迹最小），Timeline 留作多轨复杂编排可选项🟡。
## 三、Q3 答面（emission 脉冲与 SRP Batcher 坑）
- MPB 要点【确认·A·https://docs.unity3d.com/2022.3/Documentation/ScriptReference/MaterialPropertyBlock.html】：官方原文「Use it in situations where you want to draw multiple objects with the same material, but slightly different properties」+「Changing the render state is not supported」——逐 renderer 覆写、不复制不污染共享材质。
- MPB×SRP Batcher 官方定谳【确认·A·同页直读】：**「Note that this is not compatible with SRP Batcher. Using this in the Universal Render Pipeline (URP), High Definition Render Pipeline (HDRP) or a custom render pipeline based on the Scriptable Render Pipeline (SRP) will likely result in a drop in performance.」**→ URP 14 下 MPB 非正法。
- 双向实锤【确认·A·https://docs.unity3d.com/2022.3/Documentation/Manual/SRPBatcher.html】：SRP Batcher 兼容要件原文「The GameObject mustn't use MaterialPropertyBlocks」；且官方把「add a MaterialPropertyBlock to the renderer」列为**主动解除 SRP Batcher 兼容**的手段——MPB=SRP 掉批开关。
- URP 运行时改材质正法【确认·A·同页】：官方原文「use as few shader variants as possible. You can still use as many different materials with the same shader as you want」→ **少量材质实例（脑塔/地标各持独立材质）+保持同 shader variant**：运行时改 emission/颜色不破批（材质数据驻 GPU 常量缓冲）；URP lit/unlit 全系默认 SRP Batcher 兼容（原文「All lit and unlit shaders in…URP fit this requirement」）。
- emission 载体【确认·A·https://docs.unity3d.com/Packages/com.unity.render-pipelines.universal@14.0/manual/lit-shader.html】：Lit·Emission 属性官方原文「Makes the surface look like it emits lights…Emission Color…more than 100% white（HDR）…If you do not enable Emission, URP sets the emission to black and does not calculate emission」→ 脑塔呼吸灯/窗灯点灭=运行时改 Emission Color（材质实例法）；运行时开关 _EMISSION keyword 细节官方未载明🟡（落地后以 Frame Debugger 验批次）。
- 配套坑【确认·A·SRPBatcher.html】：粒子不进 SRP Batcher（原文「It can't be a particle」+粒子版 shader 除外条款）→ 粒子载体性能只靠预算+Culling，不指望合批。
