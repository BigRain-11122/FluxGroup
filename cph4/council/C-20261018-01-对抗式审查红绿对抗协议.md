## 二、红绿对抗协议（立法正身）

### 对抗三律（防互搏的机制核心）

- **律一·角色分离**：红队（审查席）只对**交付物**出问题清单，不参与设计、不给方案——「只挑刺不开方」；红队若出方案=越位违规（该轮清单作废重审）。
- **律二·对象分离**：绿队（交付席）对红队清单只有三种合法响应：**接受修复 / 举证反驳 / 提请裁决**。不得否定红队存在、不得报复性反审（对红队的质量问题走 PROBLEM-REGISTRY 正常记账，不搞对耗）。
- **律三·不重复审**：机器门禁可验的面（编译/断言/门禁链/程序计数）**不进对抗层**——红队专攻机器验不了的：体验质量、审美、词不达意、隐藏副作用、声称与实证的差距。对抗层重跑机核=浪费（双倍审查）。

### 组织：三机交叉轮换环

```
A 机交付 → B 机红审 → B 机交付 → C 机红审 → C 机交付 → A 机红审（环）
```
- 红审由被审方的**邻机**窗口执行（独立会话/独立子代理=物理上下文隔离）；同机不得自证。
- **轮换周期**：每对抗回合后角色轮换（审人者亦被审=互相监督的闭环）；固定任红队超两回合=养匪风险，强制轮换。

### 分级触发（高效落地律——对抗不摊薄效率）

| 交付级别 | 对抗强度 |
|---|---|
| P0 令/对外发布/成品呈 CEO/大额消费（≥500 积分） | **强制红绿双签**（无红签不得出库/呈报） |
| 常规轮产出 | **20% 概率暗审**（抽审面随机触发·被审方事后才知） |
| 机械活/机核面已全覆盖的小活 | 免对抗（门禁绿即过） |

### 判据与 KPI（互相制约的计量面）

- **红队 KPI**：真发现率（A/B 级问题入账数）+误报约束（A/B 级误报率>30%=该轮红队失格·council 记账）；红队漏审（后续被 CEO/市场打脸的 A 级问题）=红队连带责任。
- **绿队 KPI**：一轮过率（红签一次到手）+A/B 级问题修复闭环率（走 PROBLEM-REGISTRY 五件套）。
- **环账**：所有 A/B 级发现→PROBLEM-REGISTRY（复发计数永不归零·二犯问责既有法）。

### 裁决链

接受修复→修复验证→红签；举证反驳→红队认账或僵持→**council 裁决席一裁终局**（双引原文+证据对·24h 内裁）；重大分歧报 CEO。

## 三、与既有席位的分工（防机构打架）

| 席 | 审什么 | 不审什么 |
|---|---|---|
| 机器门禁（四门禁/CheckBundle/断言链） | 一切可程序验证 | — |
| 领域专家席（十三席/DIRECTOR-GATE） | 专深领域质量（MV 导演审/美术审/玩法审） | 不做独立质量对抗（领域内自审仍受红队抽查） |
| **红队（新设常设）** | 交付物整体质量、宣称与实证差距、跨域副作用、隐藏风险 | 不重跑机核·不出设计方案·不越领域专深（可调专家陪审） |
| council 裁决席 | 对抗僵持裁决 | 不预设立场 |

## 四、双源复审制（大交付的标准协议·星晴先例升格）

凡强制红绿双签级交付：主审（交付侧自审+专家审）之外必须有**第二源独立复审**——独立窗口/独立子代理从零起审（不看主审结论先独立判·后对照）；双源一致=加固签发；双源冲突=保守面+抽格终证（星晴 REVIEW2 模式）。
