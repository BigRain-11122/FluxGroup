### C. 根治缺口诊断（为什么六令没根治）
1. **「闲」无统一度量**：idle 判定靠各机自报心跳+值守轮人工扫读，无**机队级每小时利用率台账**（CPU/GPU/RAM/在飞单四指标）——BG-C 「忙但黑灯」vs bigstream「真闲」无法区分。
2. **自领依赖轮活**：GREEN-IDLE 自领 ≤1h 律靠 OS 循环每轮自查——**循环停跳=自领死**（BG-B 停跳史），无外部兜底。
3. **常设备货池空**：P-03 分工矩阵给了「谁该干什么」但没给「闲了马上接什么」——**无活可领**即真闲（自主领令后无单可领=N+1 问题）。
4. **产出与闲的闭环断裂**：产出计分制（C-02）计了分但**没接派工**——0 分司的「CEO 派产一件」依赖 CEO 手动。
5. **CEO 观测面滞后**：CEO 看到「闲」常来自心跳面滞后/黑灯（BG-C 心跳 STALE 但机器满载）——观测失真也是「感知闲置」源。

## 二、根治四条（机制收口案·零新动员令）

1. **机队利用率小时台账**（度量根治）：各机心跳已含 CPU/GPU/RAM 字段（P-33 立过）→值班轮每小时一行汇总（机器×利用率×在飞）入 machine-health.json（新文件但为**数据面**非规则面·法熵不计）——「闲」从此有数可指。
2. **常设备货池**（活源根治）：集团常设**≥10 件备货单池**（资产/内容/研究三线各 ≥3·各司自产线余量随时可领）——GREEN-IDLE 机器领池即产·池空=秘书处补货责任。备货池建在 fleet/backlog.md（零新台账面争议：fleet 目录既有）。
3. **心跳停跳外部兜底**（自领死根治）：值守轮点名面加「停跳机外部 ping」步（心跳 STALE >2h 的机器·值班轮直接远程探测 git log 新鲜度+进程面·如实判「黑灯但忙」vs「真停」）——区分 BG-C 型假闲。
4. **0 分派工自动化**（闭环根治）：产出计分周 0 分司=**秘书处自动从备货池派单**（不等 CEO）·fleet O 令即派——「CEO 派产一件」降级为兜底。

判据预注册（10-08 回访·与 C-01/C-02 同窗）：①机队小时台账在役（连续 7 天有行）②备货池常在 ≥10 件 ③心跳 STALE >2h 机器外部探测覆盖率 100%（当班有行）④周 0 分司数=0 ⑤CEO 「闲置」类令数（回访窗内）=0。
