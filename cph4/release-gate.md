# Release-Gate — 对外发布安全门 v1.0（CPH4 Labs）

> 溯源：CEO 令 2026-09-24 晚「对外发布前，打包的时候一定要做安全措施，不能让外部直接看到我的代码或者其他的东西。我说的比较模糊，你自己想好，而且建立顶层机制，但是也是最后一步对外公开，是我批准之后才做这一步」——设计授权=委托自决（本件即具体化）。T2 生效+7 天否决窗。
> 定位：一切「从私域到外部可见面」的包出动作的唯一门禁。**吸收并升格 P-51②（私库转公开前置门）为闸 3 的一个面**；与发布锚律（versioning §3.4 先 tag 后发）、内容合规门（BigStream M4/M5·管内容不管代码）互为引用不重复。

## 〇、一句话

**外面只许看到运行产物——源码/仓史/内部数据永不出域；对外公开=最后一步，只在 CEO 明示批准后。**

## 一、默认不可见律（闸 0）

对外面一律**白名单制**：只允许＝编译产物／容器镜像／静态资源／公开快照数据。禁止＝源码、git 目录与历史、内部数据（台账/订单/研究/规格/记忆/任务板/状态档）、策略与经营面、密钥与凭据。

## 二、打包律（闸 1·每个外部包必过）

1. **白名单构建脚本**：产物树=构建脚本**显式列入**的文件——禁直接打包仓目录、禁 exclude-list 思维（漏一件即泄露）。
2. **产物树七禁**：①`.git` ②`.env` 与一切密钥件 ③内部台账（orders/ledger/CODELY.md/HQ-FEEDBACK/backlog/state.json）④research 与 docs/spec ⑤BLUEPRINT/策略与经营面 ⑥构建缓存（`__pycache__`/`.venv`）⑦含内部路径或用户名的元数据。
3. **镜像=多阶段构建**（构建层不进最终镜像）；strip 路径与用户名。
4. **部署律**：服务器只从**私有镜像仓拉取**（禁在服务器上 clone 任何源码仓）；城市数据=`sparse-checkout` 仅 `world-public/`+census 导出路径（bootstrap citysync 已硬化 v1.2）。

## 三、三器扫描（闸 2·打包后、上线前）

1. **secret-scan**：P0=0（既有件复用）。
2. **内部面扫描**＝`Tools/release-scan.ps1`（本批新造）：对包树/镜像导出层扫「七禁清单+密钥模式+本机路径泄漏」——FAIL 即阻断（exit 2）。
3. **元数据核**：无 git 史嵌入、无 `C:\Users\` 类本机路径、无敏感时间戳面。

## 四、CEO 批准门（闸 3·最后一步）

**任何对外公开动作**——公网域名上线／私库转公开／平台发新版本／参观端开门——一律 **CEO 明示批准后执行**（批准制非报备制·批准行落 orders 台账）。
备案期 IP+自签证书试运行＝技术预演（不属对外公开），但闸 1-2 照过；先 tag 后发（发布锚律）不变。

## 五、执行面与首用例

- **首用例=服务器部署链**（购机后）：白名单镜像+三器扫描→备案期 IP 试运行（闸 1-2）→**域名公网开=闸 3 批准**。
- 各司对外打包脚本=各司自建，一律过本门（模板=本件+release-scan）。
- 过闸记录=每次发布一行（orders/司台账）；夜轮不扫（禁机制自耗）。

## 六、判据（预注册·回访）

①`release-scan.ps1` 注入测试=七禁+密钥+路径泄漏各注入一件→全 FAIL（exit 2）+清洁树 PASS（exit 0）——本批实证；②首个真实包（服务器镜像）过闸记录=部署日回访；③执法抽查=周轮随机抽一个近期对外件复扫。
