# 板块 × 小区 双层估值模型 v1 · 2026-11-16

> 执行体：`Tools/house/valuation.py`（自检 **6/6**）　数据：`hot-sectors-*.csv` + `communities-cache.csv` + `baselines.json`
> 每日：`Tools/house/daily_pull.py` 第 3/5、5/5 步（小区轮换抓 2 个板块 + 估值筛选）

## 一句话

**苏州 16 个主流板块，按公允价算净租金回报全在 0.45%–1.88% 之间——没有一个板块适合"买了收租"；排序只说明"同样租金假设下谁的价格压力最小"。**

## 一、方法：为什么这样标定才严谨

**只有平台挂牌价、没有成交价**，所以要先把"挂牌"翻译成"成交"。翻译系数只能从一个地方来：

| 标定方式 | 倍数 | 能不能用 |
|---|---|---|
| 韵佳苑：小区挂牌 17,106 ÷ 同面积段成交 14,351 | **1.19** | ✅ **同小区、同面积段、同商品** |
| 园区：挂牌加权 51,868 ÷ 成交均价 23,700 | 2.19 | ❌ **结构偏差，见下** |

**这是本轮最重要的一个坑（已写进自检的反面案例）：** 园区那个 2.19 倍看起来像"挂牌虚高 2.2 倍"，实际是两边的商品不一样——挂牌端是双湖 75,291、玲珑 65,186 的豪宅，成交端含唯亭/胜浦/娄葑的低价小户型。**拿 2.19 去除挂牌价，公允成交价会算低一半。** 所以它只作"结构差异诊断"显示，不参与任何计算。

**两层算法：**

1. **板块层**：`板块公允成交价 = 板块挂牌均价 ÷ 1.19`，区间用 1.10~1.29 给出上下限。
2. **小区层**：`小区公允成交价 = 板块公允成交价 × (小区挂牌 ÷ 板块挂牌)`。
   后一个比值是**同源同口径**，不引入跨来源误差——这是小区层能算干净的原因。
3. **投资价值**：不拍租金。用实测锚（韵佳苑 4,550 元/月 ÷ 135.15㎡ = 33.7 元/㎡/月）当全市统一租金口径，扣物业 2.05 元/㎡、维修 3%、中介半月、空置 30 天、增值税 1.5%、个税 10%，算净回报。

**外部验证（不是自证）：** 韵佳苑公允成交价 14,351 落在 20 笔真实成交的单价区间 12,953–16,438 之内；小区层算它 13,288–15,599 元/㎡，折 135.15㎡ = 179.6–210.8 万，与单房模型的合理价 178.4 万 互相印证。

## 三、小区层怎么用（以郭巷为例）

| 小区 | 挂牌 | 相对板块 | 公允成交区间 | 判读 |

| 建发独墅湾雅苑 | 26,377 | 1.21 | 20,490–24,053 | 板块内最贵 |
| 中海独墅岛 | 25,297 | 1.16 | 19,651–23,068 | 高价盘 |
| 保利悦玺 | 22,797 | 1.05 | 17,709–20,789 | 贴着板块均值 |
| 中海青公馆 | 19,750 | 0.91 | 15,342–18,010 | 中位 |
| 双湾花园 | 18,109 | 0.83 | 14,067–16,514 | 中下 |
| 万业湖墅金典 | 17,289 | 0.79 | 13,430–15,766 | 偏低 |
| **天鸿尹山湖韵佳苑** | **17,106** | **0.78** | **13,288–15,599** | **板块内倒数第二，低价盘** |
| 旭辉美澜城 | 15,413 | 0.71 | 11,973–14,055 | 板块最低 |

**结论：韵佳苑相对系数 0.78，在郭巷 12 个小区里倒数第二。** 这不是"被低估"，而是"它本来就是板块里的刚需低价盘"——与它 2016 年开盘价跌 35% 的事实一致。

**用法：** 看中某小区，用它的挂牌价跟同板块其他小区比相对系数；若某套房的报价 **低于该小区公允区间下限**，才是真便宜；落在区间内属正常议价。

## 四、每天怎么跑

1. **22:10 自动**：`daily_pull.py` 会
   - 抓官方日成交（当日终值）
   - 刷新 17 板块挂牌/在售
   - **轮换抓 2 个板块的小区**（房天下会限流，一天抓不了 17 个；缓存逐日累积）
   - 抓 2 个公众号关键词
   - 输出估值筛选 + 单房模型
2. **手动筛选**：
   ```bash
   python Tools/house/valuation.py --screen --min-yield 0.015 --min-listings 1000
   ```
3. **看单个板块/小区**：
   ```bash
   python Tools/house/valuation.py --sector 郭巷
   ```
4. **小区缓存补全**：等房天下限流缓解后，`python Tools/house/scrape_communities.py --pages 3`。缓存是**累积**的，被限流的日子不会丢数据。

## 五、失效边界（必须知道，否则会误用）

1. **租金没分化。** 全板块用同一个 33.7 元/㎡/月。真实情况是园区租金更高、相城更低，所以本表**系统性高估低价板块的回报、低估高价板块的回报**。列内排序有意义，绝对值不可当预测。
2. **1.19 溢价倍数只有一个样本（韵佳苑）。** 改善盘、豪宅盘的挂牌虚高通常更多，用 1.19 会给它们偏低的公允价。样本增加到 3 个以上小区时必须重标定。
3. **板块公允价不可与"全市二手均价 14,486"直接比。** 房天下 16 板块是核心板块集合，全市均价含吴江/相城远郊，两个宇宙不同——这正是园区 2.19 倍的成因。
4. **小区缓存目前只有郭巷 12 个**（房天下限流）。其他板块的小区层要等每日任务慢慢补，别把空表当成"没有小区"。
5. **在售套数是房天下平台自身房源，不是全市场库存。** 只能横向比"谁更挤"，不能算去化月数。

## 六、与单房模型的衔接

| 层 | 回答 | 工具 |
|---|---|---|
| 板块 | 这个板块值不值得看 | `valuation.py --sector X` |
| 小区 | 这个盘在板块里贵不贵 | `valuation.py --sector X`（小区表） |
| 房源 | 这一套的价格该出多少 | `deal_model.py` |

**三层结论必须同向**：板块综合分高 + 小区相对系数合理 + 房源价低于小区公允区间下限 → 才值得去看房。任一层不成立就放弃，不必跑完整流程。
