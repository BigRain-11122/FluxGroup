## 一句话

**自住可以接（172 万低于合理价 178 万），当投资买就别买（要房价年涨 2.5% 才够本）。**

## 一、模型长什么样

**四维体检 × 双轨定价。** 四个维度判断"这套房好不好"，两条轨道判断"这个价贵不贵"。

| 维度 | 判什么 | 判据（可验证） |
|---|---|---|
| **时间点** | 现在该不该出手 | 3 信号：库存去化月数 / 价格 3 月趋势 / 政策立场。≥2.5 可买，≥1.5 可谈，<1.5 等 |
| **板块** | 这个板块什么位置 | 在售套数 ÷ 板块月成交 = 板块去化。**缺月成交就只报位置、不给结论** |
| **小区** | 这个盘能不能流通 | 5 项：月成交 ≥3 套 / 静态去化 ≤24 月 / 房龄 ≤15 年 / 产权单一 / 无硬伤 |
| **户型** | 这个面积好不好卖 | 3 项：面积 ÷ 全市均套 ≤1.3 / 同面积段近 6 月有成交 / 总价在主流段 |

**双轨 = 本模型的核心设计。**

- **自住轨**问"比同类贵还是便宜" → 出「合理价」
  `合理价 = 同面积段成交中位单价 × 面积 × (1 − 简装 5% − 议价 3%)`
- **投资轨**问"要到手多少年化" → 出「达标需年涨多少」
  在 8 年持有、30% 首付、3.3% 利率、租金按现价下，反解使 IRR = 4% 的房价年涨幅

**为什么必须分两条**：同一个价，自住是"合理"，投资是"贵"。混成一句话就会得出互相矛盾的数——本轮之前就是这个毛病。

## 三、把之前的矛盾当场说清

之前汇报里同时出现过 **155 万** 和 **168–172 万**，看起来自相矛盾。根因是一句话里混了两个问题：

- **155 万** = 上一轮按某个目标收益倒推的"投资门槛"，口径不统一，**作废**。
- **168–172 万** = 按"比同类便宜"判的"自住出价"，对应本模型的自住轨，**有效**。
- 本轮统一到 IRR 4% 后重算，投资门槛价 = **119 万**（低于挂牌 30%，等于不现实）——所以投资结论不是"砍到某价买"，而是**"当投资就别买"**。

**以后只有两个数能用：自住合理价（178 万）和达标年涨（2.5%）。**

## 四、每天怎么用

1. **22:10 自动跑** `FluxGroup-HouseDailyPull`：官方日成交 → 平台板块 → 公众号索引 → 模型一屏，日志落 `house/realestate/logs/YYYYMMDD.log`。
2. 人工只需在换房源/换小区时改一行参数：
   ```bash
   python Tools/house/deal_model.py --price 1650000 --area 135.15 --band 128-135
   ```
3. 换了小区就改 `baselines.json` 的 `community` 段（成交中位、月成交、产权、房龄）。
4. 板块月成交一旦拿到，加 `--sector-monthly N`，板块维度就会从"—"变成真结论。

## 五、失效边界（不知道这些就会误用）

1. **房价年涨 1.5% 是假设不是预测。** 改这一个数，投资轨结论会翻转：`--years` 与 g 都在 `build_cfg` 里。
2. **不适用于**：40 年产权公寓、法拍房、有查封/共有人纠纷的房——`baselines.json` 的 `title_mixed` 只提示不拦截。
3. **板块维度目前是空的**，因为公开渠道没有板块月成交。任何"XX 板块去化 X 个月"的说法在本模型里都是不许出现的。
4. **自住合理价依赖同面积段成交样本**：128–135㎡ 段近 6 月只有 1 笔（128.91㎡ / 184 万）。**样本=1 时这个价只是方向，不是精度。** 再成交 2 笔要复核。
5. 每日任务是**登录时运行**（InteractiveToken）。机器关机或未登录当天不跑，属预期，不是故障。
