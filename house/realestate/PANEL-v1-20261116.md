# 地产线专家团 v1（席位 · 判据 · 纪律）

> 2026-11-16 立　｜　判据库：`judgment-rubric-v1.json`（47 条）　｜　执行器：`Tools/house/panel_review.py`
> 目的：把"我一个人的判断"换成"14 个席位按同一把尺子独立打分 + 反方质询"，并让每个结论都能被证伪。

---

## 一、为什么要专家团（单点判断的三类错误）

| 错误类型 | 表现 | 后果 |
|---|---|---|
| **确认偏误** | 先想买，再找理由 | 只看便宜，不看库存与流动性 |
| **口径错误** | 拿小区均价（含小户型）比 135㎡ | 得出"便宜 26%"的假象 |
| **证据不足** | 3 笔成交就下结论 | 价格锚不可靠，议价失据 |

专家团用三件事对冲：**分席独立打分**（防确认偏误）、**统一判据与阈值**（防口径错误）、**覆盖率与置信度**（防证据不足）。

## 二、14 个席位

| 席 | 名称 | 必查（3–5 项） | 否决权 | 输出 |
|---|---|---|---|---|
| **S01** | 宏观周期席 | 人口净流入、套户比、销售面积、LPR、库存去化 | — | 周期位置判断（宽松/中性/收紧） |
| **S02** | 城市基本面席 | GDP 与增速、产业密度、财政、人口结构、土地供应 | — | 城市"长期不崩"概率 |
| **S03** | 板块选址席 | 轨交 800m、通勤 30min、库存、规划新增、配套 | — | 板块评分（0–100） |
| **S04** | 小区工程席 | 房龄、容积率、车位、物业、产权性质、结构 | **产权不符即否** | 小区体检表 |
| **S05** | 房源定价席 | 三锚（租售比/同段成交/一手成本）、分位 | — | 合理价区间 + 建议出价 |
| **S06** | 改造工艺席 | 承重墙、立管、可分性、防水、排风 | **不可改即否（改造场景）** | 改造可行性 + 成本档 |
| **S07** | 租赁运营席 | 同段租金、空置天数、租客画像、定价弹性 | — | 租金区间 + 出租率假设 |
| **S08** | 财务测算席 | 月供、净现金流、IRR、盈亏平衡、敏感性 | — | 现金流与 IRR 表 |
| **S09** | 融资银行席 | 评估价、贷款成数、利率、年限、税费 | **评估价 < 成交价 10% 触发复议** | 实际首付与月供 |
| **S10** | 税务席 | 契税、增值税、个税、满五唯一、房屋性质 | — | 一次性成本与持有成本 |
| **S11** | 法务产权席 | 抵押、查封、共有、租赁权、户口 | **任一异常即否** | 产权尽调结论 |
| **S12** | 合规风控席 | 群租认定、人均 4㎡、消防、备案、物业规约 | **明确禁止即否** | 合规结论 |
| **S13** | 反方席（魔鬼代言人） | 专门找"不该买"的理由，逐条要求举证 | **可否决任何结论** | 反对意见书（必须写） |
| **S14** | 数据审计席 | 样本量、口径、时间戳、幸存者偏差、来源独立性 | **样本 < 5 笔即降级** | 证据等级裁定 |

**规则：S13 与 S14 不参与打分，只做质询与裁定。** 打分席 12 个，质询席 2 个。

## 三、评审流程（七步）

```
① 预注册    先把判断与阈值写死（"若 X 则买/不买"），再看数据
② 并行取证  各席按必查清单取数，标 A/B/C 证据等级
③ 分席打分  47 条判据，三态（过/否/未测），不猜
④ 反方质询  S13 逐条挑战："这条证据够吗？有没有反例？"
⑤ 数据裁定  S14 检查样本量与口径，决定是否降级
⑥ 加权汇总  保守分（未测按 0）+ 覆盖率 + 置信度
⑦ 出具结论  含否决项、未测清单、可证伪条件
```

**时长：单套 ≈ 3–5 小时（数据齐的话 1 小时）。**

## 四、科学纪律（六条，缺一条结论不成立）

1. **证据分级**：A=官方/实测/合同；B=多源一致/专业机构；C=单源/估算。**结论必须标最低等级**。
2. **样本门槛**：价格锚要求"同面积段成交 ≥5 笔"，否则该判据降为 C，且不得作为唯一定价依据。
3. **负控（反例测试）**：每个结论配一个反例——"如果换成同小区 84㎡，这个判断还成立吗？"不成立说明是结构性差异，不是机会。
4. **预注册**：先写"什么情况下我会买"，再看房；看完再改条件 = 自我说服。
5. **基准率**：先看"同类房源 10 套里几套能租掉/卖掉"，再看这一套。**个例再好，也受基准率约束。**
6. **可证伪**：每个结论必须写"出现什么情况，我判错了"。写不出作废条件 = 这不是判断，是信仰。

## 六、执行器用法

```bash
python Tools/house/panel_review.py                       # 用默认标的
python Tools/house/panel_review.py path/to/metrics.json  # 换标的
```

输出：逐条判定 → 层得分 → **保守分 / 已测通过率 / 覆盖率 / 置信度** → 否决项 → 未测清单 → 评级 → 可证伪条件。

**三条硬规则：**
1. **未测 ≠ 通过**：未测按 0 计入保守分。
2. **否决项未测 = PENDING**：不得签约，不管分数多高。
3. **覆盖率 <80% = C**：结论不可靠，先补数据。

## 七、本次评审结果（韵佳苑 135㎡ / 172 万）

| 指标 | 值 |
|---|---|
| 保守分（未测按 0） | **72.0 / 100** |
| 已测通过率 | 83.7% |
| 覆盖率 | **86%**（86/100 权重已测） |
| 证据置信度 | 87% |
| 否决项未测 | **3 条**：户型与产证一致、抵押查封、物业分租口径 |
| **评级** | **PENDING（否决项未测，不得签约）** |

**这就是"严谨"的样子**：分数不低，但因为有 3 个否决项没测，结论只能是"待定"，不能是"可买"。

## 八、分歧处理

| 情况 | 处理 |
|---|---|
| 两席结论冲突 | 交 S13 质询 + S14 裁证据等级；**以 A 级证据为准，不投票** |
| 证据都是 C 级 | 结论标"不可执行"，先补数据 |
| S13 反对但提不出反证 | 记录在案，不采纳，但写进"风险清单" |
| 数据缺失 >20% 权重 | 直接判 C，禁止出价 |
