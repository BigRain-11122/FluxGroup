SEC.01机体结构 · 单机点火链

一次「轮」的完整调用链——从操作系统闹钟到一次 git 提交，中间只有 五个环节：

Windows 计划任务 · Task Scheduler

闹钟层：每 10 分钟触发一次

注册为系统级任务（IgnoreNew 防重入·错峰禁补跑齐射）；执行体不是 powershell 而是 wscript 隐藏链——子进程天生无控制台窗口，全程零弹窗。

▼WSCRIPT //B //NOLOGO → POWERSHELL -WINDOWSTYLE HIDDEN
EngineTick.ps1 — 守门员脚本（纯本地·零 token）

先验三件事再点火

① 锁：上一轮还活着（锁龄 <12 分钟）就跳过本轮——防两会话重叠双写；② 闸：GateSitter 判「没活干」就熄火跳过（省下整轮模型调用）；③ 环境：CLI 路径与身份文件自检，缺件当场记账退出，不留死锁。

▼START-PROCESS → Codely CLI（工作目录 = 仓库根）
codely.exe — 无头 AI 会话（本轮的真身）

一条命令行拉起一个完整 Agent

注入整份协议导航件作为 prompt；会话内自动加载仓库根 CODELY.md 记忆、技能协议、MCP 工具桥——它不是聊天窗口，是一次「读完状态→领活→干活→提交」的封闭轮。

▼第零动作 ACTIVATE_SKILL('MINIGAME-TICK-LOOP')
SKILL.md 协议轮 · Step0 → Step7 固定顺序

探测 → 定目标 → 实现 → 门禁 → 收口

Step0 读状态机与台账锁活（绝不从头再来）；Step7 单一收口提交（产品件 + 状态手术 + 快照 + 台账行，同 commit）+ 往 ledger 写 TICK_DONE 回执。

▼四门禁 → GIT COMMIT → 台账回执
产物落盘：git + state + 台账 + 快照

轮结束 = 世界已被改写一次

提交进 git（唯一真值源）；state.json 指针前移；回执一行进 tick-ledger；看板快照覆盖式刷新——四路落盘，任何一路都能当下一轮的「读档点」。

SEC.02点火命令 · cmdarg 拆解

守门员脚本里真正拉起 AI 会话的，就是这一行（真实生产命令，路径已脱敏）：

IGNITION · EngineTick.ps1
& codely.exe
    -p  "<engine-tick-prompt.txt 全文>"   ← 协议导航件，UTF-8 单行注入
    --approval-mode yolo              ← 工具调用免审批，无人值守的前提
    --disable-next-speaker-check     ← 单轮闭环，不等下一发言人

# 工作目录 = 仓库根 → CODELY.md 记忆自动注入本会话
# stdout / stderr → tick-<时间戳>.out.log / .err.log（每轮独立日志）
# exe 路径与机器身份 ← tools\machine.json（每机一份，不入 git）
-p "<prompt>"无头一次性会话。prompt 不是一句话，是整份协议导航件：产品优先律、计分制、探测源清单、收口纪律——模型的「岗位说明书」整包注入。
--approval-mode yolo工具调用免人工审批——读写文件、跑 git、执行构建全部放行。这是「无人值守」能够成立的开关，也因此配套了下面的锁与门禁体系。
--disable-next-speaker-check单轮模式：模型输出完毕即结束进程，不会等待人类接话——轮与轮之间靠状态机衔接，不靠对话记忆。
cwd = 仓库根仓库根的 CODELY.md 记忆文件自动注入每个新会话——第 N 万轮和第 1 轮拿到同样的上下文底座，记忆不靠聊天记录，靠文件。
machine.json机器身份文件：{ machine_id, state_file, codely_cli }。同一套脚本零改动跑在三台机器上，各自读自己的身份——可携性的根。
MACHINE.JSON · 身份文件实样
{
  "machine_id":  "A",
  "state_file":  "state.json",          ← B 机 = state-b.json，各记各的
  "codely_cli":  "%LOCALAPPDATA%\...\cli\bin\win32-x64\codely.exe"
}

SEC.03排挡系统 · 两层调度

调度不是一个大管家，是两层各管各的闹钟：OS 层管「什么时候点火」，会话层管「点火之后还有哪些小闹钟」。

LAYER 1 · OS TASKS系统层：计划任务班组

  • Task Scheduler = 引擎总闸：主循环每 PT10M 一拍，IgnoreNew 防重入，触发即点火守门员
  • 注册纪律=隐藏链 + 无桌面会话（子进程零黑窗），错峰禁补跑齐射
  • 看门狗独立成班：巡全任务健康度，守夜人不参与生产
  • 节奏三档自动换挡：活跃 10 分钟 / 维护 30 分钟 / 等门轻轮（零 token 记账收口）

LAYER 2 · SESSION CRON会话层：durable cron

  • CLI 自带 cron：登记进 .codely-cli\scheduled_tasks.json，{ id + cron 表达式 + prompt } 一件一档
  • 到点自动把 prompt 注入新会话——小闹钟也能叫醒 AI（例：生成产线自检「11,36 * * * *」）
  • 与 OS 任务互补：OS 层管主干道，会话层管按分钟粒度的细分车次
  • 可一次性 / 可常驻，随协议文件走，clone 即得

▲ 本机在册任务班组（节选，23 个任务各挂一个闹钟）：

EngineTick 主循环 TickWatchdog 看门狗 TjcloudSync 每时 :13 折叠推送 EvolutionTick 每时反省 RadarTick 市场雷达 RadarDeep 深挖 GateTick 立项闸 PolicyTick 政策面 ResearchTick 调研席 RedlineAudit 红线审计 AuditTick 审计轮 Housekeeping 周日清扫 CockpitBeat 心跳班报 DailyDigest 日报 EditorSentry 编辑器哨 OllamaServe 本地模型 KeepWarm 模型保温 硬杀律 20min taskkill /T 全树 锁窗 12min 新鲜锁 + 5min 续锁

FAIL-SAFE · 三道保险轮子失控怎么办

  • 20 分钟硬杀：超时会话 taskkill /T /F 连子进程整树击杀——不给僵尸留门（孤儿子体会背着主进程的尸体继续写盘）
  • 击杀记 EXIT_254 哨兵码入账——审计规则一眼可扫
  • 锁 12 分钟自然过期：崩溃当场没人收尸也不怕，下一轮自动接管

TOKEN ECONOMY点火闸：没活不开机

  • GateSitter 前置闸：无在途活、无新订单、无旗标 → 守门员直接熄火
  • SKIP 轮只写一行账，模型调用零消耗——等门态近零成本
  • 省钱不省哨：跳过的只是模型会话，脉冲 / 探测 / 锁保活照跑，状态永远新鲜

SEC.04联机组网 · 跨机器结构

三台机器不装中央调度器，git 仓库就是消息总线——分支即频道，提交即通信：

军团机（B / C /…）· 每轮收口

只推自己的频道，永不碰主线

收口四步：fetch → merge 主线 → 定向 commit → FleetPush 推 machine/<id> 分支。因为永远只有本机写自己的分支，推送被拒在结构上不存在——机器扩到 N 台也不冲突。

▼PUSH ORIGIN MACHINE/<ID> — 各机独立频道
远端仓库 · machine/* 分支族

每台机器一条流水线记录

分支 = 该机的「交作业本」：完整历史、时间戳、批次号。判他机实况一律读远端 refs，不信本地缓存——共享快照设计上允许陈旧。

▼总控机每小时 :13 折叠（FOLD）
总控机（A）· master 唯一写手

:13 折叠车道：把所有分支并入主线

每小时合并全部 machine/* 入 master 再推送——全仓库只有一个写手碰主线。真冲突只在这里出现一次，落 merge-needed.flag 旗，交由下一轮行级手术保双方，绝不互相拒收。

▼PULL MASTER — 全员读同一真相
全员 · 下一轮 Step0

拉到新世界状态，继续干活

每轮开工先 fetch：他机成果、新订单、协议变更一次到齐。机器之间没有一条直连消息——全部通过 git 对象与约定文件交换，离线也能各干各的。

ARBITRATION防撞三层

  • 登记簿＝唯一仲裁面：每款每车道唯一 owner，认领行带时间戳——双机同款 = 事故，撞车后到者让路
  • 状态分治：A 写 state.json、B 写 state-b.json，互只读；根级统计件总控独占写，他机走本地件 + 摘要行
  • 在飞互查：动手前扫他机分支近窗日志与协作看板——三源查重（看板 + 登记簿 + 分支 log）确认无人做同件

PROTOCOL RULES联机纪律

  • 传输铁律：新机接入只走 git clone，禁拷目录——锁文件与运行态是「毒拷贝」
  • 身份不入库：machine.json 本机私有（防跨机合并静默覆写）；大件走内网点对点通道，不进 git
  • 资源台账：每机只写自己的 fleet/<机id>.json（CPU/GPU/在途负载 + verdict 容量判定），全队可读零冲突
  • 让路律：老板要用机器 → 一键 pause（生产全停、值守保留）；「全面开工」→ resume 广播

SEC.05频道系统 · 跨会话沟通

同一台机器上跑着两种 AI：有人在键盘前的交互会话，和无人值守的车道轮。它们不共享对话，靠三样东西说话：

CH.A · LOCKS锁与退避：谁在干谁说了算

  • 同仓单执行体：动手前查锁——引擎锁 / 工程认领 claims / git 在途态，有人在做就退让
  • 车道轮收口前识别「他人在途态禁碰」——交互会话与自动化互不踩脚，git 锁竞争一律让路不硬抢
  • 工程级 claims：动某款前先原子认领，同款单执行体

CH.B · MAILBOX文件信箱：追加即通信

  • 反馈队列：他机审计发现追加进队列文件，总控轮每轮开箱必扫——审计结果跨机自动回传
  • 协作看板：每机维护自己的行（正在干 / 最近交付 / 下一步）——互相看见，互相避让
  • 订单信箱：CEO 令落 orders 文件 → 各机轮内认领 → 回执核销——命令流也是文件流

CH.C · MEMORY记忆总线：轮与轮怎么「认识」彼此

  • CODELY.md 每会话自动注入——无头轮不靠聊天历史，靠这份活的岗位记忆（历史判例 / 红线 / 项目状态指针）
  • 台账 append-only 永不滚删——任何一轮都能被事后审计

CH.D · TWO BODIES两种执行体的分工

  • 交互会话（有审批弹窗）：接新任务、立项、对外沟通——「外交官」
  • 无头车道轮（yolo 全放行）：在册项目的常规迭代独占——「厂线工人」；外交官不抢工人的活，工人不等外交官

SEC.06存档系统 · 断点续跑

全套体系最关键的一格：任何一轮被拔电源，下一轮 10 分钟内原地满血。秘密只有一个文件 + 三级指针。

SAVE FILE · state.json（状态机正身·节选）
{
  "schema":      "minigame-engine-loop/state",
  "machine_id":  "A",
  "mode":        "normal_iteration",      ← 10 分钟 / 30 分钟档位在档
  "trigger": {
    "interval_minutes": 10,
    "scheduled_task":   "MiniGameEngineTick"
  },
  "projects": { "P0X": { "stage": "S3", "next_action": "…",
                 "blocked_on": "等素材", "evidence": "…" } }
}                        ← 每款一张「进度卡」：阶段 / 下一步 / 阻塞因 / 证据

POINTERS · 三级指针进度写在文件里，不写在脑子里

  • 款级：每款 stage 卡（阶段 / 下一步 / 阻塞因）——开局先读卡判阶段
  • 车道级：雷达 / 审计 / 立项各自的位置与到期
  • 事务级：【StepX 完成】标记逐笔入 tick-ledger——干到哪步，白纸黑字

RESUME · 续跑三律读档规则

  • 指针在 = 从指针处续跑：禁重推已过段、禁复跑已过门禁
  • 指针悬空（写了意图没写结果）= 按意图补跑或回滚——write-ahead 痕迹本身就是证据
  • 控制 = 改指针，不是把流程重讲一遍

CRASH RECOVERY崩溃自愈链

  • 断电 / 硬杀 → 锁 12 分钟自动过期 → 下一轮 Step0 探测接管
  • state_guard 摘要四件：快照 ID / 基线 / 上一轮结果 / 回滚标记——读档只要三秒
  • 段级回滚：每段收口 commit 即存档点，炸段只回滚本段，前段成果无损
  • 失败预算：段内返工 ≤2 轮，超限熔断降级——不在死胡同里烧机器

CHECKPOINTS长活防丢

  • 批号原子认领（号池先占后用）——两轮不会抢同一个批号
  • 长批（≥40 分钟）逐里程碑检查点提交：crash 损失 ≤1 个里程碑
  • 成功神谕：EXIT 码 + TICK_DONE 台账增量 双证判死活——进程退出码会撒谎，台账 delta 不会

SEC.07仪表盘 · 每轮一行回执

无人值守 ≠ 黑箱。每一轮留下一行可机读的账，三条实样（真实台账脱敏节选）：

TICK-LEDGER · 本轮真实回执
2026-10-15 17:27:00 | tick 20261015-171704 | EXIT_254_nullcode DONE_SEEN | out=.codely-cli\engine-tick\tick-…out.log
2026-10-15 17:27:30 | tick-skip 20261015-172730 | GATESIT_SKIP quiet-no-flags-no-open-orders | out=none
[2026-10-15 17:25:44] X2589 TICK_DONE GateSitter fold C1962 收口（merge 双亲拼接+三冲突行级手术+…）| next: 下轮常规开发候选

时间 | 批号 | 退出码+完成标记 | 日志指针 —— 一行就是一次心跳，可审计可告警可回溯

VISIBILITY三张实况面

  • 快照看板：每 10 分钟覆盖式重写 + 他机摘要行——人类一眼看全局
  • 本机看板行：当前活 / 最近实物 / 下个里程碑（≤48h）三行——过程可见
  • 哨兵：5 分钟一拍自检，闲旗 / 危旗两级熔断标记

SCORING · 防空转产出计分制

  • 能跑 / 能看 / 能用的实物 = 2 分；实际文件改动 = 1 分；纯记账 = 0 分
  • 连续 24 小时全部 0 分 = 空转判负，值守轮点名
  • 完成判据 = 验收清单全过才准宣称完成——没过就如实记未完成
